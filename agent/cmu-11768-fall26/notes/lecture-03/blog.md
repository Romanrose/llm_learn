# 当智能体的历史越来越长：CMU 11-768 Lecture 3 的上下文管理笔记

> 来源：平台字幕与官方 Slides。内容已由用户审核确认。

一个编码智能体连续工作一整天，会发生什么？它不会突然变笨，但它会开始忘记你半小时前说过的约束，会重复提交同一个功能，会在压缩上下文之后把“不要删除这个文件”抛到脑后。CMU 11-768 Fall 2026 的第三讲讨论的正是这件事：智能体的历史在自然增长，而我们需要一整套从模型架构到缓存策略再到上下文压缩的机制，让它在这个增长过程中仍然可工作、可负担。

本文依据该讲的官方 Slides（Lecture 3 slides）与逐字稿整理稿整理，Slides 页码均在关键论点后标注；逐字稿为机器翻译整理稿，引用其内容时视为“课堂讲述”，不作为官方结论。本文内容已由用户审核确认。

## 一、问题：线性增长的历史，平方增长的输入

先看一个最朴素的算术。Slides 第 3 页给出了一张表：如果每次调用大约消耗 5K token，加上固定的初始前缀 1K，那么第 1 次调用输入 6K，第 2 次 11K，第 3 次 16K，第 4 次 21K，第 5 次 26K；而累计消耗分别是 6K、17K、33K、54K、80K。也就是说，单次调用的输入随步数线性增长，累计消耗随步数平方增长（Slides 第 3 页）。

课堂上的口头版本用的是 5 个 token 起步的玩具数字，讲的道理一样：如果完全朴素地把整个历史一遍遍塞回去，成本会很快变得不可承受。讲者提到自己做过持续好几天的编程智能体会话（逐字稿 [02:02] 附近）。

那真实智能体的提示到底由什么组成？Slides 第 4 页给了一份对 OpenHands 1500 个会话的统计：平均每会话 77,922 个 token，其中系统提示加工具描述占 23%，用户消息 9%，推理轨迹 9%，模型直接回复 2%，工具调用 20%，工具结果 37%（Slides 第 4 页）。课堂上的补充是：这些会话大多只是解决单个任务，并不是持续多天的长会话；系统提示本身在 15K–18K token 量级，因为 OpenHands 对“人应该怎么做事情”有很多主张（逐字稿 [03:00]–[03:48] 附近）。

这个构成比例值得记住：真正的“对话内容”占比并不大，大头是系统提示、工具调用和工具结果。也就是说，即便用户只说了一句话，智能体的上下文也可能已经很胖。

Slides 第 5 页把长上下文问题拆成两个挑战（Slides 第 5 页）：

- **容量（Capacity）**：模型能不能真正用上所需要的证据？这由架构、位置编码和训练共同决定，并且需要评估来度量。
- **效率（Efficiency）**：系统是否负担得起服务它的成本？这由注意力、KV 内存、缓存和压缩共同决定，影响成本和延迟。

本文的结构基本沿着这两条线展开：先讲架构如何降低注意力的二次代价，再讲训练长上下文模型难在哪里，然后是 KV 缓存这条工程主线，最后是上下文压缩——也就是当你已经用尽上述手段之后，还能怎么继续。

> **学习者解释**：可以这样理解“容量 vs 效率”的分工：容量问题问的是“模型看不看得见远处的那根针”，效率问题问的是“让它看一遍要花多少钱”。两者常常互相拉扯——把窗口开大有益于容量，但直接推高服务成本。

## 二、推理的两段式：prefill 与 decode

要谈效率，先要谈推理本身怎么跑。Slides 第 7 页给出服务栈的最小图景：请求进入调度器，调度器负责排队、组批、路由，同时读写 KV 缓存；随后模型先做 prefill，再逐步 decode，最后流式返回（Slides 第 7 页）。

Slides 第 8 页把两个阶段拆得很清楚（Slides 第 8 页）：

- **Prefill**：处理全部提示位置，计算量密集，延迟随提示长度增长；输出是每个位置上的 K、V。
- **Decode**：每步只处理一个新位置，是顺序的、受内存带宽限制的，每个输出 token 一步。

Slide 上的描述是：prefill 是 compute-intensive，decode 是 sequential and memory-bandwidth-intensive。这个区分在后面反复出现——缓存省的主要是 prefill，而 decode 的代价与输出长度挂钩。

Slides 第 9 页给了四个服务指标（Slides 第 9 页）：TTFT（arrival → first token）、TPOT（输出 token 之间的间隔）、吞吐（完成的 token 或请求除以墙钟时间）、成本（输入 + 缓存输入 + 输出）。

> **学习者解释**：TTFT 对应的直觉是“我打完字要等多久才开始看到回答”；TPOT 对应“回答吐字有多快”。课堂上提到交互式编程时用户会同时在意这两个，而后台跑通宵任务时可能完全不在意，并且服务商常常会问客户更在意哪个，以便针对性优化（逐字稿 [10:02]–[10:27] 附近）。同一张 slide 的脚注指向 DistServe（OSDI 2024）作为 prefill/decode 执行模型的来源。

## 三、标准注意力为何不可持续

Slides 第 10 页是注意力复习：Q、K、V 由 X 做线性投影得到，加因果掩码后做 softmax，得到输出（Slides 第 10 页）。Slides 第 13 页点明问题：标准注意力在整个序列上做两两比较，因此代价是二次的（Slides 第 13 页）。

课堂上的口算版本是：如果目标是 100 万 token 的上下文，两两比较数量级在 10¹²（一万亿）次，而每次比较还要乘大向量，单个序列的总量级会到 10²⁰ 上下（逐字稿 [15:07]–[16:01] 附近）。这里的具体量级属于课堂上口头估算，不是 Slide 上的数据。

Slides 第 11 页展示了那张经典的“大海捞针”图（GPT-4 版本，引用 Kamradt 2023），用来提醒：模型宣称支持的上下文长度，和它实际上能有效利用的长度，是两回事（Slides 第 11 页）。课堂上讲者说这个评估“非常奇怪”：拿一堆 Paul Graham 的文章，塞进“旧金山最好的三明治店在哪”这句话，再问模型这个位置（逐字稿 [12:09]–[12:55] 附近）；类似的基准还有 RULER 和 HELMET。

> **学习者解释**：这张图之所以反复被引用，是因为它把一个容易被忽略的区别可视化了：context window 是接口规格，effective context 是行为表现。Slides 第 11 页的标题就是“Advertised vs. effective context”。

## 四、架构：把二次比较限制成常数上限

Slides 第 14 页给出核心思路：把 O(n²) 变成 O(wn)，其中 w 是局部窗口大小；对常数 w，工作量对 n 是线性的（Slides 第 14 页）。注意 Slide 的措辞：w 不一定非得是“窗口”，它只需要是比较数量的上限。

Slides 第 15 页描述混合模型的结构：若干次便宜的局部状态更新（local），中间插入一次全局计算，从完整历史中检索，然后重复（Slides 第 15 页）。用课堂上的说法：“如今广泛流行的几乎所有模型，都是某种混合模型”（逐字稿 [17:00] 附近）。

Slides 第 16 页列了六个模型的局部/全局配比（Slides 第 16 页）：

| 模型 | 局部/有状态计算 | 全局计算 | 比例 |
|---|---|---|---|
| Qwen3.8-Flash-Next | Gated DeltaNet | QSA 稀疏检索 | 36:12 ≈ 3:1 |
| GLM-5.3-Flash | Kimi Delta Attention | DSA + IndexPool | 34:11 ≈ 3:1 |
| Kimi K3 | Kimi Delta Attention | dense Gated MLA | 69:24 ≈ 3:1 |
| Nemotron 3 Ultra | Mamba-2 | dense GQA | 48:12 = 4:1 |
| Inkling-Small | 512-token window | dense GQA | 35:7 = 5:1 |
| DeepSeek-V4-Pro-0813 | 128-token window 分支 | compressed sparse / dense 交错分支 | （Slide 未给比例） |

（表内数字直接来自 Slides 第 16 页；具体模型的规格细节不在本讲范围内展开。）

Slides 第 17 页总结了四种反复出现的机制：滑动窗口注意力、线性注意力或循环模型、稀疏注意力、KV 压缩（Slides 第 17 页）。下面逐个看。

### 4.1 滑动窗口注意力

Slides 第 18 页给出的机制非常朴素：沿用同一个注意力公式，只是把可见范围限制为最近的 w 个因果位置，代价从 O(n²) 降到 O(nw)（Slides 第 18 页）。它的明确缺点是：一个局部层无法直接检索到远处的 token。

课堂上补充了一个重要细节：由于层叠效应，第一层只能从相邻块拿信息，但上一层已经携带了更早块的信息，于是窗口在深层“逐渐扩展”（逐字稿 [19:42]–[20:08] 附近）。

### 4.2 从线性注意力到 KDA

Slides 第 19–20 页串起了一条推导链（Slides 第 19、20 页）。标准形式的输出是先算归一化的因果注意力权重 a_ti，再加权求和 v_i。线性注意力的关键一步是：把 query 归一化的 softmax 权重换成双线性得分，这样求和就可以重新结合，得到一个固定大小的循环记忆 S_t，并可以写成 S_t = S_{t-1} + k_t v_tᵀ 的增量更新，输出变成 o_t = S_tᵀ q_t。

Slide 的注释写得很直白：这样做“让 softmax 可以重排”，但代价是“additive writes · interference is not explicitly erased”——写入是加性的，干扰不会被显式擦除（Slides 第 20 页）。

> **学习者解释**：可以把它理解为把“每次都要翻遍全部历史做对比”换成“维护一个会不断被写入的状态表”。好处是每步更新时间恒定，坏处是这张表不能像 softmax 那样精确地挑出“最相关的那几个”，它只是把所有写过的键值混在一起。

Slides 第 21 页是 DeltaNet：既然加性写入会累积干扰，就改成只写“预测误差”。幻灯片给出 v̂_t = S_{t-1}ᵀ k_t，e_t = v_t − v̂_t，S_t = S_{t-1} + β_t k_t e_tᵀ，其中 β_t ∈ [0,1] 是修正强度（Slides 第 21 页）。Slide 的原话是“correct along k_t · unrelated memory persists”——沿着 k_t 修正，不相关的记忆保持不动。

Slides 第 22 页加入标量遗忘门：先把整个状态按 α_t 衰减，再做同样的定向修正，α_t = 1 时退化为 DeltaNet（Slides 第 22 页）。Slide 上把 α_t 称为 global retention，β_t 称为 targeted edit。

Slides 第 23 页是 Kimi Delta Attention：把标量遗忘换成逐通道的对角阵 D_t = Diag(α_t)，每个键空间特征有自己的记忆寿命；每个通道保留相同程度时退化为 Gated DeltaNet（Slides 第 23 页）。

课堂上讲 DeltaNet 的直觉是：你在减少“预测当前 value”的误差，β 类似于学习率，控制单次更新不要太大；衰减项则是为了防止很久以前的某个奇怪 key 对未来的预测产生过大影响（逐字稿 [25:30]–[29:17] 附近）。这一段的数学细节在课堂上被明确说成“高层次”的，并指向原始论文。

### 4.3 稀疏注意力

Slides 第 24 页对比了两种稀疏方式（Slides 第 24 页）：

- **固定模式**：与输入无关，可见集合 S_i^fixed 是“最近的 w 个位置”加上固定的全局位置集合 G；代价可预测，但模式无法适配查询。脚注指向 Longformer（2020）。
- **内容相关**：S_i^dyn = TopK_j≤i g(q_i, k_j)，由学习到的选择器决定，具有自适应性，但选择器出错就会漏掉相关键。脚注指向 DeepSeek Sparse Attention（2025）。

两者都要在保留集合上重新归一化。

课堂上补充了两种实现味道：一种是每 512 个 token 左右做一次稀疏注意力，仍然是二次的但系数小很多；另一种是先用量非常廉价的注意力（比如把向量降投影得很小）选出 top-k，再对 top-k 做完整注意力（逐字稿 [31:37]–[32:43] 附近）。有听众追问相似度度量是不是余弦距离，讲者回答说通常就是点积，但是否预先归一化“我其实不知道那个细节”（逐字稿 [32:43]–[33:10] 附近）——这是一个明确承认不确定的地方。

### 4.4 KV 压缩

Slides 第 25 页给出 MLA 的形式：缓存一个潜在向量 c_t^KV = W^DKV z_t，再从它恢复出每个头的 k 和 v（Slides 第 25 页），脚注同时指向 GQA（Ainslie et al., 2023）和 DeepSeek-V2（2024）。

课堂上用更口语的方式解释了这条路线的两种做法（逐字稿 [34:04]–[35:57] 附近）：分组查询注意力（GQA）减少键和值的头数（常减少 4 倍或 8 倍），因为缓存的是 KV 不是 Q；多查询注意力是 GQA 只有一组时的特例；多头潜在注意力（MLA）不减少头数，而是把每个头的维度压小；两者也可以叠加。

## 五、训练长上下文：数据比架构更难

Slides 第 27 页给出经典的三段式路线（Slides 第 27 页）：短预训练（4K–8K，数据充足、成本低）→ 继续训练（32K–128K，长文档、打包序列）→ 长适配（128K+，任务轨迹、合成课程）。

课堂上强调了一点幻灯片没说的：互联网上并没有那么多连贯的 128K token 数据，这差不多是一本书的量级；而序列打包虽然提升效率，却不是在学跨文档注意力，甚至可能不该学（逐字稿 [36:22]–[37:33] 附近）。

Slides 第 28–30 页讨论位置编码（Slides 第 28、29、30 页）：绝对位置编码把位置向量加在进入第一层之前；RoPE 旋转 Q 和 K，使得分只依赖相对位移；NoPE 则完全不加显式位置。Slides 第 30 页还有一句关键澄清：NoPE 移除了位置外推问题，但并没有移除“训练长程行为”的需要。

课堂上有一个很值得记的问答：为什么现在因果 Transformer 可以不用位置编码？听众回答“因为我们做因果掩码”，讲者确认并展开——位置 2 的“猫”只注意前一个 token，位置 5 的“猫”注意前四个，它们从注意力第一层起嵌入就不同了（逐字稿 [40:50]–[41:45] 附近）。讲者同时指出，非自回归 Transformer 仍然需要位置编码。

Slides 第 31 页讲位置插值：把 RoPE 的每个维度统一拉伸 s = L′/L，让长位置落在预训练见过的相位范围内（Slides 第 31 页）。Slides 第 32 页讲 YaRN：按波长选择性插值，长波长完全插值，短波长保留局部相位，并加一个注意力温度修正；Slide 明确提醒“τ 的公式是在 LLaMA 模型上拟合的，是配方不是通用常数”（Slides 第 32 页）。

Slides 第 33 页列了各模型的具体扩展路径，例如 Qwen3.8-Flash-Next“262K native；完整课程未披露，partial RoPE，YaRN 扩展到 1M”，GLM-5.3-Flash“1M native；精确课程未披露，主注意力用 NoPE，不做 RoPE 重缩放”，Kimi K3“8K → 64K → 256K → 1M，NoPE”（Slides 第 33 页）。这里“未披露”是 Slide 自己的措辞，值得注意。

Slides 第 34 页给出长上下文数据来源：长文档（书、代码库、仓库、多文档语料）、打包样本、智能体轨迹、合成任务（Slides 第 34 页）。Slides 第 35 页对比了各模型的数据混合，并总结出共同的配方：连贯的长来源 + 依赖远处证据的任务 + 渐进的长度增长（Slides 第 35 页）。

课堂上还坦率地讲了为什么这部分细节少：开源模型必须公布架构才能被运行，但数据混合和训练策略是保密的（逐字稿 [47:59]–[48:47] 附近）。

Slides 第 36 页是上下文并行：显存按设备分摊为 O(n d_k / P)，通信与块注意力重叠，总计算量仍是 O(n² d_k)，是精确而非稀疏的（Slides 第 36 页）。课堂上说它大约在超过 32K 上下文之后开始变得重要，但也很麻烦，因为基础设施团队得为非标准注意力实现对应的并行 kernel；讲者举了自己想给一个较小的 Qwen 模型用上下文并行，却发现“互联网上任何地方都没有用于门控 delta 网络的 kernel”的经历（逐字稿 [49:59]–[51:41] 附近）。

## 六、KV 缓存：智能体 harness 作者最该关心的一段

Slides 第 38 页画出了多次调用之间的复用结构（Slides 第 38 页）：第 1 次调用做 prefill 建立 KV；输出在 decode 期间扩展缓存；第 2 次调用时工具结果作为新输入返回，但可复用的前缀（cached）不必重算；如此往复，前缀不断增长。

课堂上把这个账算得更直白：到第 50 步时，如果不做缓存处理，输出相关的部分会比新输入大 50 倍（逐字稿 [53:49] 附近）。（这是课堂上的量级示意，不是 Slide 上的实测数字。）

Slides 第 39 页给了两条脚注式结论（Slides 第 39 页）：Prompt Cache 那条说“计算增长比加载缓存注意力状态更快，交叉点取决于硬件”；“Can I Buy Your KV Cache?”那条说“一次性 prefill 被多个读者摊薄，单次调用成本趋近复用步的下限”，并明确区分“实测物理成本”和“服务商 API 价格”是两个不同的量。

Slides 第 40 页是价目表：列出多个模型的缓存输入 / 常规输入 / 输出价格（美元每百万 token，价格检查日期为 2026 年 8 月 30 日），例如 GLM-5.2 是 $0.26 / $1.40 / $4.40，Kimi K3 是 $0.30 / $3.00 / $15.00，Claude Opus 5 是 $0.50 / $5.00 / $25.00（Slides 第 40 页）。Slide 注明“cached”指缓存读取/命中，缓存创建可能另行计费。

课堂上据此给了一个经验规则：通常缓存 token 的价格是未缓存 token 的十分之一，所以你必须非常在意你的 token 有没有被缓存；被问到好的缓存命中率是多少时，现场给出的答案是 80–90%，讲者补充说自己觉得 90–95% 就没什么问题（逐字稿 [54:44]–[56:03] 附近）。

接下来是两条开源服务库的技术主线：

- Slides 第 41 页：分页 KV 缓存分配，块表翻译，出自 vLLM / PagedAttention（Kwon et al., SOSP 2023）（Slides 第 41 页）。
- Slides 第 42 页：RadixAttention 前缀共享，包含“匹配复用前缀并追加后缀”“分裂共享公共前缀”“按 LRU 驱逐叶子”三步，出自 SGLang（Zheng et al., 2023）（Slides 第 42 页）。

Slides 第 43 页是缓存感知路由：请求带前缀哈希 A 进入缓存感知路由器，评分 = 可复用前缀 − 队列惩罚，然后在“匹配 18K、队列 2”和“匹配 2K、队列 0”的 worker 之间选择（Slides 第 43 页）。

Slides 第 44 页给出面向缓存复用的提示设计原则（Slides 第 44 页）：稳定前缀（指令、工具、示例）、把变化的状态追加在后面、避免无谓扰动（时间戳、重排 schema）、度量复用（缓存 token、TTFT、驱逐）。

课堂上对“避免无谓扰动”给了一个具体例子：不要把当前时间日期拼进系统消息，因为它每步都在变，会破坏缓存；如果确实需要，就附加到最后一条用户消息或最后一条工具结果上（逐字稿 [01:04:24]–[01:05:18] 附近）。课堂上还提到中途动态更换工具是可以的（那没问题），但频繁换模型来省钱要非常节制，因为下次回到贵模型时该付的还是要付（逐字稿 [01:05:18]–[01:06:09] 附近）。

关于缓存驱逐，课堂上说服务商不会永远保留你的缓存，有人答“接近一小时”，讲者回应说自己知道 Anthropic 以前是 5 分钟，现在至少有延长到一小时的选项但可能略贵一点（逐字稿 [01:01:52]–[01:02:11] 附近）。有听众问是否存在缓存分层（快速设备缓存 + 慢速磁盘缓存），讲者回答“我实际上不知道那个问题的答案”，并表示这是很好的后续研究问题（逐字稿 [01:02:54]–[01:03:17] 附近）；另一位听众补充“他们通常从 GPU 卸载到 CPU”，讲者确认“是的，因为 GPU 内存太宝贵了”（逐字稿 [01:03:54] 附近）。

> **学习者解释**：把这些串起来，harness 作者的实操含义是——缓存只在“整个前缀逐字节相同”时才命中。因此系统提示、工具 schema、示例这些应当逐字不变；任何随时间变化的东西（时间戳、随机 ID、动态重排）都应当往后放，或者干脆不要放进前缀。

## 七、上下文压缩：当缓存也救不了你

Slides 第 46 页给了一个例子（Slides 第 46 页）。压缩前有四条观察：CI 任务 30 分钟后超时；检查 job log；24K 行日志里反复出现“address already in use”；设置 --workers=1 后重跑；套件通过，日志存在 /tmp/ci.log。压缩后变成：目标、原因、已验证的设置、证据路径，以及下一步动作。

Slides 第 47 页把它形式化为状态估计（Slides 第 47 页）：历史 H_t 经压缩器 C 得到工作状态 ŝ_t，约束是 |ŝ_t| ≤ B；目标是让未来动作的分布近似不变，即 p(A_future | H_t) ≈ p(A_future | ŝ_t)。

Slides 第 48 页列了压缩中各类信息的去向（Slides 第 48 页）：

- **精确保留**：锚点（目标、约束）
- **编码**：检查点（决策、进度、ID）
- **精确保留**：近期尾部（当前尝试、最新结果）
- **外部化**：证据存储（24K 行日志 → 3 个失败 + 命令 + 产物路径）
- **丢弃**：重复项、已被取代的尝试

课堂上提醒了一件事：完整历史通常还是会保存在磁盘上，所以即使压缩丢掉了内容，你仍然可以让智能体回去读历史文件；而一些好的 agent 框架会有意避免删除会话最开头的内容（逐字稿 [01:09:03]–[01:10:09] 附近）。

Slides 第 49 页把压缩策略拆成四个决策（Slides 第 49 页）：

1. **触发**：token 阈值 / 服务商溢出 / 手动请求；要为下一次输出预留空间。
2. **选择**：保护开头、压缩较旧区域、保留近期尾部；在有效的轮次或工具边界处切分。
3. **替换**：可读摘要 / 结构化检查点 / 不透明的服务商条目 / 全新上下文。
4. **恢复**：保持历史不变 / 重试或重置 / 保留可检索历史；并定义压缩失败时的行为。

课堂上补充说触发条件里有一种是“服务商强迫你这么做”，那差不多是硬性上限；很多编码智能体有 /compact 这类命令；摘要有时要求某次工具调用必须包含某些字段，有时就是自由文本；讲者还提到似乎只有 OpenAI 会把内容压缩成加密形式，让人读不到它的算法（逐字稿 [01:10:42]–[01:11:53] 附近）。

Slides 第 50 页讲重复压缩的漂移（Slides 第 50 页）：历史里的“Use CUDA 12.4”经过一次摘要变成“Use CUDA 12.x”，再过一次变成“Use recent CUDA”，最后约束消失。Slide 的公式是 ŝ_{k+1} = C(ŝ_k ⊕ R_k)——每次更新都继承上一个检查点。旁边的对策和 Slide 48 一致：精确复制锚点、保留近期尾部、检索源证据。

课堂上讲的真实故事很能说明问题（逐字稿 [01:12:22]–[01:14:03] 附近）：他们做了可能是最早的接近生产级的压缩算法，在 SWE-bench 上花了一个月左右，找到的策略完全不降低分数还省了很多 token；但放进真实系统后，它开始犯特别傻的错误，比如每次压缩就发一个 pull request——它忘了自己已经往 GitHub 发过了，于是同一个功能收到五个 PR；或者忘掉对话中途发来的用户指令，因为评估只在单条用户消息的对话上做过，而压缩时把多条用户消息压掉了。结论是：光做基准测试不够，除非基准测试极其健壮，否则还是需要在真实环境里测试。

> **学习者解释**：这个例子的教训不在于“压缩不好”，而在于“离线指标与在线行为之间存在系统性落差”。SWE-bench 这类基准往往只覆盖单轮或有限交互模式，而漂移恰恰发生在多轮、长周期、有外部副作用（发 PR、删文件）的场景里。

Slides 第 51 页给出基于延续的评估方法（Slides 第 51 页）：种入状态（约束、决策、产物）→ 应用生产压缩策略 → 继续 → 测量后续决策；四个度量维度是状态召回、任务成功、效率（token + 延迟 + 成本）、稳定性（重复压缩）。

## 八、收束：五层栈

Slides 第 53 页把整讲压成五层（Slides 第 53 页）：

1. **增长**：智能体循环反复摄入指令、动作和环境观察。
2. **推理**：prefill、decode、密集注意力和 KV 内存制造了不同的瓶颈。
3. **架构**：局部、循环、稀疏和压缩机制决定了哪些历史仍然可访问。
4. **缓存**：稳定前缀避免重复 prefill，但不减少可见历史。
5. **压缩**：保留意图、精确任务状态、近期工作和恢复路径——然后评估延续性。

第 4 条里的“但不减少可见历史”值得单独强调：缓存解决的是成本，不是容量。一个上下文已经超过有效窗口的智能体，即使缓存命中率 95%，也仍然会忘记东西。

Slides 第 54 页标注下一讲是 Agent Capabilities 3 — Skills and Memory（Slides 第 54 页）。课堂上有人问 sub agent 是否算一种上下文管理方式，讲者回答“是的，但我们后面会讲 sub agent，所以这次没有涵盖它们”（逐字稿 [01:14:52] 附近）。
