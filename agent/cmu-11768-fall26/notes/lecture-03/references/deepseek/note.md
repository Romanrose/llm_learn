## 一、学习目标

学完本讲后，你应当能够：

1. **解释智能体上下文为何快速增长**：从“线性增长的历史 → 平方级的输入/注意力计算”这一基本事实出发，说明长上下文是智能体系统的结构性问题，而非偶发工程问题（Slides 第 2–4 页）。
2. **区分长上下文的两个核心挑战**：容量（模型能否真正用上证据）与效率（系统能否负担服务成本），并知道各自对应的技术族：架构、位置编码、训练 vs. 注意力、KV 内存、缓存、压缩（Slides 第 5 页）。
3. **描述推理服务的阶段与指标**：prefill / decode、KV cache、TTFT、TPOT、吞吐、成本，并说明它们为什么决定智能体体验（Slides 第 7–9 页）。
4. **说出四类长上下文架构机制**：滑动窗口注意力、线性注意力/循环模型、稀疏注意力、KV 压缩，并解释它们在“可访问历史”上的取舍（Slides 第 17–25 页）。
5. **理解长上下文训练的三段式路线**：短预训练 → 继续训练 → 长适配，以及位置编码（绝对、RoPE、NoPE、位置插值、YaRN）在其中的作用（Slides 第 27–33 页）。
6. **掌握 KV/前缀缓存的工程要点**：为什么稳定前缀能省钱、哪些操作会“破坏缓存”、缓存感知路由与逐出策略如何影响命中率（Slides 第 38–44 页）。
7. **把上下文压缩理解为状态估计问题**：用行为保真、表示有界、可恢复性三条约束来设计压缩策略，并知道如何用“继续式评估”衡量它（Slides 第 46–51 页）。

## 二、概念主线：一条从“增长”到“压缩”的因果链

本讲的主线可以概括为：

**增长 → 推理瓶颈 → 架构选择 → 缓存复用 → 压缩兜底**

- **增长**：智能体循环不断把指令、动作、环境观察塞回上下文。Slides 第 3 页给出一个极简算例：固定前缀 + 每次新增历史，调用 1–5 的输入从 6K 增到 26K，累计从 6K 增到 80K。逐字稿里讲师用更小的数字（1、6、11、16、21、26）讲同一件事：**调用次数线性增长，累计输入平方增长**。
- **推理瓶颈**：prefill 计算密集、延迟随提示长度增长；decode 顺序执行、受内存带宽限制（Slides 第 8 页）。TTFT 对应 prefill，TPOT 对应 decode（Slides 第 9 页）。
- **架构选择**：标准注意力是全局两两比较，成本 O(n²)。局部/循环/稀疏/压缩机制本质上都在给“每次比较的数量”设上限，把 O(n²) 降为 O(wn) 或 O(n)（Slides 第 13–25 页）。
- **缓存复用**：同一前缀的 KV 不必重复计算。Slides 第 38 页展示 Call 1/2/3 中“可复用前缀不断增长”；逐字稿强调缓存命中率 90–95% 是常见良好水平（此为讲师课堂说法，非官方规格）。
- **压缩兜底**：当上下文超过可承受范围，压缩把历史 Hₜ 映射为有界工作状态 ŝₜ，希望未来动作分布近似不变（Slides 第 47 页）。

## 三、关键机制

### 3.1 智能体提示的组成（Slides 第 4 页）

Slides 给出 1,500 个 OpenHands 会话的统计：平均每次会话 **77,922 tokens**。组成比例为：

| 组成部分 | 占比 |
|---|---|
| 系统提示 + 工具描述 | 23% |
| 用户消息 | 9% |
| 推理轨迹 | 9% |
| 模型回复 | 2% |
| 工具调用 | 20% |
| 工具结果 | 37% |

逐字稿补充：系统提示约 15K–18K tokens（因 OpenHands 对工作方式“很有主见”）；推理 token 约为对用户文本输出的五倍。**注意：这些数字是逐字稿中的口头说明，Slides 只给出百分比与均值，具体区间标注待核。**

### 3.2 注意力复习（Slides 第 10 页）

符号：X ∈ ℝ^{n×d}，行 zₜ；qᵢ, kⱼ, vⱼ 为 Q, K, V 的行；d_k 为 key 宽度；掩码 Mᵢⱼ = 0（j ≤ i），−∞（否则）。

公式（待核，提取文本可能有排版错乱）：

- Q = XW_Q，K = XW_K，V = XW_V
- A = softmax(QKᵀ/√d_k + M)
- O = AV

**假设**：因果掩码保证只能看当前及之前 token；softmax 归一化使权重在 0–1 且和为 1。逐字稿指出，正是这个非线性 softmax 让注意力能“聚焦相关上下文”，也是它难以重排求和的原因。

### 3.3 局部与混合模型（Slides 第 14–16 页）

- 局部建模：只考虑常数个子集，成本 O(n²) → O(wn)，w 为局部窗口。
- 混合模型：N 次局部计算 → 1 次全局计算 → 重复。Slides 第 16 页列出六个模型的局部/全局配比：

| 模型 | 局部/状态计算 | 全局计算 | 比例 |
|---|---|---|---|
| Qwen3.8-Flash-Next | Gated DeltaNet | QSA 稀疏检索 | 36:12 ≈ 3:1 |
| GLM-5.3-Flash | Kimi Delta Attention | DSA + IndexPool | 34:11 ≈ 3:1 |
| Kimi K3 | Kimi Delta Attention | dense Gated MLA | 69:24 ≈ 3:1 |
| Nemotron 3 Ultra | Mamba-2 | dense GQA | 48:12 = 4:1 |
| Inkling-Small | 512-token window | dense GQA | 35:7 = 5:1 |
| DeepSeek-V4-Pro-0813 | 128-token window branch | compressed sparse / dense 交错分支 | — |

逐字稿补充：如今几乎所有广泛流行的模型都是某种混合模型，“很多局部 + 一次全局”是标准做法。

### 3.4 线性注意力与 Delta 家族（Slides 第 19–23 页）

**线性注意力**（Slide 20）：把 softmax 归一化替换为双线性分数，从而可重排求和：

- oₜ = Σᵢ softmax(qₜᵀkᵢ/√d_k) vᵢ → 用 qₜᵀkᵢ 替代
- 重排后 oₜ = Sₜqₜ，其中 Sₜ = Σᵢ kᵢvᵢᵀ，递推 Sₜ = Sₜ₋₁ + kₜvₜᵀ
- **新符号**：Sₜ ∈ ℝ^{d_k×d_v} 是固定大小的循环记忆。
- **假设/代价**：丢掉 softmax 的非线性 → 表达力更弱，不能做 token 间相对比较；但换来 O(n) 更新。

**DeltaNet**（Slide 21）：先读出当前关联，再只写入预测误差。

- v̂ₜ = Sₜ₋₁ᵀkₜ，eₜ = vₜ − v̂ₜ
- Sₜ = Sₜ₋₁ + βₜkₜeₜᵀ，oₜ = Sₜᵀqₜ
- **新符号**：v̂ₜ 是当前记忆预测；eₜ 是误差；βₜ ∈ [0,1] 是修正强度（类似学习率）。
- **直觉**：沿 kₜ 方向修正，无关记忆保持不变。

**Gated DeltaNet**（Slide 22）：先整体衰减，再做同样的定向修正。

- S̃ₜ₋₁ = αₜSₜ₋₁；Sₜ = S̃ₜ₋₁ + βₜkₜ(vₜ − S̃ₜ₋₁ᵀkₜ)ᵀ
- **新符号**：αₜ ∈ [0,1] 是标量保留门；αₜ = 1 时退化为 DeltaNet。
- **直觉**：每个时间步衰减一点，等价于对遥远过去打折，防止“很远的怪 key”影响当下。

**KDA（Kimi Delta Attention）**（Slide 23）：把标量衰减换成逐通道衰减。

- Dₜ = Diag(αₜ)，S̃ₜ₋₁ = DₜSₜ₋₁
- Sₜ = (I − βₜkₜkₜᵀ)DₜSₜ₋₁ + βₜkₜvₜᵀ
- **新符号**：αₜ ∈ [0,1]^{d_k} 是向量保留门；Dₜ 是其对角矩阵；I 是 d_k×d_k 单位阵。所有通道保留相同 → 退化为 Gated DeltaNet。
- **直觉**：不同特征有不同的记忆寿命，有些长期延续、有些短期。

### 3.5 稀疏注意力（Slides 第 24 页）

两类：固定模式（输入无关，成本可预测，但不能适应 query）与内容相关（query 特定，自适应检索，但选择器出错会漏掉相关 key）。两者都在保留集合上重新归一化。

- 固定：Sᵢ^fixed = {j ≤ i : i−j < w} ∪ (G ∩ [1,i])
- 内容相关：Sᵢ^dyn = TopK_{j≤i} g(qᵢ, kⱼ)
- Aᵢⱼ = softmax(qᵢᵀkⱼ/√d_k)，oᵢ = Σ_{j∈Sᵢ} Aᵢⱼvⱼ
- **新符号**：G 是固定全局位置集合；g 是学习的选择器；|Sᵢ^dyn| = K。

逐字稿举例：OpenAI 早期稀疏注意力约每 512 token 做一次稀疏；DeepSeek 用“廉价注意力先选 top-k，再对 top-k 做完整注意力”。课堂问答中讲师说相似度通常用点积而非余弦，是否预归一化“不知道细节”。

### 3.6 KV 压缩（Slides 第 25 页）

- **GQA**：减少 key/value 头数（不是 query 头数）。
- **MQA**：GQA 只有一组的情形。
- **MLA**：缓存潜在向量，再重建各头的 K、V：
  - cₜ^{KV} = W^{DKV}zₜ，kₜ^{(h)} = W^{UK(h)}cₜ^{KV}，vₜ^{(h)} = W^{UV(h)}cₜ^{KV}
  - **新符号**：cₜ^{KV} 是缓存潜在；h 为头索引；W^D 压缩，W^{UK}/W^{UV} 恢复各头 K/V。
- 逐字稿补充：GQA 通常可减少 4× 或 8× 的 KV 内存。

### 3.7 训练长上下文（Slides 第 27–35 页）

三段式：短预训练（4K–8K，数据充足、成本低）→ 继续训练（32K–128K，长文档、打包序列）→ 长适配（128K+，任务轨迹、合成课程）。

逐字稿强调：真正难的是数据——互联网上 128K 连贯 token 并不多；打包序列有助效率但不利于学习跨文档注意力。

**位置编码**：
- 绝对位置（Slide 28）：zₜ = E[xₜ] + pₜ；正弦编码 pₜ,2ℓ = sin(t/ω_ℓ)，pₜ,2ℓ+1 = cos(t/ω_ℓ)，ω_ℓ = 10000^{2ℓ/d}。
- RoPE（Slide 29）：q̃ᵢ = R(i)qᵢ，k̃ⱼ = R(j)kⱼ；q̃ᵢᵀk̃ⱼ = qᵢᵀR(j−i)kⱼ，分数只依赖相对位移。V 不变。
- NoPE（Slide 30）：zₜ = E[xₜ]，无位置向量；顺序由因果计算或循环动态推断。逐字稿解释：因果掩码下，位置 2 的“猫”只看前一个 token，位置 5 的“猫”看前四个，因此它们在注意力第一层就已不同，所以自回归 Transformer 可以不用位置编码；非自回归仍需。
- 位置插值（Slide 31）：R(t) → R(t/s)，θ_ℓ → θ_ℓ/s，s = L′/L。让长位置留在预训练相位范围内。
- YaRN（Slide 32）：θ_ℓ′ = (1−γ_ℓ)θ_ℓ/s + γ_ℓθ_ℓ，0 ≤ γ_ℓ ≤ 1；长波长全插值，短波长保留局部相位。注意力温度 τ = 0.1 ln s + 1（**Slides 注明该公式在 LLaMA 上拟合，是配方而非通用常数**）。

**数据混合**（Slide 35）：连贯长来源 + 答案依赖远距离证据的任务 + 渐进长度增长。各模型细节（Kimi K3、GLM-5、Nemotron 3 Ultra、DeepSeek V4）见 Slide 35 表格。

**上下文并行**（Slide 36）：内存 O(nd_k/P)，总工作量 O(n²d_k)，精确而非稀疏。逐字稿补充：超过约 32K 上下文后变得重要，但新机制（如门控 delta）缺少现成 kernel 是现实痛点。

### 3.8 提示与 KV 缓存（Slides 第 38–44 页）

- **调用内**：decode 时输出 token 扩展 KV 缓存。
- **调用间**：工具结果作为新输入返回；prefill 后加入可复用前缀。
- **价格**（Slide 40，USD/1M tokens，2026-08-30 核价）：例如 Kimi K3 缓存输入 $0.30 / 常规输入 $3.00 / 输出 $15.00；Claude Opus 5 为 $0.50 / $5.00 / $25.00。逐字稿概括：缓存 token 常为未缓存价格的十分之一。
- **PagedAttention**（Slide 41）：块表翻译，物理块非连续分配。
- **RadixAttention**（Slide 42）：基数树前缀匹配、复用前缀追加后缀、分割共享前缀、LRU 逐出叶子。
- **缓存感知路由**（Slide 43）：score = 可复用前缀 − 队列惩罚；示例 Worker 1 有 18K 匹配、队列 2，Worker 2 有 2K 匹配、队列 0。
- **提示设计**（Slide 44）：稳定前缀（指令、工具、示例）；把变化状态追加到后面；避免时间戳/重排 schema 等无谓抖动；度量复用（缓存 token、TTFT、逐出）。
- 逐字稿警告：每一步改系统消息（如附加当前时间）会彻底破坏缓存；中途切换模型也会让你下次回到贵模型时仍付贵价。

### 3.9 上下文压缩（Slides 第 46–51 页）

**例子（Slide 46，务必记住）**：
- Before：CI 任务 30 分钟超时 → 检查日志 → 24K 行日志、反复 “address already in use” → 设 `--workers=1` 重跑 → 套件通过，日志存于 `/tmp/ci.log`。
- After（压缩后）：目标：修 CI 超时；原因：端口冲突；已验证：`--workers=1` 通过；证据：`/tmp/ci.log`；下一步：用已测试的 worker 设置开 PR。

**形式化（Slide 47）**：
- p(A_future | Hₜ) ≈ p(A_future | ŝₜ)
- ŝₜ = C(Hₜ; B)，|ŝₜ| ≤ B
- **符号**：Hₜ 完整历史；ŝₜ 压缩工作状态；B token 预算；A_future 未来动作；C 压缩器。
- **三条约束**：行为保真、表示有界、可恢复性（复制精确锚点、保留源证据指针）。

**什么能存活（Slide 48）**：KEEP EXACT（锚点：目标、约束；最近尾部：当前尝试、最新结果）；ENCODE（检查点：决策、进度、ID）；EXTERNALIZE（证据存储：24K 行日志 → 3 个失败 + 命令 + 产物路径）；DISCARD（重复、被取代的尝试）。

**策略四决策（Slide 49）**：触发（token 阈值 / provider 溢出 / 手动）→ 选择（保护开头、压缩较旧区域、保留近期尾部、在合法回合/工具边界切）→ 替换（可读摘要 / 结构化检查点 / 不透明 provider 项 / 全新上下文）→ 恢复（历史不变、重试或重置、保留可搜索历史、定义失败行为）。

**重复压缩漂移（Slide 50）**：CUDA 12.4 → “Use CUDA 12.x” → “Use recent CUDA”，约束丢失。公式 ŝ_{k+1} = C(ŝ_k ⊕ R_k)，即每次更新继承上一个检查点。

**继续式评估（Slide 51）**：植入状态（约束、决策、产物）→ 用生产策略压缩 → 继续 → 测量后续决策。指标：状态召回（约束+标识符）、任务成功、效率（token/延迟/成本）、稳定性（重复压缩）。

逐字稿的真实故事：OpenHands 早期压缩策略在 SWE-bench 上分数不降、省了很多 token，但上线后出现“每次压缩就发一个 PR”“压掉对话中间的用户指令”——因为只在单轮对话上评估过。结论：**光做基准不够，必须在真实环境测试**。

## 四、误区清单

1. **“模型标称 1M 上下文，就能用好 1M”**——错。Slides 第 11 页用 GPT-4 大海捞针图说明“标称 vs. 有效上下文”有差距；逐字稿说较弱模型在很长上下文上会变差，RULER、HELMET 是常见基准。
2. **“注意力成本只是平方，所以优化就是少算”**——不完整。还要区分 prefill（计算密集、TTFT）与 decode（内存带宽、TPOT），二者瓶颈不同（Slides 第 8–9 页）。
3. **“线性注意力全面优于 softmax 注意力”**——错。丢掉 softmax 后表达力更弱，无法做 token 间相对比较；Delta/门控/KDA 都是在补这个短板（Slides 第 20–23 页）。
4. **“缓存只是实现细节，与我设计 harness 无关”**——错。改系统消息、附加时间戳、重排 schema 都会让缓存归零，直接放大成本（Slides 第 44 页）。
5. **“压缩就是摘要”**——不完整。压缩是状态估计，要满足行为保真、有界、可恢复三条约束，并保留精确锚点与证据指针（Slides 第 47–48 页）。
6. **“在基准上不掉分，压缩就没问题”**——逐字稿的反例证明不然：单轮评估掩盖了多轮场景的失败。
7. **“打包序列能训练长上下文”**——逐字稿指出：打包有助效率，但不利于学习跨文档/长程连贯注意力。

## 五、复习问题

1. 若固定前缀为 P，每次调用新增 h 个 token，写出第 t 次调用的输入长度与累计输入长度，并说明为什么累计是平方级（参考 Slides 第 3 页算例）。
2. TTFT 与 TPOT 分别对应推理的哪个阶段？为什么长输入会推高 TTFT，而 decode 更受内存带宽限制？（Slides 第 8–9 页）
3. 用自己的话解释：为什么线性注意力可以重排求和？这个重排换来了什么、又牺牲了什么？（Slides 第 20 页）
4. DeltaNet 中 v̂ₜ、eₜ、βₜ 各是什么？为什么说它是“只写入预测误差”？αₜ = 1 时 Gated DeltaNet 退化成什么？（Slides 第 21–22 页）
5. KDA 相比 Gated DeltaNet 的关键新增是什么？为什么“逐通道衰减”能同时表达长寿命和短寿命上下文？（Slides 第 23 页）
6. 固定模式稀疏注意力与内容相关稀疏注意力各自的失效模式是什么？（Slides 第 24 页）
