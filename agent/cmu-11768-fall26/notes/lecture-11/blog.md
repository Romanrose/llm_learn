## 一、这门课在讲什么：RL 讲义地图中的位置

Lecture 11 的主题是“面向智能体的高级 RL 算法”，副标题强调“改进智能体如何从经验中学习”（Slides 第 1 页）。在整门课的 RL 讲义地图里，今天要处理的是四个更进阶的问题：**有用的反馈、更少的等待、稳定的更新、可靠的奖励**；而“从教师学习”被放到下一讲，记忆、并行与大规模执行也在后续（Slides 第 2 页）。

**学习者解释**：可以把这一讲理解成“把最朴素的 RL 循环拆开，逐个解决它在智能体场景下暴露出来的毛病”。朴素循环是采样、打分、更新三步（Slides 第 5 页）。但当任务变成多轮工具调用、代码编辑、测试运行，这个循环会遇到几类具体麻烦：终局奖励太稀疏、同一任务内各步贡献说不清、同步等待太费时间、旧策略数据不能直接用、奖励本身可能不可靠。Lecture 11 基本就是围绕这几类麻烦展开。

## 二、一个贯穿全讲的例子：修一个 Bug

为了让讨论落地，讲义用一个具体的编程智能体任务贯穿始终（Slides 第 3 页）：

- **Prompt**：修复重试设置——零应当禁用重试，但代码返回了三；请保留其他情形。
- **初始有 Bug 的代码**：

```python
def retry_count(config):
    return config.get("retries") or 3
```

- **验证器（Verifier）**：一组测试，输入到期望输出为——Missing → 3，None → 3，0 → 0，2 → 2。

**学习者解释**：这段代码的坑在于 `or` 会把 `0` 也当成假值，于是 `0` 被替换成 `3`。测试正是为这个坑设计的。这个例子之所以好用，是因为它的成功判据清晰：四个测试全过，终局奖励为 1，否则为 0（Slides 第 4 页）。

一条成功轨迹 τ 是这样的（Slides 第 4 页）：先检查函数、发现 0 变成了 3；然后编辑代码、第一次保存补丁；接着跑四个测试、发现还有一个失败；再修改代码、保存修订补丁；最后重跑测试、四个全过。这条轨迹说明一个关键点：**最终奖励只在结尾出现，中间所有动作本身没有即时奖励**。

## 三、最朴素的训练循环与 REINFORCE 的局限

训练反复执行三步（Slides 第 5 页）：**采样**（在任务上运行智能体、收集轨迹 τ）、**打分**（验证器给每条轨迹最终奖励 R(τ)）、**更新**（用奖励改变策略参数）。目标 J(θ) 是任务 x 上的平均奖励期望，θ 是策略参数，p_θ(τ|x) 是给定任务下轨迹的概率。

朴素 REINFORCE 的做法是：用终局奖励给一条轨迹里的**每一个动作**加权（Slides 第 6 页）。成功轨迹 R(τ)=1，就提高它所有动作的似然；失败轨迹 R(τ)=0，这条轨迹**不产生任何更新**。单条采样轨迹的损失写为对时间步 t 求和的 −R(τ)·log π_θ(a_t | h_t)。

**学习者解释**：这里暴露了第一个核心痛点。在滑动条上，失败的尝试一无是处——它的动作既不被加强也不被削弱，整条经验被丢弃。但对智能体来说，一次失败尝试里可能有一半动作是对的，只是最后一步错了；朴素的终局奖励完全看不出这一点。Slides 第 6 页正是用一句提问收尾：“失败的尝试怎样还能提供学习信号？”这就是后面几页要回答的问题。

## 四、信用分配：谁该为结果负责

### 4.1 用组内平均做基线

第一种改进来自比较（Slides 第 8 页）。同一任务采四条轨迹：一条全过（R=1），三条失败（R=0）。组平均 = 0.25，用它做基线，更新权重变成 reward − baseline：成功轨迹 +0.75，失败轨迹各 −0.25。

**学习者解释**：这一步的意义在于，失败尝试不再被丢弃，而是给它的动作一个负权重，即“这些动作不如平均好”。这就是组比较（Group comparison）思想的雏形。

### 4.2 细到单步：奖励、回报与奖励-to-go

但组权重对一条轨迹内**每个动作都一样**（Slides 第 9 页）。这就带来两个反例：成功的轨迹里可能藏着一个错误动作，失败的轨迹里可能有一个真正有用的动作。讲义用两条示意轨迹说明：A 成功但中间含一个“Mistake”，B 失败但中间含一个“Helpful”。

接下来讲义引入**奖励-to-go（reward-to-go）**（Slides 第 10 页）。给定历史 h_t 之后，把剩余的奖励相加，每一步计数相同，就得到 R_t——从 h_t 之后收到的奖励总和。示例里“0+0+1=1”。

在两条示意轨迹上对比（Slides 第 11 页）：A 的每一步奖励-to-go 都是 1，B 的每一步都是 0。于是问题变成：“只观察到终局奖励时，我们怎么估计哪些步骤真正有帮助？”

### 4.3 价值函数：从历史看期望回报

讲义用“想象从 B 的某个历史 h₃ 继续采样十次”的方式给出价值定义（Slides 第 12 页）：十次续写的奖励-to-go 是 1、0、1、0、0、1、0、0、0、0，三次为 1，平均 3÷10=0.3。**价值 V_μ(h₃)** 就是在同一 rollout 策略 μ 下、所有可能续写上的这个平均；竖线表示“给定 h₃”。十个样本给出这个平均的估计。

**学习者解释**：价值的直觉是“站在这个历史位置上，平均还能拿到多少”。它把一条轨迹里隐含的“前景好不好”变成了一个可学习的数。用一个**评论家（critic）**去预测它，就是用平方误差训练：讲义举例，若 V_φ(h₃)=0.6，平均平方误差是平均三个 (0.6−1)² 和七个 (0.6−0)²，而最优预测是样本均值 0.3（Slides 第 13 页）。损失写作对 φ 最小化 E[(V_φ(h_t) − R_t)²]。

### 4.4 评论家的两种常见实现

Slides 第 14 页给出两类做法：

- **独立价值网络**：历史 h → 价值网络 φ（自带主干和输出层）→ 预测 V_φ(h)；价值损失训练整个网络。讲义标注例子为 InstructGPT。
- **策略主干 + 价值头**：历史 h → 策略主干（属于 θ）→ 停梯度 → 线性价值头 φ → 预测 V_φ(h)；价值损失只训练这个头。讲义标注例子为 MIXER。停梯度阻止价值损失更新策略主干，但策略损失仍会训练它。

### 4.5 时序差分误差与 GAE

Slides 第 15 页演示了**一步价值变化**。仍然看轨迹 B 的最后三个动作：h₃ 处 V=0.3，奖励 r₄=0，下一价值 h₄=0.6，于是 0+0.6−0.3=+0.3；h₄ 处 V=0.6，r₅=0，下一价值 h₅=0.4，得 −0.2；h₅ 处 V=0.4，r₆=0，到轨迹结束 h₆ 无未来奖励，V(h₆)=0，得 −0.4。这就是**时序差分（TD）误差** δ_t = r_{t+1} + V_φ(h_{t+1}) − V_φ(h_t)，且示例中不做奖励折扣。

GAE 则回答“后来的误差该以多大力气影响给 B 中 a₃ 的信用”（Slides 第 16 页）。取 λ=0.5，每个更晚的误差只拿到前一个的一半权重：权重分别是 1、0.5、0.25，组合得 0.3 + 0.5×(−0.2) + 0.25×(−0.4) = 0.1。公式写作 Â_t = δ_t + λÂ_{t+1}，从后往前反复。

**学习者解释**：把这几页串起来，你就得到了 PPO 这类算法的“优势估计”零件——评论家提供价值预测，TD 误差把相邻两点的价值差变成一步信号，GAE 把多步信号按 λ 衰减地加权起来，用来看某个动作比“预期”好多少。

### 4.6 过程奖励模型：把“步对错”直接学出来

除了从回报里估计价值，讲义还给了另一条路：**过程奖励模型（PRM）**（Slides 第 17 页）。它把“每一步是否正确”当作价值的替代物（surrogate）来学习。讲义例子是 5x = 6x − 14 推出 x = 14，标注者把“x = 7”标为错误。

## 五、更少的等待：同步与异步 RL

### 5.1 同步的等待成本

同步 RL 要求一批里**每条轨迹都完成后**才开始更新（Slides 第 19 页）：GPU 1/2/3 各自生成，然后一起等待，最后一起更新，下一批在更新之后才开始。

**学习者解释**：在代码智能体里，一条轨迹可能跑很多测试、调用很多工具，长短差异极大，早完成的 GPU 只能空等最慢的那条。这就是“更少的等待”想解决的问题。

### 5.2 异步：重叠 rollout 与更新

异步 RL 让 rollout 工作进程在 learner 用已完成轨迹更新时继续生成（Slides 第 20 页）。代价随之出现：**一部分完成的轨迹来自更早的策略版本**。这句话是后面“稳定更新”一整节的总引子。

## 六、稳定的策略更新：旧数据怎么用

### 6.1 陈旧轨迹

Slides 第 22 页给出具体情形：rollout 策略 μ 与当前 learner 策略 π_θ 在同一动作上的概率不同。例如 μ 给“记录的编辑”0.40，π_θ 现在给 0.70；另一些记录显示 μ 0.40、π_θ 0.20。讲义这样定义：**这条 rollout 是陈旧的，它的动作来自 μ，而 learner 用的是 π_θ**。

### 6.2 重要性采样

在固定历史 h 下，按动作在当前策略下与行为策略下的概率之比重新加权（Slides 第 23 页）。同一个“正确编辑”：行为 0.40、当前 0.70，权重 1.75；同一个“不完整编辑”：行为 0.40、当前 0.20，权重 0.50。等式写为 E_{a∼π_θ}[R(a)] 与 E_{a∼μ}[ (π_θ(a|h) / μ(a|h)) · R(a) ] 的关系。

### 6.3 长轨迹的比值爆炸

问题在于，整条轨迹的比 w 是沿途**每一步局部比值相乘**（Slides 第 24 页）：w(τ|x) = p_θ(τ|x) / p_μ(τ|x) = ∏_t π_θ(a_t|h_t) / μ(a_t|h_t)。讲义给出的示意是单个动作比值 1.05，沿轨迹乘积到 1.05¹⁰⁰ ≈ 132，从而**高方差、少数样本主导更新**。Slides 第 25 页进一步指出，累计比值 ρ_t^{cum} 把动作比值乘到时刻 t，其散布在使用工具的数学 rollout 中越靠后越大。

**学习者解释**：直觉上，一两步的小偏差无所谓，但当轨迹有上百步时，这些微小偏差连乘起来就会指数放大，一条轨迹的权重可能远大于另一条。

### 6.4 更早的动作会改变更晚的历史

Slides 第 26 页指出一个更微妙的现象：当前策略可能**很少到达** rollout 策略曾到过的历史。例子是早先的编辑“加一个 None 检查”，μ 给 40%、π_θ 给 10%，于是“代码里现在有那个检查”这个历史被到达的概率只有 0.25 倍；而在这个历史之后，“跑测试”这一步的下一动作比值仍是 1。**下一动作比值是 1，但到达这个历史的可能性只剩四分之一。**

### 6.5 谁的比值进入权重：方法对照

Slides 第 27 页把不同方法对“用响应的哪些部分”做了对照表（T 个动作）：

- **PPO / GRPO**：只用当前动作；
- **CTPO**：用到 t 为止的所有动作；
- **Full ratio**：全部动作；
- **GSPO**：全部动作，按长度归一化；
- **DAPO 与 CISPO**：也用当前动作比值，但裁剪规则不同。

## 七、裁剪策略更新

### 7.1 为什么要限制更新

Slides 第 29 页的理由很直接：陈旧 rollout 可能拿到很大的权重，让少数样本主导一次更新。

### 7.2 裁剪一个概率比值

Slides 第 30 页定义单 token 的比值 ρ_t = π_θ(u_t|u_{<t}) / μ(u_t|u_{<t})，并给出裁剪值 c_t = clip(ρ_t, ℓ, u)。示例中 ℓ=0.8、u=1.2。

### 7.3 PPO 与 CISPO 的目标

Slides 第 31 页给出两个目标（E 对采样 token 求平均，Â 估计某 token 是否有帮助，sg 表示对梯度固定 c）：

- **PPO**：J(θ) = E[ min(ρ_t Â_t, c_t Â_t) ]。
- **CISPO**：J(θ) = E[ sg(c_t) Â_t log π_θ(u_t|u_{<t}) ]，把裁剪后的比值当成固定权重。

Slides 第 32 页解释 PPO 的形状：正优势 A=+1 时，比值超过上限 1+ε 就不再奖励；负优势 A=−1 时，比值低于下限 1−ε 也不再奖励。示例中 ε=0.2。**对有帮助的动作，停止奖励高于 1+ε 的比值；对无帮助的动作，停止奖励低于 1−ε 的比值。**

### 7.4 参考模型 KL 与熵

Slides 第 33 页把三个角色摆清：**rollout 策略 μ** 生成训练批次并提供重要性比值的分母；**参考模型 π_ref** 在学习过程中保持固定，作为锚点；目标写成 max J_policy − β·D_KL(π_θ‖π_ref)，其中 β 控制惩罚强度。Slides 第 34 页给出熵奖励：目标加 α·H(π_θ)，H 度量下一 token 的不确定性，更宽的分布可能帮智能体尝试其他动作，**但不保证这些动作有用**。

### 7.5 一张总表

Slides 第 35 页把常见算法按四个维度对照：**信用来源、是否有学到的评论家、重要性比值、裁剪方式**。

- **REINFORCE**：奖励-to-go R_t 做权重；无评论家；无比值（每次都是新 rollout）；无裁剪。
- **PPO**：来自评论家的 GAE；有评论家；当前 token 比值 ρ_t；取原始项与裁剪项的最小值。
- **GRPO**：组比较；无评论家；当前 token 比值 ρ_t；与 PPO 相同的裁剪。
- **CISPO**：组比较；无评论家；当前 token 比值 ρ_t；把裁剪比值当固定权重。
- **GSPO**：组比较；无评论家；整条响应、按长度归一化；在响应比值上用 PPO 最小值。
- **DAPO**：组比较；无评论家；当前 token 比值 ρ_t；PPO 最小值但上界更高。

表下注释说明：组比较的做法是先减去组内平均奖励，再除以奖励散布。

## 八、可靠的奖励：任务选择与被奖励误导

### 8.1 无信息量的 rollout 组

Slides 第 37 页用四组四条轨迹演示：全失败（0 0 0 0）、混合（0 1 0 1）、全通过（1 1 1 1）。回忆组优势是减去组内平均：全失败组均值 0，减完全是 0；全通过组均值 1，减完也全是 0。**全零组给不出结果比较。为什么每条轨迹都失败？**

### 8.2 全失败时的三种排查方向

Slides 第 38 页列出方向：**验证器质量**（有效解可能被拒，检查需求和失败测试）、**当前能力**（模型可能还不会解这个任务，检查更强模型的示范是否成功）、**探索不足**（所有尝试可能重复同一做法，检查轨迹是否有差异）。

### 8.3 假阴性

回到修 Bug 任务（Slides 第 39 页）：一个候选实现产出了所有要求的输出（四例全对），但用了不同的源码写法；而验证器规则要求出现确切短语 “value is None”，候选没有它，于是被拒。**这是假阴性：一个有效解被拒绝。** 讲义的建议是检查行为，而不是偶然的措辞选择。

Slides 第 40 页给出后果与证据表：

- **奖励噪声**：等价的解法因措辞或实现细节拿到不同奖励。
- **基准饱和**：验证器拒绝有效解时，分数会在 100% 以下变平。

表中列出的“基准平台/上限”与证据（历史版本，2025–26 审计；这些是报告的平台或上限，τ-bench 之后已修正任务）：SWE-bench Verified ≈81%（进度在 80.9% 附近放缓，许多剩余失败有缺陷测试）；τ-bench Airline ≈70%（不一致的任务限制了可达分数）；τ-bench Retail ≈92%（标注错误限制了可达分数）。

### 8.4 假阳性与奖励黑客

Slides 第 41 页换一个方向：保持同样的任务需求，但训练测试只测输入 retries=0。候选实现 `return 0` 让“唯一被测试的情形”通过，训练奖励为 1；但 Missing/None、2 两个情形全错。**假阳性奖励了无效解，训练可能学会利用这个缺口。**

Slides 第 42 页列出编码智能体中常见的捷径：

- 环境里有互联网 → 上网找已发布的解法；
- 有 Git 历史（包括未来提交）→ 找到并复制后来的修复；
- 有模型 API key → 调用另一个更强模型来生成答案或训练数据；
- 能访问测试或测试运行器 → 不修 Bug 也让测试通过。

### 8.5 独立检查

Slides 第 43 页给出三条独立观察线：**训练奖励**衡量训练验证器上的成功；**独立成功**检查未见任务和训练验证器漏掉的行为；**成本与失败**检查工具调用、回归与重复动作。**如果奖励上升但没有独立的改进，就去检查轨迹里有没有捷径。**

### 8.6 DAPO 的动态采样与部分奖励

DAPO 应对“同奖励导致组优势为零”的办法是动态采样（Slides 第 44 页）：每个任务采四条，全 0 或全 1 的组**跳过**，只保留混合组，一直采样到批次满。示例里目标 2 组，任务 B（0 1 0 1）与任务 D（新组 0 0 1 0）被保留，批次满了就更新。**保留混合组里的每一条轨迹，包括它的失败。**

Slides 第 45 页给出**部分奖励**：把通过检查数按比例给分（例：每通过一项加 0.25）。示意任务要过 4 项检查，四条轨迹分别过 0/1/2/1：只用成功奖励时全为 0，减去均值后全为 0；加上部分奖励变成 0、0.25、0.50、0.25，减去均值后是 −0.25、0、+0.25、0。**不同的部分分数可以减少零优势的组和批次。**

### 8.7 辅助奖励的风险

Slides 第 46 页给出两组“意图 vs 实际奖励 vs 观察到的行为”：

- 意图是**有用的工具使用**，但一个 Bug 让肤浅的网页工具调用也拿分；观察到的行为是 GPT-5.1 把浏览器当计算器用，还表现得像搜索过一样。
- 意图是**一个“书呆子”人设**，但包含 “goblin” 或 “gremlin” 的比喻拿到更高分；观察到的行为是这类生物比喻变多，甚至在没有该人设提示时也出现。

### 8.8 探索坍缩

Slides 第 47 页演示：在某个历史上，早先策略给动作 A/B/C 的概率是 0.20/0.60/0.20，之后变成 0.01/0.98/0.01——几乎每次采样都选 B，其他选择很少被尝试。**熵奖励鼓励替代选择，但要检查轨迹是否真的不同。**

## 九、从教师学习（下一讲预告内容，本讲已铺垫）

### 9.1 课程与热启动

当学生很少成功时，教师可以提供成功轨迹（Slides 第 49 页）。路径是：**示范**（先学成功解法）→ **可学任务**（练模型偶尔能成功的任务）→ **更难任务**（随模型提升增加难度）。要**把早先任务留在混合里**，并用**固定评估集**衡量改进。

### 9.2 蒸馏与在策略蒸馏

蒸馏训练学生去匹配教师在一组**固定轨迹**上的动作概率（Slides 第 50 页）：在保存的历史上，教师给动作 a₃ 80%、另一个动作 20%，记作 q(·|h₃)。但学生自己行动时，它的错误可能把自己带到这个训练集里**没有**的历史。

在策略蒸馏（Slides 第 51 页）让学生生成训练历史，再在这些历史上问教师要目标：“在策略”意味着历史来自学生自己的 rollout。

### 9.3 稠密蒸馏目标与自蒸馏

Slides 第 52 页给出例子：在同一 h₃ 上，学生给两动作各 0.5，教师给 0.8 和 0.2，反向 KL 为 0.5·log(0.5/0.8) + 0.5·log(0.5/0.2) ≈ 0.223。目标是在学生历史分布 d_μ 上平均：min_θ E_{h∼d_μ}[ D_KL( π_θ(·|h) ‖ q(·|h) ) ]。

Slides 第 53 页介绍在策略自蒸馏（OPSD）：学生 rollout 到某个历史，学生的输入是任务与历史 h₃，教师的输入是**同样的任务与历史，外加一个已验证的解法**。OPSD 用起始模型的一个冻结副本作为教师，用它的下一动作概率来训练学生。

**学习者解释**：这几页的共同点是，把密度从“只在终局给一个 0/1”变成“在每一步都给一个分布”。这正是本讲开头“有用的反馈”在另一条路上的延伸。
