# 把轨迹变成权重：CMU 11-768 第八讲之智能体监督微调导读

> 待审核候选稿 · 来源：平台字幕与官方 Slides · 尚未发布。

## 一、这一讲要解决什么问题

前几讲我们讨论的“更新智能体”手段，都发生在推理时：改上下文窗口，或者改外部工件。第八讲把更新位置从“提示”挪到了模型权重本身。课程 Slides 第 4 页把三种做法并排放在一起：上下文窗口对已发生的事情保真度高，但昂贵、有噪声、且不决定什么重要；外部工件可检查、可编辑、可检索、可移植，但必须被归纳、选择和持续维护；权重更新的好处是推理更快、行为改变更广——“改一次权重，之后每一次调用都带上新行为，prompt 里什么都不用加”，代价是更新更慢、不透明、且模型特定（Slides 第 4 页）。

于是问题变成：既然 SFT 这么“重”，它到底教了什么，值得单独讲一讲？Slides 第 5 页给出四个答案：怎么写这个 harness 真正能跑起来的工具调用；对话变长时怎么继续下去；工具结果是长什么样的，从而让模型学会“等结果”而不是自己编一个结果；以及数据里附带的其他东西——额外评论、重复命令、某一种解题方式。

**关键术语**：本讲中的“轨迹”（trajectory）指一次智能体运行被记录下来的完整消息序列，包含 system / user / assistant / observation 等行；“harness”指承载智能体循环的那套系统（系统提示、工具定义、消息模板等）。这一区分很重要，因为后面“同一段轨迹在不同 harness 下长得不一样”会反复出现（Slides 第 33、44 页）。

## 二、轨迹先变成 token 序列

Slides 第 3 页给了一个 SWE-Gym 风格的具体例子：智能体拿到一个 issue 和沙箱里的两个工具（bash 和一个文件编辑工具），产出思考与命令，读命令返回的 observation，最后由仓库自己的单元测试决定这次运行是否成功。整条轨迹里 assistant 消息其实很少——逐字稿里提到只有三条 assistant 消息。

**学习者解释**：这里的要点是，SFT 学习的不只是最终答案，而是“在什么上下文里发什么动作”。这就是为什么后面的损失掩码设计会那么关键——如果不做掩码，模型会被要求去预测那些本不该由它预测的东西。

Slides 第 11 页展示了模板如何把整条轨迹渲染成一个字符串：每个边界都是一个模板 token，`<|...|>` 是单个特殊 token，其余部分是智能体自己写下和看到的内容。Slides 第 12 页给出了核心公式与掩码定义：

\[
L(\theta) = -\sum_{t:\,m_t=1} \log p_\theta(x_t \mid x_{<t})
\]

（公式按 Slides 第 12 页文本提取转写，符号细节待对照官方 PDF 核验。）

**关键洞察**：掩码是一位一个 token 的比特，说明这个 token 的预测是否计入损失。只在 assistant token 上算损失，observation 是条件上下文而不是预测目标。最小化它，就是提高“每个被记录动作在给定其之前一切时的概率”。

## 三、掩码是怎么造出来的，以及它的边界在哪

Slides 第 13 页把掩码的产生拆成三步：渲染（模板把对话写成一个字符串，并记下每个 assistant 片段的起止）、分词（字符位置变成 token 位置）、掩码（assistant 片段内为 1，其余为 0）。到训练开始时，角色信息已经没了——trainer 只看到字符串和比特（Slides 第 13 页）。

Slides 第 14 页对比了三个框架的同一决策：TRL 用 `assistant_only_loss=True`，由模板在渲染时标记 assistant 片段；Axolotl 用 `roles_to_train` 和 `train_on_eos`，在渲染后的字符串里找每轮的角色头；LLaMA-Factory 用 `train_on_prompt` 和 `mask_history`，在编码时把整轮标成训练或忽略。Slides 第 49 页给出更细的标志行为，例如 LLaMA-Factory 的 `mask_history: true` 表示只训练最后一轮、截断时保留最后一轮；Axolotl 的 `train_on_eos: turn` 表示每个被训练轮次的 EOS 进入损失。

**学习者解释**：这三者做的其实是同一个决策，差别只在“谁来记账”——只有 TRL 把这个决定放进了模板里。当你要跨框架迁移数据时，这个差别会导致静默的错配。

Slides 第 15 页讲 end-of-turn token：角色头在推理时是被提供的，因此从不是预测目标；而模型要自己产生停止 token，所以它必须在掩码内。“结束一轮”其实是三个事件而不是一个——结束这条消息、交接给工具、或完成任务；Kimi K3 的模板用不同 token 把它们分开写（Slides 第 15 页）。

Slides 第 16 页讲推理块的掩码：有两个独立的开关——推理是否留在上下文里、推理是否被训练。在上下文里，推理解释紧随其后的动作；被训练，它就变成模型自己书写的风格。Nemotron 的做法是把预算截断的推理保留在上下文中，并把人为截断从损失中掩掉（Slides 第 16 页）。

Slides 第 17 页引入 BalanceSFT 的两个组件：SSB 是一个学出来的权重，用来在损失中重新平衡推理 token 与工具调用 token；HDR 对困难样本重采样。动机是：长推理会主导损失，而真正需要正确的恰恰是那个短的工具调用；重新平衡在多轮上比单轮帮助更大。

Slides 第 18 页给出一个很容易被忽视的教训：MAI 是按样本数来选混合的，但损失是按 token 算的。STEM 和编码轨迹长得多，于是几乎占掉了全部 token。结论是——无论你按轨迹数怎么平衡，都要检查它在 token 上变成了什么。

Slides 第 19 页把这些写成开放问题：没有找到一篇已发表实验是“改动智能体 SFT 的掩码并测量后果”的；精细的掩码实验都是单轮指令调优而非智能体；唯一一个“不掩码提示反而有帮助”的案例是长提示、短答案、数据少，而智能体轨迹在这三点上全部相反。Slides 第 19 页还指出，这个实验在 8B 规模上很便宜，且“就摆在那里没人跑”。

## 四、选轨迹：老师、来源、长度、多样性

Slides 第 21 页用两行两列概括了轨迹来源：谁跑的任务（更强的模型 / 模型自己）× 你保留什么（全部 / 只保留通过的）。右上角是绝大多数智能体 SFT 数据所在的位置——更强的模型写得更好，而任务自己的测试让“只留好的”变得便宜。左下是普通蒸馏，右下是专家迭代，将在后续讲座展开。

Slides 第 22 页给了一个具体的蒸馏结果：GPT-4o 和 Claude 跑了 SWE-Gym 的任务，491 次运行通过了仓库测试；一个 32B Qwen 模型仅在这 491 条轨迹上微调，在两个 SWE-Bench 划分上的分数都涨了十点以上。Slides 第 23 页接着说轨迹数量与饱和：任务集不变、只改采样轨迹数，采样预算耗尽时准确率仍在上升，他们有的是任务，缺的是采样算力。

Slides 第 24 页提醒：每一次运行都通过了测试，但有的编辑后反复重跑测试占掉大部分轮次，有的在最终补丁里留下 print。损失会照抄每一个动作，好或不好——在这些运行上训练，模型把“乱”和“修复”一起学走（Slides 第 24 页）。

Slides 第 25 页给出一个简单但有效的过滤：数轮次，丢掉所有短于五轮的运行。轮次数量说的是这次跑花了多少工作量，而不是工作质量好不好；四轮的干净修复会被丢掉，四十轮的乱局会被保留，但平均而言它仍然有帮助。

Slides 第 26 页给出本讲最反直觉的一条：论文报告 GPT-5.3-Codex 是这五个模型中基准最强的，但它产生的学生最弱——排行榜名次在这里给了错误信号；而试两个老师、保留更好的学生，相比之下是便宜的。Slides 第 27 页说任务来源的选择对结果的影响最大，不同来源帮助不同基准，所以要在调其他任何东西之前先把力气花在这里；他们的经验结论是混合最好的四到八个来源，更宽没有帮助。

Slides 第 28 页区分两种“加数据”：两条曲线都从同一个 10K 数据集出发，只差在额外数据来自哪里。粉色曲线加同一任务的更多运行，会趋于平缓；蓝色曲线加新任务，持续攀升。Slides 第 29 页把这个问题变成一个课堂讨论：四轮解决、长轨迹错编辑后恢复、十一次无变化尝试后解决——保留哪些？哪些动作承担损失？哪个答案会被“最小轮次过滤”搞错？

**学习者解释**：这个讨论的设计意图是让人意识到，“成功”与“值得学”不是一回事。一个通过测试的运行里可能包含不该被强化的行为，而一个失败的运行里可能包含最该学的恢复过程。

## 五、一种格式服务多个数据集

Slides 第 31 页描述异构性：每个数据集由不同团队以自己的格式构建。同一个网页，有的存 HTML，有的存可访问性树。要一起训练两个数据集，你得先写两个定制转换器。Slides 第 32 页给出对策：读一次每个数据集，改写为带类型的动作与观察；对上面那个网页，同时保留 HTML 和可访问性树，而不是二选一；于是每个数据集转换一次、每个 harness 转换一次，而不是每对组合转换一次。

Slides 第 33 页讲 harness 特定渲染：数据进了统一格式，你仍然要为训练目标 harness 写回去。OpenHands、SWE-Agent 和 AgentLab 采取的动作不同，所以同一段轨迹在各自那里长得不一样。这里也是你设定系统提示、决定上下文变长时怎么办的地方；然后检查结果——工具调用能否解析、每个调用是否带一个思考、对话是否按应有的方式结束。

Slides 第 34 页给出多样性对照实验：相同 harness、相同模型、相同评测，只改训练混合；在混合数据上训练，即便在该领域自己的基准上也超过了匹配的单领域集合。

## 六、跑训练：配置、路由、打包、模板漂移

Slides 第 36 页列出三份真实配置：Nemotron 3 Ultra 打包 294,912 再到 515,000，批次 64，学习率 1.5e-5 → 1e-6；MAI 自蒸馏打包 128k，批次 2,048，学习率 1.7e-5 → 5.2e-6 并带 2% 预热；K2 Horizon 用 512K、分三个阶段、在一个高质量子集上衰减。

Slides 第 37 页讲专家路由：本讲中的前沿模型是混合专家，而公开论文里微调的模型是稠密的。在狭窄的智能体数据上微调 MoE，少数专家会吃掉大部分 token。MAI 的做法是：在监督阶段把路由平衡推得非常狠，比 RL 期间难一千倍，并把 dropout 提到 0.15。

Slides 第 38 页讲打包：训练跑在固定长度序列上，打包用多段对话填满每一条，而不是把大部分序列用 padding 浪费掉。每段对话被分配到剩余容量最紧匹配的那个包里；没有任何对话被切分或截断，这是对抗幻觉的刻意选择；相同提示被排除在同一个包之外，包随后被打乱。

Slides 第 39 页讲模板漂移：你训练时用的模板必须是你服务时用的模板，精细到空白字符。把同一段轨迹渲染两次，一次后面加工具消息、一次不加，你会得到两个不同的字符串；当工具消息被追加时，条件思考块会改变先前那个 assistant 轮次，前缀不再匹配。

Slides 第 40 页提到已发布的训练产物：K2 Horizon 的模型卡里有逐阶段的训练表（步数、token、序列长度、每个阶段是为了什么），上面第 36 页的数字就来自那张表；它还链接了 Weights & Biases 运行，并附带每个阶段的中间检查点。Nemotron 发布了后训练检查点以及训练数据和配方。

## 七、怎么知道它真的有效

Slides 第 42 页指出训练与运行之间的错配：训练一次只对一个动作评分，而且总是继续被记录的那条运行；部署时没有录像，模型采取的每个动作都会改变它接下来看到的东西。同前缀之后，记录的编辑 A 让测试通过，而模型可能产出一个合理但不同的编辑 B，测试失败——于是它进入了一个没有任何训练运行访问过的状态，低损失对此什么也没保证。

Slides 第 43 页给出实践建议：在信任任何数字之前，先检查你能不能过拟合二十个例子；如果损失不下降，bug 在上游。然后在 harness 中运行模型，在有可检查结果的任务上评测。读已发表数字时要小心，有时它们是几个 harness 中最好的；把划分与你的说法匹配——同一个任务的所有运行放在同一侧，若想说“泛化到新仓库”，就按仓库划分。

Slides 第 44 页讲跨 harness 的鲁棒性：在一个系统里收集的轨迹，会把该系统的约定连同任务一起教给模型。跨几个 harness 收集，是实验室避免训练出“只在一个 harness 里能用”的模型的常见做法。

Slides 第 45 页讲目标领域之外的回归：训练一种能力，你会移动其他能力，无论你是否测量。这里的控制是混合比，而按样本平衡不等于按 token 平衡；所以也要评测那些你并不打算改进的东西。

## 八、交给强化学习

Slides 第 47 页给出交接的核心判断：“当 SFT 模型是带着 RL 的考量来选的，RL 提供的收益最大。”完全没有 SFT 时，RL 几乎推不动基础模型；只有 SFT 也远达不到两者结合的水平；获胜配方是从一个“刻意没有训练到它自己最佳分数”的检查点开始 RL。

**学习者解释**：这句话值得多停一秒。它不是“SFT 不太好”，而是说 SFT 的目标函数不该是“在 SFT 数据上尽可能好”。如果你把模型训到在演示分布上饱和，留给 RL 的提升空间反而可能更少，因为 RL 擅长的是打磨模型已经能尝试的东西（Slides 第 8 页）。

## 九、把本讲压成一条链

1. 轨迹是记录，不是答案；SFT 把“在什么上下文里发什么动作”变成权重（Slides 第 3、5 页）。
2. 模板把轨迹变成一条 token 序列，掩码决定哪些 token 承担损失（Slides 第 11、12、13 页）。
3. 掩码的细节——停止 token、推理块、推理与工具调用的再平衡——都是会改变学到什么的设计选择（Slides 第 15、16、17 页）。
4. 选轨迹比调超参更影响结果：老师可能名不副实，来源的组合比来源的数量重要，多样性比同一分布的堆量重要（Slides 第 26、27、28 页）。
5. 统一格式能让你用多个数据集，但写回 harness 时仍要检查工具调用能否解析（Slides 第 31、32、33 页）。
6. 训练能跑起来不等于有效：训练继续录像，部署继续它自己，所以必须同时看损失和评测（Slides 第 42、43 页）。
7. SFT 的正确目标不是自己刷到最高，而是给 RL 一个好起点（Slides 第 47 页）。

## 十、留给读者的问题

Slides 第 19 页明确说，改动智能体 SFT 掩码并测量后果的已发表实验“就摆在那里没人跑”。如果你要动手，最想先动哪个开关：推理是否进损失、observation 是否进损失、还是停止 token 的拆分粒度？这个问题没有本讲给出的答案，本讲只给出了为什么它值得被问。
