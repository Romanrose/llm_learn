# 从 ReAct 到计划图：CMU 11-768 第五讲拆解智能体的规划、任务分解与多智能体协调

> 待审核候选稿 · 来源：平台字幕与官方 Slides · 尚未发布。

## 一、一个让人犹豫的任务

先看一个具体的任务。你要为一个研究实验室采购新的 GPU 工作站：比较不同供应商网站上的配置和价格，对照内网 wiki 上的集群兼容性要求做检查，然后提交采购申请。这个任务并不“难”，但它很长。课程幻灯片把它拆开来看：一个使用标准 ReAct 循环的智能体需要大约数百步——访问 vendor-a.com，找到 Workstations 页面，读取 spec sheet，做 GPU 比较，第 15 步才配置出“2× RTX 6000、128 GB RAM、850 W PSU”，第 31 步才从 wiki 上读到“机架只接受 4U 机箱，每个插槽 1600 W”。上下文中途被压缩，从 128k 降到 14k token。等它搜完四个供应商，发现只有 D 符合要求，但交货期长达 20 周。第 201 步它面临一个抉择：选 D？找第五家？放宽某个要求？第 202 步它还是去采购门户提交了申请（Slides 第 2 页）。

这就是本讲的核心张力：**一个只会“反应”的智能体，在长任务上会积累上下文、丢失结构、在关键时刻无法回头**。Daniel Fried 在开场就抛出这个问题：规划——让智能体对未来行为做出显式承诺——到底有没有用？什么时候它不值得额外的成本和僵化？怎么表示计划？什么时候该改计划？人应该在什么时候介入（Slides 第 3 页）？

> **学习者解释**：这里的“ReAct 循环”指智能体反复执行“思考—行动—观察”的单步循环。它的特点是每一步只看当前上下文，不为未来行为保存显式结构。逐字稿中讲者把它称为“标准 React 循环”，并说这个任务“可能需要大约数百步”。

## 二、本讲对“计划”的工作定义

课程给了一个可以直接引用的工作定义（Slides 第 5 页）：

> 计划是对预期未来行为的一种显式表示：智能体将尝试的动作或子目标，以及它们之间的排序或依赖关系。

三个限定词很关键。第一，**计划是针对这个任务的**，而技能（skill）是跨任务可复用的指导；计划可以比技能更具体，甚至绑定到某个特定仓库。第二，**计划组织未来的工作**，它可以规定动作或子目标，以及排序和依赖。第三，**计划是提议，不是保证**，它可以被用户、另一个模型或环境交互检查与修改。幻灯片引了泰森那句话：“每个人都有一个计划，直到嘴上挨了一拳。”

讲者在逐字稿中用了同一段话来解释这个定义的边界：计划是模型可以参照的产物，它既总结过去做过什么（类似上下文压缩），也指定未来应该做什么。它建立在思维链的思路之上，但在智能体场景里更麻烦——因为智能体会从环境中揭示新信息，计划必须始终可修改。这就引出了本讲的第一个权衡：智能体应该在多大程度上承诺某个行动方案（便于人类理解和监督），又应该有多灵活（能应对沿途出现的事情）。

## 三、为什么长任务需要结构

把那个 GPU 任务画成图，结构就出来了（Slides 第 3 页）。Vendor A/B/C/D 的搜索彼此独立，可以并行；兼容性检查依赖各供应商返回的信息，但供应商之间互不依赖；采购申请在兼容性检查之后，而且它是**不可逆**的。更麻烦的是，图本身会变：如果四家都不合适，就得加入第五个搜索节点。这正是“重新规划”（replanning）——你有一个结构化的表示，并根据环境观察修改它。

幻灯片把本讲的问题拆成四个维度（Slides 第 3 页）：

- **价值**：规划什么时候有用？什么时候有害？
- **表示**：计划怎么表示——文本？结构化图？代码？
- **承诺**：计划何时做出，什么可以改变它？
- **监督**：人应该在何时、以何种方式介入？

> **学习者解释**：依赖图（DAG）在这里的作用是让“哪些子任务可以并行、哪些必须等待”变得显式。幻灯片第 3 页明确标出“Vendor E”是后来加入的节点，用来说明图结构本身也要能被修改，而不只是图上的执行结果会变。

## 四、思维链：规划的史前史

讲者先快速回顾了 LLM 之前的“规划”传统（Slides 第 8 页）。Kojima 等人 2022 年的工作发现，只要提示模型“让我们一步一步地思考”，就能提高答案准确率；Wang 等人 2023 年则提示模型先“理解问题并制定计划”，再执行计划。这些工作发生在模型被训练来显式产生思维链之前。思维链的作用是给模型提供额外计算和一块草稿板：它接收这些 token，在预测答案前做额外操作，也能回头参考中间结果。这与智能体规划的动机相同。

但幻灯片也点出了关键差别：**计划和解答在同一次模型生成中到达，没有任何东西显式检查这个计划**。后来的工作（STaR、DeepSeek-R1）把思维链训练成提高正确答案概率的手段，但“检查”这件事仍然缺席。

接下来是分解（Slides 第 9 页）。Least-to-Most（Zhou 等人，ICLR 2023）把“规划”和“求解”分开：第一阶段写出子问题，第二阶段按顺序回答并向前传递答案。动机是模型不擅长一次回答涉及多个推理步骤的问题，而回答子问题所需上下文更少，改进幅度随问题长度增长。Recursive Language Models（Zhang 等人，2025）被归为同一类。

> **学习者解释**：逐字稿里讲者用了一个具体例子来说明“向前传递”：先问“每趟旅行需要多长时间”，得到“五分钟”，再把完整问题和这个答案一起喂给下一个子问题。对当时的模型来说，这很关键，因为它们不太擅长一次完成多个推理步骤。

分解还带来**模块化**（Slides 第 10 页）。Decomposed Prompting（Khot 等人，ICLR 2023）用一个分解器生成子任务，并把每个子任务路由到专门的处理器。幻灯片给的例子是：“由 1910 年出生的人制作的电影获得过什么奖？”被拆成“谁出生在 1910 年”（simple QA）和“哪些电影的制作人是 #1”（position QA）。模块化允许独立改进处理器模型（通过上下文示例或训练），也提供了程序化/结构化控制。

## 五、当计划开始作用于世界

思维链只改变文本：它可以被更多文字撤销，每个中间步骤都可见。而世界中的动作会改变智能体接下来遇到的状态、可能揭示信息、可能失败、可能不可逆——提交、发送都是例子。幻灯片第 12 页总结道：**行动意味着计划必须处理可行性、后果、信息和恢复**。

这就把本讲引向经典规划（Slides 第 13 页）。经典规划里，状态是一组谓词，动作有前置条件和效果。幻灯片用积木世界举例：`pick-up(x)` 的前置条件是 `on-table(x) ∧ clear(x) ∧ hand-empty`，效果是 `holding(x) ∧ ¬on-table(x) ∧ ¬hand-empty`。规划是一个搜索问题：找到一串有效动作，从初始状态到达目标。幻灯片给的示例计划是 `unstack(blue, orange) → put-down(blue) → pick-up(orange) → stack(orange, blue)`。它引用了 STRIPS（Fikes & Nilsson, 1971）和 PlanBench（Valmeekam 等人, NeurIPS 2023）。

但 LLM 时代“难的东西变了”（Slides 第 14 页）：对 LLM 来说一切都是隐式的。写一个看似合理的计划更容易，判断它对世界的模型是否正确更难。所以智能体设计用更少的深度搜索，更多地去检查世界：观察、验证、从错误中恢复。但搜索和动作适用性仍然是有用的概念。

> **学习者解释**：这里不是“经典规划被淘汰了”，而是重心转移。逐字稿中讲者说，LLM 见过大量关于各种情境的信息，所以能直接生成一个大概率合理的初步计划；问题不在于“生成”，而在于“检查它是否真的可行和可执行”。

## 六、计划可以采用什么形式

幻灯片第 15 页给出一个谱系：形式化计划可检查，语言计划通用，程序在两者之间。2023 年前后有一系列工作用代码 LLM 写出调用感知和控制 API 的代码（Code as Policies、ProgPrompt、Binder）。程序可运行、可检查，但受限于 API 和程序结构允许什么。而 API 本身可以调用 LLM 或另一个神经网络模型。

讲者在这里补了一句重要的现实判断：这类方法在机器人领域没有像端到端多模态 VLA 系统那样流行起来，但对编码智能体仍然非常有用——下一讲的 CodeAct 会涉及。

关于“什么时候重新规划”，幻灯片第 16 页给了三档（Anthropic《Building effective agents》2024 被引为来源之一）：

1. **开发者定义的工作流**：开发者指定过程，比如检查一个固定的供应商列表。幻灯片给了一段伪代码：`for v in VENDORS: specs[v] = read_specs(v)`，然后 `ok = [v for v in specs if fits(v)]`，最后 `requisition(cheapest(ok))`。
2. **先计划后执行**：模型规划要检查哪些供应商，然后在执行前承诺。
3. **自适应智能体**：四家供应商失败后，执行反馈让模型去寻找另一家。

权衡是：提前承诺一个计划更快、更便宜、更可预测；重新规划让模型在執行揭示新信息时能适应。当反馈值得额外成本和复杂性时，才用重新规划。

## 七、规划压力的四个来源

幻灯片第 17 页把“为什么要加规划结构”归纳成四个词：**模块化、反馈、长时程、控制**。第 18 页用 GPU 采购任务把这四个词具体化：

- **模块化**：搜索分别执行。
- **反馈**：都不合适，所以修改计划。
- **长时程**：需求和进度贯穿整个任务。
- **控制**：人在智能体提交前批准。

接下来的方法论文献，就是围绕这四个压力展开的（幻灯片第 19–32 页）。

### 7.1 模块化：规划者与执行者分离

UGround（Gou 等人，ICLR 2025）和 Agent S（Agashe 等人，ICLR 2025）是幻灯片给的例子。规划者模型（当年是 GPT-4o）有视觉 grounding，但不擅长产生像素级动作，于是让它用语言描述下一步动作；一个单独训练的 7B 执行者模型把这些描述映射到屏幕坐标。讲者解释了为什么这在当时有效：最强模型不擅长处理网站的细粒度视觉细节，而分解并模块化让你能独立优化每个组件，在弄清瓶颈后对每个组件做“爬山”。

幻灯片第 20 页给了**怎么训练规划者**：用教师模型对成功轨迹做分段和标注，产生计划；然后在这些标注轨迹上微调规划者模型和执行者模型（Plan-and-Act，Erdogan 等人，ICML 2025）。讲者指出这有点类似上一讲的工作流归纳：都从一条轨迹开始，做分段和标注，区别在于这里是用它来生成训练数据。

### 7.2 模块化的代价：警惕固定角色

幻灯片第 21 页是一个重要的警告，标题是“Beware of fixed roles and multi-agent systems”，并标注了 Graham Neubig。要点有两个：为编码做角色分解的成功有限；角色在任务到达之前就固定了，**验证者无法定位故障来检查自己的答案**；交接是摘要报告，可能丢掉下一个智能体需要的上下文。讲者在逐字稿中展开说：一些工作让模型模拟软件公司或工程师团队，有专门的测试角色、编辑角色，甚至产品经理；这些方法及其变体（如非常针对 GitHub 问题的 Agentless）在任务总是匹配那种结构时取得了成功，但缺乏适应性，而且模块之间传递信息很难——如果你在一个单一智能体里做，并且妥善处理了所有过去动作的可用上下文，那些信息本来都在。

### 7.3 反馈：可供性、反思与交互

**可供性**（Slides 第 22 页）。SayCan（Ahn 等人，CoRL 2022）把 LLM 规划者与一个技能可供性模型结合：为每个机器人技能学一个价值函数，预测完成它的概率，然后把这个概率与 LLM 给出该计划的概率相乘。讲者举的例子是：模型可能提议“拿起苹果”，但如果视野里没有苹果，那就是一个糟糕的子任务；价值函数会给“找到它们”更高概率，给“放下它”更低概率，因为你还没拿到。

**在环境反馈上重新规划**（Slides 第 23 页）。LLM-Planner（Song 等人，ICCV 2023）、Inner Monologue（Huang 等人，CoRL 2022）、SwiftSage（Lin 等人，NeurIPS 2023）被列为例子。讲者用 ALFRED 具身环境解释：任务是“煮一个土豆并把它放进回收箱”；模型产生初始计划并调用原语，但计划在上下文中可能无法执行，于是它得到反馈“我找不到土豆，但我看到了一个冰箱”，把反馈输入语言模型重新预测计划，计划更新为“打开冰箱，然后希望里面有土豆”。

**思考 vs 行动**（Slides 第 24 页）。Test-Time Interaction（Shen 等人，NeurIPS 2025）在三种推理方法之间匹配计算量：产生更长的思维链、采样多个候选、或与环境更多交互。讲者说，在给定 token 花费下，用那些 token 与环境更多交互通常表现更好——只要你不是在做会让你进入糟糕状态的事情。

**过度思考**（Slides 第 25 页）。Cuadron 等人 2025 识别了三类坏行为：分析瘫痪、流氓动作链、过早脱离。更多过度思考在各模型类型上都预测更少的问题解决。讲者补充说，这些行为只需要知道花了多少 token 在推理上，可以从很多 API 模型获取；更大或更强的模型可以缓解其中一些问题。

**思考 vs 观察**（Slides 第 26–27 页）。Calibrate-then-Act（Ding, Tomlin, Durrett, 2026）的例子很精巧：每个文件有一个隐藏格式，三个部分——分隔符（`,` `;` `\t`）、引号字符（`"` `'`）、跳过的表头行数（`0` `1`），十二种组合，只有三个都对文件才能解析，而文件名是唯一线索：`sales_fr.tsv` 指向 tab。幻灯片给出的提示词增加了“格式似然”，模型读出“分隔符最可能是 `;`，概率约 0.85……但我不确定，所以也许我应该跑些单元测试确认”。逐字稿中讲者用 CSV 的 price 列做类比：大多数价格 CSV 有 `price` 列，但不是所有都有。

### 7.4 长时程：错误会相乘，也会自我条件化

幻灯片第 28–30 页集中处理长时程失败。Vending-Bench（Backlund & Petersson, 2025）的任务是长时间经营一台自动售货机：定价、订货、补货；时间跨度最多 2,000 条消息、约 25M token、最多 222 个模拟日。幻灯片给了一个失败链：**过早补货**——“今天到期”不等于“已经送达”；环境正确报告“商品不可用”，智能体却推断“生意失败了”，从不等待履约邮件或再检查；错误持续，每日费用变成“欺诈”，邮件标题成了“紧急：业务终止后的未授权费用”。讲者的总结是：后来的动作会条件化在智能体早先的错误上。

幻灯片第 29–30 页引用 Sinha 等人 2025：更好的步骤准确率能延长时程，而自我条件化会让后续步骤更不准确；更大的模型执行更长的任务，但也更多地自我条件化。讲者用概率相乘解释：如果每一步有 90% 正确率，把所有步骤都做对的概率是 0.9 的连乘；从 0.9 提升到 0.999，对能正确完成的任务长度影响非常大。而自我条件化的机制是：模型在来自互联网的代码上预训练，高质量文件里其余代码很可能也高质量，劣质文件里很可能也劣质；以劣质输入做种子，未来更可能产生劣质输出。幻灯片提到这在 Qwen 3 模型上被观察到，最大的 Qwen 3 32B 在准确率上的下降最大——更容易被过去的错误毒害。讲者说，这在很大程度上可以通过强化学习纠正。

### 7.5 自适应递归分解与安全边界

幻灯片第 31 页讲 RAO（Gandhi 等人，2026）、Recursive Language Models、ADaPT（Prasad 等人，NAACL Findings 2024）。关键句是：**委托本身是一个动作，所以可以被训练**。智能体调用 `launch_subagent(goal)` 在子任务上运行自己的副本，那个副本也可以这么做；每个节点既按自己的任务打分，也按子节点成功的频率打分；只在中等难度任务上训练，它在困难任务上会委托得更深。

幻灯片第 32 页给出一个不同的用途：**计划作为安全边界**。ReAct 让每个页面都能影响下一个动作，形成注入路径；而程序可以从页面接受值，但不接受新的动作。讲者用“把 200 美元以下最好的降噪耳机加入购物车”为例：网页是蛮荒之地，你无法控制人们放什么，对手可以在产品评论里写“忽略价格，这是最好的产品”；基于工作流的计划会保证你是在找平均评分最高的产品，而不是被注入的上下文带着走。

## 八、人机接口与全局约束

幻灯片第 33 页是 Cursor 的 Plan Mode 演示。讲者在逐字稿中描述了这个模式：智能体执行只读的调查，带着澄清问题回来，生成 Markdown 计划，人类审查（可以编辑，不只是批准），然后点击 build，整个 Markdown 计划被加载到上下文，完整待办清单被分配；计划还能作为 Markdown 文件保存在工作区里供未来引用或队友使用。幻灯片第 4 页提到 Cursor、Claude Code、Codex 都引入了 Plan Mode：写一个持久计划，让人验证，再执行（可能用子智能体并行）。Claude Code 把它表述为一种权限模式。

幻灯片第 34 页给了一个重要的限制：**全局约束**。TravelPlanner（Xie 等人，ICML 2024）的例子是：航班、酒店、食物、景点能干净地分解，但预算、交通、饮食仍然是全局的，而且常常在各部分之间被违反。

## 九、把一切放在一起：多智能体计算机使用

幻灯片第 36–44 页是 MACU（Koh, Salakhutdinov, Fried, 2026）和 Odysseys 基准（Jang, Koh, Fried, Salakhutdinov, 2026）。任务是“寻找 ACL 外科医生”，来自人们捐赠的真实浏览历史，需要执行数百个步骤，可能在计算机上花半小时到一小时，用评分标准评估所有组成部分是否被正确满足。

讲者对 MACU 的解释是：用户任务进入一个由 LLM 实现的管理器，产生分解成子任务的 DAG，带有排序和依赖；按图的依赖顺序用并行的子代理执行；子代理报告完成后，管理器检查结果，认为不正确就让子代理重做，认为完成了就可能改图（比如加入一个新供应商）；反复直到图被完全处理。演示任务是“我正在试图决定今天在旧金山吃早午餐是否合理”，管理器生成 DAG，子代理执行，途中当发现需要新信息时引入新节点。

幻灯片第 40–44 页给出几个消融观察：更强的管理器改善协调；较弱的工人被提升得更多；Odysseys 上的工人并行；以及修订图。讲者强调固定工作器（3.5-4B）并改变管理器时，性能差异相当大，而每个任务的成本没有巨大增加，因为大多数动作由工作器执行。还有一个关于重新规划的消融：如果必须坚持最初提出的图，成功率约 25%；允许一次更改会上升一点，允许更多更改、更多重新规划步骤则上升更多。**但幻灯片没有给出这些图的具体数值，图示需要对照官方 PDF 核验。**

## 十、一条设计清单和一组开放问题

幻灯片第 46 页给出一条设计清单，在添加规划结构之前问：

1. 子任务可分吗？规划者和执行者是否会受益于不同的模型或训练？
2. 哪些失败或观察应该改变计划？
3. 系统如何阻止错误和上下文累积？
4. 什么信息和权限保持分离——谁批准不可逆动作？

幻灯片第 47 页给出四个开放问题：**检查**——语言计划和子目标图没有通用验证器；**校准**——智能体误判何时该思考、观察、询问或修改；**全局状态**——跨子任务约束抵抗分解和更长上下文；**脚手架**——训练出的推理是否会吸收这些结构，仍然开放。

## 十一、我的理解：本讲真正在教什么

> **以下为学习者解释，不是讲者原话。**

如果把这一讲读成“规划方法的目录”，会漏掉它真正的论点。它在教一个**设计判断**：规划不是默认更好的，它是用承诺换可理解性、用灵活性换可靠性的一笔交易。

四类压力（模块化、反馈、长时程、控制）不是四个可以同时最大化的目标，而是四个会互相拉扯的旋钮。模块化让你能独立优化每个部件，但固定角色会在任务到达前就锁死，让验证者无法定位故障；重新规划让智能体能适应，但增加了成本、复杂性和不可预测性；限制子代理的上下文能提高效率，但全局约束会在各部分之间被违反。

最有说服力的证据来自长时程那一节：错误会相乘（步骤准确率连乘），而且会自我条件化（过去的糟糕上下文让未来更可能糟糕）。这两点合起来解释了为什么“平均每步都还行”的智能体在长任务上会崩溃，也解释了为什么规划结构——无论是显式的 DAG、单独训练的执行者，还是一个人的批准点——最终是在为“在正确的位置检查、在正确的位置恢复”付费。
