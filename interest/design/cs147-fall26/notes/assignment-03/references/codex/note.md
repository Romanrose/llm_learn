# CS147 assignment-03：让项目网站成为设计决策的证据索引

## 学习目标与概念

项目网站应让陌生读者追踪问题、研究、迭代与结果。它既是作品集，也是一张可检索的证据地图。

## 可执行学习流程

1. 先列读者问题：为谁解决什么、为何相信问题成立、做过哪些尝试、当前版本能做什么。
2. 按设计过程组织资料，不要只按文件扩展名堆下载链接；在每个产物旁加一句它支持了哪项决策。
3. 首页提供简明项目说明和可访问演示；深入页面保留匿名研究记录、原型版本与变化理由。
4. 逐项检查导航、键盘访问、文字对比、移动窄屏与链接；图片附说明，视频旁给简短文字介绍。
5. 标明模拟能力、未完成部分和外部帮助；公开资料前去除个人信息。自学采用普通静态托管，不能声称有 Stanford 账户。

## 交付与自检

建议交付：网站信息架构、可运行静态页面、资源索引、访问检查记录，以及团队贡献和引用说明。

用第一次访问者能否找到关键证据评估网站。视觉漂亮但无法找到设计变更原因，仍然没有完成过程表达。

## 练习示例

虚构练习：一个课程笔记网站记录“用户找不到上一讲”，主页展示修复后的导航；案例页链接原观察、两种备选布局和最终选择理由。

## 案例页面内容表：可直接使用的交付模板

以下模板是自学建议，不是官方提交表格。

- 字段：问题情境；研究证据；备选方案；关键取舍；最终版本；未解决问题；外部来源。
- 虚构填写示例：导航改版｜初访者看不出必读｜试过按类型和按任务分组｜选按任务但保留原资源入口｜给出运行演示｜历史日期仍需改进。

每个字段都应由自己的研究、测试或实现填写。无法确认的地方写“待验证”并说明验证动作，不用虚构用户话语或成功数据补齐。提交前请另一位读者仅凭该记录复现你的过程；需要口头补充才能理解的地方，应回到文档补清楚。
