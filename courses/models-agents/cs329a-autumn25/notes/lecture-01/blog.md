# 从 Scaling Law 到自我改进智能体：Stanford CS329A 第一讲导读

## 导语

过去五年，大语言模型的进步几乎可以用一条曲线概括：投入更多计算、更多数据、更多参数，损失就会下降，模型就会变好。但这条曲线正在遇到饱和，而另一条曲线正在上升——推理时的扩展、智能体工作流的编排、以及模型用自己生成的数据改进自己。Stanford CS329A《Self-Improving AI Agents》2025 年秋季第一讲，正是从这两条曲线的交接处出发，为学生勾勒出整门课的问题地图：当“把模型做大”不再是唯一答案，我们如何让模型在推理时、在环境中、在反馈循环里持续变强？

本文依据该讲逐字稿与讲义内容整理，不复述课程提纲，而是沿着讲者的论证线索，解释几个关键概念之间的递进关系，并说明这一讲在整门课程中的位置。

## 一、预训练时代的核心信念：规模即能力

讲者用三张图开场，分别对应 scaling law 的三个维度：计算量、数据规模、参数量。随着横轴增加，纵轴的 test loss 下降，模型变好。这条经验规律支撑了从 BERT（约 3.4 亿参数）、GPT-2（15 亿）、GPT-3（1750 亿）到 PaLM（5400 亿）的指数级增长，GPT-4 则被估计在数万亿参数的量级。

规模带来三种讲者明确点名的能力。第一是基准表现的全面提升，覆盖自然语言、推理等各类评测。第二是 few-shot 乃至 zero-shot learning：早先需要针对特定领域微调，后来只需在 prompt 里给任务描述和几个例子，模型就能照做——讲者用“把 cheese 翻译成法语”的例子说明 zero-shot，用带若干英法对照例子的版本说明 few-shot。第三是 emergent behavior：某些能力只在大模型上出现。

思维链（chain of thought）是讲者重点展开的涌现行为。在 one-shot 数学题示例中，模型得到的不仅是“问题—答案”配对，还有得到答案的推理过程：Roger 起初有 5 个网球，又买了两罐、每罐 3 个，所以是 5 加 6 等于 11。模型由此学会“如何走到答案”，并把这种过程迁移到新问题。讲者特别指出，这个例子本身现在任何十亿参数级模型都能解决，但思维链作为一种特性至今仍然成立，是后来所有 reasoning model、thinking model 的基础。讲者还展示了模型规模与思维链收益的关系：小模型（如 80 亿参数的模型）几乎无法从思维链中获益，而更大的模型可以。

这一部分还埋下了一个贯穿全课的问题意识：scaling 曾经是“自然的进展”，但讲者明确说它“开始触及某种饱和点”。后面所有内容，都是对这个饱和点的回应。

## 二、ChatGPT 的跨越：不只是变大

讲者强调，ChatGPT 相对于 GPT-3 的跨越式发展，不能只归因于参数规模。2022 年 11 月发布的 ChatGPT 在极短时间内达到百万用户，而其背后的关键创新包括 instruction tuning 和 reinforcement learning from human feedback（RLHF）。

讲者把训练流程拆成几步。预训练是最简单的一步：从海量文本中预测下一个 token。此时模型“没有对错的概念”，只是统计地了解世界的状态，不知道如何遵循指令。接下来的微调步骤才是差异化所在：先用更高质量的数据做下一 token 预测（讲者提到这类数据可能耗资巨大），再做 instruction tuning——用指令加问答对的数据，教模型遵循问题并回答，数据可以是人工生成、模板与合成数据的组合，也可以包含思维链式的过程示范。

然后是 RLHF。它与前几步的区别在于目标函数和数据的构造方式：不是直接给监督式的提示和标签，而是基于人类偏好训练一个 reward model，再用它引导 LLM 的参数，使生成结果让 reward model 判定为“好”。讲者提到可以按正确性、有用性、具体性、无害性等不同维度定义奖励并加权。这里逐字稿中讲者口误说成了“RLAIF”，从上下文看所指即 RLHF 流程。

这一段的论证意图很清楚：模型能力的跃升来自“预训练 + 高质量微调 + 指令微调 + RLHF”的组合，而不是单一维度的扩大。这为下一节“推理也是前沿”做了铺垫。

## 三、推理扩展：不碰参数也能变强

讲者把时间线推到“一年半以前”，提出 inference 成为提升模型能力的新前沿。这里的关键工作是 Language Monkeys，灵感来自 infinite monkey theorem：如果一只猴子对着打字机无限打下去，终会遇到莎士比亚的作品。类比之下，让 LLM 反复求解同一个输入问题——即 parallel sampling 或 parallel generation——再配合某种 verifier 或选择机制挑出正确回答，系统整体就能输出正确答案。

讲者用具体设定说明 verifier 的形态：如果任务是生成代码，verifier 可以是单元测试，看哪份代码通过全部测试。之所以可行，是因为模型生成存在方差，可以用 temperature 控制多样性；讲者也提到温度不能太高，超过某个程度输出会变成胡言乱语。

实验结果很有说服力：在一系列数学和编程基准上，把每个问题的采样数从 1 增加到 10,000，以 coverage（至少被一个样本解决的比例）衡量，单样本时不如 GPT-4 级别模型的 Llama 8B、7B 等小模型，在增加样本后反超。讲者的解读是：模型知道的远比问它一次所展现的要多。而且有些问题在 10,000 个解中可能只有三四个正确，说明推理扩展对于触及模型核心能力是必要的。

问答环节澄清了几个重要边界。其一，可能的答案仍须由模型生成，答案空间远大于实际采样，树搜索或随机搜索的空间更大。其二，并行采样可以并行运行，延迟不是主要问题，真正的权衡在算力与成本，且随问题类型和复杂度变化。其三，有 verifier 时容易得多；没有 verifier 时，需要训练 LLM judge 或 LLM reward function，课程有专门一讲覆盖 verifier。其四，温度调参本身是研究问题，讲者提到去年有项目专门研究合适的温度。

## 四、从推理模型到自我改进闭环

讲者接着讲 DeepSeek 等模型（2024 年 12 月出现）以及 o1 系列、Gemini thinking 等的核心创新：把 fine-tuning 和 test-time scaling 结合。逻辑是：测试时扩展可以针对数学这类已知答案的问题生成大量通向黄金答案的解答，或针对编程问题生成大量高质量数据，这些数据又成为训练集的一部分，用来微调模型使其更好。这个“测试时生成—回流训练”的闭环，正是讲者所说的 self-improving 部分，也是课程命名的由来。

讲者用 OpenAI o1 在困难数学基准 AIME 上的表现说明：随着测试时算力增加（对数刻度），pass@1 准确率上升，而模型参数量不变。这与 Language Monkeys 展示的 coverage 缩放形成对照：前者衡量的是“采样足够多能否解出”，后者衡量的是“一次回答是否正确”。问答中讲者进一步区分：重复采样提升的是 pass@K 或覆盖率，推理模型提升的是 pass@1，因为模型学会了判断哪条推理链是正确的。

讲者还列出思考模型处理困难问题的若干原则：问题分析、任务分解、自我进化策略（尝试、获取反馈、优化）、自我纠正、替代方案提议。并以 o1 写 bash 脚本输出矩阵转置为例，展示模型如何自问“用户要什么、输入输出格式是什么”，如何分解出解析输入、把矩阵构建为数组的数组等子任务，以及如何在轨迹中间说“等等，好像有问题”。讲者强调，这些技能部分来自人类策划的训练数据，很大部分来自微调与从合成数据做 RL 的过程，且模型会泛化到训练数据之外。

问答中有一个值得记录的开放问题：预训练已经赋予模型能力，为什么 RL 还能带来显著跃升？讲者的回答是，整个循环尚未被完全理解，RL 与预训练数据多样性各自的贡献没有单一共识，两者都有帮助——这被讲者称为“生命的最初迹象”。

## 五、从聊天机器人到智能体

课程标题的后半部分在此登场。讲者指出，LLM 作为聊天机器人或推理模型基本上仍是单轮的，交互有趣但不一定替你完成任务。而近几个月，Claude Code、Deep Research 这类智能体开始让人做真实世界的工作流。

讲者用两个例子说明。Deep Research：想研究在斯坦福上课该在哪里租房，模型能浏览大量网站、汇总结果、给出不同地点的优缺点——这在以前不可能。Claude Code（以及 OpenAI 的编程智能体）：用英文下指令就能修改文件、找出测试用例，已成为软件工程师的日常生产力工具。

讲者给出智能体的定义性要素：模型被赋予一个目标，它规划步骤、与环境交互、根据反馈修正步骤，直到达成目标或回来说“我无法达成”。有目标概念、朝目标行动、获取反馈、决定何时停止——这就是智能体区别于聊天机器人时代的地方。此外还需要工具交互，以及某种形式的记忆来跟踪任务。

讲者诚实地指出当前局限：更简单的情况下可以端到端完成（如 Deep Research），但大多数场景仍是“非常静态的工作流”，更接近 agentic workflows 而非开放式循环。讲者展示了一个卡通化抽象：LLM 调用、verifier、critic 或 judge（LLM as a judge 范式）、工具调用（如搜索）、以及编排方式——prompt chaining（对应推理模型的任务分解）、routing（按复杂度分流）、parallelization（Deep Research 式的多路并行后聚合）、orchestrator（中央 LLM 做规划，如 Claude Code 的计划概念）、evaluator、verifier（如单元测试）。

讲者强调，这些工作流要求 LLM 更擅长规划、多步推理和自我改进——犯错时能自我纠正。这些是当前 LLM 仅靠推理还不能完全实现的新范式，也是后续讲座的主题。

编码智能体的例子被用来收束：智能体通过终端与计算机交互，做仓库导航、文件搜索、编辑行、执行命令，根据输出决定下一步看哪个文件、改哪个文件。讲者说这在去年还不太可靠，现在才刚刚开始变得可靠。

## 六、验证器：自我改进的瓶颈

问答环节贡献了本讲最重要的概念之一：generator-verifier gap。讲者指出，模型很容易生成一堆胡说八道、貌似合理的推理轨迹或看似有用的内容，但归根结底是否有用，需要建立反馈循环。在创意写作这类领域，人类反馈最终成为瓶颈；在能获得稳健验证的领域，模型才能持续改进。讲者明确说，verification 仍然是这个领域让模型变好的瓶颈之一。

这也解释了课程结构：verifier 单独成讲，LLM as a judge 有作业覆盖。讲者提到 Code Monkeys 的工作：如果能对模型生成的代码生成单元测试，再看这些测试是否让事情变好，那是很好的验证方式。在数学、代码等可验证领域，验证是给模型提供反馈、让其纠正步骤的好方法。

讲者还回应了一个关于“推理和思维链是训练烘培的还是提示工程意外发现的”问题：思维链最初是涌现行为——研究者给模型难题，发现它通过生成推理链做得更好，GSM8K 是早期迹象之一，更大模型上更明显；而推理模型是被训练去推理的，模型会收敛到知道何时需要大量推理、何时不需要。讲者说很难简单二分，因为这些行为在微调方式中被强化过。

## 七、课程地图与项目要求

讲者随后介绍课程安排：主题列表保持不变，另有一系列来自前沿 AI 实验室的 guest lectures，覆盖后训练如何演变，乃至多模态智能体与机器人学。本季度有三次作业（比对照课程多一次），以及一个课程项目。项目可两到四人组队（最多四人，也允许单人），提供 API 额度。可接受的项目类型包括：新的评估数据集或基准、围绕已有智能体系统的可靠性设计项目、在已有基准上“爬山”、质疑课上论文的某个设计决定并评估。反面例子是综述论文、拼凑的应用、或现场编程式的演示——讲者要的是有假设、有问题、有构建的研究性工作。里程碑包括十月初的项目提案、期中展示（提案后两周，需有实际进展）、最终报告和海报展示。评分上作业占一半，项目占一半。办公时间、Ed Stem、Gradescope、迟交政策等后勤事项也在这一部分交代。讲者提到上季度有学生把项目发展成了发表论文。

## 结语：这一讲在课程路径中的位置

回看整讲的结构，第一讲完成了三件事。其一，建立历史叙事：scaling law 支撑了预训练时代，instruction tuning 与 RLHF 造就了 ChatGPT，test-time scaling 与推理模型开启了新前沿，而智能体工作流正在把模型从“聊天”推向“完成任务”。其二，提出核心张力：模型能生成远比一次回答更多的正确解，但要从这些解中挑出正确的，需要 verifier、judge、工具反馈或环境反馈；验证是瓶颈，也是自我改进循环的支点。其三，给出课程的问题清单：规划、多步推理、自我纠正、验证器设计、智能体编排——这些正是后续讲座将逐一展开的主题。

因此，这一讲不是课程提纲的朗读，而是整门课的问题地图。它告诉学生：我们不再只问“模型能多大”，而是问“模型如何在推理时、在环境中、在反馈里变得更好”；而回答这个问题所需的工具——从 parallel sampling 到思考模型，从 prompt chaining 到 orchestrator，从单元测试到 LLM judge——将在接下来的课程中被逐个拆解。对于想理解 self-improving AI agents 这一研究方向的人来说，这一讲提供了必要的坐标系。
