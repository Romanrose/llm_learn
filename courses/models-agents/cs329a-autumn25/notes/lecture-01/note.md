## 一、学习目标

本讲是课程总览，目标不是教会某个具体算法，而是建立三条主线之间的连接：

1. **理解 LLM 能力演进的历史脉络**：从 scaling law 驱动的预训练，到指令微调与 RLHF 带来的对齐，再到推理时扩展（inference scaling / test-time scaling）与推理模型（reasoning models）。
2. **理解从 LLM 到 agent 的范式转变**：模型不再只是单轮聊天或单轮推理，而是被赋予目标、规划步骤、与环境交互、依据反馈修正行为，直到完成或报告无法完成。
3. **理解「self-improving」在课程语境中的含义**：把测试时扩展产生的大量高质量轨迹回灌到训练/微调中，形成「推理时生成 → 筛选/验证 → 训练改进」的循环；以及 agentic workflow 中规划、验证、自我纠错等能力为何是当前 LLM 仅靠推理尚不能完全满足的新范式。

课程原意强调：这门课讨论的是**开放式**问题，很多机制尚无共识（例如 RL 与预训练数据多样性各自贡献多少、自我改进循环为何有效），因此课程同时承担「梳理已知」与「指出开放问题」的功能。

## 二、课程主线：四个阶段与一次转向

逐字稿把 LLM 发展概括为若干阶段，并以「agent」作为本课程的落点。

### 1. 预训练与 scaling law

- 自 GPT-3 以来，扩大参数量、数据量、计算量会持续降低 test loss，得到更好的模型。逐字稿给出三条 scaling 轴：计算量、数据集规模、参数量（例如增加 Transformer 层数）。
- 逐字稿回顾了模型规模的增长轨迹（BERT → GPT-2 → GPT-3 → PaLM → 后续模型），并指出这一趋势持续到大约去年开始触及某种饱和点。注意：逐字稿中出现的参数量数字仅作为历史叙述，不应外推为课程结论。
- 规模带来的三个关键收益：
  - 各类自然语言、推理基准上的表现提升；
  - **few-shot / zero-shot learning**：仅凭任务描述或少量示例即可遵循模板；
  - **emergent behavior**：某些能力只在较大模型上出现。

**笔记解释**：scaling law 的可预测性（大致知道损失如何随计算/数据/参数下降）与涌现行为的不可预测性（在看到大模型之前无法预知会出现什么）是同一现象的两面，这一张力贯穿后续所有讨论。

### 2. 思维链（chain of thought）

- 思维链的关键不是「给出一个例子」，而是**给出得到答案的推理过程**作为示例，模型据此学习解题过程并迁移到新问题。
- 逐字稿强调：对很小的模型，思维链几乎无收益；随规模增大，模型才能利用上下文中的推理过程。这被视为一种随规模出现的涌现能力。
- 思维链至今仍是推理模型、思考模型的核心特性。

**课程原意 vs 解释**：逐字稿明确说思维链最初是**被发现**的涌现行为，而非设计时烘焙进去；后来推理模型则是**被训练去思考**的。两者要区分开。

### 3. 微调：指令微调与 RLHF

ChatGPT 相对 GPT-3 的跨越，逐字稿归因于预训练之后的微调创新，流程大致为：

1. **预训练**：next-token prediction。
2. **高质量数据上的微调**：同样是 next-token prediction，但数据质量高得多（例如书籍、创意文章等公司重金采购的数据）。
3. **指令微调（instruction tuning）**：指令 + 问答对，数据来源通常是人类生成数据、模板与合成数据的组合；也可包含思维链形式的微调数据。数据质量与通用性对最终模型质量影响很大。
4. **RLHF（reinforcement learning from human feedback）**：与监督式微调的区别在于**目标函数与数据的构造方式**——用人类偏好评分训练 reward model，再用 reward model 引导 LLM 参数，使其生成 reward model 认为好的内容。

逐字稿还提到：可以按正确性、有用性、具体性、无害性等定义不同奖励并对奖励模型加权。此处逐字稿口误出现「RLAIF」，但上下文描述的是 RLHF 流程；笔记按 RLHF 记录，不额外展开 RLAIF。

### 4. 推理时扩展与推理模型

- **Language Monkeys**（讲者实验室的工作，受无限猴子定理启发）：对同一问题做**并行采样 / 并行生成**，用 verifier 或选择机制挑出正确回答。模型输出有方差，可用 temperature 控制多样性；temperature 过高会变成胡言乱语（逐字稿提到超过约 1.2 通常不好）。
- 实验结果（逐字稿描述）：在数学与编程基准上把每问题采样数从 1 增加到 10,000，用 **coverage**（至少一个样本解决的问题比例）衡量；单样本时较弱的小模型在增加采样后可以超过 GPT-4 类模型。逐字稿强调「模型知道的远比问一次所展现的多」。
- 并行采样在延迟上有优势（可并行），但存在算力与成本的权衡边界，且随问题类型与复杂度变化。
- **verifier 是关键**：有可验证领域（代码的单元测试、数学等基于规则的领域）容易做；没有 verifier 时需要 LLM judge / LLM reward function / 工具辅助，课程有专门一讲覆盖 verifier。
- **推理模型**（o1 系列、Gemini thinking、DeepSeek 等）：把微调与 test-time scaling 结合——测试时生成大量轨迹（数学题有黄金答案、编程题有测试），筛选后作为训练数据回灌，微调模型。逐字稿称这是「thinking model / reasoning model」的重要组成，也是课程兴奋点所在的 self-improving 部分。
- OpenAI o1 发布时展示的关系（逐字稿描述）：在困难数学基准上，随测试时算力增加（对数刻度），pass@1 准确率上升。此前 scaling 主要展示在训练时，测试时同样呈现缩放规律是值得注意的现象。

**关键区分（逐字稿中明确讨论）**：
- 重复采样看的是 **coverage / pass@K**；
- 推理模型提升的是 **pass@1**——即模型学会了「哪个推理链是正确的」，而不只是「能生成正确链」。
- 关于「推理能力来自生成推理过程这一行为，还是来自逐步思考本身」：讲者回答倾向于——训练让模型成为泛化的思考者（分解、回溯、分析等技能泛化到新问题），同时基础模型本身已有一定推理能力；具体机制「没有已发表工作真正覆盖」，属于开放问题。
- 模型倾向于偏好自己生成的轨迹，即使轨迹来自更好的模型（课程后续会讲 Swirl 等论文）。

### 5. 转向 agent：为什么这门课相关

逐字稿的论证链条：

- 聊天机器人与推理模型基本仍是**单轮**或聊天格式，交互有趣但不一定替你完成任务。
- 近几个月，Claude Code、Deep Research 等 agent 开始让人们完成真实工作流（例如租房调研：浏览多个网站、总结结果、给出各地优缺点；编程 agent：用英文指令修改文件、找测试用例）。
- **agent 与聊天机器人的区别**：被赋予目标 → 规划步骤 → 与环境交互 → 根据反馈修正 → 决定何时停止（或报告无法达成）。可能需要工具交互，也需要某种形式的记忆来跟踪任务。
- 现状判断：简单场景可端到端完成；大多数场景仍是**静态的 agentic workflow**，即人工编排的图结构（LLM 调用、verifier、critic/judge、工具调用、编排），而非完全开放式的「从环境采取行动再反馈」的循环。编码与研究是开始出现后者的领域。

## 三、核心概念

| 概念 | 课程语境中的含义 |
|---|---|
| Scaling law | 计算/数据/参数增加时 test loss 下降的可预测关系 |
| Few-shot / zero-shot | 仅凭任务描述或少量示例完成任务，无需针对性微调 |
| Emergent behavior | 只在较大模型上出现、事前难以预测的能力 |
| Chain of thought | 在示例或生成中给出推理过程，帮助模型解决新问题 |
| Instruction tuning | 指令 + 问答对形式的微调，数据质量与通用性关键 |
| RLHF | 用人类偏好训练 reward model，再以其引导 LLM |
| Inference scaling / test-time scaling | 不改模型参数，在推理时通过采样等方式提升表现 |
| Coverage / pass@K | 至少一个样本正确的比例 |
| pass@1 | 单次回答正确的比例，推理模型提升的核心指标 |
| Verifier | 可实际验证输出的机制（如单元测试），是反馈循环的瓶颈之一 |
| Generator-verifier gap | 模型容易生成大量看似合理的内容，但判断其是否有用需要反馈循环；创意写作等领域的反馈瓶颈最终是人类反馈 |
| Agentic workflow | 由 LLM 调用、验证器、评判者、工具调用、编排组成的静态工作流 |
| Prompt chaining / routing / parallelization / orchestrator | 工作流的基本编排模式：链式子任务、按复杂度路由、并行化后聚合、中央 LLM 做规划 |
| Self-improvement | 测试时扩展生成数据 → 筛选/验证 → 回灌训练；以及 agent 的自我纠错、回溯等能力 |

**课程强调的原则性判断**：
- 在可获得稳健验证的领域，模型改进循环才能持续；验证（verification）是该领域让模型变好的瓶颈之一。
- 关于「预训练已包含逻辑能力，为何 RL 还能带来大幅跃升」，讲者明确表示**没有单一共识**，两种过程都有帮助，整个循环尚未被完全理解。

## 四、关键公式或原则

逐字稿未给出形式化公式，以下为课程陈述的原则性表述（非虚构公式）：

1. **Scaling 三轴原则**：test loss 随计算量、数据规模、参数量增加而下降（各自独立呈现）。
2. **推理时扩展原则**：模型参数固定，通过并行采样与选择机制，从「模型已知」中提取更多正确解；收益以 coverage 衡量，样本数增加时呈对数线性趋势（逐字稿对 Language Monkeys 与 o1 的描述均提及 log-linear）。
3. **训练-测试闭环原则**：测试时生成的高质量轨迹（经答案或测试筛选）成为训练集的一部分，用于微调，从而提升 pass@1。
4. **Agent 循环原则**：目标 → 规划 → 行动/工具交互 → 反馈 → 修正 → 终止判断；反馈可来自环境、单元测试、LLM judge 或 verifier。
5. **验证瓶颈原则**：可稳健验证之处，改进循环可持续；验证困难之处（如创意写作），人类反馈成为瓶颈。

## 六、常见误区

1. **把思维链当成设计出来的功能**。课程原意：思维链最初是涌现行为，后来推理模型才是被训练去思考的；两者不同。
2. **把 coverage 提升等同于模型变强**。重复采样提升的是 pass@K / coverage；推理模型提升的是 pass@1，即模型学会了挑选正确推理链。
3. **认为推理时扩展没有代价**。并行采样延迟可接受，但算力与成本存在权衡边界，且随问题类型与复杂度变化。
4. **认为 temperature 越高多样性越好**。过高会变成胡言乱语（逐字稿提到超过约 1.2 通常不好），需要其他技巧增加答案多样性。
5. **认为今天的 agent 已是完全自主的开放循环**。课程明确：大多数现实工作流仍是静态 agentic workflow（人工编排的图），只有编码、研究等少数领域出现开放式循环的迹象。
6. **认为自我纠错、回溯等能力纯粹是涌现**。讲者表示「很难说」：模型见过这类行为，且在被微调的方式中被强化。
7. **认为 RL 与预训练数据多样性之争已有定论**。课程明确说没有单一共识，是活跃研究领域。
8. **把「自我改进」理解为模型完全自主改自己**。课程语境更具体：测试时生成 + 验证/筛选 + 回灌训练，以及 agent 工作流中的规划、验证、纠错；验证是瓶颈。
