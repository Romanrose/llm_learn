# 让模型在真实世界中学习：从 ReAct 到执行反馈再到宪法 AI

## 导语

大语言模型在纯语言任务上已经相当强大，但一旦要把它们放进真实世界——查资料、调 API、写代码、做多步决策——单纯依靠模型内部状态的"思考"就不够用了。模型会幻觉，会对当前事件一无所知，也无法知道自己生成的代码到底能不能跑通。CS329A 第四讲围绕一个核心问题展开：**模型如何通过与外部世界的交互获得反馈，并借助这些反馈实现自我改进？**

本讲用三篇论文给出了三种不同来源的反馈：ReAct 让模型在与环境的交错推理与行动中获得 grounding；RLEF 用代码执行结果作为强化学习信号；Constitutional AI 则让模型依据一套人类撰写的原则进行自我批判与修订。三者共同构成本课程"自我改进智能体"主线上的关键拼图。下面我们按这三条线索逐层展开。

## 一、本讲在课程路径中的位置

要理解第四讲，需要先看它在整门课中的坐标。第一讲建立了大语言模型作为自然语言处理器的基本能力，也讨论了如何定义 agent 及其工作流。随后两讲由 Asia 主讲，覆盖测试时计算（test-time compute）与鲁棒验证（robust verification）。第四讲正是在这两块基础上往前推进一步：不仅要让模型"想得更多"，还要让模型**行动**，并从行动产生的反馈中学习。

讲师在开场就点明了三篇论文的共同点——它们都是模型自我改进的方式，区别只在于**反馈来自哪里**：要么是与环境的某种交互，要么是某种批判机制，要么是利用已知的正确答案来做 grounding。这个"反馈来源"的分类框架，是理解整讲的关键。它也预示了后续讲座的方向：下周会讲 RL 循环，而本讲最后提到的过程奖励模型与结果奖励模型的争论，也会在后续课程中继续出现。

## 二、ReAct：把推理和行动交错起来

### 2.1 问题动机

人类做事的模式是"先想再做，做完再看，看完再想"。讲师举了一个很生活化的例子：你决定来上这门课，是因为你思考过这门课可能如何帮到你；来了之后你观察到喜不喜欢这门课；基于这些信息你产生新的推理，也许去做作业，作业又让你决定其他事情。思考与行动之间存在一个循环。

语言模型恰恰缺乏这个循环。讲者指出，当今模型中推理已经"内化"了，但在过去几年这并不是开箱即有的能力。模型难以结合推理与行动的一个原因是它们会产生幻觉——它们没有关于环境实际发生了什么的情境信息。你问 ChatGPT 或 Claude"今天温度是多少"，除非它真的发起一次搜索调用，否则它对此一无所知。它没有在现实世界中 grounding 的概念，因此无法先行动、再把行动获得的信息结合回推理。

在此之前，学界有两条分离的路线：一条是思维链（chain of thought），让模型展示中间步骤，但这些步骤未必 grounded，因为它们只基于模型的内部状态，没有外部世界反馈；另一条是 WebGPT 这类工作，学习与网页浏览器交互，可以在交互轨迹和人类偏好上微调，但未必有显式的推理过程。ReAct 要做的，就是把这两种范式结合起来。

### 2.2 方法：在语言空间里交错生成

ReAct 提出的抽象非常简单：用提示（prompting）让模型先生成语言推理轨迹，把这段推理附加到提示中，再问模型"基于这个推理应该采取什么行动"，然后执行该行动、获得观察，再进入下一轮。讲者强调，整个过程完全发生在提示词层面——思考不会影响环境，只有基于思考采取的行动才会。这构建出的就是一个完整的 agent：有对世界的观察，有基于上下文的行动集合。

这里有一个工程上很重要的细节：**如何保证模型生成的动作是有效的？** 讲者的建议是把问题更多地框定为分类任务——告诉模型"这是世界的状态，这是接下来可以采取的有效动作集合"，让它在这个子集里选择。这通常能提供更有根据的回应。讲者提到，这一做法也被用在他们与 Google 机器人团队合作的一篇论文中，那里的世界状态和动作都必须非常有效，没有动作列表根本无法运作。

在实现上，讲义展示了一个基于冻结 LLM 的少样本方案：模型看到一些动作、思考和观察的示例，被要求采取下一个动作。对于推理轨迹，它看到的是动作和思考；对于决策任务，它看到世界状态和思考，然后决定下一步是继续推理还是采取行动。

### 2.3 具体例子：HotpotQA 上的交错轨迹

讲者用 HotpotQA 的一道题做了细致走查：**"除了 Apple Remote，还有什么其他设备可以控制 Apple Remote 最初设计用来交互的那个程序？"**

- 标准提示返回的答案不正确。
- 思维链让模型一步步展示中间步骤，但答案仍然不完全正确。
- 只用行动（先搜 Apple Remote，再根据观察里的文本搜 Front Row）也没有得到好答案，因为它发现这是一个已 discontinued 的东西。
- 而 ReAct 的交错轨迹是：先想"我必须搜索 Apple Remote，然后找到它最初设计用来交互的程序"，搜索后得到信息说这是很早推出的遥控器，最初设计用来控制 Front Row 媒体中心；再想"接下来需要搜索 Front Row"，搜不到；再想出新的检索词"Front Row Software"，搜索后弄清楚了这是一个已 discontinued 的媒体软件中心，然后基于此给出答案。

这个例子的说服力在于：推理过程是一个抽象，让模型能给出比"只采取行动然后中途返回答案"更好的结果；而交错和观察让模型表现得更好。讲者补充说，今天如果你打开 Qwen 等模型的思考模式，会看到这一切自动发生，因为这些模型已经在这类轨迹上被蒸馏过了，工具调用几乎是天生的能力。

### 2.4 实验结论与局限

在 HotpotQA（基于 Wikipedia 的多跳问答）和 FEVER（事实核查）上，动作空间非常简单，基本是在模拟人类与 Wikipedia 的交互：搜索页面、查找字符串、宣布完成。基线包括标准提示、思维链、思维链自一致性（SC，即多数投票）、以及无思考的纯行动（ACT），还有两个回退变体：ReAct 失败若干步后回退到思维链自一致性，以及多数答案出现少于一半时回退到 ReAct。

讲者给出的结论很坦诚：ReAct 通常比纯行动好，但并不总是优于思维链——它在 FEVER 上优于思维链，在 HotpotQA 上则不一定；而把思维链自一致性与回退机制结合，确实能优于标准技术。这说明了将模型内部知识与外部知识正确结合的价值。失败模式分析也很有意思：思维链中幻觉是主要失败模式，而 ReAct 因为能访问外部知识库，最终拥有有据可查的信息，模型更值得信赖、犯更少的错。此外，提示与微调之间存在差异：能微调时 ReAct 更好，能做 RL 循环则更好——这一点留到下周。

决策任务方面，讲者以 WebShop 为例：智能体根据用户指令购买产品，比如找一个有抽屉的床头柜，在模拟环境中评估交互是否成功。与模仿学习、模仿学习加 RL 相比，ReAct 的推理抽象带来更高的分数和成功率。但仍远低于人类专家——ReAct 只得到 66.6，人类专家得到 82.1（讲者明确这是该特定设置下的数字），而且多步过程中任何一步出错都会随时间级联。

讲者也点明了 ReAct 的挑战：动作空间非常大时需要更多演示，放不进上下文；多个推理步骤带来更高的推理成本。

### 2.5 课堂讨论中的延伸

课堂问答里出现了几个值得记录的洞察（这些是讨论中提出的观点，而非论文结论）：

- **模型是否知道它知道什么？** 讲者说存在相互矛盾的观点：一派认为模型非常自信地知道它们知道什么，但通常模型过度自信、校准得不好，这是仍在被解决的研究问题。对应用设计者而言，重点不是判断模型是否自知，而是**让模型使用正确的工具集，从而获得有根据的知识**。
- **环境反馈有噪声怎么办？** 可以加一层反思，让 agent 对环境反馈进行反思；回溯（backtrack）变得重要，因为噪声反馈可能让它陷入重复循环；还可以通过多次执行同一任务、取最高样本等方式建立置信度指标。
- **还有哪些认知机制值得探索？** 任务分解（task decomposition）、并行思考、记忆过去的经验。有同学提出，人类会随任务微调推理与行动的理想比例——讲者回应说，今天一些模型会过度思考（overthink），即使在简单任务上也有很长的思维轨迹，如何让模型不要思考太多是一个有趣的方向。还有同学提出复合系统（compound system）的想法：根据不同模型在子任务上的强弱进行委托。

## 三、RLEF：用执行反馈训练代码智能体

### 3.1 为什么是执行反馈

第二篇论文 RLEF 关注编码智能体（coding agents）。讲者开场问有多少人使用 Claude Code，几乎全班举手——工程和编码任务似乎已经被委托给这些智能体了。要让它们变得极强，关键在于理解用户意图，并从生成的代码中获得反馈以便迭代。

RLEF 是最早展示"通过执行反馈可以在编码 LLM 上获得更好性能"的论文之一。它给出一个端到端的 RL 微调框架：**动作是生成的代码，观察来自执行反馈（即测试反馈）**——运行测试，收集通过或失败的输出，据此给出二元奖励（binary reward），再用 PPO 迭代改进策略。

### 3.2 两个关键设计

**双层测试策略（two-tier test strategy）**：框架同时使用训练时和推理时的执行反馈。紫色块展示的推理时循环是：模型拿到自然语言问题描述（比如"写一个 hello world 程序"），生成代码，在公开测试集上评估；如果失败，执行反馈回传给 LLM 让它再试，循环直到通过或达到轮数上限。之后，通过的解法交给私有测试集决定奖励，进入 PPO 训练。讲者把左侧称为利用阶段（exploitation phase），右侧是依据执行结果更新策略、持续自我提升。

这个分离的精妙之处在于：公开测试提供即时反馈、帮助快速迭代，但它只是小子集；私有测试在生成过程中完全隐藏，只作为获取信号的方式。这样模型不能简单地记住测试输出，因为它得到的是执行反馈。

**混合令牌轮级策略（hybrid token turn-level policy）**：策略模型逐 token 生成代码，因此对生成过程有最终控制；但价值函数在轮次级别计算，评估或奖励作用于整个响应，使用 prompt 的最后一个 token，所有 token 共享一个优势值。讲者指出这更接近 GSPO 的做法——给整个序列奖励，而不是逐 token 给奖励。

### 3.3 例子与结果

讲者用一个检测回文子串（palindrome substrings）的问题走了一遍流程：第一轮生成的基础解法在公开测试中失败，还出现执行超时；收到反馈后模型生成了更好的解法，通过公开测试；提交私有测试后，依据结果继续改进模型，解法变得更好。

结果方面，讲者展示了 solve rate 随采样预算变化的曲线（注意 x 轴是对数刻度），在 Llama 3.1 上、在代码竞赛（竞争性编程问题）上训练后，RLEF 明显提升了解决率。更有说服力的是错误分析：对比第一轮、第二轮、第三轮的错误数、代码更改量和错误类型，使用 RLEF 时后续轮次的错误输出更少，编辑更有针对性，因为模型能看到自己错在哪里；没有迭代循环时，所做的编辑往往是不正确的。讲者还指出，这种训练能泛化到代码生成领域的其他基准。

课堂讨论同样贡献了几个诚实的边界：二元反馈对非常简单的问题够用，但对更难的问题可能需要错误追踪等元数据；奖励是最终结果的奖励，是否鼓励第一轮就做对取决于错误类型；过程奖励模型与结果奖励模型哪个更好，这场争论还没有完全解决，每个领域和基准可能需要不同选择；监督微调在推理轨迹上仍然可能有收益，但 RL 能解决稍新一些的问题、泛化稍好一些。讨论 SWE-bench 这类代码库超出上下文窗口的问题时，同学们提出的搜索、摘要、图表示加相似度匹配、RAG 等思路，讲者评价说这些都是解决该问题的第一步。

## 四、Constitutional AI：用原则驱动自我批判

### 4.1 从 RLHF 的瓶颈说起

第三篇论文转向模型的无害性（harmlessness）。讲者先回顾了 RLHF 的典型流程：给人类看两个模型输出，问哪个更正确、更有用、更具体，基于人类偏好构建奖励模型，再微调模型。随着模型规模增大，RLHF 相比仅做微调能明显带来更好的回复。但这条路不能很好地扩展——收集数万条人工标注极其耗时繁琐。

鉴于模型具备推理能力，Anthropic 提出了"宪法"（constitution）的概念：一套人类撰写的原则，通过描述什么是期望的行为来改进模型。这样除了撰写宪法之外，人类不需要参与在环路中。讲者解释了它为什么可行：**模型在指令遵循方面越来越强**——如果你让模型以特定方式格式化回复，它能遵循；如果你问它"这个回复是否有某种行为"，它能以真实的方式回答。

### 4.2 两阶段流程

宪法 AI 提出了 16 条原则。流程分两个阶段：

**监督学习阶段**：使用红队提示（red teaming prompts），查看模型输出，对其进行批判（critique），获得修订版本（revision），再用这些数据微调模型。讲义框图展示了批判请求的几种形式：问输出是否有有害或不道德的内容、是否有性别偏见及为什么、对幼儿是否不合适，然后分别要求移除这些内容、重写为合适的版本。讲者强调，每一条都要求模型**识别行为**并**遵循指令重写**。结果是：随着修订轮次增加，无害性提高；有用性在持续监督微调中会下降，但有用性加无害性的总和单调提高——因为让模型符合一组固定原则确实会让它变得不那么有用，这是论文自己的说法。

**强化学习阶段**：基于第一步的回复和宪法训练一个偏好模型，再微调 LLM 来最大化这个偏好模型，让模型以最有思想、最尊重、最友善的方式回复。这就用"宪法训练的偏好模型"取代了 RLHF 中对大量人类反馈的依赖。

### 4.3 帕累托前沿

结果用 Elo 分数呈现：x 轴是有用性 Elo（人类在有用性上更偏好），y 轴是无害性 Elo。预训练基础模型起点不高；标准 RLHF 只做有用性会把前沿往有用性方向推；做有用加无害则是橙色曲线；宪法监督学习仍比 RLHF 差；而带思维链的宪法 RL 能达到有用性与无害性之间权衡的最佳帕累托前沿。讲者特别澄清：课堂上有人问思维链是否导致更低的有害性评分，讲者纠正说，相关性更多不在思维链本身，而在于无害性上升时与有用性之间的反向关系——必须在这两者之间找到正确的平衡。

这一思想的可推广性也被点明：**任何你能让模型遵循一组规则、并根据它是否很好地遵循规则来启动自我改进循环的场景，都适用这种原则风格**——比如指令遵循中一组可能相互冲突的指令。

### 4.4 开放问题

课堂问答暴露了这条路线上的真实难点。有人问：宪法如果有修正案，如何低成本更新模型、确保旧规则被完全移除？讲者给了两个层面的回答：RLHF 通常作为后训练阶段，只占计算量的很小百分比（讲者说"也许 5%"），模型更新相当频繁；但更根本的是持续学习（continual learning）问题——如何让模型忘记某些知识或遵循新规则集，目前仍是开放研究问题，可解释性方法提供了一些"取消学习"的思路，但并没有证明能让模型可靠地忘记某些东西。

还有同学敏锐地指出：监督学习阶段似乎没有显式反馈，只是让模型自我批判、自我修订，然后在这批轨迹上微调。讲者确认了这一点，并补充：只要微调规模相比基础模型训练数据小得多，模型不会失去初始能力，但输出分布会开始偏向这组回应。至于 AI 反馈是否准确，讲者说偏好模型训练时确实需要测试集或验证集，也需要与人类评分做一致性检验，但规模远小于万级人工标注。讲者还提到后续工作：Self-Refine 讨论用自我反馈做迭代改进；让其他模型形成共识来批评有时效果更好，因为单个模型可能过度自信；还有工作尝试用强化学习教模型自我纠正。

## 五、结语：三种反馈，一个主线

回看整讲，三篇论文其实在回答同一个问题的三个侧面：**当反馈循环有足够信号时，你就有办法在模型的训练数据之外改进模型。**

- ReAct 的反馈来自**环境交互**。它让模型在语言空间里交错地推理与行动，决策轨迹极其可解释，工具调用在今天开箱即用的模型中几乎成为天生能力。但它的局限也很清楚：动作空间大时需要更多演示、推理成本更高，且工作流仍然高度领域特定。
- RLEF 的反馈来自**执行结果**。用公开测试做即时迭代、私有测试做奖励信号，配合轮级优势估计，在代码竞赛任务上展示了自我改进循环的有效性，并泛化到代码生成领域的其他基准。
- Constitutional AI 的反馈来自**原则与自我批判**。它用一套人类撰写的宪法替代了大量人工标注，在有用性与无害性之间打出更好的帕累托前沿，并可推广到任何"模型能遵循规则"的场景。

讲者在最后的提问环节给出了一个统摄性的判断，值得作为本讲的收束：我们目前仍在借用人类解决问题的类比，因为推理语言模型这个领域还很年轻；但归根结底要回答的是，**整个在推理空间中搜索的过程能否被自动化、是否存在良定义的流程**。游戏这类动作空间明确受限的领域可以定义搜索空间并自动探索；而我们谈的是经验、是去经历真实环境——无论是搜索工具还是别的什么——所以必须在其中收集观测再加以利用。这也解释了为什么 ReAct 作为一种方法重要：它定义了"推理—行动—再推理—再行动"的序列与工作流，而工作流正是第一讲中对 agent 的定义方式。至于这种手工设计的框架会不会被更偏 RL 的后训练方法取代，讲者的回答是"既对也不对"：抽象层面上，工具调用也只是 token，可以用奖励监督；但具体细节仍然重要，因为会计、金融、法律等领域的步骤集合高度领域特定，很难跨所有领域泛化。

这正是本课程后续要持续攻坚的地方：从 ReAct 的提示级交错，到 RLEF 的 RL 循环，再到宪法 AI 的原则驱动，反馈的来源在变，但"让模型在训练数据之外变得更好"这条主线始终未变。
