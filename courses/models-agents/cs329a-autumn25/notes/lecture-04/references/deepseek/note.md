# CS329A Lecture 4 学习笔记：Learning from Feedback with Tools/Code

## 学习目标

完成本讲后，应能够：

1. 解释 ReAct 如何在语言空间中交错 **reasoning trace** 与 **action**，并说明它相对纯 chain-of-thought（CoT）与纯 action 的差异。
2. 说明为什么执行反馈（execution feedback）可以作为代码 LLM 的奖励信号，以及 RLEF 的训练时/推理时双层循环如何组织。
3. 描述 Constitutional AI 如何用一组人类撰写的原则把“自我批判—修订”变成监督数据与偏好数据，从而替代大规模人类标注。
4. 把三种反馈来源（环境交互、可执行测试、原则驱动自我批判）统一到“self-improving loop”的框架下，并判断各自适用的任务形态。
5. 识别这些方法的失败模式与开放问题，为课程作业与项目选题提供方向。

---

## 课程主线

本讲围绕一个核心问题展开：**模型的改进信号从哪里来？** 课程用三篇论文给出三种反馈来源：

| 论文/方法 | 反馈来源 | 主要任务形态 |
|---|---|---|
| ReAct | 与外部环境（搜索、网页、模拟器）的交互观测 | 知识密集型问答、事实核查、决策任务 |
| RLEF | 代码执行结果（测试通过/失败） | 代码生成、竞赛编程 |
| Constitutional AI | 模型依据人类撰写原则对自身输出的批判与修订 | 有用性/无害性对齐 |

三者的共同结构是：先让模型产生输出，再从某种外部或半外部机制取得信号，最后把信号回灌到提示、监督微调或 RL 中。区别在于信号的“ grounding 程度”与“可扩展性”：环境观测最贴近现实但噪声大；执行反馈客观但需要可运行的任务；原则批判可扩展但依赖模型自身的判断能力。

课程最后回到一个抽象层面：**如果搜索空间是良定义的，就可以自动化搜索；如果任务不是良定义的（会计、法律、金融 agent 等），就只能把工作流写进语言空间，因此 ReAct 这类“手工定义序列”的框架仍有价值，但难以跨领域泛化。**

## 核心概念

### 1. ReAct：交错的推理与行动

**课程原意**：ReAct 是最早把 reasoning 与 acting 结合进语言模型的抽象之一。它以 prompting 实现：模型先产出推理轨迹（thought），再产出动作（action），执行后得到观测（observation），然后进入下一轮。轨迹是**交错**的（thought₁ → action₁ → thought₂ → action₂ …），而非先想完再行动。

**关键设计点**：

- **动作空间要小而明确**。课程强调，让模型生成有效动作的典型做法是把问题框定为分类式选择：给定世界状态与“下一步可用的有效动作集合”，让模型在其中选择。这在机器人等必须保证动作有效的场景中尤其重要。
- **推理轨迹作为中间抽象**。课程提到，语言模型在语言上训练，因此在“正确的抽象层次”上拥有推理 token 有助于产出正确动作；若已有良好的中间表示，推理 token 的必要性可能下降。
- **可解释性**。ReAct 轨迹使决策过程对人类可读，这被视为信任模型输出的重要因素。

**实验结论（定性）**：

- 在 HotpotQA、FEVER 这类知识密集型任务上，ReAct 通常优于纯 action；但不总是优于 CoT——在 FEVER 上优于 CoT，在 HotpotQA 上并非总优于。把 CoT self-consistency 与 ReAct 组合（含失败回退）能超过标准技术。
- 失败模式分析显示：CoT 的主要失败模式是幻觉；ReAct 因为能检索外部知识，输出更有据、更可信任、错误更少。
- 在 WebShop 这类决策任务上，ReAct 的推理抽象优于 imitation learning 与 imitation learning + RL 基线，但仍显著低于人类专家水平；多步任务中错误会随步骤级联，成功率因此偏低。
- 提示 < 微调 < RL 循环，效果依次提升（RL 部分在后续讲座展开）。

**局限（课程明确指出）**：动作空间很大时需要大量演示，无法全部放入上下文；多步推理带来更高推理成本。

### 2. RLEF：以执行反馈做代码 RL

**课程原意**：RLEF 是较早展示“执行反馈能实质提升代码 LLM”的工作。动作是生成的代码，观测是测试反馈，奖励是测试通过/失败的**二元奖励**，训练用 PPO。

**两个被强调的技术点**：

1. **双层测试策略（two-tier test strategy）**：公开测试（public tests）用于推理时的即时反馈与迭代修复；私有测试（private tests）在生成过程中隐藏，只在提交后决定奖励。这样模型不能简单记住测试输出，信号来自执行而非泄漏的答案。
2. **混合 token / turn-level 策略**：代码逐 token 生成，但价值/优势在**轮级**计算——奖励作用于整段响应，所有 token 共享一个 advantage。课程把它类比为更接近 GSPO 的“整序列奖励”而非逐 token 奖励。

**训练循环结构**：

- **利用阶段（exploitation）**：推理时反馈循环，模型生成代码 → 跑公开测试 → 失败则把执行反馈附回上下文再生成，直到通过或达到轮数上限。
- **更新阶段**：通过的解法进入私有测试得到奖励，用于 PPO 更新策略。

**实验结论（定性）**：在竞赛编程任务上训练后，solve rate 随采样预算提升（x 轴为对数刻度）；且能泛化到代码生成领域的其他基准。对迭代轮次的分析显示：有了 RLEF，后续轮次的错误输出更少、编辑更有针对性；没有迭代循环时，模型做的编辑往往不正确。课程强调“自我改进循环有效”是主要 takeaway，且它能在**足够简单的问题上用二元奖励**起作用。

**课堂讨论中的开放问题**（课程未解决，可作为项目方向）：

- 二元反馈对更难的问题是否足够？是否需要错误追踪等元数据来高效调试？
- 结果奖励模型 vs 过程奖励模型哪个更好（与另一门课的交叉内容相关），尚无定论。
- 监督微调与 RL 的相对收益仍是开放讨论；RL 被认为能对更新一些的问题有稍好的泛化。
- 代码库超出上下文窗口时的检索/摘要/图表示 + RAG + “信息是否足够”的判断循环，与 SWE-bench 类基准相关。

### 3. Constitutional AI：以原则驱动自我批判

**课程原意**：目标是提升无害性（同时保持有用性），并用 AI 反馈替代大规模人类偏好标注。核心是**宪法**：一组人类撰写的原则（课程提到 16 条），作为提示词用于引出模型对自身输出的批判与修订。

**两阶段流程**：

1. **监督阶段**：对红队提示（red teaming prompts）下的模型输出，依次发出批判请求（“是否有害/不道德/有偏见/不适合幼儿”等）与修订请求（“移除这些内容”/“重写”），在“自我批判 + 修订”生成的轨迹上做监督微调。
2. **RL 阶段**：用第一步的回复与宪法训练一个偏好模型（preference model），再微调 LLM 以最大化该偏好模型——即在没有大量人类反馈的情况下完成 RLHF 式的偏好优化。

**课程给出的趋势（定性）**：仅做宪法监督学习并增加轮次时，无害性上升、有用性下降，但“有用 + 无害”总体上单调改善（因为对齐到固定原则确实会让模型不那么有用，这是课程转述论文的说法）。在有用性 Elo（x）与无害性 Elo（y）的平面上，宪法 RL + CoT 达到二者权衡的最佳帕累托前沿；课程也指出图中“无对比”可能意味着 CoT 在无害性上更差，且无害性上升与有用性之间存在反向关系，需要找平衡。

**课程强调的机制前提**：这些方法有效，是因为模型**指令遵循能力**足够强——能按要求格式化输出、能如实回答“该回复是否具有某行为”。原则风格可推广到任何“模型需遵循一组可能相互冲突的指令”的场景。

**开放问题**：宪法若需修订（“修正案”），如何低成本更新模型并确保旧规则被移除？课程将其归入 continual learning，指出目前没有证明能让模型可靠“忘记”某些知识；RLHF 作为后训练阶段计算占比小、模型更新频繁，是部分缓解。

## 关键公式与原则

课程未给出显式数学公式，以下为可从讲授内容中提炼的原则性表述（标注为解释）：

1. **ReAct 的交错原则**（解释性形式化）：轨迹 = (thought₁, action₁, obs₁, thought₂, action₂, obs₂, …)，其中 action 从“当前状态下的有效动作集合”中选择；thought 不改变环境，只改变后续动作的条件分布。
2. **动作选择即分类**（课程原意）：给定世界状态与有效动作列表，把下一步决策框定为在该列表上的选择，比开放式生成更可靠。
3. **RLEF 的奖励原则**（课程原意）：奖励 = 私有测试的通过/失败（二元）；优势在轮级计算，整段响应共享。
4. **双层测试原则**（课程原意）：公开测试用于推理时迭代（快、可反馈），私有测试用于奖励（防泄漏）。核心不变量是“用于反馈的信号”与“用于训练的信号”分离。
5. **Constitutional AI 的目标**（解释性表述）：在有用性 U 与无害性 H 的平面上，寻找帕累托前沿；宪法监督 + RL + CoT 被报告为该前沿上的较优点。
6. **元原则**（课程总结）：当反馈循环有足够信号时，你就能在训练数据之外改进模型；反馈可以来自环境、执行、或模型依据原则的自我批判。

## 课程作业关联

课程在讲授中明确把若干讨论点与作业/项目挂钩：

- **RLEF 与作业**：课程提到作业中不针对代码，而针对数学或一般问题，**不做执行反馈，而是识别生成解法中的错误**——即把“迭代修复”的思想迁移到没有可执行测试的领域。这是理解 RLEF 的关键迁移练习。
- **ReAct 相关的项目方向**（课堂讨论中提出）：研究 thought 与 observation 的 KV cache 表示是否存在交错模式规律（observation 由环境给出而非 LM 生成，值得研究）；让模型学习不同任务的理想“推理/行动计算比例”；构建复合系统（compound system），按子任务在不同模型上做基准并按其优势委托；让模型避免过度思考（overthink）。
- **RLEF 相关的项目方向**：为更难问题设计超越二元奖励的反馈（错误追踪等元数据）；比较过程奖励模型与结果奖励模型；代码库超上下文时的检索/摘要/图表示方案（关联 SWE-bench 与 Code Monkey 等工作）。
- **Constitutional AI 相关的项目方向**：让其他模型形成共识来批判（缓解单模型过度自信），以及用 RL 教模型自我纠正（Self-Refine 等后续工作）。

## 常见误区

1. **把 ReAct 理解为“先完整推理再行动”**。课程明确：是交错的 thought₁→action₁→thought₂→action₂；每个动作的结果会告知下一个推理步骤。
2. **认为 ReAct 一定优于 CoT**。课程结果：ReAct 并不总优于 CoT（HotpotQA 上不总是），组合与回退策略才稳定超过标准技术。
3. **认为模型能可靠判断“自己是否知道”**。课程回答：模型校准不好、常过度自信；应用设计者应做的是给模型正确的工具集以获得有据知识，而不是依赖模型自评。
4. **把 RLEF 的公开测试当作训练信号**。公开测试只用于推理时反馈；奖励来自隐藏的私有测试，否则会泄漏。
5. **认为二元奖励足以解决困难问题**。课程明确这是开放问题：更难的问题可能需要错误追踪等元数据；二元奖励在足够简单的问题上被证明有效。
6. **把 Constitutional AI 当成“没有反馈”**。它有反馈，只是反馈由模型依据原则生成；监督阶段是在自我批判与修订轨迹上微调，RL 阶段另训偏好模型，且偏好模型仍需与人类做一致性检验。
7. **认为对齐到原则没有代价**。课程转述：无害性上升伴随有用性下降，需要在前沿上找平衡。
8. **认为 ReAct 式手工框架会被 RL 后训练完全取代**。课程回答“既对也不对”：若搜索空间良定义则可自动化；但许多任务（会计、法律、金融 agent）的工作流高度领域特定、非良定义，因此框架仍有价值但难跨域泛化。
