# 让模型多想几次：Stanford CS329A 第二讲中的 Test-time Compute Scaling

## 导语：不改变参数，也能让模型更强

在 CS329A 的第一讲里，课程已经把 LLM 的生命周期粗略分成三段：预训练（pre-training）、微调（fine-tuning）和推理（inference）。历史上，算力主要砸在预训练上，微调低几个数量级，而推理几乎不花钱——用户问一次，模型答一次。第二讲要动摇的正是这个直觉：**在不改变模型参数、不做任何微调的前提下，仅仅在推理阶段多花算力，模型就能变得更好、更有用。** 这就是 test-time compute scaling（测试时计算扩展），也叫 inference scaling。

这一讲在本课程整体路径中的位置很明确。第一讲建立了“预训练缩放定律”的可预测性；第二讲把同样的缩放思维搬到推理侧，并指出两者的关键差别——预训练是一次性的巨额投入，而推理扩展是每用一次就要付一次的成本，但它对任何人都可行。更重要的是，这一讲第一次系统暴露了本课程的核心张力：**生成能力可以被采样“逼”出来，但验证能力才是天花板。** 后续关于 reward model、verifier、agentic 系统的内容，都是在这个张力上展开的。

## 一、无限猴子：重复采样为什么有效

讲座从一个熟悉的定理出发：无限猴子。论文 *large language monkeys* 的做法极其简单：给定一个问题，不是只生成一次回答，而是反复询问同一个输入——10 次、100 次甚至更多——然后用一个验证器（verifier）判断哪一个回答正确，作为系统输出。

这个朴素方法的效果出人意料。一个能力较弱的模型，比如 llama 3 8B 或 7B，单次尝试时远不如 GPT-4o；但通过重复采样（repeated sampling）并挑出正确的那一个，它可以在很困难的数学、编程和问答问题上显著超过更大、更专有的模型。讲师对此的解读是：这些较小的模型其实“已经知道”答案，只是第一次尝试时不肯说出来；重复采样把这些答案诱导出来、让它们浮现。

这个范式在几乎所有尝试过的领域都成立，包括 agentic 基准。课程举了 bbench 的例子——它模拟软件工程师如何编辑代码、创建补丁。图中横轴是样本数量（1 到 1000），纵轴是覆盖率（coverage，即至少被一个样本解决的问题比例）。结果显示，像 DeepSeek 这样的模型在 1000 个样本之后可以超越 Claude 3.5 或 o1 preview，解决更多的软件工程问题。

这里有一个关键的工程含义：对编程问题，如果我们有单元测试来选出正确样本，我们就拥有了一个**端到端的自动化方式**——从一个开源模型出发，机械地“制造”出一个更有能力的模型。

## 二、从预训练缩放定律到测试时缩放定律

第一讲的预训练缩放定律说：给定一组方程，我们可以可预测地降低 test loss，存在一条可预测的路径来增加数据量、计算量和参数量。第二讲的核心贡献之一，是证明**同样的可预测性也适用于推理**。

课程展示的规律是：覆盖率与从模型中并行抽取的样本数量之间，遵循指数幂律（exponential power law）。设 C 为覆盖率，K 为样本数量，A、B 为拟合系数，就能刻画这种缩放行为。实验中，从 llama 3 8B、70B 到 gemma、pythia，参数规模横跨 7000 万到 700 亿，预测曲线都相当紧密地跟随实际观测到的覆盖率。这意味着我们可以回答工程问题：要达到某个覆盖率，需要多少样本、应该分配多少资源。而且这个规律对小模型（比如 7000 万参数）成立，对大模型成立，跨领域也成立。

为什么重复采样会呈现幂律？乍看并不直观。对单个问题，如果正确答案的概率是 P，那么 K 个答案中至少一个正确的概率可以直接用指数方程算出：1 减去 (1−P)^K。但这是单个问题的行为；我们观察到的是**一组问题上的**幂律。课程给出的答案是：要得到观察到的缩放定律，充分必要条件是问题难度呈现**长尾分布（long tail）**——在最复杂的那一端，存在大量真正困难的问题。

经验数据支持这一点：所有题目中很大一部分比较简单，一次通过（pass@1）就解决了；随着复杂度上升，pass@1 越来越低，形成一条低通过率的长尾。正是这条长尾，使得整体上呈现幂律缩放。这个论证很漂亮：它把“现象”还原成了“数据分布性质”。

## 三、算力结构的范式转移

讲师在这里插入了对本课程最重要的一段判断。以前，公司花数亿甚至数十亿美元做预训练，微调花少得多的钱，每次推理调用几乎不花钱，因为用户与模型之间是一次性的来回交互。现在有了新范式：我们可以在推理上花多得多的算力，并用它提升模型能力；而且这种推理算力**可以离线完成**——把智能体放出去解决一个问题，让它持续生成 token、持续提升答案质量。

这句话点明了 test-time scaling 与 agent 的结合点：推理不再是“一问一答”的瞬间开销，而是一段可以被调度、被预算、被优化的计算过程。这也解释了为什么这门课叫 Self-Improving AI Agents——自我改进的一部分就发生在推理时的反复生成与筛选之中。

## 四、真正的瓶颈：验证器与生成-验证差距

讲座最核心的转折在于：重复采样要成立，我们必须知道哪个样本是正确的。这就是对自动化验证的需求。

课程按“验证难度”排出了一个谱系。**容易验证的领域**：某些数学问题可以用形式化证明，用软件工具逐步验证证明策略；编程可以写单元测试，而且写单元测试往往比写整个解题程序简单得多，可以由人类提供作为验证器；AI 作为编译器——用 LLM 为 PyTorch 源码生成 CUDA 底层代码——也是可验证的，因为对任意输入，比较 CUDA 输出与源 PyTorch 输出是否一致即可。课程提到 KernelBench 这个 CUDA 生成数据集，并再次展示了覆盖率随采样数线性提升的同样曲线，因为这里默认拥有一个完美验证器。类似的还有任意两种语言之间的翻译（比如 Python、C++ 与 Java 互转），等价性更容易衡量。

**没有验证器的领域**则是另一番景象。课程比较了几种方法：多数投票（majority voting，看哪个答案出现最多）、基于模型的排序器（model-based rankers），以及覆盖率（假设有完美选择器时的上限）。结果是：多数投票在 10 或 50 个样本之后就趋于平稳，而完美验证器能达到的水平与之存在巨大差距。这就是**生成-验证差距（generation-verification gap）**：生成侧我们能产出很多好答案，验证侧我们实际能捕获的比例却很低。这个差距在更困难的问题上更明显——MATH 比 GSM8K 更难更复杂，差距也更大。即使用了奖励模型或组合方法（给每个答案打分再取最优），差距依然存在。

多数投票为什么失效？课程给出了机制解释：在一些最难的问题上，正确答案在数千甚至一万个样本中可能只出现一两次或三次。稀有，所以多数投票捕获不到。GSM8K 这类较简单数据集上多数投票有效，是因为答案更容易生成；但即便在那里，最难的一批问题正确答案频率也相当低。

顺带一提，课程在这里安排了小组讨论，学生的提问本身构成了有价值的研究线索：有人提出用知识图谱加 RAG 来在准确性与时间效率之间做混合权衡；有人设想先用自学式探索收集洞见、再进入并行采样；有人提出“验证正确答案很难、但发现错误答案很容易”的领域（物理模拟、机器人学），可以据此过滤；还有人问能否生成多个验证器再做多数投票——讲师确认这是有趣方向，但计算上非常昂贵，并透露数据集每个问题有一万个不同样本公开在 Hugging Face 上，缩小生成-验证差距可以作为课程研究项目。讲师也提醒：即使有单元测试，如果测试本身代码覆盖率不足，验证器质量依然是瓶颈。

## 五、扩展测试时计算的多种旋钮

课程随后系统梳理了 test-time scaling 的“操作面”。第一种是已讨论的**并行采样**：对同一输入生成多个答案。第二种是**顺序修订（sequential revisions）**：模型提出初始步骤或解法，然后不断修订、改进、补充，从不同角度审视，直到确信可以输出最终答案。讲师说明，这里可以先假设是人工提示驱动；但推理模型（reasoning models）现在被训练成内部自发表现出这种行为。

第三种是**如何选择答案**。除了单元测试，还有基于结果的奖励模型（outcome reward models），看最终答案并给出分数；以及过程奖励模型（process reward model, PRM），对生成解决方案的每一步给出分数。二者的区别正是“结果 vs 过程”：数学问题大约五步，结果奖励模型只看最终答案，过程奖励模型则逐步打分。讲师提到 PRM 通常也来自语言模型，因此在领域内任务上表现更好——在特定基准的子集上训练 PRM，会比跨新任务更好地帮助该任务上的测试时扩展；但作为语言模型，它们也表现出一定的跨任务泛化。至于奖励的计算粒度，不是逐 token，而是“有智力意义的结果 chunk”，可以是一步、一句，由人类标注每一步质量后训练得到。

有了 PRM，就有了**带验证器的最佳 N 采样（best-of-N sampling with a verifier）**，以及更进一步的**束搜索（beam search）**：假设每层预算四个样本，用 PRM 选出评分最高的前两个，再从它们继续采样、扩展树，用阈值决定如何保留分支。讲师明确指出，并行最佳 N、顺序修订与 PRM 引导的组合通常优于单一方法；一种简单组合是做两个并行样本、各自顺序修订，再用 PRM 或结果模型在最终答案间择优。他还提到实践上的便利：有很多现成 PRM 可以直接拿来引导自己任务的搜索，也可以基于自己的数据训练 PRM 和结果模型（OM）。

课程引用的那篇论文（最优地扩展 LLM 测试时计算可以比扩展模型参数更有效）在数学数据集上做了实验，约 12k 训练集、500 个测试问题，使用 PaLM 模型。它定义了一个难度概念：按模型在每个问题上的 pass@1、以及大量样本中有多少答案正确，把问题复杂度分成五个桶，以此得出“测试时扩展对更难还是更简单任务更有效”的结论。他们还训练了自己的 PRM，甚至微调模型来做修订；不过讲师补充，现在几乎任何指令微调过的模型，只要提示得当，都能做修订。

实验观察有几点值得记住。其一，准确率随生成预算变化的曲线中，多数投票、OM、PRM、以及混合配置表现各异；而**如何混合搭配修订与并行扩展以在给定准确率下最小化生成预算，仍是未公开的研究**。其二，按难度桶看，简单问题上“顺序对并行的比例”更高的配置（更多顺序 token）达到最高准确率；问题越难，最优比例越难说，甚至从桶四到桶五都会变化。其三，也是讲师反复强调的现象：对简单和中等的问题，额外的测试时计算可能比扩展预训练更有利；但对最难的问题，更大的模型、更多预训练仍然更好——即使有无限（或任何合理规模的）测试时扩展预算。讲师对此的评论很克制：预训练只做一次，扩展每次都要做；不是每个人都能预训练大模型，所以测试时扩展可行性高；但最难的问题仍然需要更好的模型。他还回应了“能否拿小模型微调成困难问题专家”的提问：可以，但课程讨论的是一般视角——用通用数据、常见配方训练模型，再看测试时表现。

## 六、Archon：把推理扩展当作架构搜索问题

讲到最后，课程给出一个把上述所有旋钮系统化的框架：**Archon**，一个用于推理时扩展的架构研究框架（讲师提到助教是共同作者之一）。问题陈述是：如何混合匹配不同的推理时扩展方法，构建能力与成本之间的最优前沿。

框架的输入侧包括：一组目标基准、一个推理预算、一组可用的 LLM（因为总可以混用不同模型），以及一组推理时技术。核心是一个叫 ITAS（inference-time architecture search）的优化器，它告诉我们如何把这些模型和技术组合起来，在给定推理调用预算下获得高质量结果。

课程逐一介绍了这些**推理时操作**：生成（generation），即从模型直接采样，可作为重复采样的一部分；融合（fusion），取 k 个不同回答，连同原问题一起给 LLM，让它综合出一个输出答案——讲师说这出乎意料地有效，且可归入顺序更新的类别；评论者（critic），让模型描述回答的弱点或优势；排序器（ranker），用提示让模型按质量给上一步的回答排序；验证器（verifier），返回回答的同时给出打分理由的推理过程；以及单元测试生成与评估。关于最后一项，课程举了一个具体例子：编程问题是检查输入字符串中圆括号的平衡性；模型生成的单元测试包括“给定含奇数个括号的字符串，应输出 no”，以及“遇到闭括号时必须匹配最近一个尚未匹配的开括号”；而单元测试评估更“疯狂”——不是运行测试，而是让模型根据单元测试来评估生成的答案。

这些技术有多有效？课程展示了一组胜率实验。左边图中，橙线是随机选一个回答（最差方式）；绿线是用模型给回答排序后取排名最高者，已经优于随机；蓝线是预言机选择（oracle selection），即假设有完美验证器直接挑出最好的那个，显然优于模型排序；红线是融合——把五个回答一起给模型综合出一个答案，**这个范式强到本身就能在质量上超过预言机选择**；紫色则是先选前五个再融合，说明“过滤 + 融合”结合效果更好。右边图则把回答来源从单一模型换成多模型集成（最好的模型、第二好的、以此类推），趋势基本相同。

Archon 的优化方式有几处值得注意的工程细节。为了缩小搜索空间，他们做了预处理：发现“生成、批评、排序、融合”这个序列效果很好，于是施加约束，比如第一层始终只是生成器，批评器应总在排序器或融合器之前，单元测试生成器后面必须跟一个评估操作，每层只使用一种推理时技术。优化目标是在留出数据集上建立“准确率 vs 对模型发起的调用次数”的关系，在任何给定推理预算下最大化准确率、最小化成本。优化器本身使用**贝叶斯优化**——讲师强调这是强大且有不少优秀开源软件支持的方法论，比贪婪搜索或随机选择样本效率高得多。一个有趣的观察是：**堆叠越来越多层推理时技术、让架构变“深”，确实有助于提高准确率**——最右边的配置（多模型集成、三层批评与融合器、最后一层融合）显著优于“最佳模型跑一次”或“最佳模型跑八次加一层融合”。讲师把这个现象类比于深度学习中加层让模型变好：谨慎添加的推理层正在让模型在许多任务上越来越准确。

结果层面：仅使用开源模型，Archon 就能匹配或超过当时的闭源前沿模型，在许多任务上 pass@1 大幅领先；在指令遵循、推理、数学和编程问题上，平均 pass@1 比 GPT-4o 或 Claude 3.5 Sonnet 提升 14.1%。而且 Archon 既可以做任务特定化训练（贝叶斯优化只关注一个任务），也可以做通用化训练（希望在多个任务上都好）——即便是通用版本也表现很好，能泛化到训练任务之外或有限的训练任务上。

## 结语：三个可带走的判断

把这一讲放回课程路径看，它完成了三件事。第一，它把缩放定律从预训练搬到推理侧，证明覆盖率与样本数之间存在可拟合、可预测的幂律，并给出其数据分布条件——难题长尾。第二，它确立了本课程的核心问题结构：**生成靠采样，验证定上限**；可验证领域（形式化证明、单元测试、编译器式等价检查）能端到端自动化，不可验证领域则受困于生成-验证差距，多数投票在稀有正确答案面前失效。第三，它展示了工程化的方向：并行、顺序修订、PRM 引导的束搜索、融合、批评、排序，乃至用贝叶斯优化搜索整个推理架构——而“如何在预算约束下混合这些旋钮”仍有大量未公开的研究空间。

如果要留一句话给下一讲：采样能引出模型已知的答案，但只有好的验证器知道该留下哪一个——这正是 reward model 与 verifier 要接着回答的问题。
