# 让模型学会“想清楚再动手”：Stanford CS329A 第五讲中的多步推理与规划

## 导语

如果说本课程前几讲在讨论“智能体如何从反馈中改进自己”，那么第五讲处理的是一个更前置的问题：**在采取行动之前，模型如何把一件事想清楚、拆开、走对？** 课程围绕三篇工作——Language Agent Tree Search（LATS）、SPRINT 与 SWiRL——展开，分别对应多步推理与规划中的三个互补侧面：如何在巨大的行动空间里**搜索**，如何把推理过程**并行化**以降低延迟与成本，以及如何用**合成数据与强化学习**教会模型多步使用工具并在步骤间保持正确。三篇论文的共同底色是：多步任务中的错误会沿步骤复合，因此“过程”本身值得被建模、被评分、被优化。

## 一、本讲在课程路径中的位置

CS329A 的主题是自我改进的 AI 智能体。第五讲并不是孤立的一讲，而是承接了前面关于测试时搜索与验证器的讨论：逐字稿中明确把 LATS 与之前看过的 Math Shepherd 作对比——后者用验证器在测试时给推理轨迹打分并引导扩展，而 LATS 的不同在于，评分依据的是**模型所采取行动的结果**，并引入了模型对轨迹的**反思（reflection）**。同时，LATS 又被描述为对 ReAct 框架的改进：ReAct 中“推理—行动—观察”的循环，在 LATS 里被嵌入到树搜索与规划之中。

换句话说，本讲把课程前面“用反馈改进输出”的思路，从单步或单条轨迹，推广到**多步轨迹的搜索与优化**；而后半讲的 SPRINT 与 SWiRL 则把这种多步结构从“推理时”推进到“训练时”，为后续讨论自我改进的数据与训练配方埋下伏笔。逐字稿结尾也点明，这是一个“非常活跃且正在前进的领域”。

## 二、LATS：把 MCTS 搬进语言模型的推理路径

### 问题设定

课程用旅行规划的例子说明什么叫“多步”：推理步骤是“预算多少、去哪里”；行动是浏览网页、生成查询、阅读 Reddit 或旅行博客；搜索则是根据收集到的反馈改进计划，比如考虑替代目的地或新活动。论文的动机是让 LLM 从“生成一个计划并执行”转向**鼓励多样化、可探索的多条计划路径**，因为模型在生成多样化方案、以及为达成方案做多步优化方面仍然较弱。方法上的核心动作，是把强化学习与多步规划中已知的技术——特别是多步蒙特卡洛搜索——引入 LLM 的推理路径，并让模型在与环境探索的过程中接收反馈、再带回改进后续计划与搜索。

值得注意的是课程对 LATS 与 Math Shepherd 的区分：Math Shepherd 中验证器给推理轨迹打分来引导搜索；LATS 中评分基于行动的结果，再加上模型反思与环境观察。这与 ReAct 的关系也被讲清楚了：LATS 在 ReAct 的循环上增加了记忆化步骤、反思步骤，以及“越来越多的规划”。

### 六个阶段与迷宫例子

LATS 包含六个阶段：**选择（selection）、扩展（expansion）、评估（evaluation）、模拟（simulation）、反向传播（backpropagation）、反思（reflection）**。课程用“穿过迷宫到达出口”的提示词完整走了一遍流程：初始观察是“你在一个光线昏暗的房间里，有两扇门，一左一右，目标是到达出口”。在选择阶段基于 UCT 选出待扩展节点；扩展阶段采样出三个行动——打开左边的门、打开右边的门、检查房间寻找线索；每个行动在环境中执行，观察被附加到上下文（例如打开左门后看到“黑暗的走廊，上面有画”）。

评估阶段的做法很有代表性：把一个状态的分数做成两项之和。其一是 **LM 分数**，即用 LLM 作为评判者（judge），直接要求它按 0 到 1 给这个状态打分；其二是**自一致性分数（self-consistency score）**，即采样多次行动并归类，若某个行动被采样得更多，就按其被采样的比率或频率给分——课程的例子中状态 A 的自一致性分数更高，因为可能有 75% 的采样落在行动 A 上。模拟阶段则用贪心方式从得分最高的状态一路扩展，直到终止状态（成功或失败）或达到预算；例子中从 SA 出发走楼梯，看到“出口门标记得很清楚”，得到一分。

### UCT 与反向传播

价值函数被描述为加权平均：LLM 作为评判者给出的 0 到 1 分、自一致性分数，以及 **UCT（upper confidence bounds applied to trees）**。UCT 完全借自 MCTS 文献，用来在选择节点时平衡**探索与利用**：只按当前最高值走，可能错过“现在值低、但沿路径走到最后值更高”的节点。公式上，利用项是 V(S)，另有一项鼓励探索，其中 np 是父节点被访问的次数，ns 是当前节点被访问的次数——相对于父节点访问得越少的节点，越被鼓励访问；访问得越多，这一项就越小。

反向传播发生在一条轨迹结束时：该轨迹的回报被用来更新值，并沿步骤反向传播。每个状态的值等于“旧值乘以（该节点访问次数减一）加回报，再除以该节点总访问次数”。课程特别诚实的一点是：讲者说这里面有一些数学和理论直觉，“没有证明说这是最优的”，但平衡探索与利用被认为是一种更优化的做事方式。

反向传播完成后，还会追加模型对这条轨迹的反思：成功或失败时，模型写下发生了什么、是什么导致成功或失败，课程认为这对整体质量“非常有帮助”。

### 结果与局限

实验方面，课程提到 HotpotQA——每个问题需要从至少两个不同的维基百科页面检索才能回答，因此设计上就是多步过程——以及 WebShop，一个多步的实际应用数据集（例子是找一张小型便携式收纳桌：已完全组装、指定颜色与饰面、有价格要求）。在 WebShop 上，该方法在没有任何微调的情况下、仅在测试时就能得到很高结果，甚至接近人类专家。总体结论是：LATS 把推理、行动与规划结合，把 MCTS 等已知想法引入语言模型世界，在多个领域得到很强结果，且由于是测试时方法与模块化方法，非常可移植、相对容易创建。

局限也被明确指出：**成本**——每一次反向传播和树扩展都在增加大量开销，而且论文并没有真正分析成本收益。另一个未被解决的假设是：某些场景下行动可能是**不可逆**的——如果模型正在执行一笔交易，真的采取那些动作可能带来重大后果（比如为某项服务付费），这类场景下方法可能不太适用。

课堂讨论还触及两个技术细节：有同学问 bandit learning 中是否还有其他探索算法被比较过，讲者回答没有，并指出多臂老虎机文献以及其他把探索—利用引入优化过程的方式都可以在这里探索，而这篇论文的主要贡献是“创建了一个平台，现在其他人可以引入其他优化方法”；另有同学问重复动作序列（如 A B A B）在树中如何处理，讲者的回答是：给定父节点，动作重复出现会增加该动作的计数，并在 UCT 公式中体现，理想情况下构建的是树而非全连接图，这是方法背后的假设。

## 三、SPRINT：让推理学会“并行思考”

### 从观察到动机

SPRINT 被介绍为一篇 2025 年的新论文，“甚至还没有在会议上展示过”。它的动机来自一个观察：o1、Gemini Think、Gemini 2.5 Pro 等推理模型，对更难的问题会思考更多，更长的思考对应更高的准确率；课程用 DeepSeek R1 训练过程中数学题表现变好、同时每个回答平均长度上升的图来说明这种相关性。但关键洞察是：许多长推理步骤其实是**彼此独立**的——模型尝试不同方法、把任务分解为可并行运行的子任务、以及用一些步骤验证之前的步骤，从描述推理轨迹的图上看，大量计算部分彼此独立，不需要顺序等待。

因此 SPRINT 是一个在**后训练/微调阶段**介入的框架：让推理模型通过一个**规划器（planner）**生成一组关于如何解决问题的计划，以及一组可以并行运行的**执行器（executor）**，规划与执行交替穿插、反复进行——一轮计划并行执行，再一轮计划，再一轮并行执行。课程强调，这种“规划—执行交替”正是加速推理过程的关键。

### 数据怎么造：用 LLM 标注 LLM 的轨迹

实现路径很值得注意，讲者也明确说希望学生“超越这篇论文本身”来思考这一点：当想创造数据、找出模型中的某种行为时，可以用 LLM 本身参与微调数据的创建。具体做法是：让 DeepSeek R1 生成推理轨迹和答案，再让 GPT-4o 这样的模型浏览轨迹，标注各个步骤，并且对每个步骤标注哪部分是规划、哪部分是执行——某些步骤中一个给定计划有多个执行片段。

有了这些标注，就可以用模型判断步骤之间的依赖关系，创建**DAG（有向无环图）**：例如步骤四和步骤二不互相依赖，但都依赖于步骤一。然后对步骤打包：第一步先做，第二、三步可以完全并行，以此类推。最终得到包含步骤、计划和并行执行的数据集，对大型推理模型（large reasoning model）做**监督微调（supervised fine-tuning）**，让它在推理时能输出这些标签：plan one 及其执行、plan two 及其执行，依此类推。

### 推理时到底发生了什么

讲者澄清了一个容易误解的点：推理时模型仍然是自回归地、顺序地生成计划和执行，但不同之处在于，如果它被训练成“在每个时间点只要有可以并行执行的计划就同时生成”，那么在第一步之后，它会同时生成第二步和第四步，看到结果后继续。每一步在训练中都是“一个计划加一组执行”。训练数据里 plan one 和 plan two 相邻放置，执行也相邻放置，以匹配推理时的提示方式；而在推理时，执行实际上是并行完成的。对于“如果需要重新规划，模型如何记住哪个计划对应哪个执行”的提问，回答是：模型仍然能看到所有上下文，仍然可以回到某个计划；这里教模型的是在每个时间点都思考计划，如果计划可以并行执行就并行，而不必等待 plan one 的执行来生成与它独立的 plan two。

### 结果与讨论

训练配方是：为数学数据集生成 6K 条思考轨迹，保留并行化程度更高的那些，对 DeepSeek R1 distill 7B 做监督微调。结果有两个：一是减少顺序 token 生成的目标达成了；二是**准确性也提升了**——课程描述为大约 3.5% 的提升，同时顺序 token 数量比 32B 模型高效得多。此外还有**域外泛化**：在数学数据上训练并行思考，模型在 countdown、GPQA diamond 等未训练的数据集上准确性也更高。课程还提到一个直觉性观察：更难的问题需要更多迭代的规划与执行；以及一个不那么直觉的观察：早期阶段模型表现出更多并行性与探索，后期则收敛到更少的计划、更深地投入单一计划与执行。

讨论环节涉及几个有价值的工程问题。其一，并行分支各自的答案单独看正确、顺序组合起来却可能错误——回答是：无论顺序还是并行生成，最终一切都被压缩进上下文，模型被期望在生成最终答案前解决矛盾；而且这些计划更像是解决同一问题的不同**步骤**，而非同一问题的不同解法。其二，如何保证独立任务负载均衡、不出现落后者——回答是：仍可能有落后者（第四步可能比第二步慢得多），但总时长只受限于最慢的那一个，而不是两者之和；也采取了一些措施，比如把过于简单的计划合并成更大的块来并行执行；关于跨阶段优化推理函数的精确分析，讲者表示不确定是否有。其三，关于树的宽度，讲者表示不知道确切数字，但强调任务本身需要存在并行性才能利用该方法，数学等推理任务中这种并行性普遍存在；并提到在数学数据集上，即使与某些准确率相当的方法相比，也减少了大约 40% 的顺序 token，这是很大的数字；而如果思考过程本身 token 很少，并行机会就少，方法甚至可能不如基线，它的闪光点在更难、需要更多思考的问题上。讲者还提到 Sonnet 4.5 系统卡中鼓励模型尽可能多地使用工具（至少 100 次），以此说明我们正在进入一个模型解决问题所需 token 远超以往的时代。最后，讲者指出监督微调只是起点，RL、GRPO 等方法有可能从这些数据中获得更多收益和泛化；工具使用方面（如重叠不同工具、实现墙钟时间加速）也是可以继续做的工作。

## 四、SWiRL：不调用工具的强化学习，教出会调用工具的模型

### 动机与挑战

第三篇论文 SWiRL 被定位为“多步合成数据生成并鼓励模型去做”的延续，将于下周在蒙特利尔的计算与语言建模会议上展示。动机是：许多现实任务需要多步推理与工具使用——用搜索引擎回答多跳问题、解数学题、解决软件工程问题（做项目、规划旅行、分析数据）——人类往往不止一次地使用工具并推理。挑战有二：一是多步设置中错误与复杂性会在步骤间**复合**；二是训练过程中**实时使用工具**非常困难，工具可能失败、可能很慢，而训练本身已经耗时且有挑战。课程还批评了现有微调范式（从人类反馈、AI 反馈或执行反馈中做强化学习）多是为**单步**任务优化的：模型生成一个最终答案，奖励只基于最终答案是否正确，再反向传播到动作。

SWiRL 的设计目标因此是一张清单：让模型解决复杂多步任务；知道**何时**调用工具；生成正确的查询来调用工具；执行推理步骤并在步骤间保持准确性；学会从错误中恢复；学会何时停止采取新步骤、说出“我现在准备好生成最终答案了”；同时**避免在训练过程中使用工具**，并希望模型能泛化到新工具与新任务。

### 离线造数据 + 过程奖励

流程第一步是创建合成多步数据：给定 prompt，让模型一次走一步，每一步都告诉模型它可以自由推理、创建思维链、调用工具，或提出最终答案；模型采取动作（可能是推理步骤加工具调用），环境响应被展示回模型，再问下一步。通过这种迭代提示，为不同查询生成一到三或五步不等的多步数据集。第二步是标注：用一个 LLM 作为裁判，给定先前上下文和当前动作（推理状态加工具调用），给出这一步有多好的估计——这个打分可以离线、并行地遍历大量问题完成。然后可以按不同方式过滤数据：只保留裁判认为每一步都好的（过程过滤）、只保留最终答案正确的（结果过滤）、两者都过滤，或随机。

### 训练时不执行工具

训练采用强化学习。课程用“谁年纪更大：Glenn 还是 Rossling”的例子走了一遍：动作一是搜索第一个人的年龄，裁判给出这一步的奖励；然后展示这一步的结果（已在训练数据中）、提示下一个动作（搜索第二个人的年龄）、再得奖励；最后模型准备好输出最终答案，在 answer 标签中给出答案并得到奖励。关键设计是：**训练期间不做工具调用**。所有工具调用都在数据标注阶段、在 RL 微调之外完成；训练时把提示、步骤和动作展示到第 K 步以及环境响应，要求模型采取下一步，但不执行该动作、不调用工具，只基于这个动作收集奖励用于 RL 优化。理由是：LLM 仅基于所提出动作的质量就能做得很好，不需要执行动作再评估。目标函数上，对步骤 S1 到 SK、每步后跟一个动作（推理步骤加工具调用），优化的是“给定目前为止所有上下文（离线收集的状态与动作）下单个动作的期望奖励”，并且这个动作从动作一到动作 K 都会变化。

有同学追问：裁判看不到工具输出，怎么能给出合理分数？回答是：裁判评判的是模型生成的**调用工具的查询质量**，而不是工具的输出——模型不需要知道这个人的年龄，就能判断“询问这个人的年龄”是一个好问题、一个合理的问题。也就是说，这里提供的是**过程反馈（process feedback）/过程奖励（process reward）**，工具调用被捕获在之前的上下文中。

推理时则迭代提示模型：给出可用工具（例子中是计算器），告诉它“如果你认为使用计算器会有帮助，请生成一个数学查询，用这种标签括起来”“一旦你有足够的信息，可以生成 answer 标签并给出最终答案”。模型在响应中调用计算器、给出想运行的数学运算，用户提供输出，再连同之前的思考过程与工具调用结果一起回给模型，如此迭代。

### 结果：过程过滤、跨域泛化与过程正确性

实验设置：用 227B 的模型生成多步合成数据，问题来自 HotpotQA 和 GSM8K，约 5 万条轨迹。数据过滤的影响中，一个“一开始不太直观”的发现是：只用过程过滤（裁判多数投票认为步骤是好的，但不按最终答案正确性过滤）似乎比只用结果正确、或过程与结果都正确的轨迹更有帮助。讲者的解释是：如果模型已经知道结果且正确，你可能并没有帮助它解决测试时无法解决的问题——你是在训练它以不同方式思考这些问题；而它已经在一定程度上正确掌握了一些过程。

更有意思的是**泛化**：在 GSM8K（数学题，教模型使用计算器类工具）上做多步 RL 后，在 HotpotQA 上测试，准确率从 65 提升到 75.1；而用 HotpotQA 本身（工具是搜索）优化，提升是从 65 到 73。反过来也成立：在 HotpotQA 上用搜索工具训练，模型在 GSM8K 上用 Python 也表现很好。课程把这张图称为“这篇论文中最重要的图”：在更容易创建数据的环境中造合成数据、教模型使用工具与多步思考，可以泛化到全新的工具与领域，规模化可能是一种非常强大的方法论。此外，从 100 个训练样本增加到 10,000 个样本，模型在完全不同的任务（GSM8K 数学题）上也在进步。

对“为什么变好”的解释是：查看模型在回答这些问题时每一步的平均过程奖励，微调前后对比，模型的过程正确性在整个过程中都提高了——无论分布内（HotpotQA 训练）还是分布外（GSM8K 测试）。课程还比较了监督微调：多步 RL 比监督微调好相当多；监督微调确实受益于过程与结果都经过过滤的训练数据，因为在监督微调中这是模仿学习，展示错误轨迹可能损害性能；而 RL 给模型在给定之前步骤时采取新动作的新机会，并基于新动作给予奖励，这是它能突破的原因。

## 五、三篇工作放在一起看

把三篇工作并置，可以看到一条清晰的递进线索。LATS 关心**测试时**：在行动空间中用树搜索与 UCT 平衡探索与利用，用 LM 评判加自一致性评估状态，用反向传播与反思更新价值——代价是成本，且假设行动可逆。SPRINT 关心**训练时**：发现推理轨迹中大量步骤彼此独立，于是用 LLM 标注 LLM 的轨迹、构造 DAG、微调模型输出规划与并行执行，把“想得更久”变成“想得更宽”，在减少顺序 token 的同时意外提升准确性，并展现域外泛化。SWiRL 关心**训练时的工具使用**：用离线合成数据与过程奖励，在不执行工具的前提下做多步 RL，让模型学会何时调用工具、如何从错误中恢复、何时停止，并把这种能力泛化到新工具与新领域。

三者共享同一个判断：多步任务的关键不在最终答案，而在**过程**——过程需要被搜索（LATS）、被结构化并行（SPRINT）、被逐步奖励（SWiRL）。这也正好解释了本讲在课程中的位置：自我改进的智能体不能只会“回答”，还要会“规划—行动—反思—再规划”，而这条循环既可以发生在推理时，也可以被训练进模型参数里。

## 结语

第五讲没有给出一个统一的“多步推理算法”，而是给出了三种把过程变得可计算的方式：搜索让模型在测试时多看几条路，并行让模型在训练后少等几步，过程奖励让模型在微调中把每一步走对。三篇论文的局限与开放问题同样值得记住：LATS 的成本与不可逆行动假设，SPRINT 对任务内在并行性的依赖与负载均衡问题，SWiRL 对裁判质量与离线数据分布的依赖。讲者反复提到的“这是一个非常活跃且正在前进的领域”，既是对现状的描述，也是对本讲之后课程内容的预告。
