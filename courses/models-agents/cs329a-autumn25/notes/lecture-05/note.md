# Stanford CS329A Lecture 5：Multi-step Reasoning / Planning 讲义候选稿

## 学习目标

完成本讲后，应能：

1. 说明多步任务中“推理—行动—搜索”三类步骤的分工，以及为什么单纯让 LLM 生成一个计划并执行不足以应对开放环境。
2. 解释 LATS 如何把 MCTS 的 Selection / Expansion / Evaluation / Simulation / Backpropagation / Reflection 六阶段引入语言智能体，并写出 UCT 与价值反向传播的核心形式。
3. 说明 SPRINT 的动机（长思维链中大量步骤彼此独立）、数据构造方式（用 LLM 标注 plan / execution 并构建 DAG）以及推理时的并行执行机制。
4. 说明 SWiRL 如何在训练阶段避免真实工具调用、用 process reward 优化多步轨迹，并解释其跨任务、跨工具泛化的实验现象。
5. 识别三类方法的成本、假设与失效边界。

---

## 课程主线

本讲围绕一个共同问题展开：**当任务需要多步推理、外部行动与环境反馈时，如何让模型不只是“想一遍再答”，而是搜索、并行化、并从中学习。**

三篇论文对应三种切入角度：

- **LATS（Language Agent Tree Search）**：在**测试时**把推理、行动、规划统一到一棵搜索树中，用 MCTS 式的选择与反向传播提升解的质量，代价是计算成本。
- **SPRINT**：在**后训练**阶段改造推理模型，使其学会把相互独立的计划并行生成与执行，目标是同时降低顺序 token 数与提升准确率。
- **SWiRL**：在**强化学习训练**阶段用合成多步数据与 process reward 优化每一步动作，且把工具调用完全放在离线数据构造中，避免训练时调用真实工具。

贯穿三篇论文的主线可以概括为：**把推理过程显式结构化（树、DAG、逐步轨迹），再对这种结构做搜索、并行化或优化。**

## 核心概念

### 1. 多步任务中的三类步骤（LATS 的框架）

课程以旅行规划为例区分：

- **推理步骤**：模型思考要做什么，例如预算、目的地、行程安排。
- **行动步骤**：基于推理去收集信息或改变环境，例如浏览网页、生成搜索查询、阅读博客。
- **搜索/改进步骤**：根据反馈改进当前计划，例如考虑替代目的地或新增活动。

LATS 的目标正是从“生成一个计划并执行”转向**鼓励模型探索多样化的计划路径**。课程明确指出，模型在生成多样化方案、以及为达成方案做多步优化方面仍然较弱。

### 2. LATS 的六阶段

1. **Selection**：基于 UCT 选择一个节点进行扩展。
2. **Expansion**：从该节点采样若干候选动作。
3. **Evaluation**：对新状态打分。
4. **Simulation**：从高分状态继续扩展，直到终止状态（成功/失败）或达到扩展预算。
5. **Backpropagation**：把轨迹回报沿路径回传，更新各状态的值。
6. **Reflection**：在轨迹结束后追加模型对“为何成功/失败”的反思。

课程用迷宫示例贯穿：初始观察是“光线昏暗的房间，左右各有一扇门”，采样出“开左门 / 开右门 / 检查房间找线索”三个动作，分别执行得到观察，再进入评估与模拟。

### 3. 评估：LM score 与 self-consistency score

LATS 对某动作对应状态的评分由两部分相加：

- **LM score**：用 LLM 作为 judge，提示其根据 0 到 1 给该状态“有多大希望”打分。
- **Self-consistency score**：采样大量动作（课程例子中为 50 次）并按动作类型归类，用某动作被采样的频率/比率作为分数。课程例子中动作 A 的自一致性分数更高，因为约 75% 的采样落在该动作上。

课程原意是：单一值由这两项组合而成；讲解中给出的操作是“把两个分数加起来”。

### 4. UCT 与探索-利用平衡

UCT 直接借自 MCTS 文献，用于在若干候选节点中选择扩展对象。其结构为：利用项 `V(S)` 加上一个超参数乘以一个鼓励探索的项；探索项中，`np` 是父节点被访问次数，`ns` 是当前节点被访问次数。直觉是：相对于父节点访问得少的节点，应被鼓励更多访问；访问次数多了，该项变小。

课程明确说明：没有证明表明这是最优的，但它被视为在探索与利用之间更优的平衡方式。课堂问答中还指出，bandit 文献里还有其他引入探索-利用的方法，作者并未在论文中比较；作者的主要贡献是提供了一个平台，让其他人可以引入其他优化方法。

### 5. 反向传播的值更新

轨迹结束时（无论成功或失败），回报沿步骤回传。每个状态的值更新为：

> 新值 = （旧值 × (该节点访问次数 − 1) + 回报） / 该节点总访问次数

这是课程给出的框架背后的数学，属于对“访问计数平均”的增量式更新。

### 6. LATS 与 ReAct、Math Shepherd 的关系

- 相对 **Math Shepherd** 一类用验证器在测试时引导搜索的工作：LATS 的评分不是基于推理选择，而是基于**模型所采取行动的结果**，并包含模型反思与来自环境的观察。
- 相对 **ReAct**：LATS 保留了与环境的交互，并增加了记忆化/反思步骤，且在过程中有越来越多的规划。

### 7. SPRINT：并行化长思维链

**动机观察**：o1、Gemini Think、Gemini 2.5 Pro 等推理模型对更难问题思考更久，更长的思考对应更高准确率；DeepSeek R1 训练中平均回答长度上升与数学能力提升同时出现。但长推理轨迹中**许多步骤彼此独立**：模型尝试不同方法、把任务分解为可并行的子任务、部分步骤在验证前序步骤。

**框架**：SPRINT 在后训练/微调阶段介入，让推理模型通过 **planner** 生成一组计划，通过可并行运行的 **executor** 执行计划，并可反复进行“规划—并行执行—再规划”的交替。

**数据构造**：让 DeepSeek R1 生成推理轨迹与答案，再用 GPT-4o 标注各步骤、标注每步中的规划部分与执行部分（某计划可有多个执行片段），并用模型判断步骤间依赖关系，构建 **DAG**。随后对步骤打包：如步骤一先做，步骤二、三可完全并行。

**训练**：用监督微调让模型学会输出这些 plan / execution 标签；推理时模型先生成彼此独立的 plan one 与 plan two，再并行执行（执行可使用计算器、Python 等工具），结果回到上下文后进入下一轮。

**课程报告的观察**：

- 在数学数据上生成约 6K 条思考轨迹，保留并行化程度更高的轨迹，对 DeepSeek R1 distill 7B 做监督微调。
- 相对基线，顺序 token 数量大幅下降（课程图中提到约 3.5% 的准确率提升，同时在顺序 token 上比 32B 模型更高效；具体数字以论文为准）。
- 出现**域外泛化**：只在数学数据上训练并行思考，在 countdown、GPQA diamond 等未训练数据上准确率也更高。
- 更难的问题需要更多迭代规划与执行；早期阶段并行/探索更多，后期趋于收敛到更少的计划。
- 训练数据形态是“plan one 与 plan two 相邻输出，execution one 与 execution two 相邻”，推理时执行真正并行。

**课堂澄清的要点**：

- 它始终是 next-token 预测，只是通过特殊标签让模型在同一步生成多个可并行的计划。
- 模型仍可回到先前计划、修订计划，因为它能看到全部上下文。
- 负载均衡：可以让过于简单的计划合并成更大的块，但仍可能有落后者（如第四步远慢于第二步）；总时间受最慢分支约束，而非各分支之和。
- 并行性收益依赖任务本身存在可并行的结构；对思考 token 很少的问题，并行机会少，甚至可能不如基线；方法在更难、需要更多思考的问题上收益更大。

### 8. SWiRL：用合成多步数据 + RL 训练工具使用

**动机**：现实任务（多跳问答、数学、软件工程、旅行规划、数据分析）需要连贯的多步推理与工具使用；错误会在步骤间复合；而在训练中实时调用工具很困难——工具可能失败、慢、有 bug。

课程指出，许多 RL 微调（人类反馈、AI 反馈、执行反馈）是**为单步任务优化**的：模型生成最终答案，奖励只基于最终答案，再反向传播到动作。

**设计目标**：让模型知道何时调用工具、生成正确的工具查询、在步骤间保持准确、从错误中恢复、知道何时停止并给出最终答案；同时**避免训练时使用工具**，并希望模型能泛化到新工具与新任务。

**数据构造**：给定 prompt，迭代地让模型一次走一步；每步告知模型可用工具、可自由推理/生成思维链/调用工具/提出最终答案；环境响应回填上下文。步骤数依查询从一到三或五不等。再用 LLM judge 对“先前上下文 + 当前动作（推理状态 + 工具调用）”给出奖励估计，可离线并行地处理大量问题。

**数据过滤**：可按过程过滤（judge 认为每步都是好步骤）、按结果过滤（只保留最终答案正确的轨迹）、两者都过滤，或随机；课程还提到对部分轨迹做过纠正。

**训练**：基于 RL。关键机制是——展示到动作 K 为止的提示、步骤、动作与环境响应，让模型采取下一步，但**不执行该动作、不调用工具**，只基于该动作的质量收集奖励用于优化。所有工具调用都发生在离线数据标注阶段。judge 评判的是**模型生成的工具查询的质量**，而非工具输出；例如判断“询问这个人的年龄”是不是一个向搜索引擎提出的好问题，不需要知道此人真实年龄。课程说明没有为 judge 专门训练模型，只是提示使用。

**目标函数**：设有步骤 S1 到 SK，每步后跟一个动作（推理步骤 + 工具调用）；优化的是**给定此前全部上下文（离线收集的状态与动作）下单个动作的期望奖励**，该动作从动作一到动作 K 变化。

**推理**：用标签让模型表达工具调用或最终答案；迭代提示“到目前为止发生了什么、可用工具是什么、准备好了就输出 answer 标签”。课程以计算器为例展示一次数学查询的标签化调用与结果回填。

**实验设置（课程所述）**：用 227B 模型（课程称 GMO 227B）创建多步合成数据；问题来自 HotpotQA 与 GSM8K；约 5 万条轨迹。

**课程强调的关键现象**：

- **只做过程过滤**的数据，比只保留结果正确、或过程与结果都正确的数据，对训练更有帮助。课程解释：若只保留模型已经能做对的结果，可能并没有教模型用不同方式思考新问题。
- **跨任务、跨工具泛化**：在 GSM8K 上用计算器类工具训练后，在 HotpotQA 上测试，准确率从 65 提升到 75.1；用 HotpotQA 自身（搜索工具）优化则从 65 到 73。反向亦成立：在 HotpotQA 上用搜索工具训练，模型在 GSM8K 上用 Python 也表现良好。课程认为这说明模型学到的不只是某个具体工具，而是分步思考与调用工具的方式。
- **数据规模**：从 100 个训练样本增加到 10,000 个，模型在完全不同的任务（GSM8K 数学）上也持续进步。
- **过程正确性**：RL 微调后，模型每一步的平均过程奖励在分布内（HotpotQA 训练）与分布外（GSM8K 测试）都提高。
- **RL 优于 SFT**：多步 RL 明显优于监督微调；SFT 需要过程与结果都正确的数据才更好，这符合模仿学习的直觉——展示错误轨迹可能损害性能；而 RL 给模型在给定前序步骤下采取新动作并获奖励的机会。

## 关键公式或原则

1. **LATS 状态评分**：`score = LM judge score (0–1) + self-consistency score`（课程讲解中的组合方式）。
2. **UCT 选择**：`V(S) + c × 探索项(np, ns)`，其中探索项随当前节点相对父节点访问次数减少而增大。
3. **值反向传播**：`V_new = (V_old × (n−1) + R) / n`。
4. **SWiRL 优化目标**：对每个步骤 k，优化 `E[reward(action_k) | 此前全部上下文]`，上下文来自离线收集的状态与动作；训练时不执行动作。
5. **原则：结构化再优化**。三篇论文都把隐式的“想一遍”变成显式结构（搜索树 / 计划执行 DAG / 逐步轨迹），再对结构施加搜索、并行或 RL。
6. **原则：训练与工具执行解耦**（SWiRL）。工具调用放在离线数据构造，训练只评估动作质量。
7. **原则：探索-利用需要显式机制**（LATS 的 UCT；课堂问答指出 bandit 文献中还有其他可选机制，作者未比较）。

## 课程作业关联

课程未在本讲中给出具体作业题目。可据课程强调的几条线索建立关联：

- LATS 部分：作业若涉及在测试时提升多步任务表现，需要权衡树扩展/反向传播带来的**成本**；课程明确指出论文没有真正分析成本收益，且方法假设某些动作**可逆**——若动作涉及付费、交易等不可逆后果，方法适用性受限。
- SPRINT 部分：课程把“用 LLM 标注轨迹、构建 DAG、再监督微调”作为可复用的数据构造范式，并提示 RL / GRPO 可能从这类数据中获得更多收益与泛化；工具重叠、实际墙钟加速被列为可实现的其他工作。
- SWiRL 部分：课程把“过程过滤 vs 结果过滤”“RL vs SFT”“合成数据规模与域外泛化”作为核心实验结论，适合作为实验设计题的对照维度。

## 常见误区

1. **把 LATS 的评分等同于“推理选择打分”**。课程明确对比 Math Shepherd：LATS 评分基于行动结果，并含反思与环境观察。
2. **认为 UCT 有最优性证明**。课程明确说没有证明，只是被认为能更好平衡探索与利用。
3. **认为 SPRINT 改变了 next-token 预测范式**。课堂澄清：始终是 next-token，只是通过标签让模型在同一步生成多个可并行计划，并在推理时并行执行。
4. **认为 SPRINT 总能加速**。课程指出收益依赖任务存在可并行结构；对思考 token 少的问题可能不如基线；总时间受最慢分支约束。
5. **认为 SWiRL 训练时需要真实调用工具**。工具调用全部在离线数据标注中完成；训练只对动作质量给奖励。
6. **认为 judge 必须看到工具输出才能打分**。SWiRL 的 judge 评的是查询质量（如“问年龄”是不是好搜索查询），不需要真实结果。
7. **认为 SFT 与 RL 可用同样的数据过滤**。课程指出 SFT 更依赖过程与结果都正确的数据；只做过程过滤的数据在 RL 中反而更有帮助。
8. **把 LATS 的树当成图**。课堂问答指出其哲学假设是树：同一动作在轨迹内重复出现时，在给定父节点下增加该动作计数，并通过 UCT 体现；理想情况是树而非全连接图。
