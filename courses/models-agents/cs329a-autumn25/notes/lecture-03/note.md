# CS329A Lecture 3 学习笔记：Robust Verification

## 学习目标

完成本讲后，应能：

1. 解释 **generation-verification gap** 的含义，以及为什么它构成推理时扩展（inference-time scaling）的核心瓶颈。
2. 区分 **outcome-based reward model（ORM）** 与 **process-based reward model（PRM）** 的训练方式、标签来源与适用场景。
3. 描述 verifier 在训练时与测试时的不同角色：作为重排序器（reranker）、作为 RL 奖励信号、作为可蒸馏的集成组件。
4. 理解 **process supervision** 为什么能比 outcome supervision 更好地抑制 false positive，以及它引入的额外复杂度。
5. 说明弱验证器集成（weak verifier ensemble）与弱到强监督（weak-to-strong supervision）的基本假设与工程价值。

---

## 课程主线

本讲以四篇论文为线索，呈现 verification 研究在约四年间的演进：

| 阶段 | 论文 | 核心思路 |
|---|---|---|
| 1 | *Training Verifiers to Solve Math Word Problems*（OpenAI, 2021） | 训练一个输出"解答正确概率"的 verifier，测试时对重复采样结果重排序 |
| 2 | *Let's Verify Step by Step*（OpenAI） | 从 ORM 转向 PRM，用人工逐步标注做 process supervision |
| 3 | *Math-Shepherd* | 用模型自身采样自动生成步骤标签，并把 PRM 用作 RL 奖励 |
| 4 | *Shrinking the Generation-Verification Gap with Weak Verifiers*（Stanford, 2025） | 不训练新 verifier，而是用弱监督方法聚合异构 verifier 集成，并蒸馏到小模型 |

主线逻辑：**生成能力已经足够强，瓶颈在于自动判断哪个答案正确**。四篇论文分别回答：如何训练 verifier、监督粒度应该多细、标签能否自动化、以及如何在不训练更强 verifier 的前提下提升验证质量。

## 核心概念

### 1. Generation-verification gap

模型通过重复采样可以覆盖正确答案（coverage 上升），但缺乏可靠机制从大量候选中选出正确答案（pass@1 不随之上升）。上一讲提到多数投票（majority voting）在样本数超过约几十个后就不再改善选择质量；本讲的多篇论文都把"多数投票在高采样数下失效"作为基线对照。

课程原意：这个 gap 是 verification 研究的动机来源。解释：它意味着**采样扩展与选择能力必须同步扩展**，否则多采样只增加覆盖率而不增加系统准确率。

### 2. Verifier 的基本形式

- 输入：问题 + 候选解答；输出：该解答正确的概率或分数。
- 训练标签来源：数学题有 ground-truth 最终答案，可将采样解答与标准答案比对生成二元标签。
- 测试时用法：对同一问题采样多个解答，用 verifier 打分，取最高分作为系统输出。

第一篇论文中 verifier 本身是一个语言模型，附加一个 **scalar head** 做逐 token 的二元预测；训练同时使用二元损失与常规 next-token 语言建模损失。最终解答分数取最后一个 token 之后的预测。课程提到他们做了 token 级与句子级标签的消融；token 级标签噪声更大。

### 3. ORM vs. PRM

- **ORM（outcome-based reward model）**：对整个解答给一个奖励，标签来自最终答案是否正确。
- **PRM（process-based reward model）**：对推理的每一步给分，标签来自人工逐步标注（正确 / 错误 / 中性）。

PRM 的测试时分数通常取各步概率的乘积。课程强调 PRM 的关键优势：模型可能"过程完全错误但最终答案正确"（幻觉导致的假阳性），process supervision 能显式看到每一步，因而更能抑制这类 false positive，同时鼓励可解释、人类认可的推理过程。

代价：逐步标注成本高；PRM 引入阈值等额外超参数；存在 **credit assignment** 问题——某步看起来合理但未必对最终答案有贡献。

### 4. Process supervision 的数据效率技巧

*Let's Verify Step by Step* 产出了 PRM800K（约 80 万条步骤级标签）。为提升标注效率，他们优先把"最终答案正确但中间步骤有错"的样本交给人类标注，课程称其数据效率比随机选择高约 2.6 倍。流程是迭代的：收集数据 → 训练 PRM → 用更好的 PRM 提升后续数据质量。

### 5. 自动步骤标注：hard / soft estimate（Math-Shepherd）

不依赖人工标签，把某一步的质量定义为"从该步出发到达最终正确答案的潜力"：

- **Hard estimate**：从当前步采样 n 个补全，只要有一个到达正确答案，该步标为成功。
- **Soft estimate**：用到达正确答案的补全**比例**作为该步分数。

课程指出的缺陷：难题上可能 n 个采样全部失败，导致该步得不到任何信号；若错误步骤之后仍侥幸得到正确答案，错误步骤会被误标为正确。课程提到 soft estimate 随 n 增大表现更好，但最终他们选择了 hard estimate，因为更易度量。

### 6. PRM 作为 RL 奖励

Math-Shepherd 不仅用 PRM 做测试时重排序，还用它作为奖励对生成器做 RL 微调，形成"模型生成标签 → 训练 PRM → 用 PRM 改进生成器"的自我改进闭环。课程提到这种 RL 带来的增量小于纯测试时扩展，且优化后期出现平台期。

### 7. 弱验证器集成与 weak-to-strong supervision（Beaver）

假设：没有完美的 verifier；现存最好的 verifier 也各有偏差（bias），但它们与真实正确性相关。若多个 verifier 捕捉正确性的**独立方面**，集成可强于任何单体。

流程要点（课程描述为 score-weight-select）：
1. 对各 verifier 输出做归一化，统一尺度；
2. 过滤低于质量阈值的 verifier——课程强调这是重要步骤；
3. 用极少量标注数据（课程示例为每个数据集 1% 训练标签）通过简单方法（朴素贝叶斯或逻辑回归）估计各 verifier 权重；
4. 加权组合得到最终分数。

其监督估计受 Snorkel 类 weak supervision 工作启发：在 verifier 两两独立的假设下写出概率方程，构造优化问题求权重。课程提到增益在 GPQA Diamond、MATH、MMLU Pro 等较难基准上更明显。

工程价值：可将集成"教师"蒸馏到小模型（课程示例约 4 亿参数，教师池在 70B 量级），保留约 97% 准确率而测试时计算量降低 99% 以上；蒸馏版与原始版均开源。课程还强调，在该设置下弱模型 + 验证扩展可以接近更强模型类别（如 8B 系统接近 7B 级模型的多数投票表现；70B 级系统在这些数据集上平均约 86.2%，接近专有模型水平）。

## 关键原则

1. **验证难度低于生成难度**是 verifier 有效的经验前提；课程提到"更大生成器 + 更小验证器"优于反之，但帕累托最优尺寸比例是开放问题。
2. **监督粒度决定假阳性控制能力**：步骤级监督能看到过程，因此比只看结果的监督更能拒绝"错过程、对答案"的样本。
3. **verifier 规模扩展存在收益递减**：第一篇论文中每问题采样约 400 个后验证收益趋平；采样越多，verifier 在近分候选间的区分精度越重要。
4. **集成的前提是多样性**：若所有 verifier 给分高度一致，聚合无信息增益；信号来自它们之间的一致与差异。
5. **不改生成器也能提升系统**：verifier 让基础模型保持通用，通过选择/引导获得任务收益；代价是推理成本与阈值等超参数。
6. **验证可用于三个层次**：测试时重排序、RL 训练信号、生成训练数据——三者可叠加。

## 课程作业关联

- 课程建议在项目评估设计中考虑 GSM8K 等推理基准（约 8,500 道小学水平数学题，强调多步推理、自然语言解答）。
- 明确点出的潜在研究方向：生成器/验证器尺寸比例的帕累托最优；在固定推理计算预算下如何在生成与验证之间分配 FLOPs；用评分标准（rubric）、工具调用（如计算器、SymPy）作为额外验证信号以激励自我纠错；verifier 与生成器是否同家族、同规模对效果的影响（课程表示没有已知研究直接回答）。
- 课程提到 Beaver 蒸馏后的 checkpoint 开源，可用于智能体或测试时扩展项目。
- 后续课程会涉及以单元测试作为 verifier 的编程验证路线（Code Monkeys），以及推理模型（reasoning models）与测试时扩展的关系。

## 常见误区

1. **"采样越多，verifier 一定越好"**——错。verifier 精度有限时，候选越多、近分候选越难区分，系统准确率会趋平甚至下降；需要同时扩展验证能力。
2. **"PRM 一定优于 ORM"**——课程明确指出较新方法常把两者结合以兼得优势；PRM 有 credit assignment 风险、标注成本和阈值超参数。
3. **"自动步骤标注等价于人工标注"**——hard/soft estimate 在难题上可能得不到信号，也可能把侥幸成功的错误步骤标对。
4. **"弱验证器集成就是把分数平均"**——朴素平均只是基线；课程强调需要归一化、质量过滤和基于（少量）标签的权重估计，Beaver 相对朴素集成有额外增益。
5. **"多数投票就是验证"**——多数投票只比较最终答案的重复频率，不看推理过程；课程中它在高采样数与分布偏移下均劣于训练过的 verifier / PRM。
6. **"验证只用于测试时"**——verifier 同时是 RL 奖励与数据生成机制；课程也讨论到测试时扩展主要用于生成训练数据的未来可能性。
7. **"用 PRM 训练生成器没有风险"**——若微调生成器，模型可能学会只产出 PRM 喜欢的答案而停止真正推理；课程强调此时需确保 chain of thought 合理、标签质量可靠。
