# 从自举到可扩展 RL：CS329A 第六讲中的训练时扩展

## 导语

在 CS329A 的前半程，课程把大量注意力放在测试时扩展（test time scaling）上：让模型多用工具、多写代码、多做稳健验证（robust verification），在推理阶段把答案“选”出来。第六讲则把闭环合上：如果模型能生成输出，而这些输出又能被验证、被过滤、被重新用于训练，那么算力就不只花在推理时，也可以花在训练时。讲者把这条路径称为训练时扩展（train time scaling）或扩展 RL（scaling RL），并用三篇论文串起一条清晰的技术演化线：STaR 教模型自举推理过程，DeepSeek Math 把强化学习真正扩展到数学推理，DAPO 则处理长推理链下 RL 的稳定性与工程细节。

这一讲在本课程中的位置很关键。前面讲的是如何让智能体在测试时借助工具、代码反馈和验证器把事做对；这一讲讨论的是如何把这些“做对的过程”转化为下一轮训练信号，使模型自身成为改进自身的起点。也正因如此，讲者反复强调：训练时扩展不是无条件有效的魔法，它依赖可验证性、依赖足够好的奖励信号，也依赖极其细致的实现细节。

## 一、为什么小模型能在一夜之间“变强”

讲者用 AIME 基准开场。AIME 是数学推理基准，比课程早先使用的 MATH 更难，MATH 已经饱和且被污染，所以课程和作业转向更新的基准。幻灯片给出的对比很有冲击力：GPT-3.5 这类大规模模型在该基准上的准确率被认为大约只有个位数百分比；而 DeepSeek Math 在一个 7B 模型上通过训练时扩展达到 51.7%，加上额外技巧甚至能到 60%；DAPO 方法在 Qwen 32B 上也能达到 50%。

这组对比要说明的不是“参数不重要”，而是：在推理基准上，训练时投入的算力可以在相当程度上替代模型参数规模。讲者把预训练、微调、测试时扩展和训练时扩展放在同一张范式图上：预训练是在互联网数据上训练；微调（包括 RLHF）让模型变成可用的聊天模型；测试时扩展是在推理阶段采样、多数投票、组合输出；而训练时扩展，则是把测试时扩展产生的输出拿来做过滤，再用过滤后的结果进一步微调模型。讲者说，如果你整节课只记住一个循环——生成、验证、过滤、再训练——那就算学到了训练时扩展的基本原理。

这里有一个重要的限定条件：这套循环在具有可验证性的领域效果更好。数学有标准答案，代码有单元测试，数据分析有可执行反馈，因此你知道哪些输出正确、哪些不正确。讲者用“把意大利面扔到墙上并知道它应该落在哪里”来比喻：测试时扩展需要好的验证器来挑选轨迹；训练时扩展则教模型提高 pass@1，让你更可能一次输出正确结果，但闭环验证仍然不可少。

课程也展示了 O1 系列在 AIME 上的图：横轴分别是训练时算力和测试时算力，纵轴是 pass@1。两条曲线都呈对数线性上升，说明增加训练时算力或测试时算力都能提升准确率。讲者由此提出一个学生后来的问题：训练时扩展和测试时扩展之间如何平衡？讲者没有给出精确的 ROI 曲线，而是把这个问题留到第三篇论文再谈。

## 二、STaR：用“正确答案”作为推理质量的代理

第一篇论文是 STaR。它要解决的问题很朴素：大语言模型可以用思维链（chain of thought）提升数学与常识推理，但互联网规模的数据里并没有大量现成的推理步骤；人工标注推理步骤非常昂贵；自动化生成推理又往往只适用于非常特定的领域；少样本提示（few-shot prompting）给的几个例子，效果也不如在大数据集上微调。于是 STaR 的关键洞察是：从少量带推理步骤的示例出发，让模型自己生成推理和答案，只保留答案正确的样本，再在这些样本上微调，并重复这个循环。

STaR 的流程可以拆成几步。先有一个很小的提示数据集，包含题目、推理过程和答案；再有一个较大的训练数据集，只有题目和答案。模型先在提示数据集上做少样本提示，然后对训练数据集中的题目生成推理过程和答案；用答案是否正确来过滤，保留正确解法，在模型上微调。对于模型答错的题，STaR 加入“合理化”（rationalization）：把正确答案作为提示给模型，让它反推一条能到达该答案的推理过程，再把“题目—推理—答案”加入训练集。这样训练集就能包含比模型当前能力更难的问题，推理能力得以自举（bootstrap），而不是被限制在模型原本就能解决的简单题上。

讲者特别提醒，STaR 几乎可以看作一种离策略强化学习（off-policy reinforcement learning）技术，但它非常精简。它做了几个假设：第一，最终答案正确可以作为推理质量的代理，因此过滤掉不正确答案；第二，语言模型在给定答案作为提示时，能够生成有效的推理路径；第三，初始语言模型足够强，能从少量示例中自举，如果问题类别远远超出模型能力，STaR 就不会有太大进展。

课堂讨论把 STaR 的局限暴露得很清楚。有学生问：如果模型给出正确答案，但推理过程有问题，怎么办？讲者回答，这篇论文在合理化那一步并不再做额外过滤，后续论文才引入过程奖励模型（process reward model）来评估推理链质量；这本身可以成为项目想法。又有学生问：如果模型连提示答案都推不出推理过程，怎么办？讲者说，这正是假设所基于的基准不能太难的原因，迭代地做下去，模型可能在某一点开始能处理这些题。还有学生追问负样本的作用，讲者承认，从负样本中学习还没有被完全攻克；STaR 主要从正样本学习，负样本大多被过滤掉。

实验结果方面，STaR 在 GSM8K 上相对于监督微调有提升，但只用了约 70% 到 87% 的数据；它不是真正的 RL，多次迭代后会趋于平稳。在常识问答上，人工标注者认为 STaR 生成的推理过程相当合理，而且合理化过程帮助模型用更少数据达到一定准确率。但在 GSM8K 上，合理化并没有带来显著提升，讲者解释，部分原因是问题太简单，模型本来就能做，强制思维链和提供合理化步骤效果类似。这也引出一个更一般的教训：如果问题太简单，让模型去推理的整个概念就没有太大帮助。

STaR 之后还有 VAR 和 Quiet-STaR 等变体：VAR 把生成器和验证器放在一个循环中训练；Quiet-STaR 则把推理步骤放进潜空间（latent space），用 MLP 做内部思考，而不是用英语把每一步写出来。讲者用这些变体说明，这条研究线在“如何评估推理质量”“如何从失败中学习”上仍有大量开放问题。

## 三、DeepSeek Math 与 GRPO：把 RL 扩展到数学推理

第二篇论文是 DeepSeek Math。讲者先给出一张 MATH 基准的图：随着模型规模增大，准确率通常上升；但 DeepSeek Math 的 7B 模型突然表现很好。这个飞跃来自他们正确地在训练时扩展循环中完成了 RL 部分。

DeepSeek Math 做对的第一件事是数据。此前 Minerva 在 PaLM 上通过大量科学和数学数据（如 arXiv 数据）提升 STEM 能力；DeepSeek 则说，在 arXiv 论文上训练并不是诀窍，他们从 Common Crawl 网页中筛选数学内容，并且从 DeepSeek Coder 模型开始。讲者强调，从一个已经在代码推理上改进的模型开始，效果更好；而从代码到数学的迁移显著有帮助，因为模型能更好地推理、更好地使用工具。这是第一次展示“从代码模型出发”可以在数学上做得更好。他们通过筛选和挖掘开放网络数学（OpenWebMath），获得了更好的数学领域覆盖和更大的 token 数量。

第二件事是扩大 RL。传统 RLHF 或使用验证器的 RL 常用 PPO，需要保留旧策略、新策略、critic 和奖励模型四份模型副本，模型一大就变成内存问题。DeepSeek 提出 GRPO：不要 critic 或价值函数，而是对每个问题采样多个答案，用奖励模型给每个答案打分，然后把奖励归一化为“奖励减去组均值再除以标准差”，这个归一化后的值就成为优势（advantage）的估计。讲者没有写完整公式，而是让直觉清楚：奖励模型本质上是在比较中训练的，提供组上下文可以在不保留 critic 的情况下做跨奖励比较，从而节省内存、扩大 RL 规模。

GRPO 在数学上把准确率从 46.8 提升到 51.7，是当时第一个在 7B 规模上超过 50% 的开源模型，而且没有 critic。讲者把 STaR、在线拒绝微调和 GRPO 放在一起比较：STaR 生成一次，正确得 1、错误得 0；在线拒绝微调也是在线生成，但只保留正确样本；GRPO 则在线生成、用奖励模型打分，并通过组基线计算优势。关键区别在于，GRPO 需要一个问题集上有奖励分布：如果所有奖励都是 0 或都是 1，归一化就不起作用，模型没有可学的信号。这也回应了学生关于“难题上微调是否会导致回归”的问题：如果展示的问题都太难，模型在任何时候都拿不到奖励，就没有爬坡信号；KL 散度项则用于防止模型偏离它已经能解决的问题。

讲者还指出，DeepSeek Math 改进的是多数投票（majority@K）性能，而不是 pass@K：模型变得更一致，而不是从根本上更聪明。这个区分在最后被再次强调，成为本讲最重要的开放问题之一。

## 四、DAPO：长推理链下 RL 的工程细节

第三篇论文是 DAPO。讲者说，如果你天真地放大 GRPO，在 Qwen 32B 上做 RL，很容易遇到熵崩溃、模型过度自信、训练不稳定、响应长度不可控等问题。DeepSeek 的论文在 AIME 上得到 47%，DAPO 则试图明确说明 GRPO 没有覆盖哪些技术细节，并把 Qwen 32B 上的表现从 30% 一路推到 50%。

DAPO 的第一个技术是非对称裁剪（asymmetric clipping）。标准 PPO 的裁剪对增加和减少概率的对待非常相似，低概率 token 只能爬坡那么多，高概率 token 也会被裁剪，探索可能崩溃。DAPO 让裁剪函数不对称，允许更大的增加。讲者用图说明：允许非对称裁剪时，准确率更高，熵保持得更稳定；不做非对称裁剪，熵会崩溃。熵是模型探索空间的代理指标。

第二个技术是动态采样（dynamic sampling）。GRPO 采样 64 个解，得出分布，取组基线；DAPO 则超采样，然后过滤掉全零奖励和全一奖励的组，只保留有信号的组。这样优势不为零，不浪费梯度，维持有效批大小（effective batch size）。讲者解释，RL 中你不会从全对和全错的组计算梯度，所以过滤掉它们可以让训练更有效。

第三个技术是 token 级损失（token level loss）而非样本级损失（sample level loss）。样本级损失对每个问题—答案对计算损失，长而垃圾的答案和简短的好答案获得相同权重；token 级损失则给每个 token 加权，并配合长度惩罚，控制熵和平均响应长度。讲者说，如果没有 token 级损失，熵会增长，响应长度不受控制地增长；放了 token 级损失后，训练更稳定。

第四个技术是软过度长度惩罚（soft overlong punishment）。模型遇到难题时会在最后被截断，被截断的推理链产生大量噪声；DAPO 在 token 上放渐进惩罚来处理这个问题，让训练稳定而不是增加噪声。讲者也提到，不同论文有不同做法，有的在 RL 循环中增加上下文长度，DAPO 则用惩罚函数。

这些技术叠加起来的效果是：从 GRPO 的 30% 开始，加过度长度过滤到 36%，加非对称裁剪到 38%，加软过度长度惩罚到 41%，加 token 级损失到 42%，加动态采样到 50%。讲者说，这甚至比 DeepSeek R1 蒸馏到 Qwen 32B 的结果还好，说明可以在 Qwen 32B 上自己爬山。

DAPO 的经验被讲者概括为三条 RL 原则：损失函数本身不是足够合理的代理，必须看响应长度；必须看熵，并保持它既不太低也不太高；完全准确率为一的样本百分比告诉你需要采样多少。挑战则包括：响应长度爆炸时要控制损失；要控制熵；如果一定步数后没有改进，奖励模型可能已经饱和。

## 五、三种技术如何选择，以及本讲的边界

讲者在最后把三种技术放在一起比较。如果你只有少量带推理的例子（比如 100 个），没有 RL 基础设施，STaR 是相当好的起点，能让模型开始推理，在 GSM8K 这类简单任务上看到合理改进，虽然不一定惊人。如果你有足够好的基础模型和指令数据，GRPO 是相当强的算法，即使内存不够也能工作，在标准数学推理任务上已经得到很好验证。如果你需要处理更长的推理链、更难的问题、追求最先进性能，那么 DAPO 这类工作需要控制 RL 算法和基础设施中的各种变量，对竞赛级别问题（AIME、IMO）非常有用。

但讲者反复强调边界：这三种技术总体上改进的是多数投票（majority@K）性能、答案格式化和多步连贯性，而不是基础能力，不是教模型解决新问题或在域外大量泛化。要提升 pass@K，需要模型基本能力的阶跃跳跃，这通常来自某种突破或在某个维度上的 scaling。讲者还指出，很多 RL 循环甚至 STaR 方法都取决于模型的推理能力，或者需要验证器/奖励模型；如果模型太有能力，奖励会被破解；如果奖励模型信号不足，就无法在循环中爬山。因此，什么样的验证信号足够好、能否使用验证器集成（ensemble verifier）而不是单个验证器，都是极其重要的问题。

开放问题被明确列出：为什么只有 majority@K 增加而 pass@K 不增加；推理链中的回溯、自我评估、自我纠正行为是真实涌现的，还是本来就有、只是在统计上更普遍；如何从失败中学习，目前很多技术只是把失败样本过滤掉。有前途的方向包括：在数据维度上生成更好的训练数据；在算法维度上让 RL 对奖励模型中的噪声更鲁棒；把 STaR 中的推理技术与 DAPO 中的技术结合起来。

课堂最后，讲者提到 RL 相对于预训练的占比在增长，但也提醒，奖励不够强或有噪声会成为瓶颈。这恰好呼应了本课程的主线：自改进智能体的关键不只是“让模型自己训练自己”，而是构建可靠的验证与反馈闭环，让训练时扩展和测试时扩展互相支撑。

## 结语

第六讲把课程从“推理时如何把答案选对”推进到“如何把选对的过程变成下一轮训练信号”。STaR 展示了用正确答案作为推理质量代理的自举循环；DeepSeek Math 的 GRPO 展示了如何在没有 critic 的情况下扩大 RL；DAPO 则展示了长推理链下 RL 的工程细节如何决定成败。三者共同说明：训练时扩展的有效性，取决于可验证性、奖励分布、熵与响应长度的控制，以及对失败样本的处理。它也留下了一个贯穿课程的问题：当多数投票提升而 pass@K 不提升时，我们究竟是在让模型更一致，还是在让它更聪明？这个问题，正是后续自改进智能体研究要继续回答的。
