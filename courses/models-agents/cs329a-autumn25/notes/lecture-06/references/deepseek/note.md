# CS329A Lecture 6 学习笔记：Train-Time Scaling / Scaling RL

## 学习目标

学完本讲，应当能够：

1. 解释 train-time scaling 与 test-time scaling 的区别与闭环关系，说明为什么前者本质上是“用模型自己的输出（经过过滤）再训练模型”。
2. 描述 STaR 算法的完整流程（few-shot 生成 → 按最终答案过滤 → rationalization 补全失败样本 → SFT → 迭代），并说明其关键假设与失效场景。
3. 说明 DeepSeekMath 在进入 RL 之前做对了什么（数据筛选、从 code 模型出发），以及 GRPO 相对于 PPO 的内存动机与 group-normalized advantage 的直觉。
4. 说明 DAPO 针对 naive GRPO 扩展时暴露的四类问题（entropy collapse、无效梯度、长度失控、截断噪声）及对应技术手段。
5. 判断在给定资源与任务条件下，SFT、STaR、GRPO、DAPO 各自适用与不适用的场景。
6. 识别本讲反复强调的开放问题：为什么多数技术只提升 majority@K 而非 pass@K；如何从负样本学习；推理行为是涌现还是被放大。

---

## 课程主线

本讲位于课程从“测试时技术”转向“训练时技术”的转折点。前几讲讲的是推理时采样、工具与代码反馈、稳健验证（robust verification）；本讲把这些环节闭合：**把测试时产生的、经过验证的输出，反过来用于训练模型本身**。这就是讲师反复强调的那一个循环——如果整节课只记一件事，就是它。

三篇论文按演化顺序组织，而非按最新程度：

- **STaR**：用最终答案正确性作为推理链质量的代理，自举（bootstrap）出带推理过程的训练数据，属于精简的、接近 off-policy 的方法。
- **DeepSeekMath**：在数学领域把 RL 真正跑通，提出 GRPO，使 7B 模型在 MATH 上超过 50%。
- **DAPO**：直面上难度更高的问题、更长的推理链时，naive 放大 GRPO 会遇到的一系列工程与算法问题，并给出组合式修补。

动机来自一个经验事实：AIME 这类可验证数学基准上，GPT-3.5 级别的大模型准确率很低（讲师给出的量级约为 5%），而 7B 模型经 train-time scaling 可以达到 51.7%，加额外技巧可到 60%；DAPO 在 Qwen 32B 上能到 50%。也就是说，**投入训练时算力可以在一定程度上替代模型参数规模**。这与课程名“Self-Improving AI Agents”直接呼应。

讲师给出的三范式定位：**预训练**（互联网数据）→ **微调 / RLHF**（偏好数据）→ **测试时扩展**（采样、多数投票、组合输出）。train-time scaling 就是在这个链条末端再加一环：把测试时扩展的输出过滤后用于进一步微调。

## 核心概念

### 1. 为什么推理有效，以及它在哪里最有效

思维链把 token 预算专门用于：问题分析、任务分解、自我评估与回溯、尝试不同方法（近似并行搜索）。讲师用 o1 系列早期示例说明了这几种模式（bash 脚本转置矩阵、化学 pH 计算中自我纠正公式）。

关键判断：**有验证闭环的领域（代码、数据分析、数学计算）收益远大于个人写作、文本编辑这类难以验证的领域**。胜率对比图中前者明显超过 50%，后者提升有限。这直接决定了 train-time scaling 的适用范围。

### 2. STaR

流程（讲师用“更严格”的方式复述）：

- 起点：一个小的**推理数据集**（含题目、推理过程、答案，如多选题示例），加上一个大的**训练数据集**（只有题目和答案）。
- 用推理数据集做 few-shot prompting，在训练集上生成推理过程与答案。
- 答案正确 → 保留该推理链。
- 答案错误 → **rationalization**：把正确答案作为提示给模型，让它反向生成一条能导向该答案的推理链，加入训练集。
- 在上述两组数据上微调；**迭代**外循环（论文中 warm-up 后保持恒定学习率，逐步增加内循环步数）。

关键假设（讲师明确列出）：

1. 最终答案正确是推理质量的**代理指标**（数学中通常成立），因此过滤会滤掉低质量链；代价是学不到错误推理链中的信息。
2. 给定答案作为提示时，模型能生成有效推理路径。
3. 初始模型足够强，能从少量示例自举；问题类别若远超其能力，迭代也难有进展。

实验结果要点：GSM8K 上相比监督微调有提升，且只用了约 70%–87% 的数据；常识问答上人工标注者认为 STaR 生成的推理链相当合理；但在 GSM8K 上 rationalization 并没有带来额外提升——讲师解释是**问题太简单时，强制 CoT 与提供 rationalization 效果相近**，推理的收益在问题超出直接作答能力时才显现。另外它不是真正的 RL，多次迭代后会趋于平稳。

同源变体：**VAR**（生成器与验证器一起在循环中训练）、**Quiet-STaR**（把推理步骤放到潜空间，用 MLP 而非英文 token 做“内部思考”）。

### 3. DeepSeekMath 与 GRPO

进入 RL 前的两步（讲师特别强调，与“基础模型能力不够就得先补”的观点相关）：

- 不是只在 arXiv 数据上训练（Minerva 路线），而是在 Common Crawl 网页上做高质量数学内容筛选（OpenWebMath 方向），覆盖更广、token 量更大。
- **从 code 预训练模型出发**，对数学推理与工具使用有明显帮助；这是较早展示“code → math”迁移有效的证据之一。

GRPO 的动机是内存：PPO 需要旧策略、新策略、critic（value function）、奖励模型四份副本，放大时吃不消。GRPO 去掉 critic，用**组基线**：对每个问题采样多条答案，用奖励模型打分，做 \((r - \text{mean}(r)) / \text{std}(r)\) 归一化作为优势估计。直觉是奖励模型本身在比较上训练，组内归一化提供了比较语境。

效果：MATH 上从 46.8 提升到 51.7，是当时 7B 规模开源模型首次超过 50%，且不需要 critic。但讲师明确指出该论文改进的是 **majority@K（多数解变正确、模型更一致）**，而不是 pass@K（基础能力）。

关于难度分布的关键直觉：如果一组采样全对或全错，归一化后优势为零甚至无定义，**没有爬坡信号**。这直接引出 DAPO 的动态采样。讲师也提到 KL 散度项在防止模型偏离已能解决的问题上起作用。

### 4. DAPO

在 Qwen 32B 上 naive 放大 GRPO 会出现：熵崩溃（模型过度自信）、训练不稳定、响应长度失控增长。DeepSeek 自家报告在 AIME 上约 47%；DAPO 论文要显式补上 GRPO 未覆盖的技术点：

- **非对称裁剪（asymmetric clipping）**：标准 PPO 裁剪对概率增加与减少处理对称，低概率 token 能爬升的幅度受限，探索会崩溃；放开增加侧后准确率与熵都更稳。
- **动态采样（dynamic sampling）**：超采样后过滤掉全对与全错的组，只保留有信号的组，维持有效 batch size，不浪费梯度。
- **Token-level loss 替代 sample-level loss**：避免长而 garbage 的答案与简短好答案获得相同权重；配合对熵与平均响应长度的控制。
- **软过度长度惩罚（soft overlong punishment）**：被截断的推理链会产生大量噪声，用渐进惩罚稳定训练（另一种路线是在 RL 循环中增加上下文长度）。

消融叠加（Qwen 32B，AIME）：GRPO 起点 30 → 过度长度过滤 36 → 非对称裁剪 38 → 软过度长度惩罚 41 → token-level loss 42 → 动态采样 50，超过 DeepSeek-R1 蒸馏到 Qwen 32B 的结果。

讲师由此提炼的三条 RL 原则：**损失函数本身不是足够的代理**，必须同时监控响应长度、熵（既不能太低也不能太高）、以及全对样本的比例（决定需要采多少）。

### 5. 方法选择（讲师给出的对比结论）

- 只有约百量级带推理的示例、没有 RL 基础设施：**STaR** 是合理的起点，在能力范围内的简单推理任务（如 GSM8K）上有可见提升，但不会惊人。
- 有足够好的基础模型 + 指令数据、GPU 有限、标准数学推理：**GRPO** 是验证充分的选择。
- 推理链会长得多（更难的问题、竞赛级 AIME/IMO）、需要 SOTA：必须在 RL 算法与基础设施里控制 DAPO 那一整套变量。

SFT 与 RL 的取舍：RL 在奖励信号强的领域能用更少样本爬山，但做对很难；SFT 在有大量高质量数据时更快，但不会带来推理轨迹层面的能力。

## 关键公式与原则

- **STaR 过滤准则**：保留 \(\{(\text{问题}, \text{推理链}, \text{答案}) : \text{答案正确}\}\)；失败样本经 rationalization 转为正样本。质量代理 = 最终答案正确性。
- **GRPO 优势**：\(\hat{A} = (r - \text{mean}(r)) / \text{std}(r)\)，组内归一化替代 critic；组内奖励无方差（全对/全错）时无学习信号。
- **DAPO 动态采样**：过滤 \(r \equiv 0\) 与 \(r \equiv 1\) 的组，保持有效 batch。
- **非对称裁剪**：提高概率增加侧的裁剪上界，防止探索崩溃、熵塌缩。
- **Token-level loss + 软过度长度惩罚**：控制长度与熵，抑制截断噪声。
- **贯穿性原则**：train-time scaling 的效果上限由 (a) 基础模型在该领域的现有能力、(b) 验证器/奖励模型信号质量、(c) 问题难度分布是否提供爬坡信号三者共同决定。奖励太弱或有噪声时，RL 循环的瓶颈不在算法。

## 常见误区

1. **把 STaR 当成 RL**。它只用正确样本，无负样本学习、无在线策略优化，讲师称其为“精简的、接近 off-policy”的方法，迭代后会平台化。
2. **认为过滤掉错误答案没有代价**。假正例（答案对但中间步骤无效）会进入训练集；论文本身不做过程级过滤。
3. **认为 GRPO 只是“省显存的 PPO”**。组归一化本身改变了优势估计的性质，也引入了“全对/全错组无信号”的新问题。
4. **只看 loss 判断 RL 是否健康**。讲师反复强调要同时看熵、响应长度、全对样本比例。
5. **混淆 majority@K 与 pass@K 的提升**。本讲多数技术提升的是一致性而非基础能力；pass@K 的提升通常来自能力阶跃，而非这类循环。
6. **忽视基础模型起点**。DeepSeekMath 的成功有相当部分来自数据筛选与 code 预训练，而非仅靠 RL；STaR 的假设 3 同样强调初始能力边界。
7. **认为采样数 64 是普适超参**。讲师明确说这取决于基准难度与基础模型能力，论文中的数字只是示例。
