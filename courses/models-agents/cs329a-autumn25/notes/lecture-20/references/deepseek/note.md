## 课程主线回顾

课程对自我改进智能体的定义性描述是：智能体是 LLM 的一种泛化——它有一个目标，与环境交互、收集反馈，并用反馈纠正自己的步骤，从而指导自身过程、使用工具、完成目标。在当前范式下，LLM 本身常不足以独立驱动完整目标，因此实践中大量系统是「手写工作流」，由人编排 LLM 与工具；但在编程智能体等场景中，已能看到由模型自身驱动的工作流。

课程把自我改进循环的骨架归纳为：**验证器（verifier）驱动 → 运行验证器获得反馈与奖励 → 用强化学习或搜索算法在数学、编程等任务上做爬山式优化**。前半程围绕测试时扩展（多次采样、多数投票）与训练时扩展（把推理循环中的反馈转化为奖励）展开；随后引入开放性探索（如 Alpha Evolve 类技术）、工具使用、检索与记忆、规划与多步推理，以及面向下一代模型的评估。客座讲座补充了后训练、多模型智能体、机器人学、推理，以及符号技术（symbolic techniques）——后者被明确归入工具使用大类，并被认为能为合成数据添砖加瓦。

本讲的结构是：先提出三个未来研究问题（多样性、验证、数据/任务选择），再转向「智能的效率」——即推理是有成本的，效率本身是未来研究的核心维度。

## 核心概念

### 1. 推理链多样性（diversity of reasoning chains）

课程指出的现象：用单个 LLM 生成合成数据做迭代微调（生成候选解 → 过滤错误解 → 仅在好样本上微调，即拒绝采样 rejection sampling，含 STAR 等变体），性能往往在几轮或几十轮迭代后停止提升。课程把原因归结为**缺乏多样性**：预训练数据由人类在长时间跨度内产生，天然多样；而单个 LLM 即使在高温度下为一组提示词生成输出，多样性也有限。

解决思路：使用多个在某种程度上专门化的智能体来提升多样性。

### 2. 多智能体微调（multi-agent fine-tuning）

课程描述的具体机制：

- 训练**生成智能体**（generator）与**评论智能体**（critic）。生成智能体产生大量多样化的初始解；评论智能体评估并精炼这些解。
- 迭代过程：每个生成智能体先给出初始答案；随后每个生成智能体总结并获取所有其他智能体回答的摘要，作为生成下一轮回答的一部分；评论智能体对这一组更新后的答案进行批评。
- 与单智能体批评的关键区别：不是批评单个回答，而是对多个智能体的回答做专门化与总结后再批评，因此在生成阶段、批评之前就已具备多样性。
- 课程强调的两个「免费」收益：仅靠多智能体即获得类似多数投票的效果；若各智能体训练方式略有不同，即获得多样性。
- 训练数据构造：在多次迭代中取出输出，过滤出与多数投票匹配的，对这些（提示, 回答）对做 SFT。评论模型则在混合轨迹上微调——答案在开始时正确、在辩论过程中被纠正——从而学习对比正确与错误答案。
- 课程提到一个「穷人版」朴素替代：直接用不同模型、不同提示做多次生成（这是实践中人们会做的事）。

课程报告的结果（以数学为数据集、三个开源模型）：横轴为微调迭代次数，纵轴为负对数似然（性能代理）或嵌入不相似度（越高越多样）。多智能体微调下性能持续提升，Llama 3 对该技术似乎更敏感；多样性在迭代过程中持续保持。单智能体微调则准确率崩溃或不再提升。此外在相邻领域 GSM8K 上，微调后的智能体也表现出更高性能，说明可泛化到训练域之外。

### 3. 验证瓶颈与元验证（meta verification）

课程先建立问题背景：结果奖励模型（outcome reward model）只检查最终答案是否与真实答案匹配；但这无法保证推理正确，而过程奖励模型（process reward model）非常难构建。于是出现一种困境：**模型可能最终答案正确但推理链错误；而 LLM-as-a-judge 也不可靠——被要求验证时，模型会声称不正确的证明是有效的。** 人类专家则能在无参考解答的情况下指出「下一步不能从上一步推出」或「引用中存在推理缺口」这类问题。

DeepSeek-Math V2 的做法：不只训练奖励模型，而是训练**验证器**，并额外引入**元验证器**（meta verifier）。课程描述的流程是：让人类在没有参考解答的情况下识别证明中的问题，据此训练 LLM 识别问题；元验证器审查验证器的分析是否合理、指出的问题是否真的存在、分数是否由这些问题得出（即：LLM-as-a-judge 识别推理链中的问题，元验证判断这些问题是否真实存在），并由专家标注该评估的质量。验证器被训练为在 0.5 到 1 的尺度上给证明打分；验证器改进生成器，生成器生成更难的证明，又反过来改进验证器，形成循环。

课程强调的附带收益：一旦播种了用于发现不正确证明的数据，标注就可以自动化，不必仅依赖人类。课程给出的洞察是：最好的证明获得更高验证分数，生成器能学会区分高质量与有缺陷的证明，自我验证因此可以有更好的改进循环。

课程报告的定性结果：在 DeepSeek V3 基础模型上构建，仅靠验证-生成循环，在 IMO 问题与 CNML 类问题上，证明分数随八次迭代持续攀升（课程提到「仅用正一」的设定）；在 best-at-32 设定下（从 32 个生成的证明中挑最好的），接近 2024 年 IMO 短名单的证明分数 42%。课程同时给出边界条件：该技术仍受限于「验证相对容易」的领域；若要推广，需要（a）让基于 LLM 的验证器能在无参考解答下识别问题，（b）元验证以降低验证器幻觉问题的概率，（c）给生成器额外激励以最大化质量。

### 4. 任务/数据选择：让模型自己提出训练任务

课程指出的瓶颈：当前训练栈要么用人工策划的推理轨迹（监督学习阶段），要么用专家策划的问答对（带可验证奖励的 RL）。若领域是数学就需要数学专家，是 IMO 就需要 IMO 专家，是编程就需要强程序员。随着模型继续超越人类智能，找到越来越多专家与任务的能力开始受限。

课程介绍的论文思路：**单一模型同时提出任务并解决它们**，几乎走向另一个极端——不需要外部数据来源，模型自己提出任务再去解决，形成随时间演化的课程学习（curriculum learning）。课程明确说明这一想法仍然很新，且该工作聚焦 coding 领域。

三类任务（课程基于代码编程范式构造）：

| 任务类型 | 构造方式 |
|---|---|
| 演绎（deduction） | 生成程序与输入，环境执行得到输出 |
| 溯因（abduction） | 与演绎类似：生成程序与输入，环境计算输出 |
| 归纳（induction） | 采样一个已有程序，为它生成新的输入，外加一条描述该功能的自然语言消息，环境执行并某种程度上判断是否朝正确方向走 |

机制细节：

- **proposer** 以过去生成的、被显式 prompt 的例子为条件（加入以促进多样性）。
- **任务选择的奖励**基于优化任务难度：若 solver 成功率为零，奖励为零；若成功率非零，奖励为 1 减去平均成功率。因此被选中的是中等难度任务——solver 有时成功有时失败，课程指出这通常有助于模型学习。proposer 的目标是在当前模型权重下生成最优任务难度的任务；随着模型变强，proposal 应学会提出更难的问题。
- **有效性检查**：运行程序完整性检查、实际执行以发现错误、安全检查、确保多次运行相同输入得到完全相同的输出。提出的任务在进入训练流水线前会被验证，以防 proposer 作弊或想出垃圾任务。
- **任务 buffer**：每个（输入, 输出, 程序）三元组加入 buffer，连同模型在该任务上成功/失败的次数一起保留；proposer 可从 buffer 采样参考。
- 课程把 proposer 与 solver 的关系类比为某种博弈论式的对抗，但总体上互相促进改进。

课程报告的定性结果：在 prompt 侧没有任何人工整理数据的情况下，在 coding benchmark 上达到 state of the art，并超越在数万个专家示例上训练的模型；观察到复杂度指标随时间增加、程序与答案的多样性改善、proposer 越来越多地生成更难任务；尽管只在自提出的 code 任务上爬山，在 coding 与 math benchmark 上都看到强劲表现（课程称 math 上的表现「实际上令人惊讶」，但可由该领域其他结果解释）；更大的模型相对更小的模型获得更大收益。

课程在讨论中补充的呼应：这与 SWiRL（用合成数据做逐步 RL）的发现相互印证——模型生成自己的训练数据不仅改进生成所在任务，还提升可迁移性（SWiRL 中在带检索的多跳问答上训练，模型在调用 Python、解数学题等其他工具调用上也变好，反之亦然）；且更大的模型似乎更擅长吸收这种数据飞轮并通过它泛化。

### 5. 每瓦智能（intelligence per watt, IPW）与本地推理

课程给出的趋势观察（定性表述为主）：当前处于「大型机时代」——大模型在云上运行，算力需求爆炸式增长（课程引用了云服务计算增长、英伟达同比增长、数据中心所需吉瓦量级、以及 Google 处理 token 数量从去年二月的万亿级到今年十月的千万亿级等数字，此处不逐一复述精度）；同时，对 ChatGPT 用户这一超大规模数据集的分析发现约 77% 的请求是实用指导、信息查询、写作等任务，很多并不需要最前沿模型，更小的本地模型即可处理；用户查询类型随时间变化，但绝大多数仍处于复杂度较低一侧。

课程对「本地模型」的操作性界定：活跃参数在 200 亿或以下的模型。硬件侧的观察是本地加速器 GPU 内存大幅提升，笔记本可拥有约 100 GB 内存，配合 8 位等量化版本可本地部署一些最大的模型。

**IPW 的定义（课程原意）**：平均任务准确率除以模型解决该任务的平均功耗。能力侧考察模型在单轮与推理类查询中可处理的查询百分比；效率侧考察在本地硬件上运行这些模型时每瓦能获得多少有效算力。

课程报告的结果（涉及 20 多个本地模型如量化版本、GPTQ、Llama 3 等，企业级与本地加速器，工作负载含来自 ChatGPT 的 100 万条查询及自然推理、MMLU Pro、Super GPQA 等基准，指标含准确率、能耗、延迟、算力使用，并开源了这些跨模型与硬件的指标）：

- 自 2023 年以来，本地模型的准确率（能解决的聊天查询比例）提升 3.1 倍，可处理约 88.7% 的上述查询。
- 本地加速器在效率上落后于企业级芯片，例如 Apple M4 Max 的每瓦智能比 B200 低约 1.5 倍；原因是 B200 极度针对 LLM 工作负载优化，而本地芯片设计时并未预想 LLM 会在本地运行。
- IPW 指标过去两年约提升 5.3 倍，其中 3.1 倍来自更好的模型，1.7 倍来自硬件改进。

课程由此提出的方向：混合式推理服务引擎——根据需求与资源复杂度，在本地与云端的模型和加速器之间平滑路由流量；面向能效推理的新模型架构与 kernel（本地加速器是相比云端关注度少得多的领域）；能源将成为未来最有价值的资源之一，IPW 这类指标与对能源/瓦特/功耗的测量与优化将变得重要。

## 关键公式与原则

**1. 自我改进循环的基本结构（课程反复使用的骨架）**

```
目标 → 与环境/工具交互 → 验证器给出反馈与奖励 → RL / 搜索 → 更新模型或工作流 → 重复
```

课程强调：智能体工作流朝目标推进，因此需要规划、多步推理、走错时自我纠正，以及整体上持续提升能力——这正是「自我改进」层面发挥作用之处。

**2. 任务难度奖励（课程给出的形式）**

设 solver 在某提出任务上的成功率为 $p$：

$$
r_{\text{task}} = \begin{cases} 0 & p = 0 \\ 1 - p & p > 0 \end{cases}
$$

原则：选择非平凡、非不可能的中等难度任务；随模型变强，proposer 应提出更难任务。这是课程所述 curriculum learning 的驱动信号。

**3. 每瓦智能（IPW）**

$$
\text{IPW} = \frac{\text{平均任务准确率}}{\text{模型解决该任务的平均功耗}}
$$

原则：效率指标必须与能力指标联合考察；课程明确说该指标「不仅关注能力或准确率，还关注效率方面」。

**4. 验证器的打分尺度（DeepSeek-Math V2 描述）**

验证器在 $[0.5, 1]$ 尺度上给证明打分；元验证器审查「被识别出的问题是否真的存在、分数是否从这些问题中得出」。

**5. 多样性原则（课程的核心论断）**

若用单一模型生成推理链，多样性不足会导致自我改进循环在若干轮后停滞；多样性可由多智能体专门化「免费」获得。课程把这一点列为未来研究中的开放问题：如何让推理链足够多样以持续驱动循环，以及如何跨领域泛化（当前仍局限于数学与编程等狭窄领域）。

## 课程作业关联

课程在本讲中明确提到一个课程项目：尝试在 kernel 优化问题变复杂时读取性能分析（profiling），并指出即便能为足够简单的情形设计优化 kernel，把各部分连接起来、做性能分析、改动代码中未优化的部分，在一般情况下是更难的问题；人们通常的解法是把问题分解成子部分，让模型逐部分处理，并借助参考解与知识库。课程用这个例子说明：当问题难度超出模型当前能力时，需要以有趣的方式分解问题以适配模型现在能做的事情。

这与本讲的三条主线都相关：（a）验证难度随任务复杂度上升（简单 kernel 可由编译器执行给出正确性信号与指标，复杂情形的「好」更难判定）；（b）任务分解本质上是课程学习/任务设计问题；（c）推理成本与效率（IPW 视角）在系统级优化任务中直接相关。做项目时应注意：不要假设课程给出了该项目的具体评分标准或实现细节——逐字稿只提供了上述定性描述。

## 常见误区

1. **把「智能体」等同于「更强的 LLM」。** 课程的定义是：智能体是 LLM 的泛化，关键在目标、环境交互、反馈收集与自我纠正；当前很多系统仍是人编排的工作流，只有部分场景（如编程智能体）由模型自身驱动工作流。

2. **认为拒绝采样/迭代微调可以无限提升。** 课程明确指出单模型合成数据循环常在几轮或几十轮后停滞，原因是多样性不足，而非数据量不足。

3. **把多智能体微调理解为「集成多个模型投票」。** 课程描述的机制包含辩论式的多轮总结-批评-更新，以及评论模型在「先对后错」的混合轨迹上微调以学习对比正确与错误答案；「免费多数投票」只是附带效果之一。

4. **以为结果正确就说明推理正确。** 课程明确区分结果奖励与过程正确性：模型可能答案正确但推理链错误；过程奖励模型很难构建。

5. **以为 LLM-as-a-judge 足以承担验证。** 课程明确指出：让模型验证时，它会声称不正确的证明有效；这正是需要元验证的原因——元验证审查的是「验证器指出的问题是否真实存在、分数是否由问题推出」。

6. **以为元验证可以无条件推广。** 课程给出的边界是：该技术仍受限于验证相对容易的领域；推广需要无参考解答下的问 题识别能力、降低验证器幻觉的额外模块、以及给生成器的额外质量激励。

7. **把「模型自提任务」理解为完全不需要任何外部信号。** 课程描述的流程仍依赖环境执行（程序、输入、输出）、有效性检查（完整性、安全、确定性）与任务 buffer；「无人工整理数据」不等于「无环境」。

8. **把 IPW 当作纯硬件指标。** 课程的定义包含准确率（能力侧）与功耗（效率侧）；且课程明确说本地芯片设计时并未预想 LLM 本地运行，因此本地与企业级芯片的 IPW 差异部分源于优化目标不同，不能简单读作「本地硬件全面落后」。

9. **忽略非可验证领域。** 课程明确列举：科学发现、芯片设计中需运行数天的慢仿真、需湿实验室运行的化学实验，以及创意写作等主观指标。RL 微调与测试时扩展需要近乎即时（或可等待数分钟、至多约一小时量级）的验证器；需要数百数千步迭代、不能等数天或等人收集奖励的场景，属于非可验证领域。课程给出的应对思路之一是离线收集数据训练奖励模型来预测仿真结果，但课程同时指出奖励模型的泛化性取决于数据量，且可能不准确并导致问题。

## 开放问题清单（课程明确标为未解决）

- 测试时扩展的基础原则：反复向模型提问时，正确答案为何会涌现？把成功轨迹蒸馏回模型的最佳实践是什么？
- 合成数据飞轮与持续学习（continual learning）的衔接：当前是「离线生成经验 → 隔一段时间微调」的异步范式，与人类即时、持续的学习方式不匹配；能否把正负经验以更自然的方式带回模型？课程提到可能的路径包括长期记忆系统、大规模增加有效上下文长度（effective context length）、以及 cartridge 这类把信息带入激活或 KV cache 而不改权重的方式；但课程也指出，技能迁移类问题（如跨具身泛化 cross-embodiment generalization）仅靠记忆系统无法实现，需要更新权重。
- 高吞吐、低延迟的测试时扩展基础设施（infra）：重复采样、多轮迭代、工具调用等负载与主流单轮聊天用法差异很大，系统与推理优化空间大（课程提到其实验室的 hydrogen、Tokamak 等工作）。
- 预训练：课程说明本课主要聚焦后训练与测试时扩展，预训练涉及较少，但那里有很多有趣工作。
- 混合式推理服务：按需求与资源复杂度在本地与云端之间平滑路由。
- 面向能效推理的新架构与 kernel，尤其是本地加速器。
- 能源与功耗的测量与优化，以及 IPW 类指标的主流化。
- 在可验证领域让模型越来越聪明，并尽量消除非可验证领域对标注数据的需 求——课程称这是一个有趣但计算密集的研究方向。

## 附：本讲出现的论文与工作（仅按课程提及）

- 多智能体微调（multi-agent fine-tuning），用于多样推理链的自我改进；课程提到 STAR、拒绝采样等背景工作。
- DeepSeek-Math V2：自验证循环、验证器 + 元验证器；课程提到在 DeepSeek V3 基础模型上构建，并以 GRPO 类 RL 循环为常见背景（课程原话是「很多 RL 循环通常是建立在 GRPO 之上的」）。
- 让模型自提任务并求解的工作（课程未在逐字稿中给出正式标题；讨论环节提到「绝对零（absolute zero）那篇论文」，并澄清其重点不是让智能体自我创建环境，而是任务集合的表示与模拟方式）。
- SWiRL：用合成数据做逐步 RL，多跳问答与工具调用的可迁移性（由课程讨论环节提及）。
- Alpha Evolve：开放性探索（前半程课程内容）。
- hydrogen、Tokamak：测试时扩展基础设施方向（课程提到为其实验室工作）。
- cartridge：把长上下文/上下文学习带入激活或 KV cache 而不微调权重（课程提及）。
- Kernel bench 相关工作与课程项目：复杂情形下的性能分析（profiling）难度。

课程结束语中的一条判断值得记住：现在教的内容到下次开课就开始成为历史，但基本技术随时间推移极其有价值，因为很多新东西仍建立在基本技术之上。
