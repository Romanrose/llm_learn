## 一、问题：为什么计算机使用智能体是“另一种智能体”

这门课此前讨论的智能体，大多在文本或代码空间中工作。Lecture 7 的讲者 JY Koh 一开场就点出：计算机使用智能体（Computer Use Agent, CUA）与 sui 智能体、更基于文本的智能体“有点不同”（逐字稿 [01:42.880] 前后）。不同在哪里？

**学习者解释**：文本智能体的“世界”是 token 序列，它可以读写字符串、调用 API；而 CUA 的世界是**渲染出来的图形界面**——网页、桌面应用、手机屏幕。它接收的输入是截图，执行的动作是点击、滚动、打字、滑动、轻触（逐字稿 [02:49.680]；Slides 第 2 页）。换句话说，CUA 不在“底层接口”上操作，而是在**和人类完全相同的界面上**操作。

这带来了几个连锁问题：

- **输入是像素**：模型必须从截图中理解界面上有什么、在哪里。
- **动作是 GUI 操作**：坐标、滚动量、文本输入，而不是函数调用。
- **成功标准模糊**：人类自己都未必对“任务是否完成”达成一致（逐字稿 [12:45.600]）。

Lecture 7 的主线正是围绕这三个问题展开：**如何建模、如何评估、如何训练**。

## 二、Observe–Reason–Act：CUA 的基本循环

Slides 第 3 页给出 CUA 的核心循环：**用户任务**和**环境观察（截图）**输入模型，模型产生“推理 + 动作”，基础设施验证并执行动作，环境状态改变后返回新截图。讲者用“买一个蓝色马克杯”贯穿全课（Slides 第 4–8 页）：

1. 任务：“买一个蓝色马克杯”；初始截图显示商品列表。
2. 模型推理：“我看到屏幕中央有一个蓝色马克杯，我要点击它。”输出 `{"mouse": {"left_click": [33, 201]}}`。
3. 环境执行点击，返回新截图（商品详情页）。
4. 模型推理：“配送详情在下面，我要向下滚动。”输出 `{"scroll": {"dy": 520}}`。
5. 继续输入邮编 `15213`，直到模型认为完成。
6. 环境计算奖励，通常 0/1 二元（Slides 第 8 页；逐字稿 [05:15.840]–[05:55.840]）。

这个循环在讲者口中被明确称为 **ReAct 循环**——推理与行动交错（逐字稿 [50:40.160]）。

**学习者解释**：ReAct 的关键在于“交错”。模型不是一次性输出完整计划，而是每一步都看到最新的屏幕状态，再决定下一步。这既降低了单步决策难度，也让智能体能从意外结果中恢复。

Slides 第 9–15 页用一条时间线回顾了 CUA 的“史前史”：

- **2017–2022**：MiniWoB（Shi et al., ICML 2017）等玩具环境，合成数据、简化界面，用类似游戏智能体的强化学习训练（逐字稿 [06:40.319]–[07:25.520]）。
- **2022–2024**：WebShop（Yao et al., NeurIPS 2022）引入真实商品和语言目标；WebArena（Zhou et al., ICLR 2024）用真实数据填充模拟环境；OSWorld（Xie et al., NeurIPS 2024）转向完整桌面工作流。
- **2025–2026**：MyPCBench、CUA-World 等开始用编码智能体端到端生成应用和合成数据（Slides 第 13–14 页；逐字稿 [09:35.120]–[10:19.279]）。

讲者提到 GPT-6 Astra 在 CAD 软件中做 3D 建模的演示被加速了 30 倍，实际速度慢得多且昂贵（Slides 第 15 页；逐字稿 [11:23.040]–[11:42.160]）。

## 三、评估：什么样的“成功”才算成功

Slides 第 17 页把“成功”拆成三层：

- **ACTION**：点对目标了吗？适合快速的 grounding / 模仿测试。
- **OUTCOME**：购物车里是正确商品吗？用状态检查或证据判断。
- **PROCESS**：遵守约束了吗？比如“不要结账”。

讲者强调：**评估者应该匹配你想衡量的能力**（Slides 第 17 页）。

### 3.1 静态评估（02A）

静态评估在固定观察上预测动作，不展开环境（Slides 第 19 页）。例子：

- **ScreenSpot-Pro**（Li et al., 2025）：1,581 张高分辨率专业 UI 截图，23 个应用，3 个操作系统，评估点是 point/region matching（Slides 第 20–21 页）。Slides 第 21 页给出 Blender 中构造 UV 球体网格的任务，ground truth 框在原始像素 (417, 132)–(576, 152)，点在框内得 1 分。
- **Mind2Web**（Deng et al., NeurIPS 2023）：2,350 个任务、137 个网站、31 个领域，离线动作匹配（Slides 第 22–23 页）。Slides 第 23 页的例子是“在 Brooklyn–Central 租车”，ground-truth 动作是点击 `bookCarTab`。

讲者指出静态评估的核心缺点：**假阴性**。同一个截图和任务，很多不同动作都可能是合理的，但因为你只有一组真值动作，其他合理动作会被判错（逐字稿 [17:02.800]–[17:44.320]）。

### 3.2 网络端到端评估（02B）

端到端评估让智能体在环境中真正执行任务，最后检查结果（Slides 第 25 页）。

- **程序化状态检查**：WebArena（Zhou et al., ICLR 2024）有 812 个长任务、4 个自托管域名，验证器检查环境状态而非轨迹“看起来对不对”（Slides 第 26–27 页）。Slides 第 27 页的例子是创建空仓库 `awesome_llm_reading`，验证器检查目标 URL 页面内容是否包含仓库名——注意它**不检查“空”**。讲者补充，WebArena 的验证器是 CMU 研究生手写的（逐字稿 [20:32.640]）。
- **VisualWebArena**（Koh et al., ACL 2024）：910 个任务、3 个自托管网站、25.2% 的图像输入任务，说明视觉理解本身改变了哪些任务可被表达（Slides 第 28 页）。
- **LLM/VLM 评判**：Slides 第 29 页展示用 LLM/VLM 加评分细则判断证据，例如“蓝色马克杯在购物车、价格低于 20、没有购买记录”三条都满足则 PASS。WebVoyager（He et al., ACL 2024）有 643 个任务、15 个真实网站，评判者与人类一致率 85.3%（Slides 第 30–31 页）。Online-Mind2Web（Xue et al., COLM 2025）扩展到 300 个任务、136 个真实网站，WebJudge 与人类一致率 85.7%（Slides 第 32 页）。讲者提醒：真实网站评估面临“基准漂移”，且网站所有者不喜欢被大量智能体 ping（逐字稿 [27:52.799]–[28:14.159]）。

Slides 第 33 页展示**人类审查**如何解决模糊结果：两位审阅者对同一轨迹给出 PASS/FAIL 分歧，最终依据“订单确认显示发生了禁止的购买”裁定 FAIL。讲者称人类审查仍是黄金标准，但非常昂贵（逐字稿 [28:37.200]–[29:20.399]）。

### 3.3 桌面/移动端到端评估（02C）

- **OSWorld**（Xie et al., NeurIPS 2024）：369 个任务、9 个应用、每个任务自带 setup 逻辑和应用特定状态检查（Slides 第 35–36 页）。Slides 第 36 页的例子是“用文件夹中的收据更新记账表”，验证器比较保存的工作簿与黄金工作簿，检查 A1:E8 不变、C9:C13 费用标签、金额和滚动余额（D9 ≈ −186.93，E9 ≈ 603.07）。
- **WindowsAgentArena**（Bonatti et al., 2024）：154 个任务、11 个程序、20 分钟并行扫描，用并行 VM 把多日桌面评估变成云规模扫描（Slides 第 37 页）。
- 附录幻灯片还列出 WorkArena、AndroidWorld、MobileWorld 等（Slides 第 89–92 页，待核）。

### 3.4 长时程评估（02D）

长时程任务可能需要人类数小时（Slides 第 39 页）。Slides 第 39 页展示**混合检查**：状态检查确认商品正确，过程检查发现发生了购买，最终 FAIL。讲者解释：只评结果会漏掉过程违规；长时程奖励稀疏，需要中间评分细则（逐字稿 [34:29.599]–[36:18.720]）。

- **Odysseys**（Jang*, Koh*, Fried & Salakhutdinov, 2026）：200 个真实网络任务，平均 6.1 条评分细则，主评估上限 100 步（Slides 第 40–41 页）。Slides 第 41 页的“棕榈泉婚礼旅行”例子有 8 条细则，7/8 满足得 0.875。
- **OSWorld 2.0**：108 个工作流，中位数人类时间 1.6 小时，平均 318 次智能体调用（Slides 第 42 页）。Slides 第 43 页的例子是构建 FreeCAD 支撑支架并导出匹配图纸的 STEP 模型，展示“文件存在但仍可能错误”。
- **CUA-World-Long**（Aggarwal et al., 2026）：200 个长任务，常需 >500 步，8 条质量准则，每个软件一个难任务（Slides 第 45 页）。

## 四、建模：VLM 从交错视觉历史中预测动作

Slides 第 47–55 页逐帧展示：**上下文在步骤 t 包含目标、截图 0、动作 0、截图 1、动作 1……截图 t**，模型输出动作 t（click/type/tool/stop）（Slides 第 54 页）。Slides 第 56 页进一步说明 tokenization：文本 → tokenizer + embeddings；截图 → vision encoder + projector；视觉 token 是连续 embedding，不是词表 ID；token 数量和编码器因系统而异。

**学习者解释**：这解释了为什么 CUA 本质上是 VLM（视觉语言模型）。它的“记忆”不是数据库，而是不断增长的、交错的视觉-动作序列。每一步的决策都以前面所有截图和动作为条件。

Slides 第 57 页列出前沿 CUA 的动作接口差异：GPT-6 Astra 用 Python/PyAutoGUI 或原生 computer tool，输出 `pyautogui.click(x, y)` 或 `computer_call: actions=[…]`；Fable/Opus 5 用原生 computer tool calls；Gemini 3.8 Flash 用归一化坐标 0–999 的函数调用；Qwen 3.8、Muse Spark、Kimi K3 各有 schema。讲者评论：“输出格式和 schema 因模型而异（可复现性是噩梦）”（Slides 第 57 页）。

关于动作空间，讲者说不同模型大体相似（click、scroll 等），但产生方式不同，可能是自回归输出或 XML（逐字稿 [52:48.240]–[53:23.200]）。关于为什么用截图而非 HTML，讲者认为截图简单得多，桌面没有容易获取的 HTML，且基于截图的表示“效果出奇地好”（逐字稿 [54:09.119]–[54:53.440]）。关于加载屏幕等边缘情况，常见做法是执行动作后 sleep 约 3 秒再截图（逐字稿 [55:50.160]–[56:33.119]）。

## 五、训练：预训练 → SFT → RL

Slides 第 59 页给出三阶段总览：

1. **预训练**：UI 元素和动作。boxes/labels/OCR → grounding；click/type/swipe → control（Slides 第 59–60 页）。数据来源包括 Mind2Web、AITW、OS-Atlas 等。Slides 第 60 页的例子是“CAR” ↔ 元素框/屏幕坐标，`element: bookCarTab`。
2. **后训练 SFT**：模仿有用轨迹。人类演示（目标 + 人类轨迹 → 行为克隆）和合成数据（智能体生成轨迹 → 行为克隆）。Slides 第 61 页以 MolmoWebMix 为例：36K 人类 + 105K 合成任务轨迹；AgentNet 发布 22,625 条任务轨迹、覆盖 3 个操作系统。Slides 第 62 页展示演示数据规模增长：从 2023 年 Mind2Web 2,350 任务到 2026 年 MolmoWebMix 36K 人类 + 105K 合成。
3. **后训练 RL**：Slides 第 63–64 页展示“生成经验 → 评分结果 → 改进策略”。Slides 第 65 页解释为什么需要模拟环境：真钱（重复尝试可能产生重复付费预订）、真人（预订会派车，探索影响他人）、无法干净重置（取消费用、时间不可恢复）。

**学习者解释**：SFT 学“下一步动作预测”，RL 则评估整条轨迹的结果。讲者提到 RL 阶段把成功率从约 0.5 提升到约 6 或更多（逐字稿 [01:11:46.400] 前后），并强调 RL 对长时程任务尤其重要，因为长任务的人类演示非常昂贵（逐字稿 [01:12:09.360]）。

Slides 第 66–69 页介绍 **CUA-Gym**：94 个 mock web 应用、约 32K 验证元组、110 个环境（94 mock web + 16 desktop），38% 跨应用任务。Slides 第 69 页给出数据规模消融：3,578 SFT 演示 → 在 10,858 验证元组上做 GSPO，OSWorld 性能从 62.2% 提升到 72.6%。

Slides 第 70–73 页介绍 **Gym-Anything**：200 个软件应用、3 个操作系统、10K+ 任务；创建智能体构建，独立审计验证证据；约 2,000 条成功 SFT 轨迹；平均 checklist 分数从 12.7 提升到 22.5（满分 100），完美 checklist 通过率从 1.6% 提升到 4.4%。

## 六、总结与剩余问题

Slides 第 75 页总结四点：

1. CUA 直接在 GUI 上操作，观察和行动与人类同一界面。
2. 评估应针对正确指标和行为层次：静态动作、端到端任务、长时程工作流测量方式不同。
3. 模型从交错视觉历史预测动作；CUA 是发出 GUI 动作的 VLM，有些也用代码和工具。
4. 预训练 → SFT → RL。

Slides 第 77–80 页列出剩余问题：**速度与成本**（长上下文昂贵，Game-TARS 稀疏思考、FDM-1 直接动作预测）；**个性化**（GUM 推断用户上下文，记忆需可修正，用户控制至关重要）；**基础设施与 UX**（Codex 后台计算机使用，需要同意、可见性和关闭开关）；**多智能体系统**（MACU 规划 → 并行 → 重规划，并行只有在协调保持正确性时才有帮助）。

讲者在结尾问答中补充了几个重要观点：无障碍表示（accessibility tree）对鲁棒性有价值，但纯截图表示更通用（逐字稿 [43:42.560]–[45:16.160]）；评分细则通常由 LLM 生成、人类验证（逐字稿 [45:38.720]–[46:42.720]）；不应在评估集上训练，但生成相似任务训练很常见（逐字稿 [47:46.000]–[48:07.200]）；坐标通常归一化到 0–1000，能较好迁移（逐字稿 [01:08:15.280]–[01:08:37.040]）。
