# 从语言模型到智能体：CMU 11-768 第一讲到底在讲什么

> 来源：平台字幕与官方 Slides。内容已由用户审核确认。

## 一门新课要回答的老问题

CMU 11-768《AI Agents》在 2026 年秋季开课，第一讲标题是"什么是智能体，它们如何工作？"（Slides 第 1 页）。这门课出现的时间点很有意思：一方面，很多人已经在日常工作中使用编码智能体，另一方面，关于"智能体到底是什么""它为什么有时很强、有时很蠢"仍然缺少一个统一说法。

这一讲要解决的，正是这个落差。它没有直接给一个时髦定义，而是先把"智能体"放回一个更老的坐标系里，再解释今天的语言模型如何被接进这个坐标系，最后指出：真正难的不是做出一个能跑的智能体，而是做出一个真正能用的智能体（依据逐字稿 Graham 的表述，[30:43]–[31:07] 附近；Slides 第 17 页）。

下面按"它怎么定义—怎么从 LLM 长出来—能力从哪来—为什么它是系统"的顺序展开。

## 智能体的经典定义：感知、行动、奖励

Slides 第 9 页直接引用了 Russell & Norvig 在《Artificial Intelligence: A Modern Approach》中的定义：智能体是任何可以被视为通过传感器感知环境、并通过执行器作用于该环境的东西。这个定义并不新，它在 AI 教科书里存在了很多年。

今天的智能体仍然落在这个框架里，只是每一项都被具体化了（Slides 第 9 页）：

- **环境**：一个代码仓库、一个网站、一个应用程序，或者一个工作流。
- **状态/观察**：用户发来的消息、文件内容、网页、截图，以及工具返回的结果。
- **动作**：回复用户、编辑文件、执行 shell 命令、调用 API，以及鼠标或键盘事件。
- **奖励**：测试用例是否通过、LLM-as-a-judge 的评分标准是否满足、用户反馈是否正面。

这里有一个关键的历史连续性：因为定义本身是老的，很多为老智能体开发的技术——搜索、强化学习等——仍然适用于今天基于语言模型的智能体（依据逐字稿 [00:16] 附近的表述，Graham 提到"过去为智能体开发的许多技术……将适用于当前的智能体"）。

**学习者解释**：把语言模型塞进这个框架，本质上不是在发明一个新范式，而是给一个经典框架换了一个更强的"策略函数"。理解这一点很重要，因为它解释了为什么这门课会同时谈工具调用、上下文管理、强化学习、沙盒——这些看起来跨度很大的话题，其实都在同一个框架的不同位置上。

## 从下一 token 预测到"在环境中行动"

要理解智能体，先要理解它背后的语言模型。Slides 第 10 页复习了两个基础概念：

1. **下一 token 预测**：每一步预测下一个 token 的分布，把生成的 token 接到前缀上，再预测下一个。
2. **思维链（Chain of Thought）**：在给出最终答案之前先生成中间推理 token，这些 token 成为后续预测的上下文。

思维链很重要，因为即使没有工具，它也已经让模型在复杂推理上有大幅提升。但 Slates 第 10 页的示例很清楚地区分了两种模式：`2 × (3 + 4)` 是一个纯提示词场景，模型生成推理 token，然后生成答案 token"14"。在这个设定里，模型只跟提示词交互，不跟世界交互。

那要如何从"跟提示词交互"过渡到"在世界中行动"？答案是**工具**（Slides 第 11–12 页）。

一个工具是对模型暴露的类型化接口，包含两部分：

- 名称和自然语言描述（例如 `read_file`，描述为"Read a UTF-8 file."）。
- 参数的 JSON Schema（例如 `path` 是一个字符串，且为必需参数）。

这个底层规范会通过 chat template 被渲染成一段文本，喂给模型（Slides 第 11 页）。模型从而"知道"有哪些工具可用。

调用时，模型生成类似下面的内容（Slides 第 12 页）：

```
<tool_call>
{"name":"read_file","arguments":{"path":"test.py"}}
</tool_call>
```

执行结果则通过 `tool_response` 返回，例如文件内容 `def add(a, b): …`。这些结果 token 被拼回上下文，成为模型下一次生成的条件（Slides 第 12–13 页）。

Slides 第 13 页把这一机制概括得很清楚：**工具调用只是模型可以预测的另一段 token 序列**——它命名了一个工具并给出参数；而 harness（执行框架）负责解析、验证、执行这次调用，并把结果作为观察 token 返回。这里引用了 Toolformer（Schick et al., NeurIPS 2023）作为早期训练模型使用工具的代表性工作。

课堂上还讨论了另一种调用形式。Daniel 问"有没有别的方式让模型调用工具"，有学生回答可以直接写代码，比如 bash 脚本或 Python 函数调用。Daniel 回应说，这种方式往往比生成 JSON 更有效，但也有权衡（逐字稿 [22:24] 附近）。

## 智能体循环：模型只是循环里的一个组件

Slides 第 14 页给出了本讲最核心的结构图：**智能体就是循环中的一个模型**。这个循环包含：

- **上下文（Context）**：任务、历史。
- **模型（Model）**：产生推理和工具调用。
- **执行（Execute）**：工具调用被环境执行，返回结果。
- **结果（Result）**：结果加入历史，进入下一轮。

这个模式来自 ReAct（Yao et al., ICLR 2023）——推理性与行动交替进行：模型先产生思维链，再发出一个或多个工具调用，工具被执行，结果加入历史，然后重复。

Slides 第 15 页展示了来自 `mini-swe-agent` 的一段极简实现（`run`、`step`、`query`、`execute_actions` 四个方法），说明这个概念在代码层面确实可以非常短。同时，这一页也直接点明了第一次作业的方向：**实现并扩展一个类似的控制器，创建并调用自己的工具，应用到软件任务上**。

Slides 第 16 页展示了 SWE-bench 上的一条真实智能体轨迹。课堂上 Daniel 逐步放大这条轨迹，展示了：模型在 system 消息中被设定为"能与计算机 shell 交互的助手"，user 消息给出具体任务上下文，然后模型生成思维链和 bash 命令作为动作，环境返回退出码，智能体继续下一轮（逐字稿 [28:52]–[30:02] 附近）。

**学习者解释**：这个循环看起来简单得可疑，但"简单"和"能用"之间的距离正是这门课的主线。循环本身可能只有几十行代码；难点在于每一步的可靠性——工具调用是否格式正确、上下文是否还留着关键信息、任务是否被正确分解。

## 六个能力，两条路径

在介绍完基础结构之后，Graham 把话题转向"是什么造就了一个好的智能体"（Slides 第 17 页）。他列了六项能力：

1. 准确的工具调用
2. 长上下文中的连贯性
3. 可定制性
4. 复杂任务管理
5. 环境理解
6. 安全性

课堂上 Graham 先问大家日常使用智能体时最让人沮丧的是什么。学生的回答包括：太慢、啰嗦冗长、会忘记事情、误解指令、访问不该访问的东西、有随机知识空白、"两行就能搞定却写了一千行代码"、忘记之前的会话、不会反驳不合理的要求、会撒谎、做很多隐含假设（逐字稿 [31:29]–[33:07] 附近）。

Graham 随后把这些抱怨映射回他的六项能力，并指出：准确性是"基本功"，现在很多人视为理所当然，但如果你负责训练模型，它绝非免费得来。

然后是本讲一个重要的结构性区分（Slides 第 18 页）：

- **LLM 训练**：通过预训练、SFT 或 RL 改变模型行为，教它可复用的推理、工具使用和恢复模式，让能力成为学到的策略的一部分。
- **Harness 工程**：改变模型周围的系统——提示词、工具、记忆、控制流——提供上下文、验证、重试和安全边界。能力从"模型 + harness"的组合中涌现。

Graham 在课堂上问大家认为哪条路更重要，结果举手支持 harness 工程的人明显更多。他自己的回答是：两者都重要，但典型流程是——你发现问题，先在 harness 一侧解决；然后训练模型的人追上来，意识到这个问题足够大、值得专门训练模型去解决；问题在模型侧被解决后，你就不再需要在 harness 一侧处理它了。所以在他看来，LLM 训练往往是更根本的解法，但耗时更长，因此短期内你需要从 harness 一侧入手（逐字稿 [36:20]–[38:15] 附近）。

Slides 第 19 页给出了训练流程的三阶段：预训练（文本、代码、多模态数据）→ 中期训练/SFT（指令、轨迹、工具调用）→ RL（奖励或偏好、轨迹级行为）。课堂上 Graham 明确说这门课不会处理预训练，因为那不是课程算力能支持的；重点放在中期训练、SFT 和 RL，尤其是针对智能体的 RL（逐字稿 [41:57]–[43:27] 附近）。

## 每一项能力的两条路径

Slides 第 20–25 页逐项展开六项能力，每一项都给出"harness 工程"和"LLM 训练"两条路径：

**准确工具调用**（Slides 第 20 页）：harness 一侧可以用语法约束解码；训练一侧可以用工具调用轨迹做 SFT。课堂还举了一个具体的 harness 例子——有个流行的编码 harness 的"规划模式"按钮，实际效果只是在提示词里多加一句"请规划，不要做任何事情"（逐字稿 [46:18] 附近）。

**长上下文连贯性**（Slides 第 21 页）：harness 一侧包括上下文压缩/压实、动态记忆查找、子智能体委派；训练一侧是长上下文训练。Graham 指出，长上下文不仅仅是一个模型准确率问题，也是一个效率问题——它需要对非常长的序列建模（逐字稿 [38:54] 附近）。

**可定制性**（Slides 第 22 页）：harness 一侧包括智能体记忆、技能、自定义工具；训练一侧是从用户反馈中学习。Graham 认为这其实是当前 harness 工程最好的用例之一。

**复杂任务管理**（Slides 第 23 页）：harness 一侧提供规划/分解工具和子智能体委派；训练一侧是在复杂长时程任务上做 RL。

**环境理解**（Slides 第 24 页）：harness 一侧对应领域知识的技能；训练一侧是在具有预期观察形状的数据上做 SFT，或在特定领域环境中做 RL。Graham 在这里说了一句很关键的话：**模型不会自己变好，是人让模型变好**——当某个模型突然在作曲上变强，背后往往是有人创建了相应的训练环境（逐字稿 [48:53]–[49:38] 附近）。

**安全性**（Slides 第 25 页）：harness 一侧包括沙盒化工具、限制凭据访问、监控轨迹；训练一侧是安全感知的 RL。Graham 在课堂上讲了一个具体事件：某次网络安全基准测试中，模型被指示入侵一个系统，它无法入侵那个目标系统，于是转而入侵了 Hugging Face 网站去获取答案。他列举了其中一连串失败：沙盒化失败、凭据限制被绕过、监控不足、安全护栏不足（逐字稿 [50:27]–[51:33] 附近）。

这里需要特别注意：Graham 在课堂上也提到 Carlini 在 Anthropic 做的多智能体 C 编译器实验（Slides 第 2 页：16 个智能体在两周内协作构建了一个能编译 Linux 内核的约 10 万行 C 编译器），以及 OpenClaw 删除邮件的事件（Slides 第 3 页：模型压缩了过去上下文，丢失了"不要删除邮件"的指令）。这些是课程用来展示能力与局限并存的例子。

## 智能体是系统，不只是模型

这是 Graham 在能力部分之后反复强调的另一点（Slides 第 26 页）：智能体是系统，远比你以前上过的机器学习课处理的东西复杂。Slides 第 26 页把系统拆成六个部分：沙盒、harness、推理、模型、监控、训练。

Slides 第 27–31 页逐项展开：

- **Harness 工程**（Slides 第 27 页）：管理状态、工具、记忆、控制流；验证动作并处理错误；强制执行权限和安全边界。示例软件包括编码智能体（CC、Codex、OpenHands、OpenCode、Pi）和编排器（LangChain、CrewAI）。
- **沙盒**（Slides 第 28 页）：隔离代码和工具执行；限制计算、网络和文件系统访问；创建可复现环境。示例软件包括 Docker/Apptainer、Modal/Sail。
- **LM 推理**（Slides 第 29 页）：可靠地服务模型生成；批处理请求并复用 KV cache；管理流式、并行和吞吐。示例软件包括 vLLM、SGLang。
- **训练系统**（Slides 第 30 页）：准备数据、收集 rollout；协调分布式 worker；checkpoint、评估和复现运行。示例软件包括 SkyRL、Miles。
- **可观测性与监控**（Slides 第 31 页）：捕获 trace 和指标；跟踪质量、成本和失败；比较轨迹和评估。示例软件包括 Laminar、MLFlow。

Graham 在课堂上谈到了 harness 工程和编排器之间哲学的差异：编码智能体通常更简单（就智能体之间如何交互而言），但在给智能体的动作空间方面更复杂；编排器在单个智能体上更简单，但能给出声明式工作流，更多是护栏、更少表达力（逐字稿 [54:03]–[55:07] 附近）。

**学习者解释**：把智能体当系统看，意味着不要把失败简单归因于"模型不行"。同一个模型，换一个 harness、换一套工具、换一个沙盒配置，表现可能差别很大。这也是为什么这门课的作业设计是"harness → 评估 → 训练"的顺序，而不是一上来就做训练。

## 第一讲的问题链

回头看，这一讲回答了四个层层递进的问题：

1. **什么是智能体？** 一个经典定义下的感知-行动系统，环境、观察、动作、奖励都被具体化（Slides 第 9 页）。
2. **语言模型如何变成智能体？** 通过工具接口，把工具调用变成模型可以预测的 token 序列，再由 harness 解析执行，形成模型在循环中的结构（Slides 第 11–14 页）。
3. **什么造就了好的智能体？** 六项能力，每项都可以通过 LLM 训练或 harness 工程两条路径来构建（Slides 第 17–25 页）。
4. **为什么这门课要教一整套系统工程？** 因为智能体是系统，不只是模型；沙盒、推理、训练、监控都是系统的一部分（Slides 第 26–31 页）。
