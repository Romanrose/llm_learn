## 一、学习目标

学完本讲，应能：

1. 说明智能体在没有重新训练的前提下改进自身的三条路径：上下文窗口、外部产物、模型权重更新，并比较三者的代价与收益（Slides 第 3 页）。
2. 区分四类“值得保留的经验”：episode（完整轨迹）、fact（事实）、skill（技能），以及 memory 与 skill 的交集（Slides 第 4–5 页）。
3. 说明人类编写技能与从经验中归纳技能这两条路径的分工与负担（Slides 第 6 页）。
4. 描述 Agent Skills 的包结构与“渐进式披露”三层加载机制（Slides 第 9–11 页）。
5. 说明外部记忆的读写方式，以及记忆冲突的四种处理：ADD / UPDATE / DELETE / NOOP（Slides 第 17–18 页）。
6. 说明 Reflexion 式反馈与相似轨迹条件化如何改善后续尝试（Slides 第 19–20 页）。
7. 比较文本技能与代码技能作为技能表示的优势与缺陷，并解释代码技能为何更可测、更高效也更脆弱（Slides 第 29、33、36 页）。
8. 说明技能生命周期：学习（judge → induce → admit）、使用（retrieve → act）、维护（add → repair → retire）（Slides 第 25、37 页）。

## 二、概念主线

本讲的中心问题是：**智能体如何在不从头开始的前提下变得更好**（Slides 第 1 页）。

主线可以概括为三步推进：

- **先定位经验存放的位置。** 上一讲讨论上下文窗口内保留什么；本讲讨论把东西放到窗口之外，即数据库、文件系统等外部产物；第三种是对模型权重做 SFT 或强化学习，留待后续课程（Slides 第 3 页）。外部产物可检查、可编辑、可检索、可跨模型移植，但必须被“归纳、选择、维护”。
- **再区分经验的粒度。** Episode 保真度最高但最贵；fact 是可在未来复用的知识片段；skill 是可复用的“如何行动”的知识，可用代码、文本或两者表示（Slides 第 4 页）。
- **最后讨论技能从何而来、如何被使用和淘汰。** 技能可以由人编写（编码偏好与组织政策），也可以由智能体从自身情节中归纳。两者互补：前者来源明确、质量可控但耗时；后者可自动化，但可能带噪声并产生意外后果（Slides 第 6 页）。

一个反复出现的张力贯穿全讲：**多少行为留给模型解释，多少行为固定在产物里**（Slides 第 36 页）。

## 三、关键机制

### 3.1 共享任务结构与三类经验

课程用购物网站任务说明“共享结构”：任务 1“把 Sony 耳机加入愿望清单”与任务 2“查询无线键盘价格区间”，都包含“进入商店 → 找到搜索框 → 填入查询 → 点击搜索”这一共享过程，区别只在后续的 TASK-SPECIFIC FINISH（Slides 第 2 页）。由此提出三问：表示该用文本还是代码？如何从经验中归纳？技能何时被检索、检查、修订或遗忘？

三类经验的典型例子（Slides 第 4 页）：

- Episode：完整轨迹，每一个观察和动作；“如果确切的商品、价格或序列会再次起作用”时有用。
- Fact：“这家商店只在商品页显示价格”；当事实会在未来任务中复现或需要被更新时有用。
- Skill：`填搜索框 → 点击搜索 → 打开一个结果`；当后续任务会重复同一模式时有用。

### 3.2 人类编写的技能与 Agent Skills 标准

课程用例：同一段请求被反复输入每个 PR 对话——用 Black（88 字符行宽）、Ruff（自定义规则）、公共 API 类型提示、Google 风格 docstring、所有新函数用 Pytest。当你想按固定规范反复做某事时，就把这段指导存成技能（Slides 第 8 页）。

技能的包结构（Slides 第 9 页）：

```
python-review/
├── SKILL.md          # 必需：指令 + 元数据
├── scripts/          # 可选：可执行代码
├── references/       # 可选：文档
└── assets/           # 可选：模板、资源
```

`SKILL.md` 开头的 YAML 元数据含 `name`、`description`，示例中还出现 `triggers` 列表。description 的写法是给出“何时该应用该技能”的指导，例如用户说 “review Python code”“check Python style”“lint Python” 或提到 code quality 时使用。

**渐进式披露**分三层（Slides 第 9 页表）：

| 层级 | 文件 | 进入上下文窗口的时机 |
|---|---|---|
| 1 | SKILL.md metadata（YAML） | 总是加载 |
| 2 | SKILL.md 正文（Markdown） | 智能体触发该技能时加载 |
| 3 | 附带文件（文本、脚本、数据） | 智能体读取这些文件时加载 |

系统提示中始终只有技能索引（名称与描述）。Slides 第 10 页给出 HermesAgent 的提示片段，要求模型“回复前扫描技能列表，若匹配或部分相关就必须用 `skill_view(name)` 加载并遵循其指令”，只有确实无关时才可不加载。Slides 第 11 页展示四轮中进入上下文的内容：第 1 轮只有索引（Hermes 中约 3k token），第 2 轮 `skill_view('python-review')` 把正文作为工具结果带入，第 3 轮终端运行脚本只把输出带入——**代码本身从不进入上下文**，第 4 轮按需读取 references 中的文档风格规则。

### 3.3 技能的两个来源与维护案例

技能包的来源有三类（Slides 第 14 页）：随 harness 捆绑；由人安装或编写（放入 `.agents/skills/` 或从仓库、注册表安装）；由智能体自己创建（Hermes 的 `skill_manage` 可创建、修补、删除；OpenHands 有 `/skill-creator` 从刚完成的工作流起草）。

OpenHands 的建议是：**不要从零开始写技能**；在智能体完成一个你想重复的工作流之后立刻创建，然后测试几次。

代码审查技能的维护案例（Slides 第 15 页）：维护 review 技能 → 记录每次运行 → 给每次运行打分 → 找出反复出现的失败 → 修补 SKILL.md。OpenHands 在自己的仓库上对每个 PR 运行该技能，PR 合并后由模型评判者统计有多少建议被人保留；模型分析失败记录后指出两类反复问题——忽视仓库约定（约 15%）和批准带严重缺陷的 PR（约 10%）；再由同一模型起草 SKILL.md 更新：发现严重问题时要求改动，发布建议前先对照仓库检查。

### 3.4 外部记忆与冲突处理

MemGPT 式设计把记忆分层：不更新的系统指令、从外部记忆拉取内容的工作上下文，读写都由模型发出的函数调用控制；另设单独的存储保存实际消息（Slides 第 17 页）。逐字稿中的例子是用户提到 Six Flags，系统发出工具调用在过往交互中检索相关提及，把结果放进工作上下文，模型便能据此作答。

Mem0 式流程则解决“记忆会变”的问题：消息到达后先由语言模型抽取候选记忆，用基于嵌入的检索器在数据库中找到相关的前 K 条，再由语言模型判断每条新记忆属于哪种情况（Slides 第 18 页）：

- **ADD**：尚无相似内容被存储；
- **UPDATE**：消息改变了已有记忆；
- **DELETE**：消息否定了已有记忆；
- **NOOP**：消息已被存储，或不相关。

课程在讨论中也把它与上一讲的 Delta 类比：线性注意力只能追加值，Delta 能检索并改写为特定查询存储的向量，这里的文本事实更新是同一目标的不同实现。

### 3.5 轨迹反馈与相似轨迹条件化

Reflexion（Slides 第 19 页）的循环是：尝试 → 评估者预测奖励 → 生成自然语言反思 → 重试同一任务。课程给的具体例子：问题是“1776 年 10 月 28 日在纽约白原附近进行的一系列战役是什么？”第一次回答 `Finish[Battle of White Plains]` 错误；生成的反馈指出“问题问的是一系列战役，我只给了一场战役的名字……我会确保提供更多上下文，例如战役的名称”；第二次回答 `Finish[The New York and New Jersey campaign]` 正确。

相似轨迹条件化（Slides 第 20 页，ExpeL 等）的三个要点：存储的是完整轨迹，成功与失败都存，有时在入库前被改写和标注；轨迹池可以离线收集、在线增长或预先手写；使用时用文本嵌入检索与新任务最相似的运行，作为 few-shot 示例放入上下文。

### 3.6 归纳技能：从文本工作流到代码技能

Slides 第 22 页把技能定义为任务中可复用的片段：搜索商品被表示为“`fill('element145', {query})` → `click('element147')`”，并配一段自然语言说明；价格区间报告则复用同一搜索过程再加上读取价格和汇报的步骤。这里也点出问题所在：**元素 ID 一变技能就失效**。

在线学习评估设置（Slides 第 24 页）：评估任务顺序到达，成功任务在下个任务到来前更新记忆，指标是所有已见任务的累计成功率；技能记忆随评估流增长，例如“搜索商品”“把商品加入愿望清单”“报告价格区间”。

技能生命周期（Slides 第 25 页）：

- LEARN：episode → judge → induce → admit → memory
- USE：memory → select/retrieve → act → outcomes
- MAINTAIN：outcomes → add → repair → retire → memory

Agent Workflow Memory（Slides 第 26–28 页）的做法：给出一条查询“告诉我我们商店迄今收到的、提到 satisfied 这个词的评论数量”及对应动作序列，评判模型先判断最终状态是否可能正确，若通过则用少样本提示让语言模型归纳出工作流，把非固定元素写成描述性变量名：

```
Task: Search for reviews matching "{term}"
# To find reviews for {term}, I will search for "{term}" in the reviews page
click("All reviews")
fill(757, "{term}")
click("Search")
```

Slides 第 27 页的归纳提示词要求：找出多个任务中重复的动作子集，每个工作流是常用的子例程，不得生成相似或重叠的工作流，每个工作流至少两步，用描述性变量名表示非固定元素。

技能作为文本与技能作为代码（Slides 第 29 页）对照：

- 文本 + 示例（AWM）：灵活，是智能体解释并适配当前页面的提示；但手工，智能体仍要自己发出每个底层动作。
- 代码（ASI）：

```python
def search_product(search_box_id: str, query: str):
    """Search for a product using the search box. ..."""
    click(search_box_id)
    fill(search_box_id, query)
    keyboard_press('Enter')
```

优点是可作为工具使用、可测试、可分层（技能调用技能）、高效（一次调用替代多步模型生成）；缺点是死板——即使页面已变，它也严格照做。

代码技能的归纳与准入（Slides 第 30–31 页）：从 episode 归纳出 `search_reviews(search_box_id, search_button_id, search_term)` 和 `open_marketing_reviews()` 等函数，评判模型检查最终状态与技能是否被使用，并且可以**执行生成的抽象代码**再评判结果。SkillWeaver 用伪代码描述该循环：`candidates = propose_skill(task)`、`episode = practice(candidates, task)`、若奖励模型通过则 `memory.add(candidate)`，否则 `revise(candidate, task)`。Slides 第 31 页给出一个真实 lint 例子：`identify_pill(page, imprint="M366", color="White")` 中 `color` 参数被定义却从未使用，于是补上使用 color 的分支。

压缩效应（Slides 第 32–33 页）：无记忆的基线是 50 步上限；有代码技能时 4 步完成。在五个 WebArena 站点上平均，checkpoint 到达率从 41.3（无记忆）到 59.5（文本技能）再到 80.2（代码技能），每任务步数从 24.5 降到 20.6 再降到 15.0。

泛化失败案例（Slides 第 34 页）：在一个网站归纳的技能拿到 Target 上评估——技能假设排序是点击一个下拉菜单，而 Target 的排序打开的是侧边栏，因此失败。PolySkill（Slides 第 35 页）的应对是用代码抽象：组合逻辑针对抽象方法写一次，每个网站只实现原始的浏览器动作。

表示方式的后果总结（Slides 第 36 页）：检索到的 episode 保留具体行为但长且难迁移；文本技能提供灵活指导但不提升效率；代码技能可执行、可组合、高效但可能脆弱。

### 3.7 从失败中学习、评判者质量与过度检索

ReasoningBank 的失败案例（Slides 第 38 页）：任务要求给出 Sony 蓝牙耳机的完整名称及价格区间，智能体搜索 “Bluetooth headphones Sony” 得到 5,578 条跨部门结果、每页 12 条，一路翻页直到步数上限，什么都没发给用户。归纳出的策略是：收紧查询、调整每页显示数量、使用侧边栏的类别过滤器。

不同记忆类型对失败的受益不同（Slides 第 39 页）：在归纳**策略**时失败帮助很大（ReasoningBank）；对轨迹（Synapse）或工作流（AWM）帮助较小——课程提出疑问“展示不该做什么的示范？”是否有效。

评判者准确率的影响（Slides 第 40 页）：用模拟评判者（从 oracle 到抛硬币，以固定概率翻转真标签）替代真实评判者后，性能随评判准确率变化而下降，但在相当宽的准确率区间内记忆仍带来改进。

过度检索的代价（Slides 第 41 页）：检索更多经验反而可能让性能下降（ReasoningBank 的例子；SkillsBench 对人类策划的技能也发现同样现象）。两种解释：部分经验确实无关（记忆本身的局限）；智能体条件化能力有限（可能因上下文变长而分心）。

记忆整合（Slides 第 42 页）：TroVE 会丢弃使用次数少于 ½·log₁₀(n) 的函数，n 是迄今见过的示例数。

训练归纳器（Slides 第 43 页）：技能的价值是延迟兑现的——任务 1 的奖励只说明任务是否成功，不说明保存解法是否有价值，只有后续任务才能体现。因此把后续任务放进同一个训练样本：两个相关任务在一次 rollout 中（SAGE），或一条长轨迹（AgeMem）。奖励形式可为 `r₁ + 1[both succeed] · 1[task 2 reused its skill]`。幻灯片给出的数字是（AppWorld test-normal，Qwen2.5-32B）：仅看结果 55.4，两个任务都成功 56.6，成功复用技能 60.7。

### 3.8 技能所有权与人的介入

Slides 第 45 页给出决策分工表：当政策已知、正确性是规范性的或高风险、需要上下文判断的罕见例外、需要问责归属时，人的努力更有价值；当技能必须通过交互发现、结果是可执行且廉价可测的、路由重复并产生反馈、漂移在结果中可见且可修复时，智能体的努力更有价值。

## 四、公式与数值的假设和符号

本讲的定量内容以对比数字为主，形式化程度不高，需注意：

- **累计成功率**（Slides 第 24 页）：在任务顺序到达的设置下，评估的是“迄今见过的所有任务”的成功率，而非单个任务的成功率。这意味着后出现的任务与先出现的任务被同等计入，且记忆中已积累的技能会影响后续任务。
- **TroVE 的丢弃阈值**：`使用次数 < ½·log₁₀(n)`，n 为迄今见过的示例数（Slides 第 42 页）。符号含义在幻灯片上明确，但阈值的推导依据未在提取文本中给出，**待核**。
- **SAGE 的奖励表达式**：`r₁ + 1[both succeed] · 1[task 2 reused its skill]`（Slides 第 43 页）。指示函数表示条件成立取 1。各项权重未在提取文本中说明，**待核**。
- Slides 第 33 页的三组数字（41.3 / 59.5 / 80.2 与 24.5 / 20.6 / 15.0）是五个 WebArena 站点上的平均，比较条件是“具有重复结构的 web 任务”，不应当外推到所有任务分布。
- Slides 第 13 页的 33.9% → 50.5% 是 SkillsBench 主实验的平均通过率变化；同时明确“87 个任务中有 13 个技能仍有损害”。这些数字只在该基准、该策划技能组合下成立。
- 逐字稿提到 Hermes 系统提示中技能描述总长约 3,000 token，与 Slides 第 11 页的“≈3k tokens in Hermes”一致。

## 五、常见误区

1. **以为有长上下文就不需要外部记忆。** 课程明确说，即便有百万级 token 上下文，跨多个任务仍会超出，且你希望从过去任务中保留某些东西（Slides 第 3 页；逐字稿同段论述）。
2. **把技能等同于工具或函数。** 技能可以是文本指导，也可以是代码；文本技能灵活但效率不变，代码技能高效但死板（Slides 第 36 页）。
3. **以为技能总是有益。** Slides 第 13 页指出技能在 87 个任务中的 13 个上仍造成损害，“技能可能取代更好的默认策略”；Slides 第 41 页指出检索更多经验可能导致性能下降。
4. **把失败经验一律当成有用的记忆。** 失败对归纳策略帮助大，对轨迹或工作流帮助较小（Slides 第 39 页）。
5. **假定元素 ID 稳定的技能可以跨页面或跨站点复用。** 元素编号变化或界面结构不同都会使技能失效（Slides 第 22、34 页）。
6. **忽视触发器由模型决定。** 逐字稿中的问答指出，触发与否完全取决于模型的工具调用，取决于模型能力和描述写法，因此需要对技能做评估。
7. **以为技能越多越好。** 逐字稿与 Slides 第 41、42 页都指向：无关技能会分散注意力，且可以通过使用频率剔除。
8. **把记忆当作只增不减的日志。** 记忆需要 UPDATE 与 DELETE 来处理冲突（Slides 第 18 页），也需要 repair 与 retire（Slides 第 25 页）。

## 六、复习问题

1. 上下文窗口、外部产物、模型权重更新三条路径各自的优势与代价是什么？为什么外部产物更容易在人与系统之间充当接口？（Slides 第 3 页）
