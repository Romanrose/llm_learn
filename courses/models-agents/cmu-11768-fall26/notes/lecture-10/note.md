完成本讲后，你应当能够：

1. **定义深度研究（Deep Research, DR）智能体**：说明它与“单次检索 + 短答”QA 系统的区别，并用 Slides 第 3–11 页的“办公号码”与“文献综述”两个对照例子解释“一次搜索够用”与“需要多轮搜索”的任务差异。
2. **刻画从经典 QA 到 DR 基准的四个演进维度**：搜索复杂度、领域专业性、答案质量、证据支撑（Slides 第 19–20、29–30、33–34、45–46、50 页反复出现的四栏框架）。
3. **说明主流 DR 基准各自“补上了哪一维度”**：BrowseComp / BrowseComp-Plus（搜索复杂度）、MedBrowseComp / FinSearchComp / ScholarSearch / AutoResearchBench（领域专业）、ScholarQABench / ResearchQA（答案质量与 rubric）、DeepResearch Bench（引用支撑）（Slides 第 21–50 页）。
4. **解释为什么长文答案不能用“与标准答案的相似度”评价**，并说明 rubric 加权评分的机制与“rubric 本身也要被审计”的风险（Slides 第 35–44 页）。
5. **描述 DR 智能体的推理循环与训练配方**：推理 → 工具调用 → 执行 → 回填上下文 → 继续推理 → 带引用作答（Slides 第 52–57 页）；mid-training / SFT / RL 三阶段及其数据来源（Slides 第 58–83 页）。
6. **区分 RLVR 与 GRPO 及 DR Tulu 的 evolving rubrics**：为什么短答可验证奖励不足以支撑开放式长文（Slides 第 74–98 页）。
7. **说明检索器为什么需要“读懂智能体的信息需求”**：AgentIR 的 reasoning-aware 输入、DR-Synth 的中间步骤标注，以及消融实验的结论（Slides 第 100–123 页）。

## 二、概念主线

本讲用一条清晰的因果链组织内容：**任务变难 → 评价必须变 → 训练信号必须变 → 检索必须变**。

- **任务侧**：简单事实问句只需一次搜索，答案即证据（Slides 第 3–5 页）。而“AI 智能体能否像人类专家一样综述科学文献”这类问题，没有任何单一结果能定论，需要规划、多轮搜索、反思、再搜索（Slides 第 6–11 页）。该页给出的推理轨迹是：先制定计划（区分“基准分数”与“与人类专家的直接比较”）→ 搜索（找到 Result A 基准、Result B 专家评估）→ 反思（两项研究的比较对象不同，高分不等于人类专家水平）→ 再搜索（任务与领域、评估协议）→ 给出带保留结论的最终答案。
- **评价侧**：经典 QA 基准（如 Natural Questions 的 “who wrote the score for the force awakens”）是简单查找、通用领域、短答、证据使用不明确（Slides 第 14–18 页）。DR 基准逐项替换这四个属性。
- **训练侧**：从教师轨迹模仿（SFT），到用自身 rollout 得到反馈（RL）；短答用精确匹配奖励，长文则需要覆盖、相关性、事实性与“被引来源是否支持该断言”的多维奖励（Slides 第 84–98 页）。
- **检索侧**：标准检索器只接收最新 query，丢弃推理上下文；AgentIR 主张把当前推理 τ_t 与 query q_t 一起送入检索器，并用 DR-Synth 为中间检索步骤构造局部相关性标签（Slides 第 105–123 页）。

## 三、关键机制、公式、假设与符号

> 以下公式均直接来自 Slides 文本提取；若公式排版在 PDF 中另有细节（如求和范围、期望符号位置），以官方 PDF 为准（待核）。

### 3.1 从经典 QA 到 DR 基准的四维框架（Slides 第 19–20 页）

| 维度 | 经典 QA | DR 基准的改进 |
|---|---|---|
| 搜索复杂度 | 简单查找，一次搜索 | 需多跳、难找的答案 |
| 领域专业性 | 通用网页问题 | 医学、金融、学术等专家知识 |
| 答案质量 | 短答匹配 | 多文档综合的长文报告 |
| 证据支撑 | 证据使用不明确 | 引用是否支持断言 |

### 3.2 BrowseComp 的题目构造（Slides 第 21–25 页）

构造流程：从已知答案（人物/事件/文物）出发 → 隐去名称，把事实线索组合成一个复杂问题 → 用 LM + 搜索验证难度（模型应当失败；5 次 Google 搜索不足以解决；人类 10 分钟后仍觉得困难；在子集上人工核验）。共 1,266 道人类撰写题目。示例（Slides 第 22 页，五个线索）：某虚构角色偶尔打破第四面墙、背景涉及无私苦行者的帮助、以幽默著称、其电视剧在 1960–1980 年代播出且少于 50 集，参考答案 Plastic Man。结果（Slides 第 24 页）：GPT-4o 0.6%，GPT-4o + browsing 1.9%，GPT-4.5 0.9%，OpenAI o1 (medium) 9.9%，Deep Research（*针对 BrowseComp 风格任务训练过）51.5%，人类参考匹配 25.3%（1,266 题中尝试了 1,255 题）。

### 3.3 BrowseComp-Plus：固定语料（Slides 第 27–28 页）

把 BrowseComp 的“题 + 已知答案”对的证据页收集并人工核验（标注支撑片段、逐条核对线索、标注答案文档），再加入“接近但缺一个线索”的困难负例，冻结为 830 题 / 100,195 文档的离线基准，使不同系统可在同一语料上受控比较。

### 3.4 上下文/交互轮数扩展（Slides 第 26 页）

Tongyi DeepResearch 在 BrowseComp 上的曲线显示：上下文长度 8K→128K 时准确率持续上升；插图中训练轨迹里超过 20% 的 SFT 样本含 10 次以上工具调用；评估上限为每任务 128 次工具调用。Slides 第 83 页补充：奖励随训练步数单调上升而熵相对稳定；不同上下文上限（32K/48K/64K）的响应长度趋势不同，且报告未单独分离各训练阶段的贡献（该页明确注明“These are RL training curves; the report does not isolate each training stage”）。

### 3.5 Rubric 加权评分（Slides 第 39–41 页）

$$S_c=\frac{\sum_i w_i b_i}{\sum_i w_i}$$

- 符号：$c$ 为候选答案；$i$ 为 rubric 条目；$w_i$ 为条目权重；$b_i\in\{0,1\}$ 为该条目是否被满足；分母为权重和。
- 例子（Slides 第 39 页）：问题“AI 智能体能否像人类专家一样综述科学文献？”；条目 1“报告了与人类专家的直接比较”权重 2，满足（1）；条目 2“按任务与领域限定结论”权重 1，未满足（0）。则 $S_c=(2\times1+1\times0)/3=0.67$。候选答案“OpenScholar 在 70% 的专家比较中胜出，且适用于所有领域”正是被第二条扣分的“过度推广”。
- **假设**：条目可独立二值判定、权重可事先给定、判定者（人/LM）可靠。Slides 第 42 页给出判定一致性证据：专家–LM 79%，专家–专家 80%（12 个问题、2 个系统、每答案 2 位专家评分者）。

### 3.6 相似度指标会误排序（Slides 第 38 页）

在 109 组专家比较中，以“更高相似度是否选中专家更偏好的答案”衡量偏好准确率：随机 50%，ROUGE 58%，BERTScore 57%，BLEURT 62%。Slides 第 35–37 页进一步说明：一个与参考答案高度相似但把“领域间等价性未被证明”改成“已被证明”的摘要，与正确答案极为接近却是错误的——所以“像标准答案”不等于“对”。

### 3.7 Rubric 自身会错（Slides 第 44 页）

ResearchQA 的专家审计发现：15% 的参数量化 rubric 条目属于空洞、错误或不清；典型失效包括引用不存在的论文、只是复述问题、含糊到让貌似合理的错误通过。对策是“先把标准锚定到来源，再审计其相关性与可验证性”，并以 DeepResearch Bench II 的“专家报告 + 人工修订 + 专家复核”为例。

### 3.8 引用支撑判定（Slides 第 47–49 页）

DeepResearch Bench 的 FACT 流程：抽取“断言 + URL” → 阅读被引页面 → 判定支持与否。例子：“OpenScholar 曾与人类答案比较过 [1]”判为支持；“OpenScholar 在所有领域都与专家持平 [1]”判为不支持（原文只在小样本研究问题上做了专家比较，未测试所有领域）。引用准确率 = 1/2 = 50%，有效引用 = 1 个被支持的配对。

### 3.9 智能体推理循环（Slides 第 52–57 页）

六步：① 生成推理 `<think> Find expert comparisons </think>`；② 生成工具调用 `<tool> search("expert comparisons") </tool>`；③ 执行搜索；④ 把工具输出（[1] OpenScholar、[2] DR Tulu）追加进上下文；⑤ 基于检索文本继续推理“检查被测试的任务”；⑥ 生成带引用的答案 `<answer> ... [1,2] ... </answer>`。图中约定：蓝色为模型生成文本，灰色为用户输入与工具输出。

### 3.10 训练配方（Slides 第 58–60、68–73 页）

三个阶段：mid-training（用通用预训练数据 + 智能体轨迹做持续预训练，下一 token 预测，得到 agent-ready 基座）→ SFT（输入 + 答案 + 教师轨迹，模仿成功示范）→ RL（输入 + 答案 + 策略自身 rollout，从反馈中学习）。SFT 数据流程（Slides 第 68 页）：对“答案正确 + 格式合法”“答案错误但格式合法”“答案正确但格式非法”的教师轨迹做过滤，只保留“答案正确 + 格式合法 + 轨迹连贯”者。Slides 第 73 页给出 mid-training 的价值：相同下游 SFT-B 数据下，AgentFounder 基座在 BrowseComp-en（39.9 vs 28.6）、BrowseComp-zh（43.3 vs 35.6）、GAIA（72.8 vs 71.8）上优于 Qwen3 基座。

### 3.11 RLVR 与 GRPO（Slides 第 74–79 页）

- **RLVR**：给定问题 $x$ 与已知答案 $a_{gold}$，策略 $\pi_\theta$ 采样搜索轨迹 $y_1,y_2,y_3$，验证最终答案 $r_i=\mathrm{EM}(a_i,a_{gold})$，得到奖励（例：0, 1, 1）后更新策略。Slides 注明 CMU 例子与奖励为示意性（“CMU examples and rewards are illustrative”）。
- **GRPO**：对同一问题 $x$ 采样一组尝试 $y_1,\dots,y_G$，在组内比较——低于组均值者降低概率，高于组均值者提高概率。目标函数（Slides 第 77 页）：
$$J(\theta)=\mathbb{E}\Big[\min\big(\rho\hat{A},\ \mathrm{clip}(\rho,1-\epsilon,1+\epsilon)\hat{A}\big)-\beta D_{\mathrm{KL}}\Big]$$
符号：$\rho$ 为概率比（新策略与旧策略之比）；$\hat{A}$ 为相对奖励（组内标准化）；$\epsilon$ 为裁剪范围，限制单次更新幅度；$\beta$ 为 KL 惩罚系数，使策略靠近参考模型。**假设**：组内奖励可比，且相对优势是有效学习信号。
- **异步 rollout**（Slides 第 80–82 页）：A/B/C 三条 rollout 各自完成“LM 与工具交替 → 答案 → 奖励”，凑成带奖励的批次后再做策略更新；附加效率手段包括缓存工具结果、稳健 API 处理、后台任务筛选。

### 3.12 DR Tulu 的 evolving rubrics（Slides 第 86–98 页）

奖励：
$$r_i=\frac{\sum_k w_k\,\mathrm{Judge}(c_k,y_i)}{\sum_k w_k}$$
- 符号：$y_i$ 为候选报告（Report A/B/C）；$c_k$ 为准则条目（按其权重 $w_k$）；$\mathrm{Judge}(c_k,y_i)$ 判定报告是否满足该准则。Slides 注明“图中只展示 rubric 奖励，辅助奖励略去”。
- **演进机制**：准则 $c_k$ 会依据“模型响应 + 检索到的证据”被细化，从而与策略共同演化（co-evolve），能吸收新探索到的信息并区分不同回答。开放长文报告需要覆盖、相关性、事实性、被引断言是否得到支持等更丰富信号，而短答只需答案正确性（Slides 第 84–85 页）。
- 消融结论（Slides 第 95–98 页）：仅用初始 rubric 或纯随机奖励时，演进 rubric 的增益明显；无 RL 与随机奖励作对照；SFT 即使只用 5% 数据也能显著改善冷启动，完整 SFT 混合最佳；训练中的高奖励不必然对应更高的下游表现（该说明出现在第 95 页文本中）。

### 3.13 双塔检索与对比学习（Slides 第 101–104 页）

- 检索打分：$s(q,d)=E_q(q)^\top E_d(d)$，在向量索引上取 top-k。例子：query “Who shared the Turing Award with Simon?” 的 top match 是“Newell and Simon: 1975 Turing Award”，而非“CMU campus buildings”。
- 训练损失（对比学习）：
$$\mathcal{L}=-\log\frac{\exp s(q,d^+)}{\exp s(q,d^+)+\sum_{d^-}\exp s(q,d^-)}$$
符号：$q$ 为查询；$d^+$ 为相关段落；$d^-$ 为负例段落。**假设**：同一查询下，相关段落与查询的相似度应高于所有负例；Slides 提示编码器设计、负采样与索引细节参见高级 NLP 与 IR 课程。

### 3.14 AgentIR 与 DR-Synth（Slides 第 105–123 页）

- **问题**：标准检索器只接收最新 query $q_t$，丢弃智能体的当前推理 $\tau_t$（Slides 第 105 页）。
- **方案**：把推理 $\tau_t$ + 查询 $q_t$ 一起送入检索器，并用 DR-Synth 训练它“判断哪些文档对这一步推理有用”（Slides 第 106–111 页）。难点在于标准检索训练依赖全局问题的人工相关性标签，而 DR 轨迹的中间检索步骤没有现成标签（Slides 第 107 页）。
- **消融**（Slides 第 115–118 页，四个智能体设定）：仅 query → +reasoning → +DR-Synth → 两者结合。以 Tongyi-DR 为例，48.7 → 55.5 → 59.4 → 66.3；结论是“两个组件都有帮助，结合最好”。
- **哪种历史有用**（Slides 第 119–123 页）：仅 query、先前 query、query+推理、query+推理+文档、当前推理。在四个设定中，“当前推理”给出的信号最强（例：Tongyi-DR 59.4 → 66.3）。

## 四、常见误区

1. **把基准高分当作“已达到人类专家水平”**。Slides 第 35–37、39–41 页反复强调：一个基准分数回答不了“与人类专家比较”的问题；专家偏好、引用准确率等是不同证据维度。第 11 页示范答案的措辞是“在被测试的任务上有前景；更广泛的人类专家等价性尚未被证明”。
2. **用相似度指标（ROUGE/BLEURT/BERTScore）替代人工偏好或 rubric**。第 38 页的 109 组比较显示这些指标只比随机好一点，且第 35–37 页给出了“极其相似但错误”的反例。
3. **认为 rubric 一旦生成就可信**。第 44 页：15% 的自动 rubric 条目空洞、错误或不清；rubric 本身必须先被审计。
4. **把“有引用”等同于“引用支持断言”**。第 47–49 页的 FACT 流程专门检查被引页面是否真的支撑该断言，50% 的引用准确率说明二者不是一回事。
5. **以为只靠“更多搜索次数/更长上下文”就能解决 DR**。第 26 页显示上下文与交互轮数带来增益，但第 83 页也显示不同上下文上限下策略行为不同，且训练曲线未分离各阶段贡献。
6. **把 RLVR 的短答奖励直接搬到长文任务**。第 84–85 页明确列出开放长文需要的多维信号；第 96–98 页显示演化 rubric 相比初始 rubric 与随机奖励的差异。
7. **默认检索器只需要 query**。第 105 页指出这是标准做法的局限；第 115–123 页显示把当前推理纳入检索输入并配合 DR-Synth 训练才得到最高准确率。
