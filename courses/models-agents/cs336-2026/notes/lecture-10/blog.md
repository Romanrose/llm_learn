# 推理效率：从内存瓶颈到投机采样与动态批处理

## 引言

训练一个大型语言模型是一次性的巨额投资，但真正决定一个模型能否被广泛使用的，往往是它在推理阶段的效率。在斯坦福大学 CS336《Language Modeling from Scratch》课程的第十讲中，我们深入探讨了推理这一关键环节——它不仅是模型部署后的日常运营成本，更是在智能体（agent）时代成为决定算力消耗的核心因素。

本讲的核心观点是：**推理与训练在计算特性上存在根本性差异**。训练时我们可以同时看到所有 token 并在序列维度上进行并行化，而推理必须顺序生成 token，这使得推理变得高度依赖内存带宽（memory-bound）。理解这一点后，我们才能系统地分析各种优化技术背后的原理。

本文将依据课堂内容，从算术强度（Arithmetic Intensity）的数学框架出发，逐步解析 KV 缓存、量化、剪枝、投机采样（Speculative Sampling）以及连续批处理（Continuous Batching）等技术，并说明它们在课程整体学习路径中的位置。

## 从计算强度看推理的本质

### 为什么推理如此重要？

在课程开始，讲师给出了一个令人印象深刻的对比：OpenAI 每天生成约 8.6 万亿个 token，而 DeepSeek-V4 的训练仅用了 32 万亿个 token。这意味着，不到四天时间，OpenAI 的推理输出量就等同于一次前沿模型的全规模训练量。

更关键的是，随着智能体（agent）时代的到来，推理的 token 消耗正在发生质变。在传统聊天机器人场景中，生成的内容最终要由人类阅读，而人的阅读速度是有限的；但在智能体场景中，模型需要自主思考、调用工具、进行反思，大部分生成的 token 并非直接呈现给用户，而是用于内部的推理过程。这意味着 token 生成量可以无限增长，推理效率的提升永远具有实际价值。

### 算术强度：衡量效率的标尺

要理解推理为什么是内存受限的，我们需要借用算术强度（Arithmetic Intensity）这一概念——它表示每传输一个字节的数据能完成多少次浮点运算。理想情况下，我们希望这个值越高越好。

课程的推导从最简单的矩阵乘法开始。假设我们要计算 X 与 W 的乘积，其中 X 的维度是 B×D，W 的维度是 D×F。需要从 HBM（高带宽内存）中读取这两个矩阵，计算浮点运算次数，然后将结果写回。假设使用 bf16 精度：

- 读取 X：2×B×D bytes
- 读取 W：2×D×F bytes
- 计算 FLOPs：2×B×D×F
- 写入结果：2×B×F bytes

计算算术强度并进行简化（假设 B 远小于 D 和 F）后，我们得到算术强度等于 B。对于一个 GPU 加速器，其"加速器强度"等于每秒浮点运算次数除以内存带宽。课程中以 H100 为例，这个值大约是 295。当我们的算法算术强度大于 295 时，它是计算受限（compute-bound）的；反之则是内存受限（memory-bound）的。

**极端情况**：当 B=1 时，算术强度降为 1。每次只处理一个序列，读取整个参数矩阵却只做很少的计算——这正是推理中最常见的情形。

### 预填充与生成：两个截然不同的阶段

推导完基础框架后，我们进入 Transformer 的层间分析。课程对 MLP 层和注意力层分别计算了算术强度，关键结论如下：

**MLP 层**：其计算本质是大型矩阵乘法，算术强度为 B×T（B 为批大小，T 为序列长度）。在预填充阶段（prefill），B×T 通常足够大，容易达到计算受限状态。在生成阶段（generation），T=1，算术强度退化为 B——这依赖于并发请求数量。

**注意力层**：情况更为复杂。注意力层的算术强度公式为 S×T/(S+T)，其中 S 是已生成的先前 token 数量，T 是本次生成的 token 数量。在预填充阶段（T=S），强度为 S/2，这是可以接受的。但在生成阶段（T=1），强度变为 S/(S+1)，**小于 1**。这个值远低于任何现代加速器的强度阈值，意味着注意力层在生成阶段永远是内存瓶颈。

为什么注意力层的算术强度不随批大小 B 扩展？这涉及到权重共享的基本差异。MLP 层的权重对所有序列是共享的，只需加载一次即可为整个批次服务；而注意力层中每个序列都有自己独立的 KV 缓存，增加 B 并不会摊销参数加载成本——每个序列都在做独立的小规模矩阵-向量乘法。

**结论**：预填充阶段是计算受限的，生成阶段是内存受限的。而生成阶段的注意力计算是真正的"根本性瓶颈"。

## 延迟与吞吐量的权衡

在上述数学框架基础上，课程引入了一个具体的例子：在一台 H100 上运行 Llama 2 13B 模型。这个模型具有一定的特定架构配置，我们暂不需要记住所有参数细节，只需关注性能计算的逻辑。

**内存占用的构成**：首先是参数内存——13B 参数以 bf16 格式存储，占用约 26GB。其次是 KV 缓存——它随批大小 B 线性增长，包含每个序列的键值对。总内存使用量是两者之和。

**延迟的决定因素**：由于推理是内存受限的，延迟主要由内存 I/O 决定。计算公式为（参数大小 + KV 缓存大小）除以内存带宽。这意味着延迟随 B 线性增长——更大的批处理意味着需要读写更大的 KV 缓存。

**吞吐量的非线性特性**：吞吐量约为 B 除以延迟，但存在渐近线。增加 B 确实能提升吞吐量，因为参数加载成本被更多人分摊，但 KV 缓存随之增大，边际收益递减。更重要的是，最终会遇到硬件内存上限——内存不足（OOM），无法继续扩大批次。

课程提供了一个形象的比喻：批处理就像坐公交车。单个人（批大小=1）随叫随走，延迟很低；但公交车（大批次）一次能运送很多人，吞吐量更高。你不可能同时获得低延迟和高吞吐量，必须在两者之间做出权衡。

**对 TTFT 的影响**：首 token 延迟（TTFT）本质上由预填充阶段决定，较小的批大小能改善首 token 延迟，而较大的批大小则有利于提升整体吞吐量。

## 减少 KV 缓存：多种无损与有损策略

既然确立了"内存是推理瓶颈，KV 缓存占用大量内存"这一前提，那么减少 KV 缓存顺理成章地成为核心优化方向。课程的策略介绍由浅入深，从架构到系统层面逐步展开。

### 分组查询注意力（GQA）

这是一个我们已经熟悉的概念。在多头注意力（MHA）中，每个查询头都有对应的键和值头；而分组查询注意力（GQA）保持相同数量的查询头，但只使用更少的键值头组，每个组服务多个查询头。通过减少键值头的数量（从 N 减少到 K），KV 缓存大小缩减为原来的 K/N。

课程特别强调了这一技术的历史背景：2023 年 GQA 论文证明了在保持良好性能的同时，时间开销大幅下降。值得注意的细节是，当我们在 GQA 配置上进一步增大批大小时，之前因为在批量 256 时内存溢出的情况现在变得可行了——这说明减少 KV 缓存不仅直接降低延迟，还能间接通过允许更大批次来提升吞吐量。

### 多潜变量注意力（MLA）

这是 DeepSeek 提出的技术，其思路比 GQA 更进一步。MLA 不再简单地减少键值头的数量，而是将它们压缩成低维向量存储。具体而言，不再直接计算完整的 K 和 V，而是先将激活投影到一个压缩维度 C（例如 512 维）中，再从压缩表示中恢复出实际的键和值。这样只需要存储较小的压缩向量，而不是完整的键值向量。课程提醒我们，MLA 与 RoPE 位置编码不完全兼容，因此需要额外添加维度来处理这个问题。这个技术说明，架构层面的巧妙设计可以大幅降低 KV 缓存大小，同时保持模型表现。

### 跨层注意力（CLA）

另一个共享思路是跨层共享 KV。GQA 在头之间共享，而 CLA 在层之间共享——只对部分层计算 KV 缓存，后续层直接复用前一层的 KV。这同样改善了准确率与 KV 缓存大小的帕累托前沿。

### 滑动窗口注意力与混合架构

对于长上下文场景，一个自然的想法是只注视最近的 K 个 token（滑动窗口注意力）。这样 KV 缓存就不再依赖序列长度，但代价是降低了表达能力。实践中人们倾向于将局部注意力与全局注意力交错，在部分层使用完整注意力，在其余层使用局部注意力。课程也提及线性注意力和状态空间模型（如 Mamba）作为另一种压缩历史的方式，但它们无法保证与滑动窗口注意力的对比结论，因为存在"大海捞针"式的任务——过度压缩历史必然损失信息。

### 量化与剪枝：系统层面的挤压

量化是系统优化中的常见手段，核心思想是降低数值精度。从 bf16 到 int4，每一步都减少内存占用。量化感知训练（QAT）在训练期间就模拟量化误差，让权重适应量化，但需要高昂的大量训练成本。更常见的是训练后量化（PTQ），它依赖校准集来确定缩放因子和零点，其中 GPTQ 使用 Hessian 信息修正误差，而 AWQ（激活感知量化）则观察到某些激活通道值特别大，与其交互的权重更为关键，因此为这些少数通道保留更高精度。

模型剪枝则走另一条路——直接移除不重要的部分。NVIDIA 的论文展示了如何用校准集估计不同部分的重要性（如隐藏单元激活值的大小），剪除不重要的层或单元后，用蒸馏来修复模型。这样能将 15B 的模型**压缩到 8B** 且保持良好效果，而训练成本远低于从头训练。

## 投机采样：利用"检查"与"生成"的不对称性

上述方法大多有损，而投机采样（Speculative Sampling）是课程介绍的一种**无损**加速方法。

方法的核心洞察是：**检查一个序列是否好，远比逐 token 生成一个序列要快**。预填充阶段可以并行处理大量 token，而生成阶段必须串行。因此，可以引入一个廉价的小型草稿模型（draft model）快速生成几个候选 token，然后用目标大模型并行地对这些候选进行验证。验证通过则接受，否则在残差分布上继续采样。

数学上，这本质上是修改版的拒绝采样。课程给出了一个简要的证明思路：只要接受概率设定为 min(1, q/p)，即目标模型概率与草稿模型概率的比值，那么即使草稿模型的分布与目标模型不完全一致，最终的采样结果也能保证是从目标分布中精确采样。这意味着输出质量与逐 token 生成完全一致，但速度显著提升。

实际操作中，草稿 token 数量需要选择恰当——太少则无法充分利用目标模型的批处理能力，太多则被拒绝的概率升高。课程中演示的最佳数值约为 3 或 4 个 token。此外，如果我们将前面讨论的各种技术融合到草稿模型中，效果会更好——剪枝、量化和蒸馏都可以用于构建更贴近目标模型的草稿模型。

## 动态工作负载的处理

真实的推理服务远非理想化的静态批处理。请求在不同时间到达，具有共享前缀，长度也不同。这种"参差不齐"的工作负载给批处理带来了极大挑战。

连续批处理（Continuous Batching）由 Orca 系统引入，其思路是迭代级调度：每一步为所有活动序列解码一个 token；序列完成即移除，新请求到达即加入，批次始终动态更新。即使请求长度不同，也可以通过"选择性批处理"来应对——对于 MLP 这类不依赖序列长度的操作，可以直接将不同长度的序列拼接成一个巨型批次处理。

分页注意力（PagedAttention）则从操作系统借鉴了内存管理的思想。KV 缓存不再需要连续的内存区域，而是划分为大小相同的块（blocks），通过索引管理。这解决了两个碎片化问题：内部碎片化（分配了超出实际需要的缓冲区）和外部碎片化（序列之间的空隙无法有效利用）。更重要的是，分页使得共享成为可能——多个请求可以共享相同的前缀（如系统提示词）的 KV 缓存，甚至可以在一个提示词上生成多个不同响应时实现写时复制语义。

## 本讲在课程中的位置

这门课从语言建模的基础开始（第一讲到第五讲），涉及缩放定律（第九讲），再进入推理（第十讲），最后回到缩放定律的深入讨论。推理看似独立，实际上是把先前所有内容串联起来的关键环节：

- 它与训练并行计算的基础设施（如批量矩阵乘法）形成鲜明对比，正是因为推理无法像训练那样在序列维度上并行化，才需要专门的设计。
- 它在缩放定律的背景下理解：推理的效率直接影响训练模型的规模选择和经济性。
- 它为后续的强化学习（RL）打下基础——RL 需要大量生成轨迹进行评估，推理效率决定 RL 的上限。

推理也是连接理论与实际应用的桥梁，将 Transformer 架构、注意力机制、内存带宽等底层知识与具体的系统优化技术（如 vLLM、SGLang 等）联系起来。

## 结语

本讲的核心思想可以总结为一句话：**减少 KV 缓存，但不要让准确性损失太多**。无论是架构创新（GQA、MLA、CLA）、数值精度调整（量化），还是模型压缩（剪枝、蒸馏），所有技术都遵循这个原则。

展望未来，讲师提到一个值得深思的观点：注意力机制和 KV 缓存的架构设计从根本上决定了它对推理并不友好，而新架构（如状态空间模型、线性注意力或扩散模型）可能蕴含更大的突破潜力。Transformer 当初也不是为推理效率而设计，而是为训练效率设计的——设计一个专门为推理而生的新架构，也许正是下一代语言模型的方向。

同时，系统的视角也至关重要。分页、连续批处理、投机执行这些来自操作系统和体系结构的概念，在推理场景中焕发出新的生命力。推理效率的提升不只靠单一技术，而是架构设计、训练策略和系统工程的综合优化。
