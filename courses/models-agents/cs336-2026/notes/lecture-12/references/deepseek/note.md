# CS336 Lecture 12：Evaluation（评估）

## 学习目标

完成本讲后，你应该能够：

1. 理解评估在语言模型开发中的核心地位，以及“抽象概念 → 具体指标”这一转化过程的核心挑战。
2. 清晰区分困惑度（perplexity）与各类下游基准测试（exam、chat、agentic、reasoning、safety）的适用场景与局限性。
3. 掌握各类评估方法的关键设计选择、优缺点与常见陷阱（如数据污染、LLM 评委偏差、基准饱和）。
4. 理解“评估的是方法、模型还是智能体”这一元问题，并能够根据目标选择恰当的评估策略。

---

## 课程主线

本讲围绕一个核心问题展开：**给定训练好的模型，它有多“好”？** 课程首先指出评估看似机械（定义 prompts → 获得回复 → 计算准确率），实则深刻——因为评估设定了北极星指标，潜移默化地塑造了 AI 的发展方向。随后，课程从最基础的概率视角出发，逐步介绍五类评估方法：

1. **困惑度（Perplexity）**：语言模型作为分布的最自然度量。
2. **考试基准（Exam Benchmarks）**：MMLU、MMLU-Pro、GPQA、Humanity's Last Exam。
3. **聊天基准（Chat Benchmarks）**：Chatbot Arena、AlpacaEval、WildBench。
4. **智能体基准（Agentic Benchmarks）**：SWE-bench、Terminal-Bench、CyBench、MLE-Bench。
5. **纯推理与安全基准**：ARC-AGI 系列与 HarmBench、AIR-Bench 等。

最后，课程上升到元层面，讨论评估的生态效度（ecological validity）、有效性（validity）以及“我们到底在评估什么”这一根本问题。

## 核心概念与关键原则

### 1. 困惑度（Perplexity）

**定义**：困惑度衡量语言模型 p 对数据集 D 赋予的概率质量。形式上，Perplexity = `(1/p(D))^(1/|D|)`，其中 |D| 是 token 总数。困惑度与对数损失（log loss）、似然度（likelihood）本质上是同一概念的不同表述。

**历史脉络**：
- 经典范式（2010s）：在 Penn Treebank、WikiText-103、One Billion Word Benchmark 等数据集上进行**分布内评估**（in-distribution evaluation）——在训练集划分上训练，在测试集划分上测试。2016 年纯 CNN+LSTM 在 One Billion Word Benchmark 上取得突破性进展，确立了神经网络在语言建模中的主导地位。
- 范式转变（2019，GPT-2）：在 WebText（从 Reddit 链接出去的 40GB 文本）上训练，但在标准的、其他研究者使用的数据集上进行**零样本评估**（out-of-distribution evaluation）。这开启了“在大规模数据上训练，在标准基准上评估”的新思考方式。

**“困惑度即一切”的论点**：
- 设真实分布为 t，模型为 p。可获得的最佳困惑度是真实分布的熵 H(t)，且仅当 p = t 时达到。
- 若 p = t，则模型可以对一切进行建模：以问题为条件生成答案，解决所有任务。
- 因此，持续压低困惑度将最终“达到 AGI”。

**对困惑度的批判**：
- **它可能比你需要的更多**：困惑度对每一个 token 的预测都进行惩罚，但并非所有 token 同等重要。例如，“斯坦福大学创立于1885年”中，“1885”蕴含世界知识，但“创立”这类词的信息量较低。
- **解决思路**：测量**条件困惑度**——以提示为条件，仅计算回复部分的困惑度，将注意力聚焦在相关 token 上。
- **有些基准是伪装的困惑度**：
  - **LAMBADA**：填空题（cloze task），本质是经过精心挑选位置的下一个 token 预测，要求长上下文才能解析。
  - **HellaSwag**：多项选择句子补全，在某种程度上也是困惑度。

**运行困惑度排行榜的信任问题**：
- 如果提交者只返回测试数据的 logprob，无法验证这些概率是否有效（是否求和为1）。一个总是返回 logprob=0 的模型可以获得完美困惑度，但并非有效分布。
- 相比之下，下游任务的评估更直接：黑盒 LM，给提示得回复，直接计算准确率即可。

**总结**：困惑度在语言模型开发中仍被大量使用（尤其在缩放定律中，因为它随规模平滑变化），但需要额外的基准来捕捉现实世界情况。

### 2. 考试基准（Exam Benchmarks）

**动机**：考试是人类测试的一种方式，可以精确控制科目与难度，并设计有明确标准答案的题目，便于自动评分。

#### MMLU（Massive Multitask Language Understanding）
- 57 个学科（数学、美国历史、法律、道德等），多项选择。
- 由本科生和研究生从网上公开资料收集。
- 尽管名字含“语言理解”，实际主要测试知识与推理，而非纯粹语言理解。
- 评估方式：对 GPT-3 使用少样本提示（few-shot prompting），在上下文中给出若干“问题-答案”示例，然后让模型预测最后一个问题的答案。
- 结果：小模型勉强高于随机水平；GPT-3 远高于随机，鼓舞人心。如今该基准已基本饱和（90+ 分）。

#### MMLU-Pro
- 动机（2024）：MMLU 已取得很大进展，需要更难的任务。
- 改进：移除有噪声和琐碎的问题；选项从 4 个扩展到 10 个；评估时使用思维链（chain of thought）。
- 结果：模型准确率回落到 33%，但目前已回升至约 88-90%，接近饱和。

#### GPQA（Graduate-Level Google-Proof Q&A）
- 核心思想：如果一个问题能通过查 Google 解决，那对语言模型可能太容易（因为模型在互联网上训练过）。因此需要真正困难的问题。
- 构建过程：61 位 Upwork 博士承包商出题 → 专家验证并反馈 → 出题人修改 → 另一位专家再审。
- “DIAMOND”子集：两位专家意见一致且一位非专家能答出，才被认为是好题。非专家被给予 Google 访问权限，30 分钟内仅达 34%（略高于随机）。
- 结果：人类博士专家 65%，GPT-4 当时 39%，目前已达 94%。

#### Humanity's Last Exam（HLE，2025）
- 动机：模型变得太强，需要“尽一切努力”创造真正难的考试。
- 规模与形式：2500 题，多模态，多学科，包含选择题与简答题。
- 构建过程：众包，提供 50 万美元奖金池与署名权奖励；由前沿模型进行多轮筛选。
- 防污染措施：保留未公开的私有测试集。
- 结果：发布时模型得分仅为个位数；截至本讲，顶尖模型（Mythos）也仅 64.7%。

**关键观察**：随着模型能力提升和现有基准饱和，考试难度持续攀升。选择题形式在难度上没有上限，但限制了可提出的问题类型。

**主要问题**：考试基准不能反映现实世界使用情况——少有人向语言模型提出考试式问题，大多数使用是开放式的，问题可能表述不规范且无唯一正确答案。

### 3. 聊天基准（Chat Benchmarks）

**动机**：多数人不会向 AI 助手提出选择题。开放式问题（如“甜菜山羊奶酪沙拉配什么香草合适？”）无标准答案，无法通过精确匹配评分。

#### Chatbot Arena（现名 Arena AI）
**核心思想**：使用人类偏好评估模型。

**流程**：
1. 互联网随机用户输入提示，获得两个匿名模型（A 和 B）的回复。
2. 用户评判 A 更好、B 更好、两者都好或两者都差。
3. 收集大量成对比较数据，计算 **ELO 排名**。

**ELO 评分模型**：假设模型 A 击败模型 B 的概率是 `1 / (1 + 10^((ELO_B - ELO_A)/400))`。用成对比较数据拟合 ELO 参数，最大化数据似然。

**优点**：
- 真实世界提示：用户免费使用模型，有动机做有用的事。
- 不需要所有模型比较所有提示（类似国际象棋的稀疏对局），只要图连通即可推导排名。
- 动态性：可随时间加入新提示与新模型并更新排名。

**缺点**：
- 用户分布不确定（来 LMSYS 网站的是什么人群？），可能包含垃圾发送者、操纵者。
- 二元偏好混淆了**风格与正确性**——国际象棋 ELO 有效是因为“赢”是唯一标准，而“哪个更好”定义模糊。
- 人类评者的局限：提问者通常不知道答案，如何判断正确性？存在谄媚（sycophancy）偏差——讨好的答案可能优于正确的直言。

#### AlpacaEval（2023）
- 805 条指令，指标为**相对于基线模型的胜率**：模型回复 vs. GPT-4 预览版回复，由 GPT-4 预览版评判哪个更好。
- 这就是 **LLM-as-a-judge** 的实例，是当前非常流行的评估方法。
- **已知问题**：LLM 评委偏爱较长回复，导致排行榜游戏（经微调模型仅因回复更长而获得高评分）。后续版本使用回归方法去偏。

**评估指标的验证**：AlpacaEval 与 Chatbot Arena 的相关性高达 0.98，这表明可以用低成本指标替代昂贵的人类评估。但相关性基于特定模型集合，对更强模型可能不成立。

#### WildBench
- 从 100 万条人机对话中采样 1024 条。
- 类似 AlpacaEval 使用 LLM 评委，但核心创新是使用**生成的、针对特定提示的检查清单（checklist）**——为“这个回复好不好”这一模糊任务提供明确评分标准。
- 与 Chatbot Arena 有良好相关性。

**开放式回复评估的总结原则**：
- **成对比较**（pairwise comparisons）比绝对评分（7/10 vs 8/10）信号更强。
- **注意偏差**：人类和 LLM 评委都有不同类型偏差。
- **使用多个评委**：如果一个模型得到人类评委和所有 LLM 评委的一致好评，那它可能确实更好。
- **定义评分标准或检查清单**：能极大提升评估的可靠性与明确性，无论对人类还是 LLM 评委都是如此。

### 4. 智能体基准（Agentic Benchmarks）

**定义**：评估 LLM **做了什么**（而非说了什么）。智能体 = 语言模型 + **智能体脚手架（scaffold）**，脚手架是决定如何调用 LLM、可访问哪些工具的逻辑。

#### SWE-bench
- 任务：给定代码库和 GitHub issue 描述，提交一个拉取请求（PR）修复问题。
- 评估：通过单元测试（修复前不通过的测试需要通过，且不破坏其他测试）。
- 结果：SWE-bench Verified 从 2024 年约 16% 升至 93%。

#### Terminal-Bench
- 环境：计算机终端，通过在终端中输入命令完成任务。
- 数据：229 个任务由 93 人众包，其中 89 个构成 Terminal-Bench 2.0。
- 特点：环境简单通用；人类完成任务需 1 小时到一周以上。
- 重要观察：相同模型在不同脚手架下准确率不同——智能体评估评估的是模型与脚手架的组合。

#### CyBench（网络安全）
- 40 个夺旗（CTF）任务：智能体需查看源代码、访问网络服务器，最终侵入系统提取独特字符串（Flag）。
- 发布时最好模型约 10%，现已基本被完全解决。
- 简单脚手架：连续记忆缓冲区，将行动与环境反馈拼接后送入模型；但这会导致上下文快速增长，需要更复杂的上下文管理。

#### MLE-Bench
- 75 个 Kaggle 竞赛任务：智能体查看数据、阅读描述、编写代码、训练模型、提交结果并获评分。

**现代智能体脚手架的四个关键组件**：
1. **显式规划（explicit planning）**：维护待办事项清单并逐项勾选，而非仅靠意识流式思维链。
2. **层级委托（hierarchical delegation）**：主智能体以简洁上下文调用子智能体；子智能体完成工作后只返回结果，实现封装。
3. **持久化记忆（memory）**：显式读写文件，因为上下文窗口有限，无法容纳全部历史。
4. **流程管理式的上下文工程**：何时委派、何时尝试新策略、何时写入持久化记忆，通常针对特定模型进行优化。

### 5. 纯推理基准（Pure Reasoning）

**动机**：以上所有任务都需要语言与世界知识。能否将**推理**从**知识**中分离出来，测量更“纯粹”的智力？

#### ARC-AGI 系列
- 始于 2019 年，任务设计为人类 100% 可解（以某种合理时限为限）、但对 AI 具有挑战性。
- 每个任务都是“独一无二的雪花”，记忆或迁移难以直接应用。
- 视觉图形推理任务（如图片模式补全），不依赖语言。

**发展轨迹**：
- **ARC-AGI-1（2019）**：预训练模型（GPT-3 时代）完全没有推动进展。
- 2024 年：OpenAI o1/o3 推理模型出现后，进展突然起飞，ARC-AGI-1 基本被解决。
- **ARC-AGI-2（2025）**：更多多步推理，尚未完全解决但看起来在解决路上。
- **ARC-AGI-3（2026）**：交互式环境。分数极低，仍有很大空间。

**关键观察**：
- 预训练的知识对解决 ARC-AGI 是否必要？没有预训练也没有推理模型的爆发，但预训练知识的作用在 ARC-AGI 大部分历史中不直接可见。
- 目标（分离推理与知识）极难实现，可能不存在“纯粹”推理——任务仍来自某种先验背景。
- 方法局限于人类推理（设计目标是人类可解），不延伸到超人推理（如拿更多金牌或解决开放数学问题）。

### 6. 安全基准（Safety）

**类比**：汽车安全性经过数十年才确定测试标准（撞击测试、安全气囊等）。AI 安全目前没有好答案。

- **HarmBench**：用意在造成伤害的提示测试模型，期望模型拒绝（refuse）。
- **AIR-Bench**：从欧盟、中国、美国公司政策中的监管框架出发，建立分类体系（314 个风险类别，5694 个提示）覆盖可能出错之事。
- **越狱（Jailbreaking）**：语言模型通常被训练拒绝有害指令，但可通过巧妙构造提示绕过。GCG 是一种坐标梯度优化算法，可自动优化提示以绕过安全限制，且攻击可从开源模型迁移到闭源模型。

**安全的复杂性**：
- 高度依赖语境：涉及政治、法律、社会规范，在不同国家有所不同。
- 风险多样化：幻觉（医疗、法律、金融场景）、谄媚、教唆犯罪、不平等、丧失批判性思维——有些与能力正相关（更准确减少幻觉），有些与能力冲突。
- **双重用途**：能力强的网络安全智能体既可被用于入侵系统，也可用于渗透测试提升安全性。

## 评估的元考量

### 生态效度（Ecological Validity）
评估在多大程度上捕捉现实世界使用？
- 考试基准（GPQA）远离现实使用。
- Chatbot Arena 提示来自真实用户，但用户分布不受控。

**尝试提高生态效度的基准**：
- **GDPVal（OpenAI）**：基于美国 GDP 前九大行业的 44 个职业，由约 14 年经验的专业人士创建任务（护士、房地产经纪人、影视剪辑师等）。
- **MedHELM**：121 个临床任务来自 29 位临床医生，代表临床医生实际会问的问题（vs. 标准化考试）。
- **Clio（Anthropic）**：使用 LLM 分析真实用户数据，分享人们使用 Claude 做哪类事情的总体模式。出于隐私考虑不能直接看数据，但可以让模型分析并总结一般模式。

难点：**真实感与隐私往往冲突**——理想上需要真实查询流样本，但这涉及隐私考量。

### 有效性（Validity）：我们如何知道评估有效？

#### 训练集与测试集重叠（数据污染）
- 基础模型出现前：ImageNet、SQuAD 等有明确训练/测试划分，规则清晰。
- 今天：模型在互联网上训练，你不知道数据里有什么。

**应对路径**：
1. **推断污染**：利用基准中问题顺序应该随机的性质。如果模型偏好与基准一致的特殊顺序，可能是在该基准上训练的。
2. **鼓励报告规范**：模型提供者应报告训练集与测试集重叠情况（类似统计学中报告置信区间的实践）。
3. **使用新鲜评估**：LiveCodeBench、UncheatableEval 抓取模型截止日期后的新网页作为评估集。注意时间戳也不总是安全（内容可能被复制）。
4. **私有评估集**：公司内部代码库或你的个人未公开发布写作（如被拒稿的论文）。对困惑度评估尤其有利，因为只需要数据即可评估对数概率。

#### 数据集质量
- SWE-bench 原始版本中有些单测不严谨，修复后产生 SWE-bench Verified。
- 其他基准（GSM8K、MMLU）经仔细审核后也发现了问题，如“图中没有曲线，无法回答该问题”。
- 智能体基准更难评估：测试用例可能不完整，通过测试但解决方案仍不可用；有研究表明智能体仅输出空响应即可获得 38% 分数。
- **Docent**：使用 LLM 检查智能体轨迹以检测问题——一种定性的补充方法。
- **通用建议**：无论开发新基准还是运行已有基准，都应查看实际输出并审计，确认测量的是想要测量的东西。

## 构建评估策略的原则

1. **没有唯一真正的评估**——选择取决于你要回答什么问题：
   - 用户/公司：为特定用例（如客服聊天机器人）做购买决策。
   - 研究者：测量模型的原始能力（如“智能”）。
   - 商业/政策：理解益处与危害。
   - 开发者：获得改进模型的反馈。

2. **明确游戏规则**：我们在评估**方法**还是**模型/系统**？
   - 基础模型前：评估方法（固定训练/测试划分，只有算法可变）。
   - 今天：主要评估模型/系统（一切皆可变）。
   - 例外：NanoGPT speedrun，固定数据和目标验证损失，仅评估训练速度。

3. **权衡取舍**：很难同时做到高难度、高真实感和高生态效度；也找不到完全避免污染的评估。根据目标选择愿意妥协的维度。

## 课程作业关联

本讲的内容直接关联到课程项目的评估环节。在训练完成语言模型后，你需要：
- 使用困惑度作为主要的内在评估指标（注意训练集/测试集的划分以及模型是否见过测试数据）。
- 在标准基准（如 MMLU）上进行零样本或少样本评估，以与其他模型对比。
- 注意数据污染的潜在风险——你的训练数据可能已经包含了这些基准的测试集。

---

## 常见误区

1. **认为困惑度越低模型一定越好**：困惑度是所有 token 的平均，可能包含大量不相关 token 的噪声。低困惑度不等于在特定任务上表现好。
2. **轻信基准分数**：基准可能存在数据污染（模型见过测试数据）或数据质量问题（测试用例不完整、问题本身有误）。应始终持保留态度并考虑审计。
3. **混淆 LLM 评委偏长回复与质量高**：LLM 评委常偏爱较长回复，导致排行榜游戏。应使用去偏后的指标或多个裁判交叉验证。
4. **混淆风格与正确性**：成对偏好比较无法区分模型是说得好听还是说得正确。人类评委也易受谄媚偏差影响。
5. **忽视智能体脚手架的影响**：在智能体基准中，相同模型在不同脚手架下表现差异巨大。评估的是“模型+脚手架”的联合系统。
6. **认为 ARC-AGI 是纯推理**：任务仍来自某种先验背景，不存在“纯粹”的推理；且其设计局限在人类推理范围内，不覆盖超人推理。
7. **对安全基准的过度简化**：安全高度依赖语境，单一数字无法全面代表安全性。不同国家、不同场景的安全定义不同。
