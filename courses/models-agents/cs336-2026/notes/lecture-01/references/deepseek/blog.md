# 从零构建语言模型：CS336 第一讲深度解析

## 导语：为什么要从零开始？

当我们打开 ChatGPT 或其他大语言模型时，很容易把它当作一个黑盒——输入提示词，得到答案。但在当今 AI 研究中，有一个日益严重的问题：研究人员正在与底层技术脱节。十年前，所有 AI 研究人员都会自己实现并训练模型；八年前，人们还会下载 BERT 这样的预训练模型进行微调。而今天，很多人仅仅通过提示（prompting）模型就能应付过去。

CS336 课程的核心信念是：**只有通过从底层一步步构建一切，你才能真正理解所有东西是如何运作的**。这正是本课程设计的基本出发点。

## 课程背景：为什么基础研究需要底层技术

### 抽象是有漏洞的

提示模型本身并没有问题，从抽象层次提升上看，这是一件很好的事情。但抽象是有漏洞的（leaky）——当模型无法完成你需要的任务时，没有其他补救办法。如果你真正对基础研究感兴趣，仅仅通过提示模型，你就在极大地限制你的设计空间。要从事基础研究，你需要拆开整个技术栈（stack）。

### 工业化带来的挑战

语言模型的工业化已经深刻改变了研究格局。前沿模型（frontier models）极其昂贵——GPT-4 的训练据说花费了 1 亿美元（2023 年），而现在的成本可能已经达到 10 亿美元量级。更关键的是，这些模型的具体构建方式没有任何公开细节，GPT-4 的论文明确表示不会分享任何相关信息。

当无法研究前沿模型时，我们可以构建小型语言模型。但必须清醒认识到：**小模型可能并不能代表真正的前沿模型**。

### 两个关键例子

**例子一：FLOPs 分布随规模变化**。如果我们计算不同模型规模下 MLP 层消耗的浮点运算数（FLOPs）占比，会发现一个显著变化：在 1.75 亿参数规模时，MLP 层占比约 44%；当扩展到 1750 亿参数规模时，这个比例会上升到 80%。这意味着小规模研究中的注意力优化可能在大规模下没有同样的收益。

**例子二：行为的涌现性**。即使在比较早的时期，小模型在零样本（0-shot）或少样本（few-shot）学习上的表现也几乎看不出与随机猜测的区别，只有达到某个临界规模时，能力才会突然大幅提升。

### 三类可迁移的知识

尽管存在上述挑战，我们依然可以从这门课中学到三类知识：

1. **机制（Mechanics）**：事物如何运作，什么是 Transformer，模型并行（model parallelism）如何工作——这些可以完整传递。
2. **思维方式（Mindset）**：如何着手构建语言模型，如何最大化利用硬件资源，如何认真对待扩展（scaling）——这些也可以传递。
3. **直觉（Intuitions）**：哪些数据和建模决策会带来好的性能——这些不一定能跨规模迁移。

关于直觉，有一个极其坦诚的例子：提出 SwiGLU 激活函数的论文作者 Noam Shazeer 在结论中写道：“我们不做解释。我们将这些架构的成功，归因于上天的恩赐。”这说明有些设计决策纯粹来自实验经验，无法从理论上完全论证。

### 苦涩的教训的正确解读

关于“苦涩的教训”，常见的误解是“规模就是一切，算法不重要”。但正确的解读恰恰相反：**能够良好扩展的算法才是重要的**。可以这样理解：

**准确率 = 效率 × 资源**

效率是产出除以投入，资源就是投入。当规模变大时，效率的重要性远超过资源——如果你在小规模实验时运行时间翻倍，或许只需多等一倍时间；但如果在大规模上进行，那可能涉及数亿美元的成本，即使仅 5% 的效率提升也是巨大进步。OpenAI 2020 年的一篇论文显示，2012 年到 2019 年间，ImageNet 上的算法效率有 44 倍的提升。算法与硬件的双重改进相互叠加，才带来了我们今天看到的巨大飞跃。

## 语言模型的演进：从数据压缩到智能体

### 早年：从 N-gram 到神经网络

语言模型有着悠久的历史。早在 50 年代，Shannon 就使用语言模型来测量英语的熵。在很长一段时间里，N-gram 模型被用于机器翻译和语音识别系统——它们不是系统全部，但确保了输出文本的流畅性。

现代语言模型的血统来自神经架构。90 年代出现了 LSTM；2003 年 Yoshua Bengio 在《神经网络》期刊上发表了第一个神经语言模型（一个查看小范围上下文的的前馈网络）；随后，Seq2Seq 建模、注意力机制（attention，为机器翻译开发）、Transformer 架构（也为机器翻译设计）相继出现。2010 年代涌现了混合专家（mixture of experts）模型、模型并行等多种架构、系统和优化器思想。

### 2010 年代末：预训练时代的开启

ELMo 和 BERT 标志着范式转变：在大量文本上预训练语言模型，然后在特定下游任务（如问答）上微调，会带来巨大改进。当时的标准流程是：取一个预训练模型，在特定任务上微调。

Google 的一篇论文预示了“提示输入、响应输出”的观点，但真正打开闸门的是 OpenAI——他们系统性地拥抱了规模化理念。2018 年左右发布 GPT，然后扩展到 GPT-2，2019 年训练出 GPT-3（1750 亿参数，比当时最大模型大了近 10 倍），展现出诸如上下文学习这样的涌现行为。

此时发生了三件值得一提的事：Google 训练了巨大的 PaLM 模型但训练不足；尚未与 Google 整合的 DeepMind 已经找到了计算最优规模法则；GPT-3 的发布对许多人来说是一个警钟。

### 开源模型生态的兴起

GPT-3 之后出现了一系列复现尝试：EleutherAI 创建了开源数据集（The Pile）和模型（GPT-J）；Meta 训练了 1750 亿参数的 OPT 模型但遭遇大量硬件问题；Hugging Face 的 BigScience 项目推出了 BLOOM。这些早期模型都不够强大。

过去三年中，开源模型生态系统发生了显著变化。Meta 的 Llama 系列引领潮流（Llama、Llama 2、Llama 3），Mistral、DeepSeek、Qwen 等一批中国模型也纷纷加入。现在的开源权重模型已经接近闭源模型，在工业界被广泛使用。除此之外，还有一条更彻底的开源路线——AI2、NVIDIA 和 Marin 项目不仅提供权重，还提供论文、代码和数据，让研究人员能深入理解模型的构建过程。

这些开源生态的存在意义重大：如果没有它们，这门课可能根本无法开设——正是来自这些开放模型的论文让我们能窥见前沿模型是如何构建的。

### 语言模型定义的演变

在过去十年中，语言模型的概念发生了深刻变化：

- 2018 年（BERT 时代）：一个需要微调的东西
- 2020 年（GPT-3 时代）：一个需要提示词（prompt）的东西
- 2022 年（ChatGPT 时代）：一个可以与它对话的东西
- 2026 年（智能体时代）：一个能够自主行动的东西

尽管要求不断提高，但基本原理并没有改变：我们依赖 GPU 和内核，使用梯度或类随机梯度方法优化，仍然用 Transformer 和注意力机制。变化的只是规格——需要更长上下文意味着推理效率更加重要。

## 课程结构：五个模块五个作业

课程分为五个部分，与五个作业对应：基础系统、系统、扩展、数据、对齐。

### 作业一：基础系统

目标是能够从零开始训练并构建一个语言模型。组成部分包括：

**分词（Tokenization）**：模型操作的原子单位是什么？分词器在原始输入（字节）和代表标记的整数序列之间转换。从效率角度看，分词能将长序列减少为更少标记——不仅因为注意力机制是二次方复杂度的，更因为这允许自适应计算：也许有些地方包含很多字节但应压缩为一个标记，而输入中一些更稀有或更有趣的部分则应保留为多个标记。

**模型架构（Transformers）**：你可能会见到很多重要的改进：激活函数的演变（ReLU 到 SwiGLU）、位置编码的演变（正弦到 RoPE）、归一化方式的演变（LayerNorm 到 RMSNorm、QK-norm、pre-norm 与 post-norm）、注意力计算的简化（稀疏注意力、GQA、MLA）、MLP 层的混合专家（Mixture of Experts，已成为构建计算高效 Transformer 的主导范式）。

**模型形状**：有多少层？多少个注意力头？隐藏维度是多少？专家数量是多少？这看起来只是琐碎的超参数设置，但在扩展和语言模型背景下，其实有着非常重大的影响。

**训练**：损失函数（默认下一标记预测，但预测多于一个标记似乎有帮助）、优化器（AdamW 仍常用，但 Muon 等新优化器在最新的开源模型中越来越流行）、初始化（对更大模型的训练稳定性有巨大影响）、学习率调度、正则化、批量大小，以及 MoE 特有的问题。这些看起来只是超参数，但真正以原则性的方式设置它们，将决定一次运行是彻底失败还是达到最先进的水平。

在作业一中，你要实现 BPE 分词器、Transformer、损失函数、优化器和完整训练步骤，在 TinyStories 和 OpenWebText 数据集上训练模型，并做大量的资源核算（flop 计数）以了解计算资源的分配。

### 作业二：系统

目标：最大化硬件性能。覆盖内核（kernels）、多 GPU 并行化、推理等话题。

核心原则是：**组织计算以最小化数据移动**。从 HBM 到计算单元的数据移动代价高昂。算子融合（fusion）就是对此原则的一种经典应用：只读取一次数据，完成两个计算，写回一次结果。

推理有两个阶段：预填充（prefill）和解码（decode）。预填充阶段可以并行处理所有 token，计算受限；解码阶段逐个生成 token，很快成为内存受限环节。加速解码的方法包括：剪枝（pruning）更大模型、量化（quantize）、蒸馏（distill）、推测解码（speculative decoding）——用一个便宜模型抢先运行并猜测一批 token，然后用完整模型并行验证。

### 作业三：扩展定律

设定一个极端场景：如果你有 1e25 FLOPS 的计算量（数千万美元成本），你会训练什么模型？在这种规模下，无法进行典型的超参数调优，因为你只能训练一个模型。

关键的概念转变是：不应该只考虑正在训练的单个模型，而应该考虑一种**缩放方案**（scaling recipe）——一个从 FLOPs 预算到一组超参数的映射。通过运行一系列小规模实验，拟合缩放定律（scaling law），预测在目标规模下的损失。

这里的一个重要提醒是：**缩放定律并不是自然法则，不会自动发生**。必须通过精心构建缩放方案来达到可预测性。预测性与最优性同等重要——如果在每个规模都改变超参数，就无法在更大规模时可靠外推。

经典结论：训练应该使用的数据点数量大约是参数数量的 20 倍（D = 20N）。一个 70B 参数的模型应该在大约 1.4 万亿个 token 上训练。

Marin 项目正在实际测试这一方法论：他们预注册了不同计算预算下的预测，正在训练一个外推到 1E22 FLOPS 的模型，本周可能完成后就能检验预测的准确性。

### 作业四：数据

这是最重要部分之一——数据质量基本决定了模型会有多好。数据反映了模型想要什么：你希望它说多种语言吗？擅长对话吗？能运行长时间智能体式编码任务吗？

评估是深入话题：有内部评估（指导开发过程，要求跨尺度平滑性、相对表现）和外部评估（向客户或评审者报告，关注生态效度）。困惑度（perplexity）仍是捕捉模型内在质量的很好方式——能在私有文档上运行以避免数据污染。

数据不会凭空出现。需要积极的整理：从网络爬取网页、书籍、arXiv 论文和 GitHub 代码、去重、过滤。存在法律问题（合理使用、许可数据），数据处理需要转换、过滤、去重、数据混合、合成数据等多个步骤。

### 作业五：对齐

基本模板是：从模型生成回复，用人工或验证器评分，更新模型偏好更好的回复。可通过 PPO、GRPO 或用 DPO 实现。

挑战在于强化学习算法不稳定且难以调参。大规模进行强化学习需要推理服务器和训练服务器的编排，尤其在涉及代码执行的环境时。还需要在策略一致性和最大化吞吐量之间不断权衡。

### 一切皆效率

把这些模块放在一起看，核心思维是：在给定数据和计算预算下，构建最佳模型。资源包括数据、硬件（计算核心、内存、通信带宽），目标是最大化效率。

- 系统层面：显然关乎计算效率
- 分词：直接处理原始字节很优雅，但对当前架构计算低效
- 模型架构：许多变化出于减少内存或浮点运算次数
- 数据过滤：不浪费宝贵计算在冗余或差质量数据上
- 扩展定律：用更少计算在小规模做超参数调优

## 深入分词器：从字符到 BPE

现在我们进入第一讲的核心技术单元——分词。

### 为什么需要分词器？

原始文本是 Unicode 字符串，而语言模型在通常表示为索引的 token 序列上放置概率分布。分词器就是完成这种往返转换的程序：能将字符串编码成 token 序列，也能将 token 序列解码回字符串。

一个直观认识：压缩率（每 token 的字节数）越大，意味着句子越短。这很重要，因为注意力机制是二次方复杂度的，你需要保证序列足够短。一个 20 字节的字符串如果被切成 8 个 token，压缩率就是 2.5。

### 糟糕的方案：字符级分词

字符级分词器把每个 Unicode 字符映射为一个整数码点。看似简洁，但问题很明显：

1. 有大约 15 万个 Unicode 字符，词汇表巨大
2. 许多字符很罕见（如 🌍），词汇表利用效率极低
3. 压缩率很差

### 也更糟糕的方案：字节级分词

把字符串转成 UTF-8 字节系列。词汇表很小（只有 256 个可能值），但序列变得很长，压缩率恒为 1。

### 有语义但受限的方案：词级分词

把按空格或正则表达式切分出的每个“块”称为一个 token。好处是每个 token 都有稳定语义，词汇表可能十分庞大（且无界），还有一个尴尬问题：测试时遇到没见过的 token 需要 UNK token，这很丑陋且会搞乱困惑度计算。

### BPE：字节对编码

这是 GPT-2 开始在大语言模型中使用的方案。基本想法：**在原始文本上训练分词器，为数据定制词汇表**。常见序列表示为一个 token，且全都能被分词——如果罕见，就分解成更小的单元，不需要 UNK token。

算法在概念上很简单：

1. 从字节序列开始，每个字节是一个 token
2. 统计相邻 token 对的出现频率
3. 合并出现频率最高的 token 对，赋予新索引（256 起）
4. 反复迭代直到达到目标词典大小

具体例子：假设有字符串 **"the cat in the hat"**。初始状态是一串字节索引。统计所有相邻对，发现 (116, 104) 出现两次（对应 "th"），是最频繁的。将它们合并为新 token 256。继续迭代，将 (256, 101) 合并为 257（对应 "the"），依此类推。序列在缩小，词汇表在增长。

编码新文本时，只需遍历所有合并操作，将合并应用到字符串上。解码时，用词汇表将索引映射回字节序列。

在作业一中，需要做几项改进：

- 编码时只遍历有用的合并，而不是全部
- 检测并保留特殊 token（如 &lt;|endoftext|&gt;）
- 使用预分词（如 GPT-2 的正则表达式）
- 尽可能加速实现——如果需要，可以用 Rust 或 C 重写

### 分词器的未来

课程坦诚地指出：理想愿景是实现端到端字节操作，已有相关探索（如 Byt5、Megabyte、BLT 等）看起来很有前景，但目前还没有扩展到前沿规模。所以今年仍然需要教授分词器。

任何替代方案都必须满足两个性质：

1. 模型应在某种序列抽象（chunk）上操作——不仅适用于文本，也适用于视频或 DNA
2. 块应该是可变的，允许自适应计算——并非所有字节都被同等对待

## 结语：从理解到效率

第一讲的核心信息清晰连贯：**语言模型构建的本质是在给定资源下最大化效率**。无论是选择分词策略、设计模型架构、优化训练流程，还是决定数据过滤标准，所有决策都可以从效率这一视角审视。

课程结构也体现了清晰的递进逻辑：先掌握基础（分词、Transformer、训练循环），再追求系统效率（内核、并行化、推理），通过扩展定律实现规模预测，最终以数据整理和对齐完成端到端的模型构建体验。

本周的作业一将让你亲手实现一个完整的、可运行的 BPE 分词器和语言模型训练流程。下一讲的主题将是资源核算（resource accounting）——计算模型的浮点运算量和内存消耗，以及这些数字如何指导我们的设计决策。

准备好从零开始吧——这正是理解一切的最好方式。
