# CS336 Lecture 9：Scaling Laws 中文讲义

## 学习目标

完成本节课后，你应该能够：

1. 理解 Scaling Laws 的基本思想：如何从中小规模训练结果外推大规模行为，以及为什么这是一种强大的工程范式。
2. 掌握数据 scaling laws 的直觉来源（参数估计与非参数回归），并知道实际观测到的指数（约 −0.1）意味着什么。
3. 理解“斜率稳定、截距可变”这一经验规律，并能解释它为什么对数据混合、架构比较、优化器选择等工程决策有用。
4. 掌握临界批次大小（critical batch size）的概念、估计方法及其与计算规模的幂律关系。
5. 理解 IsoFLOP 分析、下包络线法和曲面拟合法三种计算最优（compute-optimal）训练配置的估计方式，并了解 Kaplan 与 Chinchilla 结论分歧的原因。
6. 认识到 scaling laws 不是自动成立的，需要精心选择 x 轴、超参数和参数计数方式，否则预测可能严重偏移。

## 课程主线

本节课从一个实际问题出发：假设你有大量计算资源（例如一万块 B200 使用一个月），需要训练一个前沿开源语言模型。你不可能在百万美元级别的大规模运行上反复调试超参数。你需要在小的规模上完成优化，并通过某种可靠的规律外推到大规模行为。Scaling Laws 就是这种“简单、可预测的规则”。

课程结构如下：

1. **历史背景**：缩放定律不是新事物，其思想可追溯到统计学习理论和 1990–2010 年代的 NLP 工作。
2. **数据 scaling laws**：最简单的单变量关系，从均值估计和非参数回归的直觉推导其函数形式。
3. **模型与超参数层面的 scaling laws**：架构比较、优化器选择、宽高比设计。
4. **临界批次大小**：一个关键的工程量，随目标损失呈幂律增大。
5. **计算最优训练配置**：Kaplan 与 Chinchilla 之争，以及为什么看似微小的选择会导致结论的巨大分歧。
6. **实践启示**：生产级模型通常不需要 Chinchilla 最优，而应“过度训练”以利于推理服务。

## 核心概念与原理

### 1. 背景：缩放定律的历史根源

Scaling laws 并非深度学习的全新产物。其思想与以下经典脉络一脉相承：

- **泛化界（Generalization Bounds）**：理论机器学习一直关注“模型表现如何随样本量变化”。泛化界给出的误差上界通常依赖于样本量，这本质上是一种关于数据量的性能预测。
- **经验样本复杂度（Empirical Sample Complexity）**：早在 1993 年，Bell Labs 的研究者就提出在小子集上拟合分类器、用错误率衰减曲线估计大数据集上的性能，这是最早的数据缩放定律实践。
- **NLP 领域早期工作**：Banko 和 Brill 关于数据量与系统性能的研究；Kolachina 等人（2012）在机器翻译中拟合了幂次为 3 和 4 的幂律关系——这与今天讨论的幂律形式相同。
- **Hestness et al. (2017)**：课程讲师认为这是神经 scaling laws 的起点。该工作覆盖语音识别、机器翻译、语言模型等多个系统，证明了数据规模与性能之间存在优美的多项式趋势，并提前讨论了涌现（emergence）、计算量 scaling 等话题。

> **解释**：以上历史脉络说明，scaling laws 不是“纯神经网络时代”的新范式，而是从统计学习和经验机器学习中自然生长的思想。

### 2. 数据 Scaling Laws

#### 2.1 经验观察

固定模型训练流程（模型大于数据集），以规律方式增加数据集大小，观察测试损失下降。在对数-对数坐标下，损失与数据量呈清晰的线性关系，即**幂律（power law）衰减**：

$$\text{loss}(N) \propto N^{-\alpha} + c$$

其中 $c$ 是**不可约误差（irreducible error）**，$N$ 是数据集大小。双对数图中的线性关系意味着远离渐近线；接近不可约误差时曲线会偏离直线。

#### 2.2 幂律的统计直觉来源

**参数估计**：若用经验均值估计高斯分布的均值，期望误差为 $\sigma^2 / n$。对数后即为 $\log \text{error} = -\log n + \log \sigma^2$，斜率为 −1。这就是最简单的 scaling law。

**非参数回归**：若在 $d$ 维空间中估计任意光滑函数，将空间划分为大小为 $n^{-1/(d+2)}$ 的小格，则估计误差约为 $n^{-1/d}$。对应的对数-对数斜率为 $-1/d$。

**神经网络的类比**：实际观测的指数约为 −0.1 到 −0.3（Kaplan 2020、Hestness 2017），大致对应 $d \approx 10$ 左右的非参数回归器。这是一个有用的心智模型：神经网络的行为类似一个内在维度约为 10 的非参数平滑器。但课程讲师提醒，这个论证部分依赖于内在维度的估计，证据未必完全可靠，可按接受程度采纳这种直觉。

> **解释**：均值估计和非参数回归是课程用来推导 scaling laws 函数形式的 toy model，帮助理解为什么多项式衰减是自然的选择。神经网络的实际指数更慢，反映了其灵活性和高维输入的本质。

#### 2.3 数据缩放定律的工程应用

数据缩放定律本身主要用于预测，但更有趣的是工程决策支持：

- **数据混合优化**：对于两个数据源（如新闻和维基百科），可以训练小模型、拟合不同混合比例下的性能函数、找最小值、外推到大规模。这种方法成立的隐含前提是：**混合比例只影响截距，不改变斜率**。因此小规模下的最优混合在大规模下仍是最优。Data Decide（大规模实证研究）发现，不拟合缩放定律、直接选择小规模最佳混合方案，效果也很好——这与“斜率不变”论点一致。
- **数据重复使用（epoch 数）**：标准训练下约可达 4 个 epoch 而不受损害，超过后实际缩放曲线会明显差于新鲜数据预测的曲线。修正的函数形式可以预测重复条件下的行为。
- **无限计算量的极限**：即使允许无限次 epoch 和无限大的模型，性能提升也会递减，最终需要转向集成等方法。但注意：正则化、集成等干预措施改变的是截距，斜率几乎不变。
- **数据过滤的规模依赖**：计算资源少时应激进过滤、只保留高质量数据；资源多时应放松过滤、利用更多数据以避免重复。最优过滤器不是规模的固定函数。

### 3. 模型与超参数层面的 Scaling Laws

#### 3.1 架构比较

训练一组小规模的 Transformer 和 LSTM，绘制各自的对数-对数扩展曲线。如果 LSTM 的斜率（甚至截距）更差，就有证据支持扩展 Transformer 而不是 LSTM。这正是 Mamba、门控 DeltaNet 等论文的标准做法：展示新架构的扩展曲线优于普通 Transformer。

Ek 等人在 Google 的 T5 架构扩展研究捕捉到了许多后来被前沿模型采纳的架构趋势：高效注意力机制（如 Performer）扩展不佳；GLU（门控线性单元）在扩展趋势上持续优于其他选择；Switch Transformer 也有良好的扩展趋势。虽然当时的计算规模远小于今天，但这些规律仍然有效。

> **解释**：这解释了为什么许多人把 scaling laws 视为“验证干预是否真正有效”的范式性工具：如果某个架构改动在扩展趋势中不占优，它很可能不是好的干预。

#### 3.2 优化器选择

SGD 与 Adam 的对比（Hestness 的工作，语言建模 + recurrent highway network）：截距不同，但斜率非常相似。即使像优化器这样大的变化，也很少改变扩展趋势的斜率。这是一个反复出现的经验规律。

#### 3.3 宽高比与深度

- 极少的层数（如一层）严重不利于扩展；大于 1 层后各深度竞争激烈，但总体上更多层在每个计算量水平都更好。
- 宽高比（每层宽度与深度之比）近似为**尺度不变量（scale invariant）**：不同规模下最优宽高比几乎不变（约在 100 维附近）。这让你可以放心采用“固定宽高比、放大规模”的策略。

#### 3.4 参数计数的影响

并非所有参数都平等。Kaplan 等人在拟合扩展定律时发现，如果包含嵌入参数，曲线变得非常奇怪；排除嵌入参数后得到干净的趋势。但一个关键问题是：他们也排除了最后一层（softmax 层）的参数，因为嵌入矩阵和输出矩阵形状互为对偶。包含或排除这些参数对缩放定律的形状有重大影响。

> **课程原意强调**：Scaling laws 是**工程出来的，不是自动发生的**。需要选择正确的 x 轴、确保超参数正确调优，才能获得可预测的扩展。这是使用 scaling laws 时最核心的元认知。

### 4. 混合专家模型（MoE）的 Scaling

MoE 是当前训练大模型的主流方式，其扩展规律可以通过 IsoFLOP 类分析量化：

- 给定计算预算，最小化损失时，总参数量越大，最优稀疏度越高（激活参数占比越小）。
- 增加“空转参数”（增加总参数量但保持激活参数不变）仍有助于降低损失——未激活的参数仍有价值。
- 稀疏度、总参数量、激活参数量之间存在可预测的扩展关系。不同的 Q 型概率：
  - 需要区分“参数”这个概念在 MoE 语境下已被解耦为总参数和激活参数。

### 5. 临界批次大小（Critical Batch Size）

#### 5.1 概念

- **噪声受限区间（noise-limited regime）**：批次大小增加，梯度噪声降低，每个额外样本带来的收益接近完美——存在几乎线性的缩放。
- **偏差受限区间（bias-limited regime）**：达到梯度的噪声尺度后，局部下降方向与全局最优方向之间总有偏差，增加批次大小的收益递减。
- **临界批次大小**：从近似完美缩放到收益递减的转折点，是一个工程上的经验法则。

#### 5.2 估计方法（McCandless / OpenAI 的方法）

1. 选择一个目标损失值。
2. 训练几个小模型，在不同批次大小下测量达到目标损失所需的步数和样本数。
3. 归一化后，步数需求与样本数需求呈反比关系，形式上为 $S_{\min}/B + B/S_{\min}$ 类型的权衡。
4. 解平衡方程，临界批次大小约为 $B_{\text{crit}} \approx S_{\min}/E_{\min}$（所需最小样本数除以所需最小步数）。它平衡了收敛速度和总样本消耗。

#### 5.3 与计算规模的幂律关系

临界批次大小随目标损失降低（即模型质量提升）而增大，且呈幂律关系。直觉：越接近最优，噪声的影响越明显，方差缩减的价值越大。因此大规模训练运行可以采用较大的批次大小。

### 6. 学习率的缩放

- 简单的宽度缩放心智模型：模型越大，同时改变的参数越多，学习率应越小。经验法则：学习率大致按宽度的倒数缩放。
- 另一种思路是重参数化（如 μP，Maximal Update Parametrization），通过调整初始化大小和优化器步长来使不同规模下最优学习率保持不变。
- 两种哲学（估计最优学习率随规模的变化 vs. 让最优学习率不变）都在大规模训练中有成功实践。

### 7. 上游与下游性能的差异

困惑度（perplexity）与参数量高度线性相关，非常可预测。但下游任务表现不一定与困惑度完全一致。课程给出了一个极端例子：在可预测的困惑度趋势中排名靠后的模型在下游任务上反而超过了困惑度更好的模型。Scaling laws 通常对困惑度（或训练损失）适用良好，但从困惑度到下游任务的迁移远不如表面看起来可信。

> **解释**：预训练者应关注迁移问题，不能只报告困惑度。这是对“上游干净、下游可靠”这一直觉的警告。

## 关键公式与原则

| 内容 | 公式 / 原则 |
|---|---|
| 数据 scaling law（一般形式） | $\text{loss}(D) \propto D^{-\alpha} + c$，双对数图为直线 |
| 均值估计 | 误差 $= \sigma^2 / n$（斜率 −1） |
| 非参数回归 | 误差 $\approx n^{-1/d}$（$d$ 为输入维数） |
| 观测的指数 | 约 −0.1 到 −0.3，对应 $d \approx 10$ |
| 联合缩放（Rosenfeld 形式） | 损失 = 数据项 + 模型项（两个幂律之和） |
| 计算最优配置 | 固定 FLOPs 时在数据量与模型规模之间取最优权衡 |
| Kaplan 结论（近似） | 数据规模 $\propto C^{0.73}$，模型规模 $\propto C^{0.27}$（训练参数增长快于数据） |
| Chinchilla 结论 | 数据规模和模型规模基本同步增长，约 20 tokens / 参数 |
| 临界批次大小 | $B_{\text{crit}} \approx S_{\min}/E_{\min}$，随目标损失降低而增大 |

**核心原则**：

1. 对数-对数图上的线性关系 = 幂律 = 多项式衰减。
2. 远离渐近线时，幂律成立；接近不可约误差时偏离直线。
3. 斜率通常非常稳定，绝大多数干预只改变截距。
4. Scaling laws 只在正确的 x 轴、正确的超参数配置下成立——它是“工程出来的”。

## 常见误区

1. **认为 scaling laws 是自然规律，不需要调参**。实际上，不合理的预热方案、批次大小或参数计数方式都会导致缩放定律严重偏移。Scaling laws 描述的是“如果我继续用这个配方放大，结果会怎样”，而不是“所有放大都会这样”。
2. **认为 Kaplan 或 Chinchilla 的系数是普适常数**。二者的差异来自超参数、参数计数、批次大小等细节。任何一组系数都需要在自己设定的训练配置下重新验证。
3. **在接近不可约误差的数据规模上拟合双对数直线**。一旦进入渐近线区域，曲线会弯曲，幂律不再成立。必须确认自己处于幂律区间，或显式拟合常数项。
4. **直接在下游基准上依赖缩放定律**。下游任务迁移远不如困惑度干净。Scaling laws 的可靠预测对象是训练/验证损失（困惑度），下游性能不一定服从同样的规律。
5. **认为增大批次大小总是无代价**。超过临界批次大小后收益递减；批次大小的最优值随目标损失提高而增大，不是固定的。
6. **把 Chinchilla 的 20 tokens/参数当作生产级模型的黄金比例**。如果你要部署推理服务，你会倾向于“过度训练”（即训练更多 token、使用更小模型），因为推理成本往往超过训练成本。20:1 是训练计算最优，不一定是总成本最优。
7. **忽略重复数据的后果**。超过约 4 个 epoch 后性能明显受挫，且不能通过无限增加模型大小来弥补——需要采用其他方法（如集成）。
