# CS336 Lecture 2 深度解析：从 PyTorch 到资源核算——训练大模型前的必修课

> 在动手训练大模型之前，你必须回答两个问题：这个模型需要多少计算量？它需要多少内存？本讲将为你建立一套完整的"资源核算"方法论，让你在写下第一行训练代码之前，就能对成本心中有数。

## 导语：为什么需要资源核算？

在上一讲中，我们了解了语言模型（Language Model）的整体蓝图：从分词（Tokenization）到模型架构，再到训练策略。但有一个关键问题被搁置了——**在给定的硬件资源下，我们究竟能训练多大的模型？需要多长时间？**

本讲的核心目标是培养一种"资源核算"（Resource Accounting）的思维模式。这不是一个可选的优化技巧，而是训练现代大模型的**必要前提**。当你面对一个 700 亿参数的模型时，你不可能凭借直觉去猜测训练时间；你必须能够精确计算出所需的 FLOPs（浮点运算数）、内存占用，并理解硬件特性如何影响实际性能。

课程一开始，讲师就展示了两个极具实战性的问题：
1. 在 1024 块 H100 上训练 700 亿参数、1.5 万亿 token 的模型需要多久？答案是约 143 天。
2. 在 8 块 H100 上用 AdamW 优化器能训练的最大模型是多大？答案是约 530 亿参数。

这些数字不是凭空产生的，它们来自一个简单的公式：**FLOPs = 6 × 参数量 × token 数**。这个公式将成为你进行任何规模估算的起点。

## 一、张量：一切的基础

在深度学习的世界里，所有东西归根结底都是**张量**（Tensor）。参数、梯度、优化器状态、激活值、输入数据——它们都是不同形状和精度的张量。即使是像 DeepSeek 这样的大模型，其本质也就是一组具有特定形状的张量集合。

理解张量存储的内存占用非常简单：**内存 = 元素个数 × 每个元素的字节数**。例如，一个 4×8 的 float32 矩阵占用 128 字节（4×8×4）。

但现代深度学习早已超越了 float32 的范畴。让我们看看各种精度类型如何影响内存和性能：

### 精度选择：一场内存与稳定性的权衡

**float32（fp32）**：这是默认的精度，每个数占 4 字节。在深度学习中，我们很少使用更高精度的 float64，因为训练过程的随机性意味着我们不需要那么高的数值精度。

**float16（fp16）**：占 2 字节，看似是节省内存的好选择。但它的动态范围太窄——指数位只有 5 位（fp32 有 8 位）。如果你尝试用 fp16 表示 1e-8，它直接变成 0（下溢）。这会导致训练不稳定、出现 NaN 等问题。

**bfloat16（bf16）**：这是 Google Brain 在 2018 年开发的创新。它同样占 2 字节，但**拥有和 fp32 相同的动态范围**！秘诀在于它牺牲了尾数位来换取指数位。虽然分辨率（precision）变差了，但事实证明，在深度学习中这个权衡非常值得——毕竟训练过程本身带有随机性，不需要那么精细的粒度和精度。

**混合精度训练**：现代训练的标准做法是混合精度（Mixed Precision）——用 bf16 存储参数、激活值和梯度，用 fp32 存储优化器状态。PyTorch 的 AMP（Automatic Mixed Precision）库可以自动处理这个转换，在安全的情况下（如矩阵乘法）使用低精度，在危险的地方（如指数运算）保持高精度。

讲师还提到了更极端的选项：fp8 和 fp4。fp8 有两种变体，分别优化动态范围和分辨率；fp4 则每个值只有 4 比特，可能取值的范围从 -6 到 6。这些极端量化通常使用分块缩放（block scaling）来弥补精度的不足，但主要用于推理而非训练。

## 二、einops：让张量操作变得清晰

在进入 FLOPs 计算之前，讲师介绍了 einops 库——一个让张量操作变得直观的工具。传统的 PyTorch 操作如 `x @ y.transpose(-2, -1)` 很容易让人困惑：-2 和 -1 到底指什么维度？

einops 的核心理念是**给维度命名**。例如：

```python
z = einsum(x, y, "batch seq1 hidden, batch seq2 hidden -> batch seq1 seq2")
```

这个表达式清晰说明了：我们有两个输入张量，第一个的维度是 (batch, seq1, hidden)，第二个是 (batch, seq2, hidden)，输出是 (batch, seq1, seq2) —— 同时自动在 hidden 维度上求和（该维度未出现在输出中）。

einops 还提供 `reduce`（用于求和、求均值等操作）和 `rearrange`（用于重塑维度）。这些工具让代码更具可读性，也减少了人为错误。讲师特别强调：**习惯 einops 后，你会以不同的方式思考张量操作**——不再纠结于转置和索引，而是聚焦于数据流本身的逻辑。

## 三、FLOPs：衡量计算量的标准

**FLOPs（浮点运算数）**是衡量计算量的核心指标。它记录的是浮点运算的次数，如加法和乘法。与之容易混淆的是 **FLOP/s**（每秒浮点运算次数），后者衡量硬件速度。

计算一个操作的 FLOPs 通常很简单：

**矩阵乘法（MatMul）**：对于一个 B×D 的矩阵乘以 D×K 的矩阵，FLOPs = 2 × B × D × K。这个 2 来自每次乘法和加法。这在大多数情况下是准确量级（忽略了 D-1 次加法而非 D 次这种细微差别，对于大矩阵几乎无影响）。

**逐元素操作**：FLOPs = 元素个数。例如，ReLU 每次比较算一个 FLOP。

**关键洞察**：对于足够大的矩阵，**矩阵乘法的 FLOPs 远远大于其他操作**。这就是为什么我们在设计模型时，要尽量将计算重负载集中在矩阵乘法上。

### 6ND 公式的推导

现在让我们推导那个神奇的公式：**训练一个模型的 FLOPs ≈ 6 × 数据点数 × 参数量**。

假设一个简单的深度网络，每层是矩阵乘法加 ReLU：
- 前向传播：2 × B × D × D（这是矩阵乘法的 FLOPs，B 是数据点数，D 是参数维度）
- 反向传播：需要计算两个梯度——对输入的梯度（即回传的消息）和对参数的梯度。这两个操作各需要 2 × B × D × D 的 FLOPs，所以反向传播总共是 4 × B × D × D。

总 FLOPs = 前向 (2BD²) + 反向 (4BD²) = 6BD² = **6 × 数据点数 × 参数量**（这里参数量 = D²）。

这个公式对于 Transformer 也是一个很好的近似，只要上下文长度不太长（如果上下文长度过长，注意力机制会引入额外的二次项）。

## 四、从理论到实践：MFU 与算术强度

知道模型的 FLOPs 只是第一步。真正的问题在于：你的硬件能否高效地执行这些操作？

### MFU：模型 FLOPs 利用率

**MFU（Model FLOPs Utilization）** 衡量实际达到的 FLOP/s 与理论峰值的比值：

```
MFU = 实际 FLOP/s ÷ 宣传 FLOP/s
```

问题在于，实际 FLOP/s 往往远低于规格说明书上的峰值。H100 的 bf16 峰值大约是 989 TFLOP/s（1979 除以 2，因为 1979 是稀疏模式的数值，稠密模式减半）。但在实际训练中，MFU 达到 50% 就已经很不错了。

为什么 MFU 这么低？答案在于**内存带宽**。

### 算术强度：计算与内存的平衡

这就是为什么我们需要理解**算术强度**（Arithmetic Intensity）：

```
加速器强度 = FLOP/s ÷ bytes/s（H100 大约是 989e12 ÷ 3.35e12 ≈ 295 FLOPs/byte）
算法算术强度 = FLOPs ÷ bytes（特定工作负载）
```

**核心规则**：
- 如果算法算术强度 < 加速器强度 → **内存受限**（Memory-bound）：瓶颈在数据传输
- 如果算法算术强度 > 加速器强度 → **计算受限**（Compute-bound）：瓶颈在计算本身

让我们看几个具体例子（假设 bf16，2 字节/数）：

**ReLU**：读 x（2n 字节）+ 写 y（2n 字节），FLOPs = n（一次比较）。算术强度 ≈ 0.25 → 严重内存受限。这意味着 ReLU 的性能实际上与计算无关，完全取决于传输速度。

**GELU**：虽然计算量更大（约 20n FLOPs），算术强度 ≈ 5，但仍然远低于 295 → 还是内存受限！**所以 GELU 和 ReLU 相比并没有显著的性能劣势**——瓶颈根本不在于计算。

**点积**：读两个向量（2n + 2n 字节），FLOPs = 2n。算术强度 ≈ 0.5 → 内存受限。

**矩阵向量乘法**：读 x（2n）+ 读 w（2n²）+ 写 y（2n），FLOPs = 2n²。算术强度 ≈ 1 → 内存受限。这正是**推理**（单个 token 逐个生成）的场景。

**矩阵乘法**：三个 n×n 矩阵参与，FLOPs = 2n³，传输字节数 = 6n²。算术强度 ≈ n/3 → **计算受限**！矩阵越大，这个比值越大，硬件利用率越高。

这个分析解释了为什么训练（使用大批量、大矩阵）比推理（单 token 逐步生成）的硬件利用率要高得多。也解释了为什么总有人强调"扩大批量大小"——更大的矩阵不仅数据效率更好，计算效率也更高。

### 为什么 MFU 只有 50%？

现在我们可以回答这个问题了。即使训练过程充斥着计算受限的矩阵乘法，仍然会有许多内存受限的操作（如激活函数）穿插其间。此外，GPU 的异步执行、通信开销等因素都会拉低实际利用率。所以，MFU 达到 50% 是常态，70-80% 则非常优秀。

## 五、训练的内存清单

现在让我们转向训练的实际内存需求。以一个深度网络为例：

**参数**：对于 L 层、每层 D×D 的矩阵，参数量 = D²L。用 bf16 存储：2 × 参数量 字节。

**梯度**：每个参数对应一个梯度，用 bf16 存储：2 × 参数量 字节。

**优化器状态**：这里通常使用 fp32（4 字节/参数）以保证稳定性：
- AdaGrad：存储梯度平方，4 字节/参数
- AdamW：存储一阶矩 + 二阶矩，8 字节/参数！

**激活值**：训练需要存储前向传播的中间结果用于反向传播。对于每层：2 × B × D × L 字节（bf16）。这解释了为什么批量大小（B）和层数（L）会显著影响内存需求。

**关键洞察**：现代深度学习训练中，**优化器状态往往消耗最多内存**，远超模型参数本身。这导致了一个悖论：16 位模型参数确实节省了内存，但为了训练稳定性，优化器状态仍然需要 32 位精度，这构成了主要的存储开销。

## 六、内存优化策略

既然内存如此宝贵，讲师介绍了两种重要的优化方法：

### 梯度累积（Gradient Accumulation）

当我们想使用大批量（如 64）但内存无法容纳时，可以将其拆分为多个微批次（如 4 个 16 的微批次）：

1. 在每个微批次上计算梯度
2. **不清除**梯度，而是累加
3. 每积累 4 个微批次后，执行一次参数更新

通过这种方式，我们可以享受大批量的训练稳定性，同时将激活内存降低了 4 倍。代码改动仅几行，却带来了显著的内存节省。

### 激活检查点（Activation Checkpointing）

默认情况下，训练需要存储所有层的激活值（O(L) 内存）。激活检查点（也称梯度检查点或重计算）通过**用计算换内存**：

**核心思想**：
- 在前向传播中，只存储某些"检查点层"的激活值（比如每 sqrt(L) 层存一个）
- 在反向传播中，当需要某个层的梯度时，从最近的检查点重新计算缺失的激活值

**权衡分析**：
- 不检查点：内存 O(L)，计算 O(L)
- 完全检查点（不存任何激活）：内存 O(1)，但计算 O(L²) —— 因为每一层都要从头重新计算
- 每 sqrt(L) 层设检查点：内存 O(sqrt(L))，重计算开销 O(sqrt(L))——这是在内存和计算之间的一个理想平衡

## 结论与展望

本讲的核心收获可以概括为以下几点：

1. **一切皆为张量**：模型、数据、优化器状态，本质上都是张量，内存计算是资源核算的基础。
2. **einops 让张量操作清晰明了**：通过命名维度，大幅减少出错概率。
3. **6ND 公式**：训练一次迭代的 FLOPs ≈ 6 × 数据点数 × 参数量，让你能快速估算训练成本。
4. **算术强度与 Roofline 分析**：理解一个计算是内存受限还是计算受限，是优化性能的前提。
5. **内存优化**：梯度累积和激活检查点是降低训练内存需求的两大实用工具。
