Three Adaptation Paradigms

     Weight updates (Fine-tuning / RL)
     Pros: strong and compact at inference
     Cons: slow iteration, infra heavy, hard to audit/rollback


     Retrieval (RAG)
     Pros: injects facts, modular
     Cons: weak for procedures and contexts, tool protocols, “how-to” knowledge


     Context evolution (this talk)
     Pros: fast test-time learning, interpretable, model-agnostic
     Cons: needs stability + cost control at long horizons (next few slides)

Formalizing Context Evolution as a System Problem
• With ACE, we have a state and an update operator over that state, under an autonomous
  agent loop architecture


• State: a better representation of evolving context as first-class citizen
    • Sections
    • Itemized bullets + metadata → localization, fine-grained retrieval, incremental
      adaptation, periodic de-duplication and clean-up
• Update operator: delta updates + deterministic merge
    • Compact delta contexts instead of full rewrites → preserves old knowledge, avoids
      collapse, enables batching/parallel learning
• Architecture: autonomous loop + structured division of labor
    • Separates execution, insight extraction, and integration (and allows iterative
      refinement)

Where We See This Going
• We can treat context as a fast, test-time medium for continual learning, and then selectively
  distill it into weights when it stabilizes.
• Parallel context learning at scale: Combee, COLM 2026
• Meta-evolution for memory systems and harnesses: Meta-Harness, COLM 2026
• Safety + correctness of updates (ML + systems)
• Consolidation (learning): In-context or weight-update self-distillation
