     Actor-Critic Methods
          A better baseline: want to push the probability of an action from a state, if this action was
          better than the expected value of what we should get from that state.

          Q(s,a) and V(s) - action and state value functions!
          Q(s,a): how much total reward should I expect by taking action a from state s.
          V(s): how much total reward should I expect from state s.

          We are happy with an action a in a state s if the advantage function A(s,a) = Q(s,a) - V(s) is
          large. Otherwise we are unhappy with an action if it’s small.

          Using this, we get the estimator:

      Reinforcement Learning from Human Feedback
      Step 0: Pre-train LLM and perform supervised fine-tuning;
      Step 1: For each prompt, treat the LLM as a policy and sample multiple responses from the model;
      Step 2: Humans rank these outputs by quality;
      Step 3: Train a reward model to predict human preferences / ranking, given full model responses;
      Step 4: Use RL (e.g. PPO, GRPO) to fine-tune the model to maximize the reward model’s scores.

     The RL Part: PPO
     3 components:

     1. Actor model/policy: LLM that has been pre-trained and supervised fine-tuned;
     2. Reward model: Trained and frozen model that predicts human preference as a scalar reward, given full
     model responses;
     3. Critic model/value: Learnable value function takes in partial model responses and predicts value V(s).

     Recall Actor-critic models!!


                                                               Critic: evaluates how good the action is




                                                               Actor: decides what actions to take
25



     The RL Part: PPO
      Algorithm:
      1. Generate responses: LLM produces response for a given prompt;
      2. Score responses: The reward model assigns reward for each response;
      3. Compute advantages A(s,a) = Q(s,a) - V(s). Value model estimates how much better a specific action a
      (i.e., word) is compared to an average action given state s (i.e., prompt + generated words so far).
      4. Optimize policy: Update the LLM by optimizing the PPO objective (KL + clip to penalize large changes);
      5. Update value: train the value function to be better at estimating values given partial responses.

      GRPO (Deepseek R1)
       Key differences: GRPO forgoes the value model, instead estimating the baseline from average of rewards
       from a group of responses (requires large group size for accurate baseline estimation).




[Guo et al. Deepseek-r1: Incentivizing reasoning capability in LLMs via reinforcement learning. arXiv 2025]
 27



      GRPO (Deepseek R1)




             Key differences:
             1. Group of responses used to compute advantage and gradient updates.
             2. No learned value function, just simple statistics of rewards over a group.
             3. Abandon reward models and use rule-based verifiers (binary checks, test-cases, length, format).



[Guo et al. Deepseek-r1: Incentivizing reasoning capability in LLMs via reinforcement learning. arXiv 2025]

      Direct Preference Optimization
      DPO is not actually doing reinforcement learning.
      It does not infer rewards from preference data, instead directly increases likelihood of preferred responses
      and decreases likelihood of other responses.

      More similar to supervised learning, also known as ‘offline preference optimization’.




[Rafailov et al. Direct preference optimization: Your language model is secretly a reward model. NeurIPS 2023]
