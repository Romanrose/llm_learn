         Q: Why start a new subprocess.run for every action instead of keeping one shell open?

         A: With one long-running shell, the harness has to guess when a command’s output is finished, and one bad or interrupted
         command can break the shell for every later step. subprocess.run returns when the command exits, with its output and exit
         code. The cost: cd and export don’t carry over, so the model writes cd src && pytest.

      run(): Exceptions as Control Flow
        def run(self, task):                                                                                       ① rules + task
            self.messages = []
            self.add_message("system", render(system_template))
            self.add_message("user",   render(instance_template, task=task))                                       ② loop
            while True:
                try:
                    self.step()                                                                                    ③ recoverable → tell the LM
                except NonTerminatingException as e:   # format error, timeout
                    self.add_message("user", str(e))
                except TerminatingException as e:      # submitted, limits
                    self.add_message("user", str(e))
                                                                                                                   ④ terminal → exit
                    return type(e).__name__, str(e)



        Q: Why does every problem become an exception instead of a returned error code?

        A: Errors start deep inside query, parse_action and execute_action; run() handles them in one place: recoverable ones go
        back to the model as a message, terminal ones end the run.
