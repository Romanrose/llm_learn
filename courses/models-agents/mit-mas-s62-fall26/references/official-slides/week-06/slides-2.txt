    Recap: Harness Evolution
    MEM1: treat memory as internal state in context autonomously updated by LLM
    CLM: treat entire context as persistent file autonomously maintained and rewritten by LLM
    Meta-Harness: treat entire harness as a file system autonomously modified by LLM

    What’s common about all these methods?
    - Simple, no hand engineering, end-to-end
    - New paradigm that generalizes what can be autonomously optimized
      (memory -> context -> harness)
    - Scalable results for zero-shot, in-context prompting, fine-tuning

    RLM: more structure in task decomposition and context management with recursive calls to
    sub-agents. but still highly scalable!

      When Does Multi-Agent Work?
      More agents does not automatically improve performance: scaling depends on
      task structure and multi-agent topology.




[Kim et al., Towards A Science of Scaling Agent Systems. Nature Machine Intelligence 2026]
 26



      When Does Multi-Agent Work?
      Finding 1: Multi-agent systems only help for certain types of tasks.

                                                                                        Ex 1. Finance agent (MAS wins +81%)
                                                                                        -> Task naturally decomposes
                                                                                        (revenue/cost/market)

                                                                                        Ex 2. PlanCraft (MAS loses -70%)
                                                                                        -> Sequential dependency
                                                                                        (action 1 affects action 2)
                                                                                        -> Splitting tasks hurts rather than helps

                                                                                        Guidelines:
                                                                                        Parallelizable tasks -> centralized
                                                                                        Exploration needed -> decentralized
                                                                                        Sequential dependency -> single-agent

[Kim et al., Towards A Science of Scaling Agent Systems. Nature Machine Intelligence 2026]
 27



      When Does Multi-Agent Work?
      Finding 2: Different base models exhibit different cost-performance tradeoffs.
      OpenAI: performance plateau despite increasing cost.
      Google: higher cost, higher performance.
      Anthropic: MAS can hurt performance.




[Kim et al., Towards A Science of Scaling Agent Systems. Nature Machine Intelligence 2026]
 28



      When Does Multi-Agent Work?
      Finding 3: Increasing number of agents does not always improve performance.
      Tool-heavy tasks (e.g., 16-tool workflows) suffer from multi-agent coordination overhead, with
      penalties compounding as environment complexity increases.




[Kim et al., Towards A Science of Scaling Agent Systems. Nature Machine Intelligence 2026]
 29



      When Does Multi-Agent Work?
      Finding 4: Mixtures of heterogeneous agents can outperform better base agents.
      We don’t need expensive models everywhere. If single agent baseline > 45%, MAS hurts.
      Cheap orchestrator + expensive execution sub-agents seems to work well.




[Kim et al., Towards A Science of Scaling Agent Systems. Nature Machine Intelligence 2026]
 30



      When Does Multi-Agent Work?
      Finding 5: Agent-system performance can be predicted.
      A scaling law using models, tasks, MAS setup as parameters predicts the best architecture
      87% of the time. From heuristics ("try a setup") to more principled science of agent design.

     Multi-Agent Evolution
     Given multi-agent systems don’t always work and depend on critical hyperparameters
     (e.g., task, base models, topologies), there have been recent attempts at automating
     the multi-agent design space, instead of relying on hand engineering.
     i.e., Multi-agent evolution/optimization.

     What can be evolved?
     - Individual models and agents (i.e., models, context, harness)
     - Multi-agent system (i.e., agent roles, communication, topologies)
     - Shared information (i.e., common memory, tools, skills)

     Lecture Summary
     • Planning and task decomposition is increasingly important for efficient agents.
     • Multi-agent systems bridge planning + execution, decentralized exploration,
       multimodal agents. But they don’t always work better!
     • Multi-agent evolution can help turn hand engineering into autonomous
       optimization of multi-agent systems.
