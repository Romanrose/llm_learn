      Guest Lecture: Self-Distillation
                                                            Idan Shenfeld
                                                            Idan Shenfeld is a Member of Technical Staff at Thinking Machines Lab.
                                                            He did his PhD at MIT with Pulkit Agrawal in the Improbable AI Lab, where
                                                            he worked on reinforcement learning for language models, and in
                                                            particular on how a model can keep learning new skills without forgetting
                                                            what it already knows. His paper RL’s Razor (ICLR 2026) showed that on-
                                                            policy RL forgets less than supervised fine-tuning because it stays closer
                                                            to the original model. The follow-up, Self-Distillation Enables Continual
                                                            Learning (ICML 2026; Best Paper, ICLR Lifelong Agents Workshop),
                                                            turned this into a method that needs no reward: given a demonstration in
                                                            its prompt, the model becomes its own teacher. Cursor has since used
                                                            self-distillation to train Composer 2.5. During his PhD, he also worked on
                                                            LLM post-training at Google DeepMind.

       Recap: RL for LLMs: PPO and GRPO
                                                                                                                 An LLM as a policy: each token is an action
                                                                                                                 prompt x = “What is 5 + (2 × 3)?”

                                                                                                                       action yt ~ πθ(·|st)

                                                                                                                  x    5    +    2   is   7   ,   … 21     .      r=0

                                                                                                               state st = (x, y<t)                       reward: once, at the end


                                                                                                                 a wrong answer (21 ≠ 11) → r = 0




          policy-gradient loss: L(θ) = − Σt At log πθ(yt | st)
          PPO / GRPO in practice: L(θ) = − Σt min( ρtAt , clip(ρt, 1−ε, 1+ε) At ), ρt = πθ(yt|st) / πold(yt|st)


          PPO: At = Q(st, yt) − V(st)                                                                     GRPO: Âi = ( ri − mean(r) ) / std(r)
          V = a learned value model (GAE)                                                                 over G answers to the same prompt; no V

       Recap: On-Policy Distillation and Self-Distillation
        prompt: “What is 5 + (2 × 3)?”                                                                                           ① student writes y ~ πθ
                                                                                                                                 ② teacher scores every token
                                                                                                                                 ③ student moves toward it



          reverse KL per token: KL(πθ ‖ πT) = Eyt~πθ[ log πθ(yt|st) − log πT(yt|st) ]
          gradient: ∇KL = − Eyt~πθ[ At ∇log πθ(yt|st) ], At = log πT(yt|st) − log πθ(yt|st) (as E[∇log πθ] = 0)
          → a policy-gradient loss: L(θ) = − Σt At log πθ(yt|st)

                  OPD: the teacher is another, bigger model πT                                                self-distillation: the teacher is the model itself + c

        teacher reads        x    y<t    → πT(yt | x, y<t)                                             teacher reads    c   x   y<t   → sg[ πθ(yt | c, x, y<t) ]

         At = log πT(yt|st) − log πθ(yt|st)                                                              At = log πθ(yt|c, st) − log πθ(yt|st)
         e.g. Qwen3-32B teaching Qwen3-8B                                                                c = a demo (SDFT), the solution (OPSD), feedback (SDPO)

       RL vs OPD
                                                                    same loss: L(θ) = − Σt At log πθ(yt | st)

                                                                                                           RL At = r − baseline
                                                                                                           → one number for all tokens


                                                                                                           OPD At = log πT(yt|st) − log πθ(yt|st)
                                                                                                           → one number per token


                                      RL                                                                               OPD

         information                  O(1) bits per episode                                                            O(N) bits, N = tokens

         learns toward                high reward (can be hacked)                                                      the teacher (its ceiling)

       OpenClaw-RL: Training on Human Feedback
                                                                                                                example: a TA uses the agent to grade homework


                                                                                                                 agent: Correct answer: 220. Your solution is correct.



                                                                                                                      user: Too brief. Tell the student why each step is right.



                                                                                                                ① RL: a judge reads the reply: good or not?
                                                                                                                → r = −1: the same A for every token of the answer

                                                                                                                ② Self-distillation: the judge turns the reply into a hint h
                                                                                                                (“explain each step”); the same model with h in its prompt is
                                                                                                                the teacher
                                                                                                                → At = log πθ(yt | h) − log πθ(yt), per token


         loss = ① + ②, on the same responses, in one update
         ① a score on every turn, but one number; ② which tokens to change, but only when the reply has a correction

      Batch → Mini-batch → Micro-batch

                       training batch = B × n = 5120 responses                                       n = rollout.n = 5 responses per prompt
                                                                                                     → B × n = 5120 responses = one rollout

                                                                                                     M = ppo_mini_batch_size = 256 prompts
         mini-batch 1           mini-batch 2           mini-batch 3           mini-batch 4
                                                                                                     → B ÷ M = 4 optimizer steps
         M × n = 1280           M × n = 1280           M × n = 1280           M × n = 1280
                                                                                                     mini-batch: the data for one weight update

        GPU 1      GPU 2        GPU 3     GPU 4      GPU 5       GPU 6       GPU 7     GPU 8         G = 8 GPUs (data parallel)
         160        160          160       160        160         160         160       160          → M × n ÷ G = 160 responses per GPU

          4        4        4        4        4        4        4        4        4        …         → 160 ÷ m = 40 micro-batches = grad accumulation
                                                                                                     micro-batch: split only so it fits in GPU memory

        Q: On-policy = trained on samples from the current weights. Mini-batch 1 or 2: which is on-policy?

        A: 1 only. With more than one mini-batch, the model is updated after each one, so from 2 on it is no longer the policy that sampled
        the rollout: πθ ≠ πold.

       The Same Step in verl
       # PPOTrainer.step(), sync mode (verl default)
       self._add_batch_to_generate()                                                                                                   ① rollout: n responses per prompt

       batch = self.replay_buffer.sample(batch_size=B)                                                                                 ② reward: scored as each finishes

       self.checkpoint_manager.sleep_replicas()                                                                                           free GPU memory for training

       batch = self._balance_batch(batch)                                                                                              give every GPU similar total tokens

       batch = self._compute_old_log_prob(batch)
       if self.use_reference_policy:
             batch = self._compute_ref_log_prob(batch)                                                                                 log-probs (old, reference) and values

       if self.use_critic:
             batch = self._compute_values(batch)
       batch = self._compute_advantage(batch)                                                                                             ③ advantage: the algorithm

       batch = self._update_actor(batch)                                                                                               ④ update: one step per mini-batch

       self.checkpoint_manager.update_weights(self.global_steps)                                                                        ⑤ weight sync → rollout engine
