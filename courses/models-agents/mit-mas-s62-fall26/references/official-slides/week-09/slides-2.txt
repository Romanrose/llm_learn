Other works in Competitive LLM Self-Play
● Language Self-Play (Kuba et al., 2025): shared model; open-ended prompts, learned reward.
  Rₚ = −E[Rₛ] + self-reward regularization (prevents collapse).
  Added +0.7 pp over RL alone: 39.5% vs 38.8% AlpacaEval win rate (Llama-3.2-3B).
● Absolute Zero Reasoner (Zhao et al., 2025): Python-verified deduction, induction, abduction.
  Rₚ = (1 − r̄ ) 𝟙[0 < r̄ < 1]; Rₛ = 𝟙[correct]. No human task data.
  7B-Coder: 50.4 vs 44.3 AceCoder-Rule RL (+6.1 pp aggregate); different data/recipes.
● R-Zero (Huang et al., 2025): math questions; majority-vote pseudo-labels, no executor.
  Rₚ = max(0, 1 − 2|p̂ − ½| − repetition penalty); malformed tasks get 0.
  Qwen3-4B: 49.93 vs 45.01 with untrained challenger (+4.92 pp); no standard RL-only control.
● STP (Dong & Ma, 2025): conjecturer–prover self-play in Lean / Isabelle.
  Filter: 0 < proof pass rate ≤ ¼; lemma-use, elegance and diversity checks.
  Expert iteration on verified proofs; LeanWorkbook: 26.3% vs 13.2% prior expert iteration.
● Self-Challenging Agents (Zhou et al., 2025): tool-use tasks include executable verifiers.
  No learned proposer reward: filter using passing solutions + failing cases; R ₛ = verifier.
  8B: 23.5 vs 12.9 PAE (+10.6 pp mean pass@1); both use synthetic-task RL.
● Skill Self-Play (Huang et al., 2026): an evolving skill library guides task generation.
  Rₚ = 𝟙[valid] · (1 − 2|vₛ − ½|), with repetition penalty during RL.
  Tool calling: +2.8–6.5 pp vs Qwen/Granite base; comparator is unguided SP, not RL-only.

The Issue with Competitive Self Play
- The proposer is incentivized to generate hard problems, and it does.
- But not all hard problems are useful for the solver’s training.
- How do we incentivize the proposer to generate hard, useful
problems?

Other Cooperative Self Play Works
● SGS (Bailey et al., 2026):
  Adds a Guide that scores conjectures for relevance to unsolved targets and mathematical naturalness, steering
  self-play toward useful subproblems.
● LADDER (Simonds & Yoshiyama, 2025):
  Recursively generates easier variants of failed problems and learns from their
  solutions to build the skills needed for the original problem.
● SEAL (Zweiger et al., 2025):
  Learns to generate its own finetuning data and update instructions, rewarding self-
  edits by the adapted model’s downstream performance.
● CPMöbius (Li et al., 2026):
  Trains a task-generating Coach with rewards tied to the Player’s post-update
  accuracy gains, aligning the curriculum with learning progress.
● CompassPlay (Pu et al., 2026):
  Rewards task proposals by gradient alignment with target capabilities,
  approximating their learning value without additional solver training.
● Self-Play Pretraining (Cowsik et al., 2026):
  Co-trains a program generator and byte predictor from scratch, rewarding data
  whose gradients align with the learner’s recent progress.

Verification and Error Propagation
● Recursive training can amplify errors across generations
● Unreliable filtering lets models reinforce their own mistakes
● Sufficiently reliable self-verification can prevent collapse, even with
  fully synthetic data

Self-Improvement: The Sharpening Mechanism

● Use the model’s own scoring signal to select responses, then train it to
  generate those responses more reliably.
● Sharpening amortizes expensive inference-time selection into the
  model’s weights.
● Better self-scores imply better answers only when the scoring signal is
  useful.
