    Glossary of what is Stored in Harness
    Eg. In a coding agent harness

    Episode/trajectory: state, action, next state, next action (e.g., good debugging examples)
    Feedback: rewards, critiques, human preferences (e.g., user prioritizes clean code)
    Facts: semantic knowledge (e.g., sorting function has certain complexity)
    Tools: task-specific atomic (external) action (e.g., running python interpreter)
    Skills: task-agnostic reusable procedure (e.g., use gdb to debug)
    Artifacts: generated pr optimized outputs (e.g., generated code)
    Plans: decomposed tasks and sub-goals (e.g., read requirements, write, modularize)
    Experience: often used vaguely, encompasses trajectories, feedback, skills

      Context Language Models
      Wrapping up our discussion of context, memory, and harnesses, Context Language Models natively manage
      their own context by treating context as a file and allowing models to make unrestricted edits to this file.




      Context-as-a-file implementation: LM’s live context as a directly editable file with path provided in system prompt. LM
      edits this file using Bash commands, just like other files. Edits to context file are synchronized with the LM’s context.

      Multi-agent extensions: multiple context files can coexist and remain synchronized with their respective LLMs agents.
      Subagents can be initialized and terminated by creating and deleting additional context files.



[Shao et al., Context Language Models. arXiv 2026]

     Harness Part 2: Tools and Skills
     Definition of tools: A task-specific atomic action that the agent can execute.
     e.g., searching for a specific paper from a database and retrieving into context.

     Definition of skills: A task-agnostic reusable procedure that an agent learns as part
     of completing a task. Often combines reasoning and multiple tool calls.
     e.g., how to do a comprehensive search, clustering themes, writing a summary.

     Summary of Harnesses
     My favorite methods out of the ones covered today:

     MEM1: treat memory as internal state in context autonomously updated by LLM
     CLM: treat entire context as persistent file autonomously maintained and rewritten by LLM
     Meta-Harness: treat entire harness as a file system autonomously modified by LLM

     What’s common about all these methods?
     - Simple, no hand engineering, end-to-end
     - New paradigm that generalizes what can be autonomously optimized
       (memory -> context -> harness)
     - Scalable results for zero-shot, in-context prompting, fine-tuning
