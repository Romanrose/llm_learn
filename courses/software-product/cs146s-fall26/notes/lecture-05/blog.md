# 把“我每次都得提醒你”变成一个可维护的 Skill

> 围绕 CS146S Fall 2026 lecture-05 的独立文章。文中场景为本站假设案例，分析和实践建议由本站编写；课程主题依据见[官方讲义](https://docs.google.com/presentation/d/15bPu5c-i8D8McTh6l7SpUPk2n9M_Y-CdDQLfyzL8RD8/htmlpresent)。课表与课件日期存在一天差异，详见本讲笔记。

每次整理课程，我们都会提醒智能体三件事：先核对学期，作业链接要追到官网，打不开的材料不能写成已经读过。重复到第三次，这些提醒已经形成了一段可以整理的工作经验。

## 先定位可以观察的问题

把提醒直接复制成一篇长文还不够。需要进一步说明它什么时候生效、要检查哪些来源，以及证据不够时如何记录。例如，资料接入 Skill 可以要求保留来源和检查日期，却不应强迫所有课程都具有公开视频。这样，流程既能复用，也容得下真实世界的差异。

## 给这项改进一个验收方式

维护 Skill 可以像维护一项小功能：有适用场景，有失败案例，有修改记录，也有验收。一次新增只解决一个反复出现的问题，再观察它是否带来新的误触发。真正节省时间的是稳定减少纠正次数，而不是拥有很多 Markdown 文件。

可以把上述思路放到一个很小的练习里：只改变一项配置或流程，保存修改前后的同一任务记录。观察现象是否改变，再决定是否扩大使用范围。若任务本身、数据或环境同时变化，就应保留这些差异，避免把偶然成功当成稳定效果。

## 回到课程主题

怎样判断一段提示词是否值得变成 Skill？ 这个问题值得带着具体项目反复检查。官方材料提供了本讲讨论的起点，本站案例提供的是一个可尝试的应用方向；要确认适合自己的实现，仍需取得任务执行和验收证据。
