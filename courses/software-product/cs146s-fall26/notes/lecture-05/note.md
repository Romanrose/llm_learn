# CS146S 第 05 讲：Agent Skills：把重复纠正变成可复用流程

> 基于官方讲义的中文学习笔记。课表日期为 2026-10-06，链接课件标注 2026-10-07；保留课表日期并记录差异。下方问题分析、对照表和练习为本站补充，不是官方作业或逐字稿。

## 课程依据

官方讲义讨论 Skills 的按需加载、适用场景、范围控制与组合，建议从日常对话中反复纠正的步骤提取流程，并配套验证。 [阅读官方讲义](https://docs.google.com/presentation/d/15bPu5c-i8D8McTh6l7SpUPk2n9M_Y-CdDQLfyzL8RD8/htmlpresent)。

## 从一个问题开始

怎样判断一段提示词是否值得变成 Skill？

一个可复用流程应当有清楚的输入与完成标准。以接入课程为例，查找来源、核实学期、关联作业、检查页面是稳定部分；每门课的官网结构是变化部分。将两者分开，流程才能跨课程复用。若规则只适用于某个特例，把它放进所有任务的默认上下文反而可能增加干扰。

## 实现时的对照表

下面是本站设计的检查视角，可结合自己的项目使用。

| 观察对象 | 需要明确什么 | 自查问题 |
| --- | --- | --- |
| 触发条件 | 什么请求需要它 | 避免与其他流程争抢任务 |
| 操作步骤 | 要读什么、调用什么 | 保留必要的依赖顺序 |
| 参考资料 | 详细背景放在哪里 | 按需读取，避免一次灌入 |
| 验收条件 | 什么证据说明完成 | 不要只检查是否生成文字 |

## 动手练习

回看自己最近几次手动纠正智能体的记录，选出一个重复问题，为它写下触发条件、输入、步骤和验收。再用一个应该触发和一个不该触发的任务检查范围。修改流程时保留版本，以便知道哪条规则造成改善或退化。
