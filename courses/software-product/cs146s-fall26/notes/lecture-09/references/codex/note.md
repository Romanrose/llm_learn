# CS146S 第 09 讲：Agent-ready 仓库：先让开发环境可以自证

> 基于官方讲义的中文学习笔记。仅依据已读取的官方讲义整理，不复述未取得的课堂口头内容。下方问题分析、对照表和练习为本站补充，不是官方作业或逐字稿。

## 课程依据

官方讲义把测试、可靠构建、文档、约定与可验证检查作为 Agent-ready 环境的基础，并讨论后台任务的环境隔离和共享资源问题。 [阅读官方讲义](https://docs.google.com/presentation/d/1yCxocmUrGIN7IrC42WB6NW08PtYYFLe1ombDj3Ay6_8/htmlpresent)。

## 从一个问题开始

智能体失败，是任务太难，还是项目根本没有准备好？

仓库准备度可以从一个具体任务开始评估，而不是先追求一个综合分数。记录从干净环境到首次成功验证的步骤，就能看到哪些知识只存在于维护者脑中。隔离也应逐项判断：独立 Git 工作目录可以分开文件修改，但不能自动隔离端口、数据库或外部账户。

## 实现时的对照表

下面是本站设计的检查视角，可结合自己的项目使用。

| 观察对象 | 需要明确什么 | 自查问题 |
| --- | --- | --- |
| 启动 | 新的工作目录能运行项目 | 隐藏依赖和手工环境 |
| 验证 | 有稳定检查能证明结果 | 无测试或不稳定的构建 |
| 理解 | 目录和约定能被发现 | 过期文档和隐含知识 |
| 隔离 | 并行工作不会相互覆盖 | 共享数据库、端口与外部服务 |

## 动手练习

请另一位同学或一个新会话仅依据仓库说明完成启动和一次小修改。记录每次需要额外提示的内容，再把其中稳定的信息补回合适位置。接着列出并行任务会争用的资源，为每项指定独立配置或串行执行方式。
