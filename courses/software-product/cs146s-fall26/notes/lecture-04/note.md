## 从一个问题开始

接入协议之后，工具为什么仍然可能不好用？

协议统一了连接方式，并不会替你确定业务权限或任务语义。设计一个课程资料查询工具时，调用者需要知道它查的是哪学期、返回的是官网链接还是本地正文、空结果意味着什么。把这些信息放进明确的输入输出，通常比让模型猜测多个接口之间的关系更容易核验。

## 实现时的对照表

下面是本站设计的检查视角，可结合自己的项目使用。

| 观察对象 | 需要明确什么 | 自查问题 |
| --- | --- | --- |
| API | 应用提供的接口 | 调用方处理参数和业务流程 |
| MCP | 标准化暴露工具与上下文的连接层 | 接入后仍需落实授权与验证 |
| Skill | 可复用的任务过程 | 说明何时使用、如何完成与验收 |
| 工具结果 | 执行事实和错误 | 区分无结果、无权限与服务失败 |

## 动手练习

设计一个只读的课程资源查询接口，显式输入 course_id、term、resource_type；输出来源 URL、资料类型、访问状态与检查时间。用“无此学期”“权限不足”“查询成功但无结果”三个用例检查错误是否能指导下一步。这是本站练习，不是官方作业。
