# 从 Transformer 到 LLM：解码器如何赢得语言模型之战

## 导语

在 CME 295 的第一讲里，我们从“模型如何理解文本”这个问题出发：文本先被切成 token（tokenization），再被映射为嵌入（embeddings）。word2vec 不知道上下文，RNN 会遗忘过去，而 2017 年的《Attention Is All You Need》用直接连接取代循环，给出了 Transformer。第二讲接续这条线索，回答一个自然的问题：既然 Transformer 在机器翻译上表现优异，我们能否把它的收益推广到其他领域？答案不是单一模型，而是一段“做减法”的历史——人们分别保留编码器或解码器，最终仅解码器（decoder-only）架构胜出，并沿着规模、效率与位置编码等方向被不断改造，成为今天所说的大语言模型（LLM）。本讲因此处在课程路径的枢纽位置：第一讲给出架构，第二讲说明这个架构如何演化为 LLM，后续讲座再深入训练流程、生成与推理。

## 一、拆解 Transformer：编码器与解码器的分岔

原始 Transformer 由两部分组成。编码器负责计算输入文本的有意义嵌入；解码器则以自回归（autoregressive）方式逐个 token 生成输出，生成时关注已预测的 token 以及编码器给出的输入表示。本讲的第一条主线，就是把这个整体拆开来看。

只保留编码器，得到的是 BERT（bidirectional encoder representation from transformers）。它利用多头注意力让所有输入 token 互相注意，并在序列左侧引入一个特殊的 CLS token。由于编码器对所有 token 做自注意力，CLS 对应的嵌入已经与全序列交互，可以承载“这句话在讲什么”的信息。于是 BERT 的用法是：先算出输入的有意义表示，再把它投影到下游任务的类别上。情感抽取就是典型例子——判断一条推文是正面还是负面；也可以取某个 token 的嵌入，判断它是名词还是动词。

BERT 的训练分两步。第一步是预训练（pre-training），用代理任务（proxy tasks）让模型理解文本如何书写。第一个代理任务是掩码语言建模（masked language modeling，MLM）：随机破坏输入中的一些 token，让模型借助注意力从上下文推断被破坏前的原始 token。讲义中的例子是 “a cute teddy bear is reading”，破坏 cute 和 reading，让模型预测它们。第二个代理任务是下一句预测（next sentence prediction，NSP），输入两个句子，判断它们是否前后相接，目的是让模型在文档层面而非句子层面学习文本。预训练通常昂贵且只做一次；第二步是微调（fine-tuning），用一小组带标签的数据把 CLS 嵌入投影到具体用例上，通常数百条数据即可。

BERT 的优点是表现相当不错，且依赖双向的自注意力机制，这正是其名称中“bidirectional”的由来；缺点则是仍需微调，而且从仅编码器模型生成文本并不显然——课程把这一点留到第八讲再展开。

## 二、仅解码器与文本到文本：GPT 的路线

反过来，只保留解码器，就得到 GPT（generative pre-trained transformer）。它的核心思路是把任何任务都表述为文本到文本（text-to-text）问题：给定一些文本作为输入，唯一的工作是预测下一个 token，这种逐 token 预测称为自回归解码（autoregressive decoding）。仍以情感抽取为例，你只需把“这个句子是正面还是负面？”连同句子一起放进模型，模型直接回答正面或负面，微调不是必需步骤，除非想让模型更好。

这与编码器-解码器架构有何区别？相似之处是两者都能自回归生成文本；区别有二。其一，编码器-解码器对输入做特殊处理，输入进入编码器后所有 token 彼此交互，是双向注意力（bidirectional attention）；仅解码器中，输入 token 只能与自身及之前的 token 交互，用的是因果注意力（causal attention）。其二，编码器-解码器多了一个编码器，需要区别对待输入，这对机器翻译这类“有源文本、有目标文本”的任务说得通，但对文本生成这类任务，输入该放什么并不清楚。仅解码器更通用，因为它把所有东西一视同仁。课程明确指出：两种范式都有人尝试，但压倒性地，人们选择了仅解码器，原因之一是它更简单，不需要单独的编码器处理输入。

这里还埋下了一个技术细节：解码器中原有的交叉注意力（cross attention）组件负责接收编码器的嵌入，在仅解码器架构中也被去掉了。剩下的骨干非常简单：一个因果多头注意力层，只关注每个 token 及其之前的 token，外加一个前馈神经网络，计算主要发生在这里。

## 三、规模化与缩放定律：越大越好，但要算得清

人们选择仅解码器之后，做的事就是把它规模化（scale up），因为观察到它随规模变大而变好。2020 年代的几篇论文量化了这一点：模型性能几乎可以写成训练 token 数量的函数，也是模型规模的函数。更有趣的发现是 token 效率：模型越大，达到某一性能所需的训练 token 越少。讲义中的图以测试损失（test loss）为纵轴、处理过的 token 数量为横轴，颜色越亮表示模型越大，而大模型曲线整体更低——越低越好。

但硬件有限。于是自然的问题是：给定计算预算，该把多少用于扩大模型，多少用于增加训练 token？课程先澄清了记号：flops（小写 s）是浮点运算（floating point operations），用来衡量计算量；大写的 FLOPS 或 FLOPS/s 则是计算速度，衡量硬件性能，两者极易混淆。2022 年的一篇论文发现，模型规模与训练数据规模之间存在最佳平衡点，并指出当时大多数模型其实训练不足——相对于训练所用的 token 数量，它们的规模太大了。论文用两个计算预算相同的模型说明这一点：一个约 700 亿参数、用更多 token（课程提到约 1.4 万亿）训练；另一个 200 多亿参数、用更少 token 训练，结果规模更小的那个表现更好。由此得出参数与 token 的大致关系：一个参数对应约 20 个 token。课程也提醒，这讨论的是训练计算最优，生产中还要服务模型，请求量很大时也有动机不把模型做得太大。

有同学问这是不是交叉熵，课程确认：任务是下一 token 预测，要让预测尽量接近标签，通常用的就是交叉熵。至于数据质量，课程的观点是：对预训练而言，重要的是规模而非质量；训练过程后续步骤更强调质量，那会在第三讲展开。

## 四、为什么叫“大”：规模、骨干与 MoE

LLM 代表大语言模型。语言模型是因为它给 token 序列赋予概率，在这里就是预测下一个 token 并赋予概率；大则体现在模型规模——通常是数十亿乃至数千亿、数万亿参数，训练数据至少数千亿 token，如今甚至数十万亿，还需要大量 GPU，并依赖仅解码器的 Transformer。

规模带来一个现实问题：对给定输入 X，真的需要模型中的所有参数吗？课程用了一个思想实验：满屋子人里，你有数学问题，该问所有人，还是只问数学专家？这正是混合专家（mixture of experts，MoE）的思路——针对给定输入只激活模型的一个子集。MoE 早于 LLM 出现：它有若干专家，外加一个门（gate），也叫路由器（router），根据输入决定用哪个专家、用多少。稠密（dense）MoE 仍然激活所有专家，只是给更相关的专家更高权重，问题在于没有省下计算；真正有趣的是稀疏 MoE（sparse MoE），它只选出 top-k 个专家，输出是这些专家输出按门控给出的重要程度加权求和，只对被激活的专家求和。

那么 MoE 放在架构哪里？课程引导出的答案是前馈神经网络，因为计算量通常集中在那里；多头注意力层是 token 之间交流的地方，不是通常通过投影计算有意义嵌入的地方。这里的专家就是一个前馈网络。路由在 token 级别进行，每个 token 自己决定去哪个专家。路由器怎么学会的？靠反向传播（back propagation）。但这里有个训练难题：模型可能过度依赖少数专家，即路由坍塌（routing collapse），有效模型规模反而小于专家与权重的总数。原因是富者愈富——最初被选中的专家最先被更新、变得更好，其他专家闲置。对策是负载均衡辅助损失（load balancing auxiliary loss），鼓励被路由到各专家的 token 比例大致均匀。有同学指出选 top-1 或 top-2 不可微，课程解释用 stop gradient 算子：在损失里把路由到专家 i 的 token 比例当作常数，只通过路由概率反向传播，路由器仍能被改变。

课程还提到 2026 年的两个实践趋势：一是共享专家（shared experts），无论路由器选哪些专家都会被激活，因为每个 token 总有一些计算始终必要，避免专家都去学同样的基础再专精；二是专家数量选得更高，不是 8 或 16，而是 60 甚至上百，让专家更专门化、更细粒度，经验上性能更高。讲义展示的近期前沿开源 LLM 截图里，专家数量在几百的量级（如 384、256），每次前向传播激活约 8 个专家，模型规模达数百亿甚至万亿参数。有同学问缩放定律对 MoE 是否仍成立，课程回答：那篇论文基于稠密 LLM，作者们通常会针对自己的设置做小规模实验，看定律是什么，再据此选参数。

## 五、位置信息：从加性嵌入到 RoPE

自注意力让所有 token 直接相连，代价是丢失位置信息。原始论文尝试了两种方法。其一是学习位置嵌入（position embeddings），为每个位置索引学一个嵌入，加到 token 嵌入上；问题在于训练时没见过的更长序列，其位置嵌入无从得知。其二是确定性公式，可以泛化到任意序列长度，作者们说两种方法性能大致相同，而固定方式更好。

课程用看手表的类比解释公式：时针、分针、秒针频率不同，合在一起就能确定时刻。位置嵌入同理，用不同频率的余弦和正弦，低索引对应高频率、变化快，高索引对应低频率、变化慢。关键性质是：位置 m 与 n 的嵌入点积是 m−n 的函数（借助 cos(a−b) 的三角公式可得），因此 m 等于 n 时相似度最大，位置接近则相似度高，远离则低。有同学担心这会不会让远距离 token 交互更少、重蹈 RNN 覆辙，课程回应：直观上更近的 token 只是更可能相关，但并非不相关，直接连接仍然保留，模型仍有机会与远处 token 交互——十页文档里，同句内容可能比相隔很远的内容更相关，但远处 token 仍可交互。

然而今天人们并不用这种加性位置嵌入。原因是：你只在注意力层关心 token 位置，因为那是通信发生的层，而加性嵌入被加到 token 嵌入上、被所有层处理，前馈网络其实并不关心 token 在位置五还是十二。于是人们尝试把位置信息“外科手术般”地只注入注意力层：一是在 softmax 中学习偏置项，但偏置需要学习，可能受训练数据偏置影响，且不能泛化到所有距离；二是 alibi，即带线性偏置的注意力，偏置随 m 与 n 的距离变化；而今天常用的是 RoPE（rotary position embedding，旋转位置嵌入）。

RoPE 不添加偏置，而是直接改变查询和键：按各自位置旋转它们。课程用二维旋转矩阵演示，向量乘以旋转矩阵即旋转向量；当查询按位置 m 旋转、键按位置 n 旋转后，自注意力公式中出现的量是 n−m 的函数。它可扩展到任意位置，不需要学习；推广到更高维时按二维块分块旋转，角度是索引的函数，小索引与大索引角度不同。课程展示：查询与键的点积随位置距离增大而大致衰减（并非严格单调），这正符合我们对远距离 token 的预期。

## 六、注意力与归一化的现代化改造

注意力层也有变体。编码器中人人可见，解码器中 token 只能看到自己和之前的 token，但每层都如此是否必要？计算量很大。滑动窗口注意力（sliding window attention），也叫局部注意力（local attention），只关注到一定距离为止。课程回应了“这不是又回到 RNN 问题吗”的疑问：模型不止一个块，注意力发生好几次；即使每个 token 只看自己和前一个 token，堆叠多个块后，它实际上能看到超出限制的 token 的表示，这与卷积神经网络中感受野（receptive fields）的想法类似。

另一个问题是解码时的内存。预测下一个 token 时，查询要与之前所有 token 的键比较；每次重新计算太浪费，于是把键存起来复用。但键占内存，且注意力是多头的，同一层同一 token 有好几个键，解码越长存得越多。于是有了跨头共享键和值的方法，例如分组查询注意力（group query attention，GQA）：设定一定数量的组，组内共享键和值的投影矩阵；相比之下，原始多头注意力每个头都有需要学习的全部投影矩阵。课程强调：查询用一次就不再需要，没人在意；要省的是键和值。如今 GQA 被大量使用。

归一化方面，原始 Transformer 用 post-norm：先执行子层操作，加到输入上，再归一化，即对 X 加子层(X) 做归一化。问题在于残差连接的初衷是让输入直接通过以改善梯度流动，而这里 X 被包在层归一化之内。如今改用 pre-norm：先归一化输入，送入层，再加到 X 上。层归一化本身也有替代：RMS norm（root mean square norm，均方根范数）效果同样好，不需要重新中心化，只需重新缩放并学习一个因子。课程总结：过去是 post-norm 加 layer norm，如今是 pre-norm 加 RMS norm；当今常见组合就是 RoPE、局部注意力、GQA、pre-norm 和 RMS norm。

## 七、解码策略：确定性、温度与引导解码

课程后半段转向生成。模型最后投影到词表空间，经 softmax 得到下一个 token 的概率分布。最直觉的做法是取概率最高的 token，但逐 token 优化局部最优，生成完整序列后可能并非联合概率最优；束搜索（beam search）一次跟踪 k 条路径，是折中方案，但完整联合概率计算上太昂贵。课程引导同学发现两种方法的共同弱点：确定性——同样的输入总得到同样的路径。思想实验是：聊天机器人对同样的问候总回同一句话，会显得机械；人面对相似提示会略有不同。课程也承认实践中上下文会变（比如时间信息），但仍会看到机械行为。当然，确定性在某些场景是优点：需要可复现的自然语言任务，比如文本摘要希望每次输出一致；后续评估讲座中的 LLM as a judge 也希望评分一致。

于是回到概率分布直接采样。为免处理整个分布，可以在最可能的 top K 个 token 中选（top K），或选累积概率达到给定比例的那部分 token（top P）。温度 T 调节分布形状：常规 softmax 相当于 T 等于 1；T 大于 1 分布更平坦，T 很小则更尖锐，高概率项被强调、其余被压向零。课程强调确定性是连续的，温度是一个可调设置，不是二选一。

一个有趣的事实：即使温度为零，实践中也并非完全确定。原因是 LLM 推理引擎会把你的请求和其他请求一起批处理，问题出在浮点数的非结合性（non-associativity）——加法顺序会影响结果，大数加小数再减回大数可能得到零，分开算却能拿回小数。课程提到批处理不变性（batch invariance）的概念，并推荐了 Horus Haye 的相关博客。

工业场景常需要结构化输出，比如 JSON，解析失败下游就麻烦了。只靠请求格式并非 100% 可靠，引导解码（guided decoding）则根据目标语言的语法限制下一步可预测的 token 范围。

## 八、提示与上下文：窗口、腐化与上下文学习

提示（prompting）部分先厘清术语。你输入提示，模型自回归地逐个计算 token；上下文窗口（context window）不只是你输入的内容，因为生成的每个 token 都要放回输入层，所以它与输出长度相关联。上下文长度有计算上的上限，也有直觉上的理由。课程给出数量级：输入约 100 万 token 是行业标准，输出约 10 万 token；一个 token 约为一个单词的 3/4，一页约 500 个 token，因此 10 万 token 约是一本书，100 万是一本大书。课程还提醒上下文腐化（context rot）：“大海捞针”（needle in a haystack）测试把关键信息放在上下文某处再检索，上下文越长，检索越难；信息混在噪声中，精确检索在概念上就可能不现实。因此实践上提倡上下文压缩（context compaction），每次开始新对话。

不改变任何权重提升性能的技术是上下文学习（in-context learning）：给出示例和解答，而非调权重。零样本（zero-shot）直接问泰迪熊的年龄，对比给几个问答示例，模型会学会格式甚至隐式推理；但少样本学习（few-shot learning）如今用得越来越少，因为推理模型越来越强，且少样本会让模型对特定示例过拟合，更希望基于推理的方式。提示调优（prompt tuning）把示例转化为指令，手工编写放在示例位置；少样本的缺点还包括输入 token 更多，增加成本和延迟。思维链（chain of thoughts）是里程碑式论文，在少样本提示中教模型如何得到答案，模型学会推理路径、整体提升性能；课程强调不要把它纯粹视为上下文学习技术，它远不止于此，推理模型使用的思考 token 沿用同一概念。自洽性（self-consistency）则生成多条推理路径，通过多数投票得到更稳定的答案，尤其在算术领域。

## 结语

回看第二讲，主线是一次“做减法”的历史：拆开 Transformer，仅编码器给出 BERT 的双向表示与预训练加微调范式，仅解码器给出 GPT 的文本到文本范式并最终胜出；随后是规模化的经验规律与计算最优的权衡，MoE 用稀疏激活换参数规模，RoPE、滑动窗口、GQA、pre-norm 与 RMS norm 构成现代 LLM 的常见配置；最后落到生成侧的温度、采样、引导解码，以及提示侧的上下文窗口与上下文学习。这些内容承接第一讲的架构与嵌入，也为第三讲的训练流程、后续的推理模型与评估讲座铺路。课程反复出现的判断值得记住：人们尝试过所有变体，真正活到今天的是仅解码器，原因之一是它更简单、对输入没有特殊处理；而“更大更好”背后，始终有一笔要算清的计算账。
