## 一、学习目标

学完本讲，应能：

2. 描述 BERT 的两阶段训练：**pre-training**（MLM、NSP）与 **fine-tuning**，以及各自的代理任务逻辑。
3. 解释 decoder-only 架构为何把一切任务表述为 **text-to-text**，以及它与 encoder-decoder 在因果/双向注意力上的区别。
4. 理解 scaling law 的基本结论：性能随模型规模、训练 token 数、算力提升；更大模型具有更高 **token efficiency**；存在模型规模与训练 token 数之间的**计算最优**配比。
5. 说明 **Mixture of Experts（MoE）** 的动机、dense/sparse 区别、router、top-k 激活、**routing collapse** 与 **load balancing auxiliary loss**。
6. 区分 **post-norm/pre-norm**、**LayerNorm/RMSNorm**、加性位置嵌入与 **RoPE**、全注意力与 **sliding window attention**、MHA 与 **GQA**。
7. 解释自回归解码中的贪心、beam search、top-K、top-P、temperature，以及 **guided decoding** 的作用。
8. 说明 **in-context learning**、few-shot、chain of thoughts、self-consistency 的基本思想。

## 二、课程主线

上一讲回顾：文本先 **tokenization**（子词分词在词表规模与序列长度间折中），再计算 **embeddings**；word2vec 不懂上下文，RNN 会遗忘远处信息；2017 年《Attention Is All You Need》用直接连接替代循环，引入 query/key/value 与多头注意力，形成 encoder-decoder Transformer。

本讲主线：

1. **拆解原始架构**：只用 encoder → BERT；只用 decoder → GPT。人们尝试过所有变体，最终 decoder-only 成为生成式 LLM 的主流。
2. **规模化**：decoder-only 被不断放大，scaling law 量化了数据、参数、算力与性能的关系；2022 年工作指出多数模型训练不足，并给出参数与 token 的近似配比。
3. **降低推理成本**：MoE 让模型总参数变大，而每次前向只激活部分专家。
4. **改进原始层设计**：位置编码（RoPE）、局部注意力、GQA、pre-norm、RMSNorm。
5. **解码与提示**：从概率分布中如何选 token；如何用 guided decoding 保证结构；如何用上下文学习与推理提示提升表现。

## 三、核心概念

### 1. Encoder-only：BERT

- 只取 encoder，利用多头自注意力让所有输入 token 互相注意（双向）。
- 在序列左侧引入特殊 **CLS token**；由于它已与所有 token 交互，其编码嵌入可承载整句信息，用于分类等下游任务。
- 也可取单个 token 的嵌入做 token 级任务（如词性判断）。

**训练两阶段：**

- **Pre-training**：用代理任务让模型理解文本如何书写。
  - **Masked Language Modeling（MLM）**：随机掩码部分 token，用上下文预测原始 token；实际做法为避免偏差会略复杂。
  - **Next Sentence Prediction（NSP）**：输入两个句子，判断是否前后相接，意图让模型在文档层面学习。
  - 预训练昂贵，通常只做一次。
- **Fine-tuning**：接一个投影层，把 CLS 嵌入投影到目标类别，用少量带标签数据调整权重。课程提到通常数百条量级即可，但仍需做微调，这是缺点之一。

**优点**：表现好；双向自注意力即 BERT 名称来源；微调数据需求较小。
**缺点**：仍需微调；仅编码器模型如何生成文本并不显然（课程留到第 8 讲）。

### 2. Decoder-only：GPT

- 只取 decoder，把任何任务表述为 **text-to-text**：给定文本，唯一工作是预测下一个 token。
- 采用**自回归解码（autoregressive decoding）**，一次预测一个 token。
- 因为模型已具备适配用例的能力，微调不是必需步骤；例如情感分类可直接把句子连同“正面还是负面”的询问放入模型，让它直接回答。

**与 encoder-decoder 的区别（课程明确给出两点）：**

1. 注意力方式：encoder-decoder 对输入做**双向注意力**；decoder-only 对输入 token 只能注意自身及之前的 token，即**因果注意力（causal attention）**。
2. 是否单独处理输入：encoder-decoder 有额外 encoder 专门处理输入，适合机器翻译这类有明确源文本/目标文本的任务；decoder-only 对所有内容一视同仁，更通用。

课程结论：两种范式都能自回归生成文本，但今天活下来的是 decoder-only，原因之一是更简单、不需要单独 encoder 处理输入。

### 3. Scaling law 与计算最优

课程引用的 2020 年工作给出近似定律：模型性能是训练 token 数量、模型规模的函数；并发现**模型越大，token 效率越高**——达到某性能所需训练 token 更少。

记号提醒：

- **flops**（小写 s）：浮点运算量，衡量计算量；课程给出语言模型训练 flops 约 10^25 量级。
- **FLOPS**（大写 S，或 /s）：计算速度，衡量硬件性能；两者极易混淆。

2022 年工作：给定计算预算，模型规模与训练数据规模之间存在最佳平衡；当时多数模型**训练不足**（相对训练 token 数，模型过大）。课程提到两个同预算模型的对比：较小的（约 700 亿参数）用更多 token（约 1.4 万亿）训练，反而优于更大但 token 更少的模型。结论是参数与训练 token 的近似关系约为 **1 个参数对应 20 个 token**。

课程补充：这是“训练计算最优”；生产中还要服务大量请求，因此也有动机不让模型太大——这是另一个问题。

问答要点：这里的损失是**交叉熵**，因为任务是下一 token 预测。关于数据质量，课程观点是：**预训练阶段规模比质量更重要**；后续训练步骤（第 3 讲）更强调质量。

### 4. 为什么叫 LLM

- **Language model**：给 token 序列赋予概率、试图预测下一 token 的模型。
- **Large**：模型规模常达数十亿至数千亿、最近甚至数万亿参数；训练数据至少数千亿 token，如今可达数十万亿；需要大量 GPU；架构上依赖 decoder-only Transformer。
- decoder-only 中，原本连接 encoder 与 decoder 的 **cross attention** 也被去掉，骨干变得非常简单：因果多头注意力层（每个 token 只关注自身及之前 token）+ 前馈神经网络（主要计算发生处）。

### 5. Mixture of Experts（MoE）

动机类比：房间里各有数学、物理、生物专家，数学问题不必问所有人。对给定输入只激活参数子集，就能扩大模型规模而不必每次前向承担全部计算。

- **Dense MoE**：仍激活所有专家，只给相关专家更高权重——没有达到省计算的目的。
- **Sparse MoE**：真正选择并只激活部分专家，通常选 **top-k**（k 可为 1、2 或设定值）。输出是各被激活专家输出的加权和，权重由 **gate/router** 给出，只对被激活的 K 个专家求和。

**放在架构哪里？** 课程明确：放在**前馈神经网络**处，因为计算量集中在那里；多头注意力是 token 之间交流的地方，不是通常做投影计算有意义嵌入的地方。router 对每个输入决定激活哪些专家，专家本身就是一个前馈网络。

**路由粒度**：在 **token 级别**进行，每个 token 各自决定去哪个专家。

**训练挑战：routing collapse（路由坍塌）**——模型倾向只依赖一小部分专家，导致有效模型规模小于专家与权重总数。原因是“富者愈富”：训练初期被选中的专家最先被更新、变得越来越好，其他专家闲置。对策是损失中加入 **load balancing auxiliary loss**，鼓励各专家被路由到的 token 比例均匀或大致均匀。

**不可微问题**：top-k 选择不可微。课程解释用 **stop gradient** 算子，把路由到专家 i 的 token 比例在损失中当作常数，只通过路由概率反向传播，从而仍能更新 router。

**当今实践（课程所述）：**

- 使用**共享专家（shared experts）**：无论 router 选哪些专家，共享专家总被激活；用意是每个 token 总有一些必要的基础计算，避免专家都重复学同样的基础再专精。
- 专家数量选得更高（60 或上百，而非 8 或 16），让专家更专门化、更细粒度；课程称经验上更细粒度带来更高性能。
- 课程展示的近期前沿开源 LLM 截图中，专家数量在几百量级（如 384、256），每次前向激活约 8 个；有的未使用共享专家；模型规模为数百亿至万亿参数。

**问答要点**：scaling law 原论文基于 dense LLM，并非基于 MoE；实践中作者会针对自己的设置做小规模、少 token 的缩放实验，看定律形状再选参数。关于辅助损失公式中专家数 n 出现在分子：因为 f_i 与 p_i 都除以 n，求和后除以 n² 再乘 n，等价于除以 n，故写成乘 n。

### 6. 位置编码：从加性到 RoPE

自注意力提供直接连接，因此丢失 token 位置信息。原始论文尝试两种方法：

- **学习位置嵌入**：为每个位置索引学习一个嵌入，加到 token 嵌入上。问题：推理时遇到比训练更长的序列，超出训练位置的位置嵌入未曾学过。
- **确定性公式（正弦/余弦）**：可泛化到任意序列长度；课程称原作者表示两种方法性能大致相同，固定方式更好。

**正弦位置编码的直觉**：像手表时针/分针/秒针，不同频率的指针组合可精确指示时间。公式中较低索引对应较高频率（变化快），较高索引对应较低频率（变化慢）。

**关键性质**：位置 m 与 n 的嵌入点积是 m−n 的函数（利用 cos(a−b)=cos a cos b+sin a sin b）。m=n 时 cos(0) 最大，故相近位置相似度高、相距远则低。

**为什么今天不用它**：位置信息只在**注意力层**真正重要（那里判断 token 相关性）；加性嵌入会被所有层处理，而前馈网络并不关心 token 在位置 5 还是 12。人们希望把位置信息“外科手术式”地只注入注意力层。

**课程提到的方法演进：**

- 在 softmax 中学习偏置项（依赖 m、n 距离）；缺点是需要学习、可能受训练数据偏置影响、不能泛化到所有距离。
- **ALiBi**：带线性偏置的注意力，偏置随 n−m 变化。
- **RoPE（rotary position embedding）**：不加偏置，而是按各自位置**旋转 query 和 key**。旋转矩阵作用于向量后，自注意力中会出现作为 n−m 之差的函数的表达式；无需学习，可扩展到任意位置。高维情形按二维块分块旋转，角度是索引的函数。课程指出 query 与 key 点积的量级随距离增大总体衰减（非严格单调），符合“相距更远 token 相关性更低”的直觉，同时保留直接连接、不剥夺交互机会。

课程结论：原始论文用加性位置嵌入，今天人们用 **RoPE**。

### 7. 注意力层改进：局部注意力与 GQA

- **Sliding window attention（局部注意力）**：每个 token 只注意一定距离内的位置，降低计算。看似会像 RNN 一样丢失远处信息，但因为模型堆叠多个块，token 可通过中间 token 间接看到超出窗口的表示——类似卷积网络的**感受野**。
- **KV cache 与 GQA**：自回归解码时，已解码 token 的 key/value 可缓存复用；但多头注意力下每个 token 每层有多个 key，解码越长内存占用越大。query 用一次即可丢弃，所以优化集中在减少 key/value 的投影矩阵数量：
  - **Grouped Query Attention（GQA）**：设定若干组，组内共享 key/value 投影矩阵；课程称如今大量使用。
  - 课程还提到跨头共享 key/value 的思路。
- 课程总结的“今天常见组合”：**RoPE、局部注意力、GQA、pre-norm、RMSNorm**。

### 8. 归一化：post-norm → pre-norm，LayerNorm → RMSNorm

- 原始 Transformer：先做子层操作，加到输入，再做归一化，即 **post-norm**：Norm(X + Sublayer(X))。问题：残差连接本意是让输入直接通过以改善梯度流动，但这里 X 被包在 LayerNorm 内。
- 当今做法：**pre-norm**——先归一化输入，送入层，再加到 X 上，让残差连接发挥梯度流动作用。
- **LayerNorm**：对所有激活重新中心化，含 gamma 与偏置 beta，有助训练稳定与收敛。
- **RMSNorm**（root mean square norm）：不重新中心化，只重新缩放，只学一个因子；课程称效果同样好，因此人们倾向使用。

### 9. 解码：如何选下一个 token

模型末端把 D_model 维嵌入线性投影到词表空间，再经 softmax 得概率分布。

- **贪心**：直接取概率最高的 token。弱点：逐 token 局部最优，生成完整序列后联合概率未必最优。
- **Beam search**：计算上无法求完整联合概率，改为同时跟踪 k 条路径，每步保留 k 个最好的。
- 二者共同弱点：**确定性**。课程用思想实验说明：聊天机器人对相同问题总给相同回答会显得机械；人类对相似提示会有细微不同的回应。课程也提醒实践中上下文会变化（时间等信息），该思想实验不严格适用，但机械行为仍可感知。
- **采样**：从分布中采样。可用 **top-K**（只在最可能的 K 个 token 中选）或 **top-P**（取累积概率达到给定比例的那部分 token）。
- **何时需要确定性**：需要可复现的自然语言任务，如文本摘要每次输出一致；以及用 LLM as a judge 做评估时希望评分一致。其余多数场景非确定性更有吸引力。
- **Temperature T**：常规 softmax 对应 T=1；T 越大分布越平坦（指数内趋近 0，趋于均匀），T 越小分布越尖锐（高值被放大、其余被压低，接近 one-hot）。温度是连续可调的设置，不是二选一。
- **确定性的现实复杂性**：即使 T=0，理论上应确定，但推理引擎会把请求与其他请求一起**批处理**；由于浮点数的**非结合性**（加法顺序影响结果），可能出现非确定性。课程提到 **batch invariance** 概念并推荐相关博客，但未展开实现细节。

**Guided decoding**：工业中需要 JSON 等结构化输出，仅靠提示“请输出 JSON”通常可用但不是 100%。引导解码在每一步根据目标语言的语法限制可预测 token 的范围，从而保证格式合法。

### 10. 提示与上下文

- **Context window**：不只是用户输入的提示；生成过程中每个新 token 都会被放回输入层，因此上下文窗口与输出长度相关联。课程给出量级参考：输入约 100 万 token 是行业标准，输出约 10 万 token（并说明该数字刚更新过，可能很快进入百万级；某个新发布模型未公布最大输入长度）。
- token 直觉：一个 token 约为一个单词的 3/4；一页约 500 token；10 万 token 约一本书，100 万约一本大书。
- **Context rot**：课程用“大海捞针”测试说明，上下文越长，模型越难精确检索放在窗口某处的信息；噪声过多使精确检索在概念上不现实。因此有**上下文压缩（context compaction）**、每次开新对话等实践，也解释了为何没有无限上下文窗口。
- **In-context learning**：不改权重，通过给出示例与解答教模型。零样本 vs 少样本：few-shot 让模型学会格式甚至隐式推理。课程指出如今 few-shot 越来越少用，因为推理模型越来越好；few-shot 的缺点是会让模型对给定示例过拟合，更希望基于推理的方式。**Prompt tuning** 技术把示例转化为指令，通常手工编写。few-shot 另一缺点是增加输入 token，提高成本与延迟。
- **Chain of thoughts**：里程碑论文，在少样本提示中教模型如何得到答案，模型学会推理路径、总体提升性能。课程强调不要把它纯粹看作上下文学习技术，它远不止于此；后续会讲使用思考 token 的推理模型。
- **Self-consistency**：生成多条推理路径，通过多数投票得到更稳定的答案（课程以算术为例）；留待推理模型讲座展开。

## 四、关键公式与原则

1. **注意力基本式**：softmax(q kᵀ / 缩放常数) · v；位置偏置方法即在 softmax 内加入依赖距离的项。
2. **正弦位置编码的点积性质**：cos(ω_i(m−n)) 对应两位置嵌入在某维上的点积；整体点积为各维求和，是 m−n 的函数，m=n 时最大。
3. **RoPE 的核心**：用旋转矩阵按位置旋转 q、k，使注意力表达式成为 n−m 的函数；无需学习、可外推。
4. **MoE 输出**：ŷ = 对被激活的 K 个专家求加权和，权重来自 gate；路由在 token 级。
5. **负载均衡辅助损失**：鼓励各专家被路由的 token 比例均匀；对不可微的 top-k 用 stop gradient，只通过路由概率反传。
6. **Temperature softmax**：T>1 更平坦，T<1 更尖锐，T=1 为常规 softmax。
7. **原则**：预训练阶段规模优先于质量；后续训练阶段质量更重要（课程明确区分）。
8. **原则**：位置信息应只注入注意力层，而非被所有层处理。

## 六、常见误区

1. **把 flops 与 FLOPS 混为一谈**：前者是计算量，后者是计算速度。
2. **认为 BERT 能直接生成文本**：课程明确说仅编码器生成并不显然，留到第 8 讲；不要据此断言“不可能”。
3. **认为 decoder-only 与 encoder-decoder 只差一个 encoder**：课程给出两点区别——因果 vs 双向注意力，以及是否单独处理输入。
4. **认为 MoE 放在注意力层**：课程明确通常放在前馈网络，因为计算集中在那里；注意力是 token 交流处。
5. **认为 MoE 每次前向激活所有专家**：那是 dense MoE；稀疏 MoE 只激活 top-k。
6. **认为路由是可微的**：top-k 不可微，需 stop gradient 处理。
7. **认为 scaling law 直接适用于 MoE**：原论文基于 dense LLM；MoE 需针对自身设置做小规模缩放实验。
8. **认为位置嵌入应加到所有层**：课程指出位置信息只对注意力层有意义，前馈网络不关心位置；这是 RoPE 等方法的动机。
9. **认为局部注意力必然丢失远处信息**：堆叠多个块可像感受野一样间接扩大交互范围。
10. **认为 T=0 一定完全确定**：批处理与浮点非结合性可能导致非确定性；课程称之为计算层面的现象。
11. **认为上下文窗口只等于用户输入**：生成 token 会回填输入层，窗口与输出长度相关。
12. **认为 few-shot 总是更好**：课程指出其过拟合示例、增加成本与延迟，且推理模型时代使用减少。
13. **把 chain of thoughts 仅当作上下文学习技巧**：课程强调它远不止于此。
