# 从分词到自注意力：Transformer 如何把文本变成可计算的表示

## 导语

CME 295「Transformers & Large Language Models」的第一次课承担着一个特殊任务：它要在两小时内，把听众从「文本是一串字符」带到「Transformer 的编码器—解码器结构如何完成一次机器翻译」。这几乎是一次压缩比极高的知识传递。课程主讲 Afin 在课堂上坦言，第一讲大概是「就我们看到的概念数量而言最难的一讲之一」。正因如此，理解这一讲的组织逻辑，比记住其中任何一个公式都更重要：它不是零散知识点的堆叠，而是一条从「模型看不懂文本」出发、逐层逼近「自注意力」的论证链。本文按这条链条重述本讲的核心内容，并说明它在整门课程中的位置。

## 一、这门课要回答什么问题

课程的目标被表述得很直接：告诉你 LLM 是如何工作的，特别是理解其架构的底层机制——transformer 是什么、LLM 如何训练、如何使用、擅长什么与不擅长什么。目标受众也相当广：想做研究科学家的、想做个人项目的、以及任何需要「AI 素养」（AI literacy）的人。先修要求不高：一点线性代数（知道矩阵和乘法）、一点机器学习基础（损失函数、神经网络、embedding），课上会讲到这些，但提前了解更好。

一个值得注意的细节是：这门课去年已经录过像，但今年仍要重讲，因为这个领域发展太快。Afin 举的例子包括后训练（post-training）方面的策略蒸馏（policy distillation）、AI agent 尤其是 coding agent，以及「传统上是一次预测一个 token，但如今有越来越多模型采用不同方法，比如从扩散（diffusion）的角度」。这解释了本讲的一个定位：它讲的是 2017 年的骨架，但整门课会不断往这个骨架上添加新东西。

课程结构上，共九讲，一场期中（约覆盖前四讲）、一场期末（覆盖后五讲），期末占总成绩 50%，考试为多选题加自由回答题，去年的考题已放在网站上供参考。没有作业，但 2025 年的练习题已可用。每张幻灯片底部通常附有来源，供深入查阅——这是本讲一个隐含的学习方法论：两小时远不足以覆盖全部内容，幻灯片是索引，不是边界。

## 二、为什么必须从分词（tokenization）开始

本讲的第一个技术概念是分词，但它的引入方式值得玩味：不是因为分词本身有趣，而是因为「文本并不是模型能理解的东西。模型理解数字」。所以第一个目标是找到一种方式，把文本表示为数字。做法是先把文本切分成不可再分的实体，每个实体叫一个 token，再用向量表示每个 token。可用的 token 集合叫词表（vocabulary），切出来的 token 数量叫序列长度。

这里出现了本讲第一个、也是反复出现的论证模式：**提出朴素方案，暴露其缺陷，由此逼出下一个方案**。

- **词级分词**：按空格切分。优点是简单、可解释。缺点有三：英语的词有大量变体（单复数、阴阳性），词表会变得非常大；无法保证 bear 和 bears 这类同指一物的 token 得到相近的表示，也就无法利用同词根的知识；训练时没见过的词会落入词表外（out of vocabulary），模型根本没有它的表示。
- **字符级分词**：按字符切分。没有词表外风险，词表很小，对大小写和拼写错误更鲁棒。但序列长度会变得长得多，而「模型复杂度是序列长度的函数」，计算会慢得多，嵌入的可解释性也差得多。
- **子词级分词**：介于两者之间。利用从训练语料中学到的词知识，把常见字母组合切成一个 token。于是 reading 可以切成 read + ing，bear 和 bears 共享 bear 这个 token。缺点是需要额外工作，且分词方式高度依赖训练分词器时所用的数据类型——所以「你需要确保你用来学习如何分词的数据实际上与你的最终目标是一致的」，做多语言工作时尤其要保证语料能代表所有感兴趣的语言。

子词分词是当今最流行的方案，其代表是 **BPE（byte pair encoding，字节对编码）**。Afin 讲了它的要点：从初始 token 集合（比如字母表）出发，识别训练数据中最频繁的 pair，为合并后的 token 设计专门的 token 加入词表，重复这个过程直到达到期望的词表大小。好处是 token 从数据中学到，常见组合被识别出来，序列长度变短，模型处理文本更快——效率就来源于此。

随后是特殊 token（special token）：表示词表外片段的 unknown token；标记序列起止的 BOS 与 EOS，主要在生成时使用——输入 BOS 告诉模型「开始生成」，模型在结束时输出 EOS 告诉你「生成完了」；以及为了让序列达到统一大小的 padding token，因为「硬件喜欢维度相同的东西」。Afin 特别强调这个列表绝非详尽，不同系统有不同惯例，如今还有 user、assistant 这类特殊 token。

课堂上有个提问很有价值：现在 LLM 的词表大小是什么量级？答案是数十万，比如二十万左右，且这些分词器能处理英语也能处理其他语言。另一个提问是：让分词器处理多语言，是否会让它在某一特定语言上不专业？回答是「很难说」——语言之间可能存在协同效应，但固定的词表大小会被不同语言的 token 填充，若只关心一种语言，可能得到更长的序列长度，效率上或许有损失，表示上则「不是特别清楚」。这种坦诚的「有得有失」，本身就是课程态度的一部分。

## 三、从 one-hot 到 word2vec：表示为什么要「有意义」

有了 token，下一个问题是：如何表示它们。最朴素的做法是 one-hot encoding——每个 token 是彼此正交的向量。Afin 的反问是：「这是好事吗？不，这不是好事，因为它没有告诉你关于这些 token 是什么以及它们如何相互关联的任何信息。」你希望 teddy bear 与 soft 相似，因为泰迪熊是柔软的。为什么要有意义的表示？因为你要把文本作为模型输入去产生输出——生成下一个词、预测某个类别——所以你需要理解文本里有什么。

早期方法是 **word2vec**，通过代理任务（proxy task）学习表示：代理任务不是最终目标，而是为了达成其他目标而学的任务。连续词袋（continuous bag of words）版本是预测上下文词之间的词，skip-gram 版本是预测给定词周围的词。Afin 用「a cute teddy bear is reading」演示了最基础的神经网络：输入是大小为词表 V 的 one-hot 向量，一次矩阵乘法得到大小为 D 的隐藏状态（潜在表示），再一次矩阵乘法回到大小为 V 的概率分布，用 softmax 归一化，目标是让正确词的概率尽量接近 1，用交叉熵损失惩罚偏差，反向传播更新权重。对 cute→teddy bear 等每个相邻词对重复这个过程，遍历整个语料。

结果是：网络中间学到的潜在表示本身变得有意义。相似 token 的表示相似，甚至出现了 Paris 对应 France、Berlin 对应 Germany 这样的关联。

但课堂上的提问环节揭示了这种方法的局限，而且这些局限是由学生提出的，这使论证更有说服力：

1. 训练中没见过的词就没有表示；
2. 词表变大时维度会增大——但这「不是这种方法特有的」，任何方法都要为词表中每个元素找到表示；
3. **一个词可以有多种含义**。cute 在「a cute teddy bear」和讽刺性的「oh how cute」中含义不同，但表示相同。经典例子是 bank：河岸 vs 去银行；
4. **词序不重要**。「孩子抱着泰迪熊」和「泰迪熊抱着孩子」词完全相同，含义完全不同，但得到相同的 embedding。

## 四、RNN 的贡献与它无法回避的瓶颈

针对词序问题，2010 年代的主导模型是 **RNN（循环神经网络）**。它在每个位置不仅输入当前 token，还输入一个隐藏状态，该状态编码到目前为止看到的序列的含义，并作为下一次预测的输入的一部分。于是模型不再孤立地看 token，而是考虑到目前为止解码的序列——这让词序进入了模型。RNN 当年被用于分类、情感提取、词性标注、生成等一堆任务。

但 RNN 有一个局限：它把整个序列的含义编码在一个单一向量中，而这个向量不断被修改，所以它难以记住很久以前出现的词，这就是**长距离依赖（long range dependency）**问题。Afin 的例子很生动：「Oh, my teddy bear is so cute. It is 3 feet tall.」——这里的 it 指代前面出现过的东西，如果指代的东西隔得很远，仅靠那个时刻的隐藏状态就很难梳理出来。变体 **LSTM（long short-term memory）** 通过额外维护一个细胞状态（cell state）来更长时间地携带信息，但「即便是这样的变体也有其局限性」。

还有两个问题：长距离依赖实际上源自更深层的**梯度消失问题（vanishing gradient problem）**，它给反向传播带来限制；以及 RNN 每次预测下一个 token 都必须拿到封装了迄今一切信息的隐藏状态，所以「你总是必须一次一个 token 地往前走」，训练极其缓慢。它在当时取得了很好的结果，「但也算不上惊艳」。

## 五、注意力：与过去建立直接连接

于是引出了本讲的核心概念：**注意力（attention）**。它的想法是：与其仅仅依赖隐藏状态来封装你迄今所见序列的含义，不如让模型拥有直接连接到过去所见 token 的通路。在翻译例子里，要把「a cute teddy bear is reading」译成法语并预测下一个词，知道你想翻译的那个词是什么会非常有帮助——但在传统 RNN 中你无法直接访问它，只能通过隐藏状态。注意力让模型自己学习哪些 token 重要，并让预测依赖于那些重要的 token。

2017 年的论文《Attention Is All You Need》是转折点，因为它依赖的**自注意力（self-attention）**被证明非常可扩展：给模型更多数据、更多算力、更多参数，确实能看到比以前大得多的性能提升。自注意力的定义是：为了计算给定 token 的表示，把它表达为序列中所有其他 token 的函数，而不是「该词本身加上封装了序列含义的隐藏状态」的函数。

课堂上有个尖锐的提问：如果让每个 token 与所有其他 token 交互，怎么知道词的顺序？Afin 承认这确实会丢失词序概念，「而这实际上是后面才会处理的事情」——位置嵌入正是为此存在。这种先承认缺口、再指出补救位置的讲法，比掩盖问题更有助于建立正确的心智模型。

接下来是本讲最重要的记号系统：**查询（queries, Q）、键（keys, K）、值（values, V）**。查询是「试图确定给定 token 是关于什么的实体」，它想看自己与序列中每个 token 的键有多相似；确定相似度后，每个 token 关联一个值向量，表示就是这些值的加权平均，权重由查询与键的相似度决定。Afin 的例子：想知道什么最能描述 teddy bear，查询会发现 cute 相当好地描述了 teddy bear，于是 Q_teddy bear 与 K_cute 的点积会很高，最终表示会严重依赖 cute。Q、K、V 本身是可学习的量，用投影矩阵（projection matrices）从输入 token 表示投影得到。

然后是那个被 Afin 称为「可能是关于 transformer 最重要的公式」的矩阵形式。课堂上 Shervin 后来给出了完整版本：

$$
\text{Attention}(Q,K,V)=\text{softmax}\left(\frac{QK^\top}{\sqrt{d_k}}\right)V
$$

Afin 先解释了为什么它能给出上面描述的加权和：Q 矩阵含 q1 到 qn，K 转置的每一列是某个键向量，两者相乘得到 n×n 矩阵，每个单元格是某个查询与某个键的点积；再乘以 V，就得到「Q_i K_j V_j 的求和」这类结果。Shervin 补充了两点：softmax 是为了得到和为 1 的概率分布；除以 √d_k 是因为维度 d_k 会影响求和过程中的方差，归一化后才「一切都正确地归一化」。Afin 还半开玩笑地提示：这个公式很可能出现在期中考试里。

## 六、Transformer 的完整计算流程

最后一部分由 Shervin 用一个精确例子把全部内容串起来。原始 transformer 面向机器翻译（论文中用英语到法语、德语），包含两个组件：**编码器（encoder）** 为源文本计算有意义的表示；**解码器（decoder）** 利用编码器的表示和自身正在计算的内部 embedding 生成翻译。

**输入阶段**：以「a cute teddy bear is reading」为例，先分词（为示范任意性，Shervin 采用了与子词不同的切法），加上 BOS/EOS。然后查嵌入查找表（可学习的权重），再加上位置嵌入（position embedding）——原始论文把它加在输入开头，与 token embedding 以相加方式结合。位置嵌入有两种获得方式：学习得到，或用不同频率的正弦余弦函数。学习方式的明显缺点是，若输入比训练时见过的更长（比如训练只学了 500 个位置却来了 1000 个 token），就无法表示。不同频率的思路则用「手表」作类比：小时、分钟、秒以不同频率转动，合在一起就能精确读出时间；这样的表示有个好性质——彼此接近的位置相似，彼此远离的位置不相似。

**编码器**：输入先经过自注意力层。用 W_Q、W_K、W_V 三个投影矩阵把输入投影到查询、键、值的空间。Shervin 在这里仔细对齐了维度记号：输入序列长度为 n，嵌入大小为 D_model；投影矩阵大小分别是 (D_model, D_Q)、(D_model, D_K)、(D_model, D_V)，得到的 Q、K、V 是 n 行、列数分别为 D_Q、D_K、D_V；由于要做矩阵乘法，必须有 D_Q = D_K。QKᵀ 得到 n×n 矩阵，softmax 后每一行是某个查询在键上的概率分布，用来给值加权求和。这不是做一次，而是做八次（多头，multi-head），并行学习不同的投影，最后拼接，再用 W_O 投影回模型空间。Afin 用卷积神经网络的多滤波器（filter）作类比解释多头：这是模型用不同投影矩阵、以不同方式学习同一件事。transformer 有个很好的性质：很多操作保持嵌入的原始维度不变，从 D_model 出发，经过一堆注意力计算，最终还是 D_model。之后进入前馈神经网络（feed-forward neural network），单隐藏层，把 D_model 投影到通常更大的 D_FF，以允许学习复杂表示。这样的层在原始论文里重复 N=6 次。编码器末端，每个 token 得到一个上下文感知的、学习得到的表示。

**解码器**：从 BOS 占位符开始，查嵌入表、加位置嵌入，进入解码器。第一层是**掩码自注意力（masked self-attention）**，「因为这里发生的是因果性的，每个 token 只看它自己和它前面的 token」。Shervin 解释了掩码的计算技巧：用一个三角矩阵掩掉某些连接，被掩位置取负无穷，经 softmax 后变成零。他给出的心智模型是：「忘掉来自给定 token 的所有连接以及所有在它之后的连接，我觉得作为心智模型这就够了。」第二层是**交叉注意力（cross attention）**：查询来自已解码的 token，键和值来自编码器——「你是在问自己：我怎样才能把这个 token 表示为输入文本中所有 token 的函数？」之后又是前馈网络，最后接线性层和 softmax，把表示变成词表空间上的概率分布以预测下一个词。取最大值选出下一个 token，把它作为输入放回解码器，重复同样流程，直到遇到 EOS 停止。这就是**自回归（autoregressive）**生成。

**那些「技巧」**：Afin 在问答中集中讲了几个工程组件。**残差连接（residual connection）**：「与其说某一层的输出是 x 的某个函数，你所说的是你的层的输出是 x 的某个函数再加上 x」——像是在对 x 进行修改，而不是完全改变 x，实践中这有助于反向传播，让模型学得更好。**层归一化（layer normalization）** 对激活值归一化，帮助收敛。**dropout** 在训练时以一定概率有意丢弃一些单元，避免模型过度依赖某些特征，从而泛化更好。**标签平滑（label smoothing）**：预测「what a nice day」时，不要求模型 100% 预测 day，因为「what a nice class」同样成立；把标签软化（比如目标 90%，剩下 10% 分给词表其他词），作者发现这能在机器翻译上提升指标（Afin 提到 BLEU 是这类指标）。

**到底什么让它奏效**：有听众问，这一切看起来很复杂，精确提炼的话是什么让它工作？Shervin 的回答是：论文标题多少道出了秘诀——注意力层是关键；其次是前馈神经网络，「网络的大部分参数都在这里」，模型容量和学习主要发生于此；其余只是帮助学得更好的技巧，「当然还有数据的质量，那是另一个层面的复杂性」。他还提醒，后续课程会看到很多组件被去掉，只依赖这些组件的一个子集并反复使用。

课堂最后还澄清了两个易混点：注意力层里的 softmax 和最后一层的 softmax 功能不同——前者是把查询投影到键的空间上，后者是为预测下一个 token；BOS 只作为解码器输入出现，不出现在解码器输出端，判断停止要看 EOS。

## 七、这一讲在整门课程中的位置

从课程自述看，这条学习路径是清晰的：第一讲停在 2017 年，交付的是架构层面的「底层机制」；接下来几讲讲如何训练这样的模型；课程第二部分讨论这些模型如何驱动今天我们交互和使用的 agent，以及如何在多个系统中使用。第一讲因此具有双重身份：它既是全课程的概念密度峰值（分词、表示学习、RNN、注意力、Transformer 全部登场），又是后续所有内容的最小公分母——不理解 Q/K/V 和 softmax 的两种用途，就无法理解训练目标，更无法理解 agent 系统里模型在做什么。

值得注意的是本讲对「领域在动」的自觉。Afin 明说今年重录是因为新进展太多，并举了后训练、agent、「一次预测一个 token」之外的新范式（如 diffusion 角度）；他还提到去年讲到一半时有些新东西发布，于是边教边更新。这提示学习者：第一讲给出的架构是稳定的参照系，而不是课程的终点。

## 结语

回看整讲，最有价值的或许不是那个被特别提示「可能很重要」的注意力公式，而是贯穿始终的推理方式：每个设计都从上一个设计的具体失败中长出来——词级分词败于词表外与词形变体，字符级败于序列长度，于是有子词与 BPE；one-hot 败于正交、无相似性，于是有 word2vec；word2vec 败于多义与词序，于是有 RNN；RNN 败于长距离依赖、梯度消失与串行计算的缓慢，于是有注意力和自注意力；自注意力本身丢失词序，于是有位置嵌入；解码器不能看未来，于是有掩码。理解这条链条，比记住任何单个组件都更接近这门课想传达的东西：Transformer 不是一组需要背诵的模块，而是对一系列具体约束的回应。
