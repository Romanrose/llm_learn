# 从“续写文本”到“有用的助手”：Stanford CME 295 第三讲中的 LLM 训练全流程

## 导语

如果只看第一讲和第二讲，transformer 和大语言模型（LLM）似乎是一个“架构问题”：编码器、解码器、注意力、位置嵌入、归一化，再加上缩放定律（scaling laws）和混合专家（mixture of experts）。但一个架构不会自己变成有用的模型。CME 295 第三讲的主题正是把这套架构“跑起来”的过程：**LLM training**。本讲从最基础的 next token prediction 出发，依次走过预训练（pre-training）、中期训练（mid training）、长上下文训练、监督微调（SFT）、奖励建模与 RLHF、DPO，最后落到推理模型（reasoning model）的训练思路和一个真实开放权重模型的案例。它的核心线索可以概括为一句话：**训练不是一个动作，而是一条逐步把“语言模型”塑造成“有用助手”的流水线**。

在课程整体路径中，这一讲处在承上启下的位置。第一讲给出 transformer 的基本组件，第二讲讨论如何把这些组件做得更大、更高效；第三讲则回答“这些组件如何被数据和时间打磨”。同时，本讲明确把强化学习的数学细节推到第四讲，把基础设施问题推到第五讲，把编码器式方法和更广的推理话题留到后续讲座——也就是说，第三讲是整门课从“模型结构”转向“训练流程”的枢纽。

## 一、起点：预训练就是学会预测下一个 token

讲者先用一个历史对比开场：如果这门课在十五年前开设，人们会为每个用例单独训练模型——垃圾邮件检测一个、情感提取一个、翻译一个。而今天的思路是迁移学习（transfer learning）：先做一次大规模的一次性预训练，让模型学习关于语言的知识，再针对具体用例调整。这个“先通用、后专门”的划分，构成了本讲后续所有阶段的基本框架。

预训练的数据来源被描述为“大量文本、大量代码、大量生成内容”：网页文本、多语言文本、Python 等代码、数学、科学材料。训练目标则是 next token prediction。讲者用一段文本举例：把文本 tokenize 后，喂入序列起始 token（beginning of sequence token），让模型预测第一个 token，再把本该出现的 token 喂回去预测下一个。关键在于，这个过程**高度可并行化**：实际训练时会把整个输入一次性喂入，为所有位置同时预测下一个 token，底层可以看成一个巨大的矩阵乘法。这里依赖的正是第一讲见过的 masked self-attention：预测某个位置时，只能关注它自己及其之前的 token，从而模拟推理（inference）时“只能依赖已解码内容”的设置。

讲者特别讨论了教师强制（teacher forcing）：无论模型预测什么，下一步的输入永远是文本中本应出现的词。有学生追问：这样训练时模型没有把自己生成的内容作为输入，训练和推理之间是否存在不匹配？讲者承认这是一个很好的点，并预告后续会看到解决方法。这个悬念其实埋下了整讲的伏笔——后面 SFT、RLHF、DPO、on-policy distillation 都在不同层面回应“训练分布与模型自身输出之间的差距”。

## 二、损失函数：从第一性原理推出交叉熵

讲者没有让听众死记公式，而是从最大似然出发。目标是学习参数 theta，使模型看到训练数据的概率最大化。一个序列的概率可以写成 p(x1) 乘以 p(x2|x1) 一直乘到 p(x_n|x1…x_{n-1})，即所有 token 条件概率的乘积。但概率都在 0 到 1 之间，连乘会趋向零，带来数值不稳定，因此取对数，把乘积变成求和；机器学习习惯最小化，于是取相反数；再除以 token 数量，避免损失随序列长度缩放。这就是交叉熵损失（cross entropy loss）。

讲者还介绍了每字节比特数（bits per byte，BPB）：交叉熵损失的绝对值依赖于分词器（tokenizer），不同分词器的模型之间损失不能直接比较；BPB 通过乘以 token 数除以字节数、再乘以 1/log 2，把损失表达为与分词器无关的“比特”单位。这里“B 是什么”的提问得到了明确回答：B 是输入中的字节数。

这一段看似基础，实则奠定了后面所有阶段的共同语言：无论是 SFT 还是偏好优化，目标函数都围绕“给定输入和过去 token，预测目标 token 的概率”展开，只是“目标 token”从任意文本变成了回答、获胜答案或推理链。

## 三、数据：预训练的真正难点

讲者强调，大量精力被投入到“训练什么数据”上。预训练语料通常规模巨大，量级是数万亿 token，最近甚至达到数十万亿 token；他举例说，相对较新的开放权重模型 GLM5 是在 30 万亿 token 上训练的。数据准备本身是一项复杂工作，讲者引用 GLM5 的训练流水线图说明其复杂性，并明确表示本课不会重点讲基础设施，而会在第五讲专门讨论。

关于数据重复，讲者提到有论文研究“数据受限”情形：如果只有固定数量的 token，是停止训练，还是在同样的 token 上多训练几轮？答案是可以重复，最多大约四次，能带来更好的性能。这里存在权衡：更多唯一 token 与更高质量数据、是否重复之间的取舍。讲者还引用 DataComp-LM，说明这项工作试图把“高质量数据集”与“更好架构”的影响分开——两个人各自训练模型时，性能提升可能归因于架构，而非数据，因此需要把架构侧归一化，才能梳理出数据质量的作用。至于数据混合（例如 20% 代码、50% 网页），一种常见做法是在不同数据混合上训练多个小模型，观察各自表现，再推断放大后可能有效的混合比例。

## 四、中期训练与长上下文：预训练之后的“补课”

近年来出现了第二个阶段：中期训练（mid training），目的是注入与用例更对齐的任务知识。如果关心推理，就让模型接触更多代码和数学文本；仍然做 next token prediction，但使用更高质量的数据。另一个目标是让模型看到更长的上下文：预训练通常出于效率考虑使用数千 token 量级的序列长度，而实际输入可能是数万甚至数十万 token。

长上下文训练的关键在位置编码。既然现在人们用 RoPE，而 RoPE 没有可学习参数，理论上可以“开箱即用”；但如果只在短序列上训练，模型从未见过长序列的旋转，推理时就会困惑。因此需要长上下文训练阶段，通常还会对 RoPE 频率做小调整。讲者以 YaRN 为例：如果直接把短上下文模型放到长上下文上训练，长位置差异对模型来说完全是没见过的；人们于是对频率进行插值，使长位置差异落在短上下文训练时见过的频率范围内。有学生问“怎么确定会遇到什么长度”，讲者回答这是预先规划好的：GLM5 的例子中，短上下文训练使用 4,000 长度的输入，长上下文训练则拉到 128k 甚至 200k；推理时使用调整后的频率。

长上下文的困难不止计算量。自注意力是每个位置关注其他所有位置，复杂度是 n 的平方，从 4,000 扩展到数十万，计算量会大幅增加；更难的是获得“需要长距离依赖才能预测某个 token”的数据——你需要构造出“利用很久以前的信息在很远的未来做预测”的观测，这不是轻易能想出来的。

讲者还提醒了一个现实限制：预训练、中期训练和长上下文训练结束后，模型会有一个知识截止日期（knowledge cutoff date），训练数据截止到某个日期，之后的事情模型完全不知道。他举的例子是 GPT6 Astra 的数据截至 2026 年 4 月 30 日。这个知识在时间上是固定的，但后续技术可以绕过这一限制。

## 五、一个关键的教学例子：泰迪熊与洗衣机

本讲反复使用同一个提示来标记各阶段的行为差异：“我能把我的泰迪熊放进洗衣机吗？”

在纯预训练阶段，模型不会回答问题，而是自动补全。它可能输出类似“泰迪熊通常由聚酯纤维和棉等材料制成，有塑料眼睛，有时还有小配件……有用吗？不，没用。”这正是 next token prediction 的本性：它在续写文本，而不是在回答。

SFT 阶段的目标是改变模型行为，使其与期望对齐。做法是构造输入-输出对：指令是输入，回答是目标。损失仍然是 next token prediction，但输入是指令加上已解码的回答，只惩罚预测回答的部分，不惩罚输入。讲者明确回答学生提问：不会惩罚预测输入，因为输入是给定的，你的意图不是预测 prompt。SFT 数据的规模远小于预训练：非常特定的用例可能只有数百或数千个例子，通用助手式行为可能有数百万个例子，但相比预训练仍然小几个数量级。经过 SFT，同样的提示可能得到“不会，它可能会被损坏。试试手洗。”——它回答了问题，但语气未必理想。

RLHF 阶段则进一步对齐人类偏好。讲者用另一个提示引出问题：“建议一个我可以和我的泰迪熊一起做的新活动。”SFT 后的模型可能说“我建议你实际上不要花时间和泰迪熊在一起”——这是一个回答，但不是想要的回答。到目前为止我们只告诉模型该做什么，还没告诉它不该做什么；而且 SFT 数据不是模型自己生成的，是我们强行喂给它的。偏好对齐正是为了处理这两个问题。

## 六、奖励建模与 RLHF：把“哪个更好”变成可优化的信号

偏好数据的收集方式有三种：逐点评分、成对偏好、列表排序。讲者解释，成对数据最常用，因为人类判断“A 比 B 更好”比在绝对尺度上断言“A 好”容易得多。这里还顺带指出一个诊断价值：如果 SFT 后的模型行为不当，有时说明 SFT 阶段喂了非预期的数据，因此偏好阶段也是检查 SFT 数据质量的好时机。

有了偏好对，就需要一个能泛化的奖励模型（reward model）。奖励建模通常使用 Bradley-Terry 公式：y_i 优于 y_j 的概率等于 sigmoid(r_i 减 r_j)，即两个奖励之差的 sigmoid。训练时使用成对损失（pairwise loss）：对每个提示，有获胜回答 Y_W 和失败回答 Y_L，让奖励模型给获胜回答更高奖励、失败回答更低奖励。讲者从交叉熵的同样思路出发解释这个损失：你想最大化“获胜回答优于失败回答”的概率，取对数，再取相反数来最小化。关于奖励模型的架构，讲者给出两种选择：利用 LLM 主干，取最后一个输入 token 的嵌入表示投影到某个空间；或者使用仅编码器（encoder-only）模型，做完自注意力后直接投影。前者的好处是可以复用已有主干。

RLHF 的第二阶段是强化学习：奖励模型被冻结，只更新 LLM 的权重。目标函数通常由两部分组成：最大化奖励，同时不要偏离参考模型太多。讲者解释后者时呼应了 LoRA 的动机：模型已经足够好，知道如何回答问题和大量知识，你不希望把权重改变太多；而且奖励模型并不完美，有时明明很好却说不好，所以需要惩罚相对于参考模型的过大差异。这里还引出一个关键术语：奖励黑客（reward hacking），即模型朝奖励模型喜欢的方向走，而这未必是好事。讲者明确把“具体如何更新权重”的数学留到第四讲，本讲只建立直觉。

## 七、DPO：用监督方式表达偏好优化

讲者指出 RLHF 很复杂：需要奖励模型、需要大量注意力调超参数。于是人们尝试用监督方式表达同样的问题，这就是直接偏好优化（direct preference optimization，DPO）。DPO 的损失函数与奖励模型的损失函数非常相似，关键假设是把奖励 r 写成“正在调整的模型相对于参考模型的概率的对数”乘以某个系数。这样损失会激励模型相对于参考模型提高生成获胜答案的概率，同时降低生成失败答案的概率。讲者提醒，公式看起来吓人，但如果把 Bradley-Terry 公式记在心里，把左右两项解释为“正在调整的模型与参考模型之比的函数”，就会更有意义。参考模型就是 SFT 阶段结束时的模型。

讲者还点出 DPO 的一个局限：它基于固定的输出计算损失，而不是根据模型正在产生的输出来计算。也就是说，RLHF 是同策略（on-policy）方法，利用 LLM 的实际输出；DPO 更接近异策略（off-policy）。这个区分在后面训练推理模型时再次出现，并成为理解 on-policy distillation 的伏笔。

回到泰迪熊例子：经过偏好调优后，回答可能变成“不，最好不要，你的泰迪熊可能会受伤，轻柔的手洗更安全。”——语气更友好。讲者用这个例子说明，偏好方法可以用来改变语气等行为特征。

## 八、推理模型：可验证奖励与 GRPO

讲者把推理（reasoning）简单定义为“解决问题的能力”，并对比两类提示：知识型问题（“斯坦福 transformers 和 LM 课程的课程代码是什么”）知道就知道、不知道就不知道；数学问题（“你的熊出生于 2020 年，这只熊现在多大了”）则需要想一下年份差。第二讲结尾介绍的思维链（chain of thought）通过少样本示例激励模型展示推理链，但问题是“我们不想总是告诉 LM 这么做，我们希望 LM 自己这么做”。

讲者回顾了时间线：2024 年 9 月，OpenAI 率先展示了这种技术在数学和编码任务上带来的性能提升；之后几乎所有前沿实验室都有了使用相同策略的模型；2025 年 1 月，DeepSeek R1 是第一个真正走完“如何做”过程的开放权重模型，其论文大概是第一篇真正解释推理模型如何训练的论文。他还提到一个现实变化：2025 年识别推理模型要看用户界面各处的标记，而今天几乎所有模型都是推理模型，用户能看到的往往只是“思考努力程度”的设置。

推理链为什么敏感？讲者给出两个原因：有论文表明，对某些第三方提供商，可以通过玩弄 API 恢复完整的推理链；这些推理链可能包含大量关于用户、关于聊天、关于之前提到的内容的信息，出于安全原因不应暴露；另一个原因是不想让推理链被公开用于训练他人模型。因此用户界面在 2025 年到现在变化很大，推理链不再像以前那样开箱即得。讲者还提醒成本：使用推理模型时，既要为看到的内容付费，也要为模型产生的、通常隐藏的推理链付费。

训练推理模型的核心是奖励。与偏好阶段不同，这里的奖励是**可验证的**：编码任务跑测试用例，数学问题与真实答案比较。因此可以设计一个依赖最终答案正确性、同时要求答案包含推理链的奖励。训练使用 RL 算法，讲者预告第四讲会深入讲解越来越流行的 GRPO（组相对策略优化）。在高层次上：给定查询，让策略输出多个响应，判断这些响应是否正确，计算“一个答案相对于组内有多好”的优势（advantage）；如果好得多，就让模型多做那种；如果不是，就少做，同时仍然通过相对于参考模型进行惩罚。目标是在不太偏离基础模型的情况下最大化优势。这里不需要奖励模型，只需要问题真实答案的知识。

讲者展示了效果：模型性能作为 RL 步数的函数上升，推理链的经验长度也上升。但他随即指出核心局限：奖励非常粗糙，是整个输出级别的——要么整个输出正确，要么整个输出不正确；而偏好调优那类方法虽然有 token 级信号，却基于不是模型产生的序列，是离策略的。前者是稀疏信号，后者是稠密但非模型生成的信号。

## 九、On-policy distillation：把两者的优点结合起来

讲者介绍了一批新训练策略中越来越流行的技术：同策略蒸馏（on-policy distillation）。给定 prompt，模型生成回复；不依赖贯穿整个序列的稀疏信号，而是让一个教师模型（teacher model）评估生成的每一个 token，惩罚学生模型（student model）与教师模型之间的偏差。好处是：它是 on-policy 的，因为使用学生自己的生成；同时它是稠密的，因为得到 token 级别信号。

如果没有现成的教师怎么办？有一种变体叫同策略自蒸馏（on-policy self distillation）：对同一个任务使用同一个模型，但把答案告诉教师模型——也就是同一个模型——这样它就知道如何引导自己的回复。讲者说这项技术已被纳入大多数前沿开放权重模型。另一种设置是使用专门的教师模型：一个非常擅长数学，一个非常擅长工程，然后对学生模型相对于这些教师进行稠密监督。

## 十、真实案例：GLM5 的训练流水线

讲者把最后一部分交给 Shervin，聚焦一个实际用例：GLM5。他先推荐了一个 benchmark 聚合器，说明开放权重模型通常稍微落后于闭源前沿，但好处是很多会把背后的“秘密配方”公开出来。

**预训练阶段**：网页数据通常用 Common Crawl，如今其中很多被 AI 生成内容污染，因此需要启发式规则修剪，通常最后只保留约 1% 的输入。然后是权威网站如 Wikipedia，提供通用知识；还有一些事实不在主要网站上，需要更用心筛选进入数据混合。代码数据（如 GitHub）是重点，因为今天的 agent 主要以不同形式的编程问题呈现；某些语言在混合数据中出现不多（例如移动端特定数据），需要筛选。数学和科学论文用于增强推理。GLM5 的预训练大约在 4K token 的低上下文长度下运行，并分成两个阶段：第一阶段粗粒度学习语言结构，聚焦网页数据；完成后加入代码和推理混合内容，同时仍有网页数据但比例更小。训练时纯粹做 next token prediction，目标不是生成有用的句子，而是学习语言的大型概念；没有格式良好的序列开始/结束批次，而是把大量数据切块、把属于一起的文档拼接起来填满上下文长度，因此批次不一定以序列开始 token 开头。

Shervin 还谈到模型坍缩（model collapse）：即使假设模型完美，从多样分布中有限采样也无法捕获所有长尾细节，模型输出天生不会具有相同分布；模型只是近似器，不会输出完美分布；再加上后期阶段注入的偏好，某些“承重”内容相对于真实分布被大幅提高频率。这就是数据 curation 技术重要的原因。关于训练轮数，通常是 O(1)，但被分类器判定为更高质量的数据可能多跑几轮。

**中期训练阶段**：在 GLM5 案例中，目标纯粹是增加上下文长度，因此数据混合主要由更长篇幅的数据组成，以匹配关注的领域。代码情况下关注带 issue 的 PR 和代码 diff，这些通常占用更多上下文，然后有余裕放入整本书等。Shervin 提到 context rot（上下文腐化）：更大上下文长度下，LLM 可能难以记住早先提到的事实，因此在合成数据中可以在中间注入事实、之后再引用。中期训练也有类似预训练的若干阶段：第一阶段专注代码，第二阶段专注其他更长篇幅数据，训练策略略有不同。这里不是把所有东西分块全部放进去预测下一个 token，而是以合适方式打包文档、避免截断，称为 best fit packing（最佳适配打包）；如果剩下太多空间，可能对上下文做 padding（填充），仍然是 next token prediction。

**SFT 阶段**：更高质量数据进入，训练 token 数量级大幅下降。强调通用有用性；当今模型认识到专注推理是高价值的，因此注入大量推理和编码数据。论文提到一种策略是插入通向给定工具调用的推理，这对训练推理能力也很棒，例如模型想要执行工具调用时。你会看到交错的推理以及 think token 的存在。Shervin 提醒，所有这些推理会计入账单，但你看不到，因为它在 think token 之间——这是模型拥有一个草稿板（scratchpad）的方式。SFT 不再是纯粹的 next token prediction：输入 prompt 部分不尝试猜测下一个 token，因为那是用户输入；想拟合的是希望 LLM 给出的答案，因此损失更加局部化。

**RL 阶段**：GLM5 论文将其分为三部分。推理强化学习（reasoning RL）：数学竞赛等数据，有地方思考答案，也有可验证的答案。智能体强化学习（agentic RL）：把 LLM 放进一个 harness（运行框架），让它能使用运行测试之类的手段验证自己做的事情是否正确，例如 bug 修复——把失败的测试修成通过的测试。通用强化学习（general RL）：更开放，提出基础正确性、情商、任务特定质量等维度；情商是专家数据标注者对于什么是有用答案的看法，等等。然后根据答案是否符合所寻找的，提高某些 token 出现的概率，而不是其他 token。

最后，Shervin 回应了一个合理担忧：我们确定学到的一切都被保留了吗？有时确实没有保留，这就是为什么 RL 最后阶段有一个同策略跨阶段蒸馏（on-policy cross-stage distillation）阶段，针对之前检查点的教师模型——更具体地说，是 SFT 之后的检查点，以及第一个 RL 阶段之后的检查点——确保没有丢失任何能力。

他还提醒对开放权重模型的技术报告保持批判眼光：数据背后的一些“秘方”并不总是写明的；新闻中常有厂商抱怨别人蒸馏他们的数据，这也可能是数据混合的一部分，但当然不会写在技术报告里。他提到一个编码智能体案例：一个极简的智能体以极简的 harness 取得了出色性能，作者真正深入理解了这些模型如何能有出色表现——所有这些阶段都专注于开发推理能力，这使你能够避免在 harness 中放入过多上下文；因此可能看到对 harness 工程的需求越来越减少。最后，他提到这些推理数据和训练促成了数学等领域的进步，例如最近 OpenAI 发布了一些开放问题的解决方案。

## 结语：一条流水线，一个核心张力

把第三讲压缩成一张图，就是：预训练学语言 → 中期训练注入任务知识与长上下文 → SFT 塑造助手行为 → 奖励建模与 RLHF/DPO 对齐偏好 → 可验证奖励 + RL 训练推理 → on-policy distillation 防止能力遗忘。每个阶段的数据规模、损失形式和信号密度都不同，但都在回答同一个问题：**如何让模型的行为接近我们想要的行为**。

本讲最值得记住的，可能不是某个公式，而是几个反复出现的张力。第一，**训练分布与模型自身输出之间的不匹配**：teacher forcing 埋下它，SFT 的数据不是模型生成的，DPO 是 off-policy，而 RLHF 和 on-policy distillation 试图用模型自己的输出（on-policy）来缓解。第二，**稀疏信号与稠密信号之间的权衡**：序列级可验证奖励很粗糙，token 级偏好信号又可能不是模型生成的；on-policy distillation 试图把“on-policy”和“稠密”结合起来。第三，**能力保留与行为对齐之间的平衡**：RLHF 惩罚偏离参考模型，跨阶段蒸馏防止遗忘，奖励黑客则提醒我们奖励模型并不完美。

这些张力也解释了为什么第三讲要把强化学习的数学推到第四讲：本讲的任务是先让听众看清整条流水线的形状、每个阶段的动机和它们之间的接口。等到第四讲进入 GRPO 等算法的细节时，这些直觉会成为理解数学的脚手架。而对于整门课而言，第三讲之后，transformer 不再只是一个架构图，而是一个被数据、损失、偏好和奖励反复塑造的对象——这也正是“Transformers & Large Language Models”从结构走向系统的关键一步。
