# 从奖励到梯度：LLM 强化学习后训练的三条路线

## 导语

在 CME 295 的课程路径上，前三讲搭起了 LLM 训练的基本骨架：预训练教会模型理解文本与代码，监督微调（SFT）把模型调教得“有用”。到第四讲，我们进入训练流程的最后一环——偏好调优（preference tuning）与推理能力提升，而这两件事在课程中被统一到同一个技术框架下：基于强化学习（RL）的后训练。这一讲之所以特别，是因为它是全课程数学密度最高的一讲；也正因如此，它承担着把前几讲“只闻其名、未见其形”的损失函数真正推导出来的任务。本文按照课程的论证顺序，先建立 RL 与 LLM 之间的概念映射，再推导策略梯度这一核心公式，然后依次考察 PPO、GRPO 与 on-policy distillation 三种方法如何各自应对三个反复出现的挑战，最后说明这些方法在课程整体学习路径中的位置。

## 一、把 LLM 放进 RL 的语言里

课程先从最朴素的 RL 图景讲起：一个智能体（agent）与环境（environment）交互，处于某个状态（state），依据策略（policy）π_θ 选择动作（action），转移到新状态并获得奖励（reward），目标是最大化收集到的奖励之和。

这套语言映射到 LLM 上非常自然：智能体就是 LLM；状态是输入；动作是下一个要采样的 token；而策略 π_θ 就是模型在给定输入下输出的概率分布——这正是上一讲 SFT 中见过的记号，π 代表 policy。课程在这里提醒了一个关键的设计选择：定义 token 级别的奖励很困难，所以实践中奖励往往定义在响应（response）或补全（completion）级别。此时可以把输入看作提示（prompt），把动作看作整个响应，π_θ 就是给定提示下输出某个响应的概率。

奖励从哪里来？课程把情境分成两大类。第一类没有答案的绝对真值（ground truth），评判带主观性，典型做法是用人类偏好把语气更好的响应排在更差的之上，并用 Bradley-Terry 公式以成对方式建模、训练一个奖励模型——这类方法叫 RLHF。第二类是答案可以被可验证地判定对错的情形，比如数学题有确定的解、编程题能通过测试用例，这类方法叫 RLVR（reinforcement learning with verifiable rewards），通常出现在推理领域。

这里有一个课堂问答值得记录，因为它澄清了 RLHF 的工程结构：生成每个补全时并不需要真人在环——人们先训练好奖励模型，之后在循环里用这个冻结的奖励模型评估响应。这也解释了课程反复出现的“冻结的奖励模型”这一表述。

## 二、目标函数的梯度：为什么要“奖励乘以对数概率的梯度”

设定清楚后，课程进入数学部分。目标函数是最大化期望奖励：找到参数 θ，使得从策略 π_θ 采样轨迹（trajectory）时的奖励期望最大。要优化它，就需要梯度。

推导只用了一个数学恒等式：一个函数的对数梯度等于该函数的梯度除以该函数。反过来用，就是“函数的梯度 = 对数梯度 × 函数”。把它代入期望奖励的积分表达式，就得到策略梯度公式：目标函数的梯度，等于“奖励 × π_θ 的对数梯度”在轨迹从 π_θ 中采样时的期望值。

课程特意停下来解释这个公式的直觉，因为这是整讲最值得记住的一句话：**如果奖励为正，梯度会激励模型提高这类动作的概率；如果奖励为负，则激励模型降低这类动作的概率。** 课程还说明，在 LLM 情形下期望实际是先对一组提示、再对给定提示下的回复求期望。

由此得到更新规则：采一个提示 x，从模型生成补全 y，评估奖励，计算“奖励 × 对数概率梯度”，然后做梯度上升——注意是 θ 加上 α 乘以梯度，因为这里要最大化而非最小化。

课程在此强调了一个与预训练、SFT 都不同的性质：这是 on-policy 设定，每次更新都需要模型自己生成回复，而生成是串行的——拿到一个 token 才能问下一个 token 是什么，无法并行，因此非常昂贵。这为后面所有算法设计埋下了伏笔。

## 三、三个挑战：噪声梯度、缺失的 token 级信用分配、无约束的漂移

在正式介绍算法之前，课程先把朴素方法的问题摆出来，共三个。

**第一，梯度方差高。** 课程举了一个具体例子：同一个提示下有好答案和坏答案，好答案奖励 101，坏答案奖励 100。101 确实大于 100，但两者都很高，模型感受不到它们之间的差异，于是会先因为好结果做大幅更新、再因为坏结果做大幅更新，梯度噪声很大。解决办法是引入基线（baseline）：如果知道平均而言 100.5 大致是“还行”，那么 +0.5 就是好、−0.5 就是坏，梯度方差会低得多。

**第二，缺少显式的 token 级信用分配（credit assignment）。** 课程用了贯穿全讲的 Teddy 例子：Teddy 在密封盒子里，你把盒子搬到厨房，然后问“Teddy 在哪里？”模型回答“第一步，Teddy 从盒子里爬出来。第二步，Teddy 走到厨房。第三步，答案是厨房。”最终答案正确，但中间步骤错了——Teddy 一直待在盒子里，并没有走路。由于奖励在补全级别，原始做法会激励这个回答的所有 token 更频繁地出现，包括错误的中间步骤。

**第三，策略可能偏离起始模型太远。** 训练开始时模型已经过预训练和 SFT，已经足够好；而且奖励模型本身可能不完美，存在奖励黑客（reward hacking）的风险。课程用了一个自嘲的例子：如果只用课堂结束时掌声的强度来衡量讲课好坏，那讲两小时与课程无关的笑话也可能拿到掌声，但这与真正的目标并不对齐。所以需要对策略的漂移施加约束。

这三个挑战构成了后续三种方法共同的“考纲”。

## 四、PPO：用价值函数换基线，用裁剪换约束

PPO（proximal policy optimization）相对朴素方法有两个不同：最大化优势（advantage）而不是奖励；不偏离之前的策略太多。课程指出，名字里的“P”对应的就是第二点。

**优势项。** 奖励回答的是“这个答案相对于提示有多好”，而优势想问的是“相对于我们对这个提示的期望，这个回答有多好”。课程引入价值函数（value function）来构造基线：给定部分补全，如果继续从策略中采样解码，期望的最终奖励是多少？在 Teddy 例子里，解码到“in”时期望奖励假设是 0.6，到“the”是 0.7，到“box”因为答案正确跃升到 0.95，最后是 1。于是“box”这个 token 的优势，最简单地算就是 0.95 − 0.7 = +0.25。这样既有了基线，又定位到了单个 token 的贡献——恰好同时缓解了第一和第二个挑战。

课程诚实地给这个算法加了引号：实际情况更复杂，因为一个 token 可能不仅提高眼前的奖励，还把模型放到一个让未来 token 更容易获益的位置。课程用“教朋友数学概念”作比：教概念带来考试成功这个短期奖励，而考试成功又可能让他走上后续成功之路——不能把未来所有成功都归因于教概念，但其中一部分应当归因。这正是广义优势估计（generalized advantage estimation，GAE）背后的思想。课程明确说明它不在考试范围内。

课堂问答澄清了两个实现细节：价值函数和策略在实践中是两个模型、联合训练；奖励模型是事先训练的，价值模型则是随策略一起训练的，因为价值函数的定义依赖于“如果你按正在训练的策略继续下去”的期望奖励。

**裁剪与 KL。** 由于生成补全昂贵，人们希望用一批数据做多次更新。此时采样用的策略变成 π_old，于是出现当前策略与旧策略的概率之比，课程要求把它记作 ρ 而不是 R，以免与奖励混淆——这个量叫重要性采样比（importance sampling ratio）。但比值不加控制会让策略漂移过远，于是 PPO 裁剪目标函数：优势为正时，目标函数随 ρ 线性增长，梯度会一直激励模型增大这个概率；裁剪后，一旦 ρ 超过某个范围，梯度变为零，激励被消除。优势为负时对称地处理。

课程还引入第二种约束方式：KL 散度，作为惩罚项比较当前策略与参考策略。这里必须区分三个策略：π_θ 是正在更新的当前策略；π_old 是生成这批数据的策略，会随批次更替；π_ref 是固定的基础策略，始终不变。课程确认：实践中常常两个约束都用——相对旧策略的迭代约束，加上相对参考策略的绝对约束。

课程还顺手把上周 DPO 的公式接了过来：DPO 损失里的 β，与 KL 惩罚里的 β 是同一个 β——β 越大，偏离参考策略一点点就会让 sigmoid 接近饱和，因而偏离的激励越低。同时课程再次提醒，读 PPO 论文时要注意：公式里的 L 不是损失而是目标函数，要最大化；R 是比值不是奖励。

PPO 的代价也很明确：必须训练价值函数，这是它“很麻烦”的核心原因——需要额外的带宽来承载价值模型的训练。

## 五、GRPO：把“组”当作基线

GRPO（group relative policy optimization）的最大卖点是：不需要价值函数。它替代价值函数的办法非常直观：给定一个提示，用正的温度值采样多个回答，分别计算奖励，然后用“奖励减去该组奖励的均值、再除以标准差”得到优势。这样每个回答都能相对于同组的其他回答感受到自己好不好。

课程用一个示意图走完了 GRPO 的完整流程：取提示，让策略生成 G 个输出，用奖励模型（或确定性的可验证奖励）评估每个输出，按组归一化算优势，用优势算梯度，同时对偏离参考模型的惩罚（裁剪加 KL）照旧保留。整个系统只需要策略模型、奖励模型和参考模型，奖励模型在推理、数学、编程场景下甚至是可选的。这直接消解了第三个挑战中“训练额外模型”的负担，也通过组内比较降低了梯度噪声。

但课程紧接着指出了 GRPO 的两个遗留问题。

**其一，长度偏差。** 课程展示了训练中观察到的现象：模型在数学问题上的性能趋于平台期后，回复长度仍倾向于增加。解释藏在归一化项 1/|o| 里：回复短时这个系数大，回复长时系数小。于是对负优势的坏答案，短坏答案受到大的向下惩罚，长坏答案只受到轻微的向下惩罚——相对而言，模型会偏好较长的坏答案而不是较短的。课程提到后续工作对此做了修正：DAPO 让所有 token 贡献相同，把归一化改为对输出求和；Dr. GRPO 则直接去掉这个归一化项。课程还提到另外两个潜在偏差：用奖励标准差归一化会因输入复杂度不同引入偏差，可以移除；以及对上下界使用相同的 ε 时，概率极小的动作很难获得被更多生成的机会，不利于多样性，因此可以对上下界取不同的 ε。

**其二，仍然没有 token 级信用分配。** 课程回到 Teddy 例子：GRPO 只看最终答案，中间步骤对或错都关联同一个最终奖励，即使步骤错了也归因相同的优势。长期看模型平均而言或许能学对，但这非常低效，因为每一步可利用的信息都被浪费了——损失函数的每一项在局部是有噪声的，正确行为的学习依赖长期平均。课程讨论了过程监督这条替代路线：它需要专门的标注，在步骤级别切分并分别标注；而步骤内部仍有歧义（“Teddy 在厨房工作”，错在“工作”还是“厨房”？），递归下沉到 token 级别就又回到“需要额外训练一个模型”的老问题——而这正是当初放弃 PPO 想要避免的。

## 六、On-policy distillation：向更强的分布对齐

课程最后提出一个保留 on-policy、保留密集 token 级信号、又不训练额外奖励模型的方案。思路来自课堂提问引出的概念：蒸馏。蒸馏本质上就是下一 token 预测，把信息从一个模型传递到另一个模型。

比较两个下一 token 预测分布用的损失是 KL 散度。课程强调它不对称，并给出一个便于记忆的读法：KL(P‖Q) 是“在一个由 P 支配的世界里，用 Q 来近似有多糟糕”。常规蒸馏让教师 T 支配世界，但这里想对学生做 on-policy，于是自然写成反向 KL——学生在前、教师在后。

反向 KL 的性质是本节课最精巧的一段推理：当教师概率非零而学生接近零时，这些项对求和贡献不大，即对这类不匹配“宽容”；但当教师概率很小而学生非零时，比值会非常大且权重非零，产生巨大的项。这使学生倾向于 mode seeking，即学到教师分布中的峰值。课程坦承，原始论文其实混合了两者，所以反向 KL 并不显然就是更好的那个。

具体做法是：让学生基于提示生成补全，然后逐步问教师——在包含学生已生成 token 的上下文下，这个 token 对你来说有多大意义？Teddy 例子里，学生说“Teddy climbs”，教师会认为“climbs”不是高概率 token，于是惩罚。课堂上有个精彩的追问：为什么“box”也没有被惩罚？答案是，一旦“climbs”进入上下文，教师可能把 Teddy 理解成会攀爬的存在（比如人类），于是“走路”也落入可能性范围——这说明上下文会改变教师的判断。

这套方法的优点是：监督信号是 token 级别的、密集的；它是 on-policy 的，模型相对于自己的补全变好；没有奖励模型，也就没有东西可以被 hack——如果真的把损失降到零，那就是对齐到了教师分布，这是一个很好的边界情况。课程引用 Thinking Machine 的博客中的玩具消融研究：先做 SFT 再做 on-policy distillation，SFT 带来的性能增量会被大大缩小，说明该方法在计算受限时性价比更高。

局限同样清楚：首先你得有一个更强的教师；如果你正在训练前沿模型、你自己就是最好的，就没人能教你。其次，信号来自教师分布而非真实标签，教师分布可能不完美、覆盖不全。课程提到一个巧妙的解法：既然教师调用是 teacher forcing 的，就可以把答案以及通向答案的一切注入提示，让同一个模型扮演教师——这就是 on-policy self-distillation。课程还提到多教师 on-policy distillation，用领域专家作为不同教师，经验上比单教师更不易遗忘。课堂问答也点明了适用场景：on-policy distillation 更适合系列中更快的模型，前沿模型则可能更多依赖 GRPO 这类方法。

## 七、三条路线的对照与本讲在课程中的位置

把三种方法放在一起看，它们其实是在回答同一组问题的不同取舍。PPO 用价值函数同时解决基线（降噪）和 token 级信用分配，用裁剪加 KL 解决漂移，代价是要联合训练价值模型。GRPO 用组内归一化替代价值函数，省掉了额外模型，噪声也小了，但代价是失去 token 级信用分配，并引入了长度偏差这类归一化副作用。On-policy distillation 用教师分布提供密集的 token 级信号，无需奖励模型，但受制于教师的能力与覆盖。

回到课程路径上：第三讲给出预训练与 SFT 的交叉熵框架，第四讲补上了偏好调优与推理提升的损失函数推导——上一讲“只闻其名”的 RL 目标，在这里变成了可计算的梯度；而上一讲 DPO 公式中的 β，也在这里与 KL 惩罚接上了头。再往前看，这一讲建立的“策略—奖励—优势—约束”这套词汇，是理解后续后训练与推理模型讨论的基础。课程最后以“希望你们周末愉快”收尾，但这节课留下的三个挑战——噪声、信用分配、漂移——会以不同形式反复出现在之后的算法变体里。
