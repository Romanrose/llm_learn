# 让 LLM 装得下、跑得快：CME 295 第五讲「LLM systems」的技术地图

## 导语：从“模型是什么”到“模型怎么跑起来”

Stanford CME 295 的前四讲完成了一条清晰的认知路径：Transformer 是 LLM 的基础架构，LLM 本质上是把 decoder 部分规模化，并把一切建模为 text-to-text 问题；模型规模达到数十亿乃至数万亿参数，预训练阶段要在数万亿甚至数十万亿 token 上训练。到了第五讲，问题性质发生了变化——不再问“LLM 是什么”，而是问“我们如何在实践中让它运作起来”。

这是一个关键的转折。讲师在开场就点明了这节课的定位：前面所有内容在很大程度上还是理论上的，而这一讲要回答两个贯穿始终的问题：

1. **我们如何让模型适配硬件？**
2. **我们如何让它变快？**

这两个问题不是并列的修辞，而是整讲的组织原则。文章将沿着讲师的推进顺序展开：先看单个 GPU 内部能做什么（FlashAttention），再看多块 GPU 如何协作（各类并行），最后进入推理侧的系统优化（KV cache、paged attention、GQA/MLA、speculative decoding）。每一部分都对应上述两个问题的一次具体回答。

## 一、问题的起点：为什么 GPU 内存是硬约束

要理解后面所有技术的必要性，必须先理解约束从哪里来。

LLM 的 decoder 内部结构相对简单：masked multi-head attention 加 feedforward neural network，而这两层“实际上只是一堆矩阵乘法”。矩阵乘法天然适合并行化——结果矩阵的每个元素都是独立的点积，可以同时计算——而 GPU 恰好有很多核心和专门硬件来做这件事。这就是为什么这节课的核心是“如何聪明地利用这些 GPU”。

但 GPU 的资源是有限的。讲师以 Nvidia H200 的数据表为例（定性地说，这是“市面上一个非常好的 GPU”），指出三个关键规格：算力速度（以 teraflops 度量）、内存容量（该例中为 141 GB）、以及数据传输速度（每秒数 TB 量级）。这里有一个容易混淆的术语需要澄清：**flops**（带小 s）是浮点运算次数，度量算力预算；**flops/s** 是每秒浮点运算次数，度量硬件性能。第二讲提过前者，而这一讲开始真正用到后者。

约束有多紧？做一个粗略估算：假设模型有 1000 亿参数，每个参数用 floating point 16 存储（16 位即两个字节），那么仅仅存储参数就需要 200 GB 内存——已经超过那块“非常好的 GPU”的 141 GB。而这还只是“拥有参数”；训练时还需要存储 activations、gradients、optimizer states，全都是大量内存。讲师由此得出结论：**GPU 内存是第一个限制，使用这些模型的成本是第二个限制**。

这里值得强调一个方法论上的细节：讲师用的数字都明确标注为“粗略计算”和“数量级参考”。这种定性而非精确的表述方式，恰恰是理解系统问题的正确姿态——重要的不是 141 还是 192，而是“参数量乘以每参数字节数”与“单卡内存”之间那个无法回避的数量级鸿沟。

## 二、单卡之内：FlashAttention 的两个核心思想

面对内存约束，第一层优化发生在单个 GPU 内部。讲师首先引入 GPU 的存储层次：**HBM**（high bandwidth memory）容量大（就是数据表上那 141 GB），相对快，但相对于 **SRAM** 慢大约一个数量级——HBM 的传输速度大约在每秒一太字节量级，而 SRAM 在每秒数十太字节量级。SRAM 快得多，但小得多，只有数百兆字节量级，装不下大对象。计算发生在片上的 compute units 里，HBM 在片外。

问题出在 self-attention。计算 $QK^T$ 会产生一个 $N \times N$ 的矩阵，$N$ 是序列长度，可能达到数万；即便只是一千，也是一百万个条目。朴素的实现方式是把这个大矩阵写进 HBM、读回来做 softmax、再写回去、再读出来与 V 相乘。而 softmax 的麻烦在于：要得到某个分量上的值，必须处理整行——分母是该行所有分量指数之和。这就是为什么朴素方法不得不多次往返 HBM。

**FlashAttention 的第一个思想：把 softmax 拆成可迭代的分子与分母。** 讲师用一个三元素的行向量 $S_1, S_2, S_3$（对应 query 与三个 key 的点积）做演示。要计算 $\text{softmax}(S) \cdot V$，即 values 的加权和，权重为 $\exp(S_i) / \sum_j \exp(S_j)$。关键观察是：把求和符号放进分子，整个表达式变成“分子之和除以分母之和”，而分子 $N_{T+1} = N_T + \exp(S_{T+1}) V_{T+1}$、分母 $D_{T+1} = D_T + \exp(S_{T+1})$ 都可以增量更新。于是不必先物化整个 $N \times N$ 矩阵再对它做 softmax，而是把小分量送进 SRAM，边算边更新分子分母，最后只需两者相除。

**第二个思想：数值稳定性。** 直接对 $S_i$ 取指数可能产生非常大的数，导致数值不稳定。解决办法是分子分母同乘一个常数——这个常数取“到目前为止遇到的最大 $S_i$ 的负指数”，记作 $M$。由于指数性质，$\exp(S_i) \cdot \exp(-M) = \exp(S_i - M)$，先算减法再取指数，避免了大数。到了第二次迭代，需要用新的最大值 $M_2$ 重新缩放之前所有的和，缩放因子恰好是 $\exp(M_1 - M_2)$。讲师在黑板上的推导看起来繁琐，但他明确说这“大概是最难的部分”，并归结为两个要点：迭代计算分子分母，以及通过重新缩放避免数值不稳定。关于“$C$ 可能等于零”的提问，讲师的回应也值得记住：如果某个项非常小到无法表示，设为零即可；真正糟糕的是非常大的值无法表示，因为那个大值本来在对求和做出贡献。

**第三个思想：反向传播中的重计算。** 训练时，反向传播需要注意力矩阵来计算梯度。通常做法是前向传播时把它存进 HBM 供反向使用。但 FlashAttention 的选择是：**丢弃它，在反向传播中即时重新计算**。这在直觉上似乎是浪费——已经算过的东西为什么再算一遍？但讲师指出，当那个东西非常大、必须在访问缓慢的地方物化时，重计算反而带来加速。代价是更高的计算量（讲师给出 75.2 对 66.6 的 GFLOPS 对比，并明确说“这些数字只是给你数量级参考”），但运行时间少得多。

讲师特别强调：**FlashAttention 是精确的方法，不做任何近似**。它只是利用 GPU 各组件的读写时间不对称性，以更聪明的方式搬运数据。文献中还有 FlashAttention 2、3、4 等版本，它们在此基础上做优化，并适配新的 GPU 系列（如 Hopper 系列的 H100/H200、Blackwell 系列的 B100/B200）。讲师的态度很务实：不必深入细节，重要的是理解“为什么要这样做”和“融合操作 + 重计算”这个技巧。

## 三、跨卡扩展：五种并行，五个维度

单卡优化的天花板是明确的：模型本身可能就装不下。于是问题进入第二个层次——如何利用不止一块 GPU。讲师先列举了训练时需要存储的四类东西：模型参数、activations（随序列长度和批大小增长，因为 transformer 让所有 token 与其他 token 交互）、gradients、以及 Adam 类优化器需要跟踪的多个量。这些加起来远超单卡内存。

**数据并行（data parallelism）** 是最直观的思路：把数据划分到多块设备上，独立执行前向和反向传播，然后同步梯度更新。朴素实现会在每块设备上复制模型、梯度、优化器状态，冗余严重。**ZeRO（Zero Redundancy Optimizer）** 的思路是“不要重复自己”，把这些量分片到各 GPU 上。代价是通信：如果设备上没有全部参数，做前向传播时就需要向其他设备请求。讲师对此的回应很坦率——这确实会花时间加载参数，但你是在“训练不了”和“训练得很慢”之间做选择。

**模型并行（model parallelism）** 则是把模型计算本身拆开。讲师介绍了四种：

- **张量并行（tensor parallelism）**：在矩阵层面拆分。self-attention 有多个 head，各 head 的计算可以独立完成，分到不同设备上各自做投影再组合；feedforward 层也可以按行/列分解矩阵。
- **流水线并行（pipeline parallelism）**：按层拆分，设备零算第一部分、传给设备一算第二部分。问题是设备会空闲等待——讲师称之为 **bubble**，并指出这是人们正在努力优化的领域，本讲不展开。
- **上下文并行（context parallelism）**：针对超长序列。每个设备保留一组 query，keys 和 values 在设备间交换。讲师用两个设备、两个 token 的例子演示：各自算自己的 Q、K、V，做完本地运算后交换 K、V 再重复。
- **专家并行（expert parallelism）**：建立在 MoE 概念上。把专家放在不同设备上，先做 self-attention，进入 feedforward 部分时确定每个 token 该去哪个专家，把 token 发过去、算完再送回来。

加上数据并行，就是所谓“五个 D”。讲师反复强调两点：**这些方法可以组合使用**，不是二选一；但**也不要把并行度拉到最大**——并行以设备无法被充分利用为代价，GPU 非常昂贵（按小时租用），而且通信开销真实存在。

至此，训练侧的两个问题都有了回答：让它装得下，靠把参数、激活、梯度、状态分布到多块 GPU 上；让它跑得快，靠数据并行处理不同 batch、模型并行化模型计算。

## 四、推理侧：延迟、内存与“坏情况变好情况”

课程后半段交给 Shervin，转向推理优化。开场的两种情境对比极具启发性：10 个 token 输入、10k 个 token 输出，与 10k 个 token 输入、10 个 token 输出，哪个更快？答案是后者——因为自回归解码必须一次一个 token 地生成，而 prefill 阶段可以并行处理全部输入 token。

这引出三个延迟指标：**TTFT**（time to first token）、**TPOT**（time per output token）、**TTLT**（time to last token）。从纯 infra 角度看，前两个是关注重点：TTFT 反映排队策略和 prefill 策略是否良好，TPOT 反映用户能否舒适地看到输出逐字生成。TTLT 本质上与模型在做什么有关——用户大量请求泰迪熊故事会增加 TTLT，但这不意味着系统不好。讲师还提到一个经验现象：输出价格约为输入价格的五倍，并说明这不是规定性的真值关系，只是值得注意的经验观察。

为了判断系统在内存与计算之间的位置，需要三个概念：**计算吞吐量**（那些 teraflops 数字，是数据类型的函数）、**内存带宽**（HBM 到 SRAM 再到计算单元的传输速度限制，与 SRAM 有数量级差距）、以及把两者联系起来的 **算术强度（arithmetic intensity）**——定义为计算量与移动内存量的比值。把它们画在一起就得到 **roofline model**：一条像屋顶的线，折点叫 **ridge point**，在这一点上既不受内存限制也不受计算限制。讲师给出的直觉是：解码时你加载全部权重却只预测一个 token，处于受内存限制的区域；而 prefill 配合 FlashAttention 这类优化，应该处于受计算限制的区域。这也解释了为什么“屋顶线”这个名字没有更深含义——只是因为线看起来像屋顶。

**KV cache** 是推理复用的基础：过去计算的 keys 和 values 被缓存下来供后续 token 使用。讲师区分了两种缓存：解码时逐 token 依赖的 KV cache（其定价包含在输出成本中），以及跨轮次复用的缓存（比如多轮对话后新查询以历史内容为锚点，价格大约只有新输入的十分之一）。紧接着的问题是内存管理：如果天真地为每个查询按最大可能输出预留一整块内存，而实际 completion 往往远小于最大值，就会产生大量“未被使用但同时不可用”的碎片。**Paged attention** 的解法是给内存一个逻辑视图：把键值放进大小为 B 的块中，维护元数据记录每个查询的键值放在哪里。B 太小则元数据庞大，B 太大则碎片化重现；讲师说实践中 B 取 16 是典型数量级。

接下来是减少要跟踪的向量数量。**GQA（grouped-query attention）** 把 query 分成 G 组，每组共享一套 key/value 投影：G 等于 H 退化为 MHA，G 等于 1 则是 multi-query attention（讲师明确说这是另一个你不想要的极端，因为键值表达力不足以构建足够好的特征）。讲师给出一个具体算例：G 等于 2、H 等于 24 时，内存占用减少 1 − 2/24，即 91%，并提到 G 等于 2 是 Qwen 3.8 Flash Next 采用的值。对于“参数更少是否损害表达力”的提问，回答是肯定的——这是权衡，通常通过预训练时的网格搜索和消融研究来确定 G；实践中发现太接近 H 时性能提升只是边际性的。**MLA（multi latent attention）** 更进一步：借助类似 LoRA 的矩阵分解思路，先把 H 个（或 2G 个）向量压缩成一个很小的共享表示，在键和值之间共享第一个投影矩阵，于是每个 token 只有一个向量。

最后是 **speculative decoding**。既然自回归生成慢、而验证 token 便宜（prefill 时和训练时可以并行输入），那就用一个 **draft model** 先生成接下来 K 个 token，把它们连同 prompt 一起交给 **target model** 验证。规则是：如果目标模型比草稿模型更有信心，接受；否则以概率比率接受；拒绝则用残差分布采样。讲师用全概率公式和联合概率公式现场证明了这套拒绝采样（rejection sampling）机制确实复现目标模型的概率分布——推导过程中把 $D(x)$ 与 $T(x)$ 的最小值、以及 $\max(0, T(x)-D(x))$ 的归一化项逐项消掉，最终得到 $T(x)$。这个证明是整讲技术密度最高的段落，但结论很清晰：**拒绝是要不惜代价避免的**，因为一旦退出循环，之后草稿做的一切都成了浪费的工作；所以要让两个分布对齐。实现对齐的两条路径是知识蒸馏（让草稿拟合教师的下一 token 分布）和多 token 预测（同一个 LLM 训练 K 个头，用它们做草稿、只用第一个做验证器）。讲师还提到一个“免费”的好处：放进目标模型的所有东西都被计算了，所以顺带得到了下一个 token。

## 五、本讲在课程路径中的位置

回看整个 CME 295 的结构，第五讲是一个明确的枢纽。前四讲建立了“LLM 是什么”的理论基础——transformer、decoder 规模化、text-to-text 建模、预训练的数据规模。第五讲则把这些理论全部翻译成系统约束：decoder 是矩阵乘法，所以要用 GPU；矩阵乘法产生 $N \times N$ 的中间结果，所以有了 FlashAttention；参数和优化器状态装不下，所以有了五种并行；推理的自回归特性决定延迟结构，所以有了 KV cache 管理和 speculative decoding。

更值得注意的是这一讲培养的思维方式。讲师在 FlashAttention 部分反复说“关键是理解我们为什么要这样做”；在并行部分说“你是在训练不了和训练得很慢之间做选择”；在推理部分用 roofline model 把“快”和“便宜”量化成可判断的位置。这些都不是可以死记的公式，而是在内存与计算的永恒博弈中定位问题的框架。讲师最后展示的那个 AI 分析聚合器首页——三分之二面积被推理相关图表占据——正是这个框架的现实注脚：这些内容“是人们最关心的”。

## 结语

CME 295 第五讲回答了两个看似简单的问题：如何让模型装得下，如何让它跑得快。答案分布在三个层次：单卡之内，用融合操作和重计算把 HBM 往返降到最低；多卡之间，用数据并行与四种模型并行把参数、激活、梯度、状态分散开；推理侧，用分页内存管理、GQA/MLA 压缩、speculative decoding 把每个 token 的成本压下来。每一个技术都不是孤立的技巧，而是对同一个约束——内存有限、带宽有限、GPU 昂贵——的具体回应。理解了这些约束，也就理解了为什么这节课虽然“比平常更繁琐”，却是人们最关心的部分。
