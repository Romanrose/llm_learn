## 第一部分：课程导论

### 1.1 为什么开设这门课

**核心问题**：研究人员正在与底层技术脱节。

- 2016 年：研究人员自己实现并训练模型
- 2018 年：下载预训练模型（如 BERT）进行微调
- 现在：直接通过 API 提示（prompt）模型

虽然提升抽象层次能提高生产力，但这些抽象是**有漏洞的（leaky）**。当你想做基础研究时，仅靠提示模型会极大限制你探索的设计空间。理解语言模型如何工作的方式是**通过构建（understanding via building）**。

### 1.2 工业化带来的挑战

前沿模型（frontier models）极其昂贵且细节不公开：

- 2023 年 GPT-4 据称训练花费约 1 亿美元
- GPT-4 技术报告明确表示不分享构建细节
- 小规模模型可能无法代表前沿模型的行为

**两个例子说明规模差异**：

1. FLOPs 分配随规模变化：小规模时注意力层约占 44% FLOPs，大规模（175B 参数）时 MLP 层升至约 80%
2. 涌现行为（emergence）：小模型上 0-shot/few-shot 学习几乎无效，达到临界规模后才突然大幅提升

### 1.3 可迁移的知识类型

| 知识类型 | 内容 | 能否跨规模迁移 |
|---------|------|--------------|
| 机制（Mechanics） | Transformer 是什么、模型并行如何工作 | ✅ 可以 |
| 思维方式（Mindset） | 如何最大化硬件利用、认真对待扩展 | ✅ 可以 |
| 直觉（Intuitions） | 哪些数据/建模决策带来好性能 | ⚠️ 不一定 |

关于直觉：有些设计决策无法从理论上论证。SwiGLU 激活函数的提出者 Noam Shazeer 在论文中直言：“我们不提供解释……将成功归因于上天的恩赐。”

### 1.4 苦涩的教训（The Bitter Lesson）

- **错误理解**：规模就是一切，算法不重要
- **正确理解**：**能够良好扩展的算法**才是重要的

核心公式：

```
准确率 = 效率 × 资源
```

效率在大规模下更重要——小规模实验运行时间翻倍可以等待，但大规模运行涉及数亿美元成本，效率提升即使只有 5% 也是巨大进步。经验数据：2012-2019 年 ImageNet 上算法效率提升约 44 倍。

**课程框架**：在给定数据和计算预算下，什么是最佳模型？即**最大化效率**。

### 1.5 语言模型历史脉络

**前神经时代**：Shannon（1950s）用语言模型测英语熵；N-gram 模型用于机器翻译和语音识别。

**神经时代的关键组件**：LSTM（1997）、首个神经语言模型（Bengio，2003）、Seq2Seq（2014）、Adam 优化器（2014）、注意力机制（2015）、Transformer（2017）、混合专家（2017）、模型并行（2018-2019）。

**基础模型崛起**：ELMo、BERT（预训练 + 微调范式）、T5（文本到文本统一框架）。

**规模化的拥抱**：GPT-2（1.5B，流畅文本）、缩放定律（Kaplan 2020）、GPT-3（175B，上下文学习）、PaLM（540B，训练不足）、Chinchilla（70B，计算最优缩放）。

**开源生态**：EleutherAI（GPT-J）、Meta OPT（175B，硬件问题多）、BigScience BLOOM（176B）——这些早期复制品都不强。此后 Meta 的 Llama 系列引领潮流，加上 Mistral、DeepSeek、Qwen 等，开源权重模型已接近闭源模型。更进一步的开放包括 AI2、NVIDIA 参与的 MARIN 项目，提供权重 + 论文 + 代码 + 数据。

### 1.6 语言模型定位的演变

- 2018（BERT）：用于微调的东西
- 2020（GPT-3）：用于提示的东西
- 2022（ChatGPT）：可以对话的东西
- 2026（智能体）：可以自主行动的东西

**基本面未变**：仍依赖 GPU 和内核、梯度方法、Transformer 和注意力。变化在于规格：需要更长上下文，推理效率更关键。

## 第二部分：分词（Tokenization）

### 2.1 基本概念

**分词器（Tokenizer）** 在原始输入（字节）和整数序列（token）之间转换：

- `encode(string) -> list[int]`：将字符串编码为 token 索引
- `decode(list[int]) -> string`：将 token 索引解码回字符串

**往返性质（roundtrip）**：`decode(encode(s)) == s` 必须成立。若实现的分词器不能往返转换，则存在问题。

**压缩率** = 字节数 / token 数。压缩率越高，序列越短，对注意力机制（二次复杂度）越有利。

### 2.2 朴素分词方法的缺陷

**字符级分词器（CharacterTokenizer）**：
- 每个 Unicode 码点作为 token
- 约 15 万个 Unicode 字符 → 词汇表过大，许多字符罕见（如 🌍），利用率低
- 压缩率差

**字节级分词器（ByteTokenizer）**：
- 按 UTF-8 编码后的字节划分
- 词汇表仅 256，但压缩率为 1，序列过长
- 无法利用注意力机制的上下文窗口

**词级分词器（WordTokenizer）**：
- 按正则表达式（如 `\w+`）切分
- 每个 token 有语义，压缩率不错，但词汇表可能无界
- 遇到未见过词需使用 UNK token，会干扰困惑度计算

### 2.3 BPE 算法详解

**背景**：BPE（Byte Pair Encoding）由 Philip Gage 于 1994 年为数据压缩提出，2016 年被引入 NLP 用于神经机器翻译，GPT-2 首次将其用于大语言模型。

**核心思想**：基于训练数据构建词表，常见的字节序列合并为一个 token，罕见序列分解为多个 token。

**训练算法**（以 `"the cat in the hat"` 为例）：

1. 将字符串编码为字节序列作为初始 token
2. 统计所有相邻 token 对的出现次数
3. 找到出现频率最高的对
4. 将该对合并为新 token（编号从 256 开始递增）
5. 更新序列和词表
6. 重复直至达到预设的合并次数

示例过程：
- 初始：`t,h,e, ,c,a,t,...`
- 第 1 次合并：`t,h` 出现 2 次 → 合并为 256
- 第 2 次合并：`256,e` → 合并为 257
- 第 3 次合并：`257, ` → 合并为 258

**编码（encode）**：对新文本，按训练好的合并顺序依次应用合并操作。

**解码（decode）**：按 token 的字节值拼接后解码为 UTF-8 字符串。

### 2.4 实际 BPE 的优化方向

讲义中的实现是完整但非常慢的版本，作业 1 中需要优化：

1. **稀疏合并遍历**：不应遍历所有合并操作，只遍历对当前序列有效的合并
2. **特殊 token 处理**：如 `<|endoftext|>` 需要检测并保留
3. **预分词**：使用 GPT-2 的正则表达式先切分文本块，再对各块应用 BPE
4. **实现语言**：Python 不够快时，可以考虑 Rust/C 等

### 2.5 有效的分词器应满足的性质

即使未来摆脱分词，任何替代方案也应满足：

1. **模型应在某种序列抽象（chunk）上操作**：不仅文本，视频、DNA 序列等领域的单字节信噪比很低，需要提升建模层次
2. **块的大小应可变**：支持自适应计算，将更多模型容量分配给输入中更有趣的部分

## 关键原则与公式

### 效率框架

```
最佳模型 = f(数据预算, 计算预算)
最大化效率 = 给定资源下取得最好结果
```

### 缩放经验法则

Chinchilla 缩放定律（将在作业 3 中深入）：
- 计算最优时，训练 token 数 ≈ 参数量的 20 倍
- 例如：70B 参数模型 ≈ 1.4T token
- 注意：未考虑推理成本，实际中常使用比计算最优更小的模型

### 训练稳定性原则

- 平衡表达力（expressivity）、稳定性（stability）、效率（efficiency）
- 参数和梯度范数应处于“金发姑娘区”（既非爆炸也非消失）

## 常见误区

1. **“苦涩的教训 = 规模至上”**：这是错误解读。正确理解是：能够良好扩展的算法才重要。

2. **“缩放定律是自然法则”**：缩放定律不会自动实现，必须通过精心构建缩放方案（scaling recipe）才能获得可预测的外推。

3. **“小规模上的直觉可以迁移到大规模”**：注意力和 MLP 层的 FLOPs 占比随规模变化，涌现行为在小规模上不可见——某些直觉无法跨规模迁移。

4. **“分词器只是细节问题”**：分词影响压缩率（即序列长度，直接影响注意力计算量）和自适应计算能力，是效率优化的重要环节。

5. **“推理时用更大的模型更准”**：实际中常训练小于计算最优的模型，因为推理成本会纳入考量。
