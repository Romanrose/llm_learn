# 从零构建语言模型：CS336 第一讲「概览与 Tokenization」深度解析

> 如果你对语言模型的理解停留在「调用 API」层面，这门课会彻底改变你的认知。本文带你走进斯坦福 CS336 的第一讲，看看在编码智能体都能零样本生成语言模型的今天，为什么我们依然需要从最底层理解一切。

## 导语：为什么「从零开始」如此重要？

想象一下这样的场景：你是一位研究者，想要在前沿语言模型领域做出突破。你打开 ChatGPT，输入精心设计的提示词，期待模型能帮你完成一些创新性的工作。但在某个瞬间，你会发现——模型做不到你想要的事情，而且你完全不知道如何修复它。

这正是斯坦福 CS336 课程诞生的初衷。当 Percy Liang 在课堂上说出「研究人员正在与底层技术脱节」这句话时，他指出了一个深刻的问题：十年前，所有 AI 研究者都会自己实现并训练模型；八年前，人们还会下载 BERT 进行微调；而今天，大多数研究者只是通过提示 API 模型来「应付过去」。

这种抽象层次的提升确实带来了生产力的飞跃，但抽象是有漏洞的。如果你对基础研究真正感兴趣，仅仅通过提示模型，你就在极大地限制所能探索的选项集合和设计空间。要突破这些限制，你需要把整个技术栈拆开来看——而这，就是 CS336 的核心哲学：**通过构建来理解**。

但这里有一个尴尬的事实：前沿模型已经工业化了。GPT-4 的训练成本据称达到 1 亿美元，而现在可能已经攀升到 10 亿美元量级。各大实验室的 GPU 集群规模惊人，而关于这些模型如何构建的细节，几乎没有公开信息。

那么，我们能在课程中学到什么真正可迁移的东西？Percy 给出了一个精妙的分类——知识分为三类：

- **机制性知识**：事物如何运作，什么是 Transformer，模型并行如何工作
- **思维方式**：如何着手构建语言模型，如何从硬件中榨取最大价值
- **直觉**：哪些数据建模决策会带来好的性能

第一类和第二类知识可以很好地教授，它们确实能迁移到更大规模。但第三类——直觉——未必能跨规模迁移。有些设计决策根本无法从理性上解释，纯粹来自实验经验。就像那篇引入 SwiGLU 激活函数的著名论文在结论部分写的那样：「我们不提供任何解释。我们将这些架构的成功，以及其他一切，归因于神圣的恩赐。」

关于「苦涩的教训」，Percy 也澄清了一个常见误解：规模就是一切，算法不重要——这是错误的理解。正确的理解是：**能够扩展的算法才是重要的**。换句话说：

> 模型精度 ≈ 效率 × 资源

效率在更大规模下反而更重要。如果你做小规模实验，运行时间多了一倍，多等一倍时间就好；但如果是数亿美元的投入，即使是 5% 的改进也是大事。从实证角度看，OpenAI 2020 年的论文显示，2012 到 2019 年间 ImageNet 上有 44 倍的算法效率提升。

这引出了整个课程的问题框架：**在给定的数据和计算预算下，你能构建的最佳模型是什么？** 换句话说——最大化效率。

## 语言模型的历史脉络：从香农到智能体

Percy 用一段历史回顾向我们展示了语言模型的演进路径。1950 年代，香农就用语言模型测量英语的熵。很长一段时间里，N-gram 模型被用于机器翻译和语音识别系统。现代语言模型的谱系则来自神经架构：1990 年代的 LSTM，2003 年 Yoshua Bengio 发表的第一个神经网络语言模型，然后是 Seq2Seq 建模、注意力机制，最终催生了 Transformer 架构。

到了 2010 年代末，事情开始变得有趣。ELMo 和 BERT 带来了「预训练 + 微调」的范式，在大量文本上训练语言模型，然后在下游任务上微调，看到巨大改进。但真正打开闸门的，是 OpenAI 拥抱扩展理念——从 GPT 到 GPT-2，再到 GPT-3。GPT-3 有 1750 亿参数，几乎是当时最大模型的 10 倍以上，并且展现出了涌现行为，比如上下文学习。

这之后，开放模型生态开始蓬勃发展。Eleuther 创建了开放数据集和模型，虽然规模不大；Meta 的 OPT 试图复现 GPT-3，但遇到了很多硬件问题。直到过去三年，Meta 的 Llama 系列引领潮流，Mistral、DeepSeek、Qwen 等纷纷加入，我们现在有了接近闭源模型水平的开放权重模型。

但 Percy 特别强调了一条超越开放权重的工作线：像 AI2、NVIDIA 参与的 Marin 项目，不仅提供权重，还提供论文、代码和数据，让我们能够更全面地理解这些模型是如何构建的。他强调：「如果没有这些模型，这门课程就不可能存在。由于仍然有许多论文在发表，介绍这些大型 MoE 和 RL 系统是如何运作的，这让我们至少能窥见这些前沿模型是如何构建的。」

语言模型的概念也在不断变化：曾经是需要微调的东西，然后变成可以通过提示词使用的东西，ChatGPT 时代变成可以对话交流的东西，而现在——我们正处于智能体（agent）的时代。尽管要求越来越高——更长的上下文、更复杂的推理——但基本原理并没有改变太多：我们仍然基于 GPU 和内核构建，仍然使用梯度方法优化，仍然有 Transformer 和注意力机制。

## 课程安排：五个作业，完整的构建路径

CS336 是一门 5 学分的课程，有五个相当繁重的作业。根据课程评价，即使是第一个作业，实际上也相当于 CS 224n 的五个作业。Percy 坦诚地列出了选课的理由——对理解事物运作方式的执着需求，以及锻炼研究和工程能力——但也明确告诉你什么时候不应该选这门课：如果你这学期想做出研究成果，或者只想学习 AI 最新的热门技术（比如多模态、智能体），这门课不是正确的选择。

课程内容分为五个部分，对应五个作业：

### 1. 基础（Assignment 1）

这是最初两周的内容，目标是能够从头构建并训练一个语言模型。组成部分包括：数据分词、定义架构、实现优化器并训练模型。这是整个课程中最基础也最关键的一步。

### 2. 系统（Assignment 2）

目标是最大限度地利用硬件。涉及内核、多 GPU 并行化、推理优化。在这一部分，你会接触资源核算（追踪 FLOPs 都花在哪里）、roofline 分析（判断计算是受计算能力限制还是内存带宽限制）、算子融合、tiling 等概念。

一个关键见解是：内存和计算单元不在同一个地方，你必须将参数从内存移动到计算单元，进行计算，然后再移动回去。而这往往是瓶颈所在。例如 B200 在 bf16 精度下有 2.25 petaFLOPS 每秒的计算速度，但内存带宽只有 8TB 每秒——数据移动的成本极高。

### 3. 扩展规律（Assignment 3）

如果你有 1e25 FLOPs 的计算量（数千万美元的算力），你会训练什么样的模型？在这个规模下，你不能做典型的超参数调优，因为你可能只能训练一个模型。关键思维转变是：我们不应该关注单个模型，而应该思考**缩放配方**（scaling recipe）——从 FLOPs 预算到超参数的映射。

通过运行一系列小规模实验，拟合缩放定律，你可以预测在目标规模下的损失。这样就能在真正投入巨资之前，优化缩放配方并预测结果。但要注意：缩放定律不是自然法则，你必须通过精心构建缩放配方来把它们「召唤」出来。可预测性至少和最优性一样重要。

一个经典的经验法则是：训练应该使用的数据点数量是参数数量的 20 倍。所以一个 70B 参数的模型应该在大约 1.4 万亿 tokens 上训练。（不过这个数字会根据数据集和架构变化，也没有考虑到推理成本。）

### 4. 数据（Assignment 4）

数据的质量基本决定了模型最终能有多好。这一部分先讨论评估——这定义了模型应该具备的能力。这里有一个重要区分：内部评估指标（用于模型开发，重要的是跨规模平滑性和相对性能）和外部指标（面向客户或审稿人，生态效度很重要）。

然后讨论数据获取和处理的完整流程：网页爬取、转换（HTML 转文本）、过滤（去除低质量内容）、去重（避免冗余和记忆化）、数据混合（如何权衡不同来源）。数据还有法律问题——很多 GitHub 代码没有许可证，如何解读？在受版权保护的数据上训练是否属于合理使用？

### 5. 对齐（Assignment 5）

到目前为止，我们用完全监督的方式训练模型。但对齐阶段使用弱监督：批评比生成更容易。基本模板是：让模型生成回应，通过人工、验证器或语言模型裁判打分，然后更新模型偏好更好的回应。涉及 PPO、GRPO 或 DPO 等算法。

在规模上做 RL 会有很多系统层面的挑战：需要一个推理服务器和一个训练服务器，推理服务器必须生成 rollout，如果涉及代码执行还需要处理环境交互。这是一个「巨大而美妙的混乱局面」。

## 深入第一单元：Tokenization

现在让我们聚焦本讲的重头戏——Tokenization。Percy 半开玩笑地说：「每年我都希望我不必教分词，因为理想是真正实现一种端到端的、直接操作字节的方法。」但前沿模型仍在使用分词器，所以教授分词器仍然是明智的。

### 问题定义

语言模型在通常表示为索引的 token 序列上放置概率分布。原始文本是 Unicode 字符串。分词器（Tokenizer）就是在字符串和 token 序列之间进行往返转换的组件。

让我们看一些具体例子。在 GPT 分词器中，「hello」和「 world」（带空格）是两个完全不同的 token，它们之间没有任何关系。数字可能以每几位数字作为一个 token 的形式表示。不同分词器策略不同，有些试图让每个数字都是一个 token，但那样会急剧增加 token 数量。

这里有一个关键指标：**压缩比**（每个 token 的字节数）。压缩比越大，意味着序列越短，这对注意力机制很重要——注意力是序列长度的二次方复杂度，你需要确保输入序列更短。

### 三种朴素方法的失败

Percy 用三个具体例子展示了为什么朴素方法都不行：

**字符级分词器**：每个 Unicode 字符变成一个整数。大约有 15 万个 Unicode 字符，词汇量太大，而且许多字符非常罕见，词汇表利用效率低。压缩率也不好。

**字节级分词器**：将字符串转换成 UTF-8 字节序列，所有数字在 0 到 255 之间。词汇量很小（256），但压缩率是 1——太差了。序列太长，而 Transformer 的上下文长度有限。

**单词级分词器**：按空格或正则表达式分块。每个 token 都有意义（因为词汇是人类发明的），但词汇量大小是训练数据中不同分块的数量，可能无界。测试时会遇到从未见过的标记，需要 UNK 标记——那真的很糟糕，会搞乱困惑度计算。

### BPE：数据驱动的有效启发式

字节对编码（Byte Pair Encoding）最初由 Philip Gage 在 1994 年引入用于数据压缩，后来被引入 NLP 用于神经机器翻译，GPT-2 首次将其用于大语言模型。

基本思想很优雅：在原始文本上训练分词器，构建针对数据定制的词汇表。常见序列用一个 token 表示，罕见序列被分割成多个 token，任何内容都可以被分词——不需要 UNK 标记。

算法在概念上很简单：

1. 从字节序列开始，每个字节初始是一个 token
2. 统计相邻 token 对的出现频率
3. 合并出现频率最高的相邻对，创建一个新 token
4. 重复直到达到目标词汇表大小

让我们看一个具体的玩具例子。字符串「the cat in the hat」：

- 初始化为字节序列：t-h-e-c-a-t-i-n-t-h-e-h-a-t
- 统计相邻对：116,104（t,h）出现 2 次
- 合并为 256 号 token，代表「th」
- 继续合并：256,101（th,e）→ 257 代表「the」
- 再合并一次 → 258

随着时间推移，序列在缩短，词汇表在增大。在这个例子中，压缩比达到 1.5。

对新文本编码时，你只需遍历之前学到的所有合并操作，并应用到新字符串上。解码时则将 token 映射回字节。

### 效率与工程实现

Percy 坦诚地承认：这个实现能工作，但非常慢。当前的编码方法要遍历所有的合并操作——合并次数基本上等于词汇表大小减去 256。在作业 1 中，学生需要：

- 只遍历真正相关的合并操作（需要构建索引）
- 检测并保留特殊 token（如 `<|endoftext|>`）
- 使用预分词（如 GPT-2 的 regex）
- 尽可能快——如果有必要，可以用 Rust 或 C 实现

### 从效率视角看 Tokenization

这门课反复强调效率视角。Tokenization 的底层逻辑也是效率：

- **减少上下文长度**：1000 字节可压缩为约 250 个 token，这对注意力机制至关重要
- **自适应计算**：某些地方确实包含大量字节，但应该压缩成一个 token；输入中更稀有或更有趣的部分应保留为多个 token——模型应该把「智能」分配到有趣的地方

### 未来方向

Percy 提到，已经有很多端到端的、直接操作字节的方法（如 ByT5、Megabyte、BLT 等），看起来很有前景，但还没有被扩展到前沿模型。任何替代方案都必须满足两个特性：

1. Transformer 需要在某种序列的抽象表示上运行——这不仅针对文本，还有视频或 DNA 序列，单个字节或单元的信噪比很低，必须进行抽象
2. 分块应该是可变的，需要自适应计算——不是所有字节都一视同仁

「任何端到端的解决方案，我认为也必须具备这些特性。」Percy 说，「也许明年我就不用教这个了，但今年我们还是得用分词。」

## 结语：效率是贯穿始终的主线

回顾整讲，一个清晰的主题浮现出来：**最大化效率**。课程中几乎所有设计决策都可以从这个角度理解：

- 系统层面：显然关于计算效率
- Tokenization：处理原始字节很优雅，但用当今模型架构计算效率很低
- 模型架构：很多变化是为了减少内存占用或 FLOPs
- 数据过滤：避免浪费宝贵计算在坏数据上更新梯度
- 缩放定律：用小模型做超参数调优，节省计算

Percy 用资源管理的视角总结了这一切：「你有数据，有硬件（包含计算核心、内存、通信带宽），你只是在试图弄清楚，在给定一组固定资源的情况下，如何根据某个评估标准构建最好的模型。」

今天，我们处于计算受限的状态。明天，我们可能会变成数据受限。但不变的思维方式是：**随时思考你的方法的效率**。

这就是 CS336 想要传授的核心——不是一套固定的知识，而是一种看待语言模型构建的方式。当你掌握了这种思维方式，面对任何新环境、新挑战，你都有信心去应对。正如 Percy 所说：「这门课类似于『统计学习理论』——它给人们足够的深度，让他们觉得其他的一切似乎都比较容易。」
