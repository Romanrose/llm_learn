## 第一部分：背景与核心问题

### 为什么要做多模态

- 世界本质上是多模态的：文本、图像、音频、视频并存。
- 最终目标是构建 **全模态模型（omni model）** ：能够接受任意模态组合的输入，并输出任意模态组合的结果。
- 例如：输入一张图片和一段视频，就它们提问；将音频转换为图像等。

### 为什么用 Transformer

- 尽管尝试过其他架构，但大量实践证明 **Transformer 在大规模多模态任务上仍然是最优选择**。
- Transformer 以 token 进行交互，token 可以理解为一个语义信息单元。对于文本，token 是子词（subword）——这已经是我们在词元化一讲中解决的问题。
- 问题是：**像素本身没有语义**。因此必须解决两个问题：
  1. 如何输入非文本数据（理解）？
  2. 如何输出非文本数据（生成）？

本讲主要关注第一个问题。

## 第二部分：CLIP（Contrastive Language-Image Pre-Training）

### 背景与动机

- 在 CLIP 出现之前，计算机视觉模型通常在人工标注的数据集（如 ImageNet）上训练。
- OpenAI 研究者的想法是：能否利用互联网上大量的（图像，描述文本）对，像语言模型利用海量文本那样，从嘈杂的数据中学习？
- CLIP 是这一思路的代表作，也是现代视觉语言模型的基础。

### 核心方法

给定一批 `N` 个（图像，文本）对（例如 32768 个）：

- 用 **图像编码器** 将每张图像编码为向量（I₁, …, Iₙ）。
- 用 **文本编码器** 将每个文本编码为向量（T₁, …, Tₙ）。
- 目标是：对于图像 I₁，它与对应文本 T₁ 的点积应远大于它与所有其他文本的点积；对于文本 T₁ 同理。这本质上构成了 2N 个 softmax 分类问题。

**实现方式**：
- 图像编码矩阵为 `n × d`，文本编码矩阵为 `n × d`。
- 归一化后，用温度参数缩放的点积计算相似度矩阵。
- 计算交叉熵损失。

### 数据

- 论文使用了 4 亿个（图像，文本）对，从网上搜索挖掘。
- 原始数据集未发布。OpenCLIP 使用 LAION-5B（50 亿对）数据复现，并用于数据过滤（CLIP 本身被用于过滤数据，存在 bootstrap 过程）。
- **数据预处理**：图像是任意分辨率，神经网络需要固定尺寸。做法是将较短边调整到 336 像素，然后中心裁剪为 336×336 正方形。这是一个简化处理，对分类任务影响不大，但对 OCR 等任务会损坏信息。

### 视觉编码器：Vision Transformer（ViT）

- CLIP 论文实验了 ResNet 和 ViT，发现 **ViT 效果最好**。
- ViT 的做法：将图像切成小块（patch），如 14×14（CLIP）或 16×16（原始 ViT），每个 patch 作为 token，加位置嵌入，送入标准 Transformer。
- CLIP 中不用简单的平均池化，而是用 **attention pooling**：先对所有激活做全局平均，再用该向量作为 query，对所有位置的 key 和 value 做注意力，得到更有信息量的向量。
- 最佳模型为 **ViT-L/14@336px**（L = large，patch 14×14，336×336 分辨率）。训练时先在低分辨率训练，后半段提高分辨率。
- 位置嵌入：论文中尝试过 2D 变体，发现对分类任务影响不大。

### 文本编码器

- 标准 GPT-2 风格 Transformer（63M 参数，12 层）。
- 输入加 BOS，追加 EOS，取最高层 EOS 的激活作为整段文本的表示。

### 亮点结果与消融

- **零样本 ImageNet 超越监督模型**：零样本 CLIP 在 ImageNet 上超过了在 120 万张标注图像上训练的 ResNet-50。
- 零样本预测方法：拿图像和候选标签文本做点积，取最大值。
- **消融实验**：尝试从图像直接预测文本（词袋或语言模型目标），发现与 CLIP 的对比排序目标相比计算效率低得多——对精确 token 序列建模对学习语义表示并不重要。

### 局限

- 需要大批量（如 30000），否则损失退化。
- softmax 在整个 batch 上进行，不可分解，并行化困难。
- 捕捉的是高层语义，不够细粒度。

## 第三部分：SigLIP（Sigmoid Loss for Language Image Pre-Training）

### 核心区别

- CLIP 是多类分类（正确配对 vs 所有其他配对）。
- SigLIP 只是**二元分类**：判断给定的（图像，文本）对是否匹配。对角线元素为正样本，非对角线为负样本。

### 损失函数

```
log_sigmoid(点积 × 标签)
```

标签为：对角线元素 = 1，非对角线元素 = -1。目标函数非常简单。

### 数据

- 使用 WebLI 数据集（数十亿个图像-文本对），来自网页抓取。
- 对含文字的图像应用 OCR 提取文本；支持 100 种语言；保留质量最高的 10%。

### 训练效率

- CLIP：256 个 TPUv3 上训练 10 天。
- SigLIP：32 个 TPUv4 上训练 5 天，计算更快地完成。
- 关键创新是实现并行化：每台设备只在本地计算部分损失，然后循环交换文本嵌入，计算非对角线负样本，最终覆盖所有组合。

### Batch Size 解耦

- SigLIP 将 **batch size 与损失解耦**。与 CLIP 不同，改变 batch size 不改变损失函数形式。
- 在 batch size 小于 16K 时显著优于 CLIP；可以扩展到 1M，但 32K 已达到临界点，继续增大帮助不大。

## 第四部分：视觉语言模型（VLM）

### LLaVA（Large Language and Vision Assistant）

#### 架构

- 视觉编码器：CLIP（ViT-L/14）。
- 文本解码器：**Vicuna**——基于 Llama，在 ShareGPT 对话数据上微调的语言模型。
- **投影器**：线性投影矩阵 W，将视觉向量映射到文本嵌入空间。Flamingo 和 Q-former 使用了更复杂的投影方案。

#### 数据

- 基于 MS COCO（带边界框和人工标题标注）。
- 向 GPT-4 提供标题或检测到的物体，生成对话、详细描述和复杂推理，共 158K 合成样本。

#### 训练

- **阶段一（对齐）**：冻结视觉编码器和语言模型，只训练 W。
- **阶段二（微调）**：冻结视觉编码器，训练 W 和语言模型。

#### 突出能力

- 能进行视觉推理，如“这张图片有什么不寻常的地方”——识别出“你通常不会在小型货车的后部熨衣服”。

---

### LLaVA OneVision

#### 主要升级

- 视觉编码器：SigLIP（使用最后一个 Transformer 层前后的 grid features）。
- 文本解码器：Qwen-2 72B。
- 投影器：2 层 MLP 替代线性投影。
- 支持多张图像和视频。

#### AnyRes 高分辨率处理

- 问题：CLIP 会缩放裁剪到 336×336，对 OCR 等需要细粒度信息的任务不可用。
- **AnyRes 方案**（LLaVA 1.5 引入）：
  - 将图像分解为多个块，每个块匹配视觉编码器期望的分辨率（如 336×336）。
  - 分别编码每个块，然后拼接所有向量。
  - 如果 token 过多，用双线性插值减少。
- 这是对动态分辨率的适应性设计——Transformer 天然适合处理不同长度输入。

#### 三种输入模态的 token 平衡

- 单张图像：高分辨率（完整降采样 + 最多 9 个裁剪块）。
- 多张图像：每张用基础分辨率。
- 视频：每帧用更低分辨率（最多 32 帧），避免数据集被重复帧主导。

#### 数据策略

- 哲学：**高质量优于数量**，数据高度任务化（VQA、表格问答、找差异等）。
- 大量数据是蒸馏 GPT-4 得到的。
- 包含单图、多图和视频数据。

#### 模态间迁移

论文发现了有趣的迁移现象：
- 只在单张图像上训练了图表/图示数据，但能泛化到多张图像场景（表格 + 图表问答）。
- 只在单图中训练了 OCR，在多图中训练了关系推理，却可以泛化到多截图 GUI 代理任务。
- 只在单图中训练了视觉提示（visual prompting，用圆圈高亮区域），却能泛化到视频中跟踪被高亮的玩家。

这暗示：即使每个任务看起来是独立的监督学习，当任务种类足够多时，模型能够获得跨模态的迁移能力。

---

### Qwen-VL 系列

#### Qwen-VL（第一代）

- 视觉编码器：OpenCLIP 的 ViT-bigC（14×14 patch）。
- 适配器：一层交叉注意力，加入 2D 位置编码，映射到固定长度 256。
- 特殊 token：图像标签 `<img>`、边界框标签 `<box>`、引用标签 `<ref>`。

**三阶段训练**：
1. 大规模低质量数据：冻结 LLM，训练视觉编码器和适配器（14 亿样本）。
2. 高质量任务数据：训练所有参数。
3. 指令微调：冻结视觉编码器，训练适配器和 LLM。

支持中文问答、输出边界框、OCR 等功能。

#### Qwen2-VL

- 更大的视觉编码器（675M 参数）。
- **动态分辨率**：每个 224×224 块用 ViT/14 编码，每 2×2 压缩为 1 → 每个块产生 66 个 token。小图像（公式）只产生 8 个 token，大图像可多达 11000 个。
- 视频：每秒采样 2 帧，最多 16384 个 token。

**多模态 RoPE（MRoPE）**：
- 1D RoPE 中，内积只依赖于 token 间的距离。多模态版本扩展到 3D：高度、宽度、时间。
- 每个位置由坐标三元组定义，对每个维度分别计算 RoPE 后拼接。

#### Qwen3-VL

**语言模型**：
- 使用 Qwen-3（有 dense 和 MoE 变体，最大 235B-A22B）。
- 长上下文 256K，对长视频理解很重要。

**视觉编码器**：
- SigLIP-2（架构与 SigLIP 相同，向后兼容）。

**改进的 MRoPE（交错）**：
- 原始 MRoPE 将 [t t t w w w h h h] 分别分配给不同频率段，导致所有时间维度都是低频、高度都是高频。
- 改进后交错排列 [t w h t w h t w h]，让所有轴都能接触低高频。

**显式时间戳**：
- 之前时间信息隐含在位置编码里；现在将时间作为显式 token（如“0秒”是一个 token）。
- 这允许直接引用具体时间点（如“两秒之后发生了什么”）。

**按 token 长度归一化的损失**：
- 视频样本很长，默认 every token 等权会让视频样本主导训练。
- 方案：按每个样本长度的平方根归一化损失，降低超长样本的影响。

**DeepStack 适配器**：
- 不再将视觉编码器当作输出向量序列的黑盒。
- 将视觉嵌入直接注入语言模型多个层的残差流中，实现更深度融合。

**训练**：
- 预训练 4 个阶段：先训练适配器，再逐步在 8K → 32K → 256K 序列长度上训练全部参数。
- 后训练：长思维链 SFT、知识蒸馏、强化学习。

### 关于 VLM 的常见问题

- **这些模型只输出文本**。所有多模态输入在前端编码，生成始终是文本。因此生成图像的逻辑（如判断生成质量）不在此范围内。
- **对齐阶段需要预训练好的 LLM 和视觉编码器**。只训练适配器来连接两者。训练时确定一个 token 预算，没有自适应阈值。
- **视觉编码器参数量远小于 LLM**。原因是视觉编码器做局部操作（理解小块），基本不做推理；模型的能力主要由语言模型承载。例如 LLaVA 的投影器远小于 ViT，ViT 通常不到十亿参数。

## 第五部分：Chameleon——统一的离散 token 方法

### 核心思想

之前的 VLM 将图像编码为连续向量注入 LLM，但无法生成图像。Chameleon 的答案是：**将一切映射为离散 token**。

优点：
- 可以用完全相同的方式分析和生成图像。
- 文本和图像真正生活在同一个空间。
- 训练就是普通的语言模型训练——没有适配器，没有微调视觉编码器。

示例：提示“我无聊了，能给我看些鸟吗”，模型输出文本 → 图像 → 更多文本和图像，交错生成。

### VQ-VAE 图像分词

- **VQ-VAE（Vector Quantized Variational Autoencoder）** 将图像映射为离散编码。
- 学习一个码本（codebook），如大小 8192，包含图像块的原型向量。
- 编码器输出连续向量后，舍入到最近的码本条目，这就是表示。
- 解码器从该编码重建图像，通过最小化重建损失训练。

**实际效果**：512×512 图像 → 1024 个 token，每个 token 来自大小为 8192 的词汇表。再用 BPE 训练新的 tokenizer。

### 训练与稳定性

- 阶段一（80%）：大规模无监督数据（290 万文本 token、150 万文本/图像 token、400B 交错 token）。
- 阶段二：高质量数据混合。

**训练不稳定的根源**：
- 文本 token 熵低、较可预测；图像 token 熵极高（“这个蓝色调是什么？”）。
- 混合训练导致参数范数增长和损失漂移。
- 缓解方案：QK 归一化、z-loss 正则化。

### 评价

- 优雅：单一模型以同样方式对待所有模态。
- 缺点：性能不够好；离散化丢失细粒度信息（如小字 OCR）；多模态训练困难。

VQ-VAE 风格的方法曾流行于图像生成（因为 Transformer 需要离散输出），但在扩散模型出现后逐渐失去主导地位。

## 总结与当前共识

1. **前沿模型必须多模态**：原生多模态/全模态已是大势所趋。闭源模型（Gemini、GPT）的具体架构未知，很可能是连续编码器 + 扩散生成的组合（推测，无公开细节）。

2. **根本挑战是编码非文本模态**：理解与生成需求不同：
   - 理解需要高层语义（CLIP 类表示即可）。
   - 生成（或 OCR）需要细粒度细节——CLIP 的 336×336 裁剪会丢失信息。

3. **数据加权是关键**：视频信息密度低于文本，不应让视频样本主导训练（平方根归一化损失）。

4. **当前最佳实践**：连续编码器（CLIP/SigLIP）+ Transformer + 扩散模型生成。即使 CLIP 已有近五年历史，这类方法仍是捕捉图像语义的首选。

## 常见误区

1. **误区：VLM 能生成图像。** 实际上主流的 VLM（LLaVA、Qwen）只接受图像输入，输出始终是文本。图像生成需要额外的扩散模型或 Chameleon 那样的离散 token 方法。

2. **误区：视觉编码器参数量应与 LLM 匹配。** 视觉编码器做局部操作、参数量远小于 LLM，模型大部分推理能力来自 LLM。

3. **误区：图像 token 与文本 token 一样可预测。** 图像 token 熵高得多，导致训练不稳定，需要特殊处理（如按长度归一化损失、QK 归一化）。

4. **误区：任意分辨率图像可以直接输入 ViT。** 需要 AnyRes 式的分块处理或动态分辨率设计，否则会丢失细粒度信息。

5. **误区：多模态模型越大越好，数据是唯一的挑战。** 数据质量与数量并重，且需要关注模态间的 token 数量平衡。
