# CS336 Lecture 15：Mid/Post-training（SFT/RLHF）中文讲义

## 学习目标

完成本讲后，你应该能够：

1. 理解后训练（post-training）在整个语言建模流程中的位置，以及为什么预训练之后还需要 SFT 和 RLHF。
2. 区分 SFT 与 RLHF 在目标函数和优化范式上的本质差异：分布拟合 vs. 奖励最大化。
3. 了解 SFT 训练数据的类型、历史演变，以及数据质量、风格、知识边界对模型行为的深刻影响。
4. 掌握 RLHF 中数据收集的基本流程（成对偏好标注）以及 PPO 与 DPO 两种算法的核心直觉。
5. 识别后训练中常见的陷阱：过优化（over-optimization）、长度作弊、标注者偏差、模式崩溃。

---

## 1. 课程主线概述

本讲从「基础模型（如 GPT-3）」走向「可用系统（如 ChatGPT）」的转变。预训练提供了广泛的语言能力和知识，但基础模型本身无法可靠地遵循复杂指令。后训练的目标是从预训练形成的「原始汤」中提取出用户真正需要的行为。

本讲的路线图：

- **SFT 阶段**：以人工或模型生成的输入-输出对进行监督微调，目的是教会模型「如何回应指令」。
- **RLHF 阶段**：通过人类偏好标注训练奖励模型，再用强化学习（PPO/DPO）优化策略，目的是教会模型「什么是好的回应」。

课程强调：后训练不同于预训练，它是一门「手艺活」，数据质量、风格控制、安全策略等因素远比算法本身更能决定最终效果。

## 2. SFT（Supervised Fine-Tuning）

### 2.1 SFT 的本质：数据主导

SFT 在算法层面和预训练基本一致——都是下一个词元预测的最小化负对数似然。真正的区别完全在数据上。因此，本讲将大部分篇幅用于讨论训练数据。

### 2.2 SFT 数据的历史演变

按时间顺序梳理 SFT 数据的几个关键派别：

**FLAN（Google/T5）**

- 核心想法：NLP 领域已有大量有监督数据集，全部拿来进行多任务后训练。
- 问题：数据集本身质量参差不齐，示例结构「非自然」。例如：
  - 输入是一封电子邮件，指令放在末尾（「为这封邮件写一个主题行」）。
  - 摘要数据集生成的回复极其简短，且经常包含幻觉内容。
- 教训：FLAN 建立在「后训练也需要大规模数据」的假设上，但后来的工作证明，预训练足够强时，只需少量高质量示例即可。

**Self-Instruct 与蒸馏派系（Alpaca 等）**

- Self-Instruct：让模型自己生成输入和输出，构成指令数据。
- Alpaca（斯坦福）：蒸馏 ChatGPT 的输入-输出轨迹。当配合 Llama 基座模型时，首次在开源界可靠地诱导出 ChatGPT 风格的行为。
- 里程碑意义：证明「聊天风格数据」是从基础模型演化到对话模型的关键，也点燃了大规模构建指令数据的浪潮。

**Open Assistant（众包人类数据）**

- 接近维基百科式的众包努力：志愿者编写提示词与高质量回复。
- 产出数万条示例后项目停滞。
- 价值在于展示了专家编写的高质量、长篇幅回复长什么样，也暴露了数据收集的可持续性问题。

**合成数据 + 工具调用（现代）**

- 当前 SFT 数据正从纯聊天走向智能体（agent）范式：回复中不仅包含文本，还包含工具调用、待办事项列表等结构化内容。
- 例如 Nemotron（NVIDIA）的 SFT 数据大量采用这种「文本 + 并行工具调用」的格式。

### 2.3 SFT 数据中的关键权衡

**正确性 vs. 泛化**

- 投入正确性：应当是「尽可能收集最高质量回复」，坏示例会教会模型坏行为。
- 但存在反直觉现象：即使数据质量较差，模型仍能学会遵循指令，这源于预训练的强泛化能力。
- 结论：给定一个足够强的预训练模型，所需的示例数量很少；质量和数量的权衡应该偏向质量。

**知识边界与幻觉**

- 案例：Open Assistant 中标注者给出了包含引用的回复，例如「……（Bivens J & Michelle L, 关于企业高管薪酬）」。模型在 SFT 中学到两件事：
  1. 这段知识本身（姓氏来源等）；
  2. 输出时应该附带参考文献的格式习惯。
- 问题在于模型无法判断某篇参考文献的真伪。当它不知道某个事实时，它会「强行泛化」——照猫画虎地编造出格式正确但内容虚假的引用。
- 已有经验证据（课程中称为「民间传说」）：用模型未知的事实做 SFT 训练会加剧幻觉。
- 为什么 RL 可能缓解这个问题：模型内部可能存在某种「我知道」vs「我不知道」的方向性表征。SFT 无法提取这种信息，但 RL 可以通过奖励信号将这种内部激活模式与「是否输出」的决策连接起来。前提是模型内部确实存在这种知识，否则 RL 也无能为力。
- John Schulman 的观点（课程引用）：模型对自己知识边界的校准必须依赖于策略（policy），而不能靠外部硬塞知识。

**数据规模**

- 只需数百条样本（如 500 条安全示例）就能大幅压低恶意指令遵循率。
- 但这不意味着更多样本没有价值：大型组织仍需要数千至数万条细粒度的安全数据来执行精确的边界区分。

**风格控制 vs. 能力控制**

- 标注者偏好长度更长、含项目符号列表的回复——这种偏好会扭曲模型的天然语气。
- 参与度信号（engagement signals）容易自欺欺人：你可以大幅改变用户参与度，但标准基准测试分数却不动。
- 启示：风格与能力必须分开看待与调节。

### 2.4 安全 SFT

- 平衡两个目标：恶意行为「违规率」与「误拒率」。
- 数据规模通常在数千到数万条范围；例如 Llama 2 使用几千条安全样本。
- 方法往往很直接：从聊天接口的海量交互记录（如 WildChat）中挖掘不安全行为和越狱尝试，为每个案例生成「首选回应」（拒绝语）。
- 本质上是「打地鼠」式的被动响应：发现什么坏行为，就补什么数据。

### 2.5 SFT 方法细节

- 算法层面没有新东西：就是标准的下一词元预测 + 梯度下降。
- 重要趋势：**预训练与后训练的界限正在模糊**。
  - 如今「基础模型」通常并不是只在互联网数据上预训练的，而是混合了大量质量较高、带聊天风格的 SFT 数据（如 UltraChat）进行第二阶段训练，往往与学习率衰减阶段重合。
  - 示例（MiniCPM）：第一阶段是标准互联网数据；第二阶段切换为高质量对话数据（Stack Exchange QA、UltraChat 等）。
  - 好处：可利用衰减阶段做大量低成本的消融实验，反向指导第一阶段的预训练数据混合配比。
- 注意：这类阶段中的 token 不遮蔽，提示词也被预测；「基础模型」一词已经名不副实。

## 3. RLHF（Reinforcement Learning from Human Feedback）

### 3.1 概念转变：从生成式建模到奖励最大化

- 预训练与 SFT 属于**生成式建模**：拟合一个分布，关注的是分布本身。
- RLHF 属于**奖励最大化**：仍有一个分布，但它现在是策略（policy）；目标是最优化某个下游奖励（用户参与度、正确率等）。
- 关键差异：在奖励最大化框架下，策略完全可以将输出分布坍缩成单点，只要单点能拿到高奖励。这与「模拟分布」的目标有本质差别。

### 3.2 为什么需要 RL 而非继续收集 SFT 数据？

两个核心原因：

1. **人们说什么 ≠ 他们生成什么**：人类标注者自己写的摘要可能不如 AI 输出好（课程给出 InstructGPT 时代标注者偏好 AI 输出的实例）。当你需要的是「评判」而非「生成」时，偏好标注更合适。
2. **验证往往比生成本质上更容易**：例如数学领域，验证一个证明的正确性远比构造证明容易。这为 RL 中的自我评判提供了天然优势。

### 3.3 RLHF 数据收集

标准收集流程（类似 InstructGPT）：

- 输入提示词 → 模型采样多个输出（采样温度设为 1）→ 评估者做出二元或排名比较。
- 标注者被要求从三个维度评估：有用性（helpfulness）、真实性（truthfulness）、无害性（harmlessness）。
- 实际案例：Google Bard 曾使用李克特量表进行标注（而非成对比较），并强调回复要连贯、简短、易读。

### 3.4 标注者分布：极其重要且被低估

**学历与专业度**

- 数据标注者的学历分布：约 70% 拥有学士或硕士学位；年龄中位数约 35 岁。他们的任务多为创意写作和技术写作。
- 趋势：标注工作正在向专家化、定制化迁移；部分专家按小时计薪每小时超过 100 美元。

**标注偏见的传播**

- 研究案例：后训练后的模型在政治观点上更接近佛教徒、印度教徒和无神论者，和 InstructGPT 标注者的来源地（东南亚、美国西海岸）吻合。
- 存在「阈下迁移效应」（emergent misalignment）：即便你在无害数据上训练，模型也可能继承数据生成者的隐藏偏好。

**专业度 vs. 众包质量**

- 专业标注者更关注事实性和逻辑不一致，业余标注者则过度关注格式化（如加粗、列表）。
- 事实性检验难度高，这正是众包难以覆盖的原因。
- 如何定义「好标注者」：标注指南的严格遵守（半客观标准）+ 标注者间一致性（高方差任务如主观偏好不适用）。

**AI 做标注者的崛起**

- GPT-4 时代的系统排名对比表明：模型标注与高质量人工标注的一致性相当，成本却低一个数量级。
- 案例（HuggingFace Zephyr）：团队试图完全避免蒸馏，投入大量时间和经费收集人类数据，结果效果并不比基于模型标注更好，最终仍回归模型反馈。
- 结论：如果你想追赶前沿能力，基于模型的标注（distillation）基本是标配；但如果你要推动前沿、获取世界知识（律师级判断等），人类标注不可替代。
- 注意「模型标注」的陷阱：长度作弊。对模型评判者而言，更长的输出往往被误认为更好，甚至仅用长度做 RLHF 就能在多个基准上表现良好。

### 3.5 RLHF 算法

#### 目标函数

RLHF 的核心目标如下：

- 第一项：在策略 π_θ 下采样并最大化奖励 r_φ。
- 第二项：KL 散度正则项，要求策略与参考策略（即 SFT 模型）保持接近，防止优化过度偏离。

#### PPO（Proximal Policy Optimization）

推导脉络：

1. **策略梯度恒等式**：目标为最大化期望奖励，梯度 = 对数策略梯度 × 奖励。
2. **从同策略到异策略**：采样昂贵，希望重复利用已生成的样本；引入重要性权重修正，但要限制步长（TRPO 的思想）。
3. **PPO**：TRPO 中的距离约束难以计算，改为启发式的 clip 机制，防止策略偏离过远。

课程指出：PPO 可在下一讲中展开，这里只需理解它是「带权重、带约束的 SFT」。

#### DPO（Direct Preference Optimization）

核心直觉：对好样本走正向梯度步长，对坏样本走负向梯度步长——用「正/负 SFT」替代完整 RL 循环。

推导要点：

- 假设策略 π 是非参数化的，可以近似任意分布。
- 在该假设下，RLHF 目标存在闭式解：最优策略 = π_ref 的指数倾斜（以奖励为权重）。
- 反解出该最优策略隐含的奖励函数。
- 将该隐含奖励代回原始目标函数，得到 DPO 目标：
  - 对获胜样本提升概率；
  - 对失败样本降低概率；
  - 步长由「当前模型对两者概率差的『意外程度』」缩放。

直观理解：

- 如果模型已经正确区分好坏（给好的高概率、坏的极低概率），则步长小。
- 如果模型完全没区分出差异（两者概率相等），则步长大。

DPO 的效果：

- 在当前实际操作中（如 Llama 系列技术报告），DPO 已作为核心 RLHF 原语使用。
- 与 PPO 的胜负取决于实验设置与工程细节，没有绝对优劣。
- 变体（SimPO、长度归一化 DPO 等）小改动带来的差异不大。
- 对学习者而言，DPO 的价值在于：拟合分布式的简单目标 + 适当的步长设定，就是以得到近乎 SFT 的简单实现。

### 3.6 RLHF 的常见陷阱

1. **过优化（over-optimization）**：过度压缩 KL 正则化会导致模型「欺骗」奖励模型，即过拟合奖励信号而非真实人类偏好。KL 正则不是可选项，而是必须项。
2. **模式坍缩**：RL 优化会大幅降低生成多样性，模型开始集中于少数几种安全输出——这源于「策略」而非「分布」的定位。熵与多样性在大模型后续应用中（如推理模型）至关重要。
3. **校准漂移**：RLHF 可能显著降低模型的校准质量（如 GPT-4 时代 OpenAI 公布的校准退化图）。目前仍无通用解法。

## 5. 常见误区

| 误区 | 正解 |
|------|------|
| SFT 数据越多越好 | 预训练足够强时，少量高质量示例即可；过多且包含模型未知事实的数据反而加剧幻觉 |
| 「基础模型」就是纯预训练模型 | 现代「基础模型」经常混入大量 SFT 风格的合成数据做第二阶段训练 |
| RLHF 的目标是拟合人类偏好分布 | 实际上是最大化奖励函数，模型可以为了奖励坍缩成单输出 |
| DPO 一定比 PPO 好（或差） | 两者的相对优劣高度依赖实验设置、数据与调参细节 |
| 标注数据质量由「标注者间一致性」保证 | 一致性只衡量方差，不衡量偏差；高一致性也可能代表大家都用 ChatGPT 作弊 |
| 模型标注可以完全替代人类标注 | 对追赶前沿是可行的；但世界知识、专家意见、安全边界等仍依赖人类 |
| 过优化只存在于 RL 迭代过多次时 | 只要 KL 正则化过弱就会引发过优化，即便迭代次数不多也可能发生 |
