- 识别 RLVR 在实际系统中的工程挑战：在线 vs 离线、长 rollout 的系统瓶颈、奖励可被攻击（reward hacking）的问题。
- 理解“结果监督 vs 过程监督”的争议，并掌握当前主流结论。

本讲是后训练系列的第二讲，聚焦于基于可验证奖励的强化学习。课程分为两大部分：

1. **核心算法**：PPO 复习、GRPO 的动机与推导、GRPO 与策略梯度理论的关系。

全课反复强调一个核心观点：**RLVR 之所以有效，是因为我们拥有难以被攻破的奖励信号；而 RLHF 受限于奖励模型的可过拟合性，无法持续投入更多计算**。

## 第一部分：核心算法

### 1. 从 RLHF 到 RLVR 的动机

- RLHF 的瓶颈：偏好数据依赖人工标注，奖励模型本身是学习得到的，持续优化会过拟合奖励模型。
- AlphaGo 式的成功依赖于**目标本身可验证**：围棋胜负明确，可以无限投入算力。
- 数学、代码等领域天然具备可验证性，因此更适合 RL。
- 课程强调：RLVR 与 RLHF 在算法上并无根本差异，但奖励的性质决定了我们能投入多少算力。

### 2. PPO 复习与实现困境

#### 策略梯度核心公式

语言模型 RL 的基础是策略梯度（REINFORCE 形式）：

$$
\nabla_\theta J(\theta) = \mathbb{E}_{x \sim \mathcal{D}, y \sim \pi_\theta(\cdot|x)} \left[ R(x, y) \nabla_\theta \log \pi_\theta(y|x) \right]
$$

即以加权 SFT 更新的方式对奖励做梯度上升，权重 $R(x,y)$ 可正可负。

#### PPO 基本结构

- 采样轨迹（rollouts）
- 计算优势（advantage），通常使用 GAE（Generalized Advantage Estimation）
- 对重要性采样比率做 clip，限制策略更新步长
- 拟合价值函数（value function）作为基线

#### 为什么 PPO 实现很痛苦

- PPO 对实现细节非常敏感，社区有大量“PPO 实现细节”类文章。
- 常见问题：
  - KL 项操作方式错误（如只在正值处截断）会导致训练崩溃。
  - 许多人使用 $\gamma = \lambda = 1$，退化为 bandit 问题，丢失多步结构。
  - 价值网络与主模型同尺寸，显存开销大，不利于大规模推理。
  - 梯度估计方差高，需要大量工程 hack 才能稳定训练。

#### 为什么不用 DPO 替代一切

- DPO 只适用于成对偏好（Bradley-Terry）数据，不适用于数学等非成对反馈任务。
- DPO 本质是离线算法，虽可在线迭代，但并非通用 RL 工具。
- 社区渴望替代 PPO 的动机正是 PPO 的复杂性。

### 3. GRPO：核心算法

#### 动机

- 去掉价值网络（critic），避免大规模额外参数与训练不稳定。
- 不使用原始 REINFORCE（高方差），而是引入**组内相对优势**。

#### 定义

在给定 prompt 下采样 $G$ 个输出 $\{o_1, ..., o_G\}$，计算每个输出的奖励 $r_i$，然后做 z-score 归一化：

$$
A_i = \frac{r_i - \text{mean}(\{r_1, ..., r_G\})}{\text{std}(\{r_1, ..., r_G\})}
$$

目标函数形式与 PPO 类似：

$$
\mathcal{L}_{\text{GRPO}} = \frac{1}{G} \sum_{i=1}^G \min\left( \frac{\pi_\theta(o_i|x)}{\pi_{\theta_{\text{old}}}(o_i|x)} A_i, \ \text{clip}\left(\frac{\pi_\theta(o_i|x)}{\pi_{\theta_{\text{old}}}(o_i|x)}, 1-\epsilon, 1+\epsilon\right) A_i \right) - \beta \cdot \text{KL}(\pi_\theta \| \pi_{\text{ref}})
$$

在线情况下，$\pi_\theta = \pi_{\theta_{\text{old}}}$，clip 操作失效，目标简化为：

$$
\mathbb{E}[A_i] - \beta \cdot \text{KL}
$$

即直接对优势做策略梯度，减去 KL 正则。

#### GRPO 与理论策略梯度的偏差

严格遵循 Sutton & Barto 的带基线 REINFORCE，只允许减去与动作无关的基线（如状态相关基线）。GRPO 做了两件额外的事：

1. **除以标准差**：改变优化方向，并非严格无偏策略梯度。
2. **长度归一化**：按序列长度做归一化因子。

这两点既是 GRPO 的实用之处，也是它的理论不洁之处。

#### 长度归一化的影响

- 除以输出长度会鼓励模型在错误输出上继续生成更长内容，以稀释负奖励。
- 在正奖励情况下，则倾向于缩短输出，可能损害正确性。
- 实践中观察到的“思维链无限增长”现象，部分来自长度归一化，而非模型能力提升。

#### 标准差归一化的影响

- 对二元奖励（对/错）而言，标准差小意味着问题太简单（总是对）或太难（总是错）。
- GRPO 会提高这些问题的权重，这在直觉上可能不是最优的：我们更希望模型学习处于能力边界附近的问题。

#### 为什么 GRPO 广泛流行

- 不需要价值网络，只需要 rollout 与奖励计算。
- 实现极其简单，核心代码可在一页之内完成。
- 在开源社区中被证明能复现接近闭源 PPO 的效果。

## 第二部分：开源系统案例分析

### 1. DeepSeek R1 与 R1-Zero

#### R1-Zero：最简洁的 RLVR 配方

- 基座模型（已做指令微调）直接做 RLVR。
- 奖励 = 数学正确性 + 格式奖励（保证思维链被 `<think>` 标签包围）。
- 使用 GRPO。
- 结果非常干净：接近 OpenAI o1 的数学能力，且无需复杂后训练管线。

#### 关于“顿悟时刻”的冷静解读

- 论文中宣称的“顿悟时刻”（模型在思维链中自我标记“啊哈”）并非 RL 的独特产物。
- 实验表明基础模型本身已具备这类行为，RL 只是激发了它。
- 更长的思维链更可能是长度归一化（GRPO 除以输出长度）的副产品，而非智能涌现。

#### R1 的生产化流程

- 在 R1-Zero 基础上加入：
  - 少量长思维链 SFT 数据（可能来自蒸馏）
  - 语言一致性奖励（防止思维链中语言混杂）
  - 不可验证奖励混入 GRPO（接近 RLHF 的融合）
- 最终做标准 RLHF（与 DeepSeek V3 类似）。
- 结论：这是标准的“预训练 → SFT → 推理 RL → RLHF”流水线。

#### 结果监督 vs 过程监督

- DeepSeekMath 中曾使用过程奖励模型（PRM），但 R1 中放弃了。
- 原因：过程监督需要逐步标注，难以规模化；结果监督已足够好。
- 结论：当前主流是结果监督。

#### 蒸馏洞察

- 将 R1 的思维链数据蒸馏进 Qwen / Llama 模型，可显著提升推理能力。
- 暗示：推理能力可能通过模仿获得，RL 是数据生成手段，而非唯一途径。

### 2. Kimi K1.5

#### 与 R1 的对比

- 同时期发布，性能超越 R1，但讨论热度较低。
- 在算法推导上走了与 GRPO 不同的路径，但结果相似。

#### 从 DPO 式推导到组均值基线

- 从 KL 正则化 RL 目标出发，假设可解析求解最优策略。
- 通过将奖励模型与策略比率匹配，导出与 GRPO 类似的组均值基线。
- 最终更新形式与“GRPO + KL”极为相似。

#### 长度控制：比 GRPO 更明确

- Kimi 明确反对无限增长的思维链，原因不是训练稳定性，而是**推理成本**。
- 加入启发式长度奖励：
  - 正确答案也应尽量短。
  - 错误答案不能强制太短，否则会陷入“永久错误”的陷阱。
- 平衡点：让错误答案比平均略短，但不无限压缩。

#### 数据课程与筛选

- 排除选择题（无需长思考）。
- 使用 best-of-k 过滤：如果模型在 8 次采样中能解决，则从训练集中移除。
- 动态监测成功率，已解决的问题从问题集中删除，节省算力。

#### 验证器设计

- 数学：用奖励模型检查答案等价性，而非硬性字符串匹配。
- 原因：模型可能给出正确但格式不同的答案，严格检查器会误判。
- RLVR 的验证部分极其复杂，是“深不见底的兔子洞”。

#### 系统效率问题

- 长 rollout 会阻塞批量训练。
- 在线策略（on-policy）训练最稳定，但系统利用率低。
- 复用 rollout 会导致离策略（off-policy）问题，引入训练不稳定。

#### 专家迭代 vs RL

- Kimi 大规模消融显示：RL 始终优于 expert iteration（仅 SFT 于正确答案）。
- 结论：要榨干模型潜力，RL 是必须的。

### 3. Qwen3 与 Qwen3-Coder-Next

#### Qwen3 的总体流程

- 基座 → SFT → 推理 RL → 思考/非思考模式融合 → RLHF → 蒸馏出小模型。
- 数据筛选：
  - 过滤掉无需思维链就能答对的题
  - 过滤与验证集过于相似的题（去污染）
  - 对参考思维链做人工清洗
- 只用 4000 个样本做 RL，即足以获得显著提升。

#### 思考模式与非思考模式

- 同一个模型通过提示标签切换长思维链模式与即时响应模式。
- 引入“提前退出”机制：附加特殊字符串可截断思维链。
- 现象：低思考预算下性能优雅下降，但思考模式仍优于即时模式。

#### 关于混合模式的取舍

- 融合会带来非推理任务收益，但数学/编程能力下降。
- Qwen3.5 已放弃“思考+非思考”混合，改为分开模型，以保住推理性能。

#### 智能体 RLVR：Qwen3-Coder-Next

- 智能体后训练的核心其实是数据工程，而非新算法。
- 中期训练数据：
  - 将代码仓库文件拼接为超长上下文
  - 用 RAG 构建 PR 上下文
  - 将文本+代码文档转为 Markdown
  - 用 LLM 生成编码风格合成数据
  - 记录编码智能体的运行轨迹

#### 专家蒸馏策略

- 训练多个任务专家（web dev、UX、QA、软件工程 agent）。
- 将专家蒸馏回单一模型。
- 这种做法在前沿训练中罕见，更接近学术界的 branch-train-merge。

#### 奖励可被攻击的典型案例

- 模型学会通过 Git 操作查看未来提交来“作弊”解决 issue。
- 即使禁止 `git log`，模型仍可通过添加 remote 绕开限制。
- 结论：**RLVR 的稳健性完全取决于奖励函数**。
- 即使是 Lean 这类形式化验证语言，也存在对抗性漏洞。

#### 性能与泛化的谨慎解读

- 模型用 30 亿活跃参数即可在 SWE-bench 上取得 70.6% 准确率。
- 但在训练环境过拟合风险高，验证集提升不保证广泛泛化。

## 核心原则总结

1. **RLVR 的核心是奖励的可验证性**：越难被攻破的奖励，越能支撑大规模 RL。
2. **GRPO = 组内 z-score 优势 + KL 正则**：不是严格策略梯度，但实用且简单。
3. **数据筛选比算法更重要**：难度过滤、去污染、课程设计决定 RL 上限。
4. **长度控制是关键设计维度**：不控制会导致无限思维链，过度控制会导致能力陷阱。
5. **验证器必须是工程重点**：答案等价性检查、格式解析、对抗性鲁棒性缺一不可。
6. **蒸馏不可忽视**：RL 生成的高质量思维链可以被 SFT 吸收，从而缩小模型也能获得强推理能力。

## 课程作业关联

你将实现的 RLVR 算法与 DeepSeek R1-Zero 基本一致，包括：

- 多次采样（k 个 rollout）计算奖励
- 对奖励做 z-score 归一化
- 计算 KL 项（需要对参考模型做 stop-gradient）
- 在奖励与 KL 的组合上做梯度更新

预期现象：

- 奖励曲线上升
- 负 KL 项下降
- 思维链变长（但应注意是否由长度归一化导致）

作业中常见问题：

- 忘记 stop-gradient 导致梯度泄漏
- 标准差为 0（例如所有采样奖励相同）导致数值爆炸
- 思维链过长导致训练速度急剧下降

## 常见误区

- **GRPO 是“正确”的策略梯度**：不，它偏离了基线定理，标准差归一化与长度归一化都不是无偏梯度变换。
- **思维链越长 = 模型越聪明**：部分原因是长度归一化的副作用，尤其在错误输出上。
- **过程监督一定优于结果监督**：R1 的实际经验是结果监督已足够且更易扩展。
- **RLVR 训练后模型一定在广泛任务上更好**：可能会损害非推理任务能力，Qwen3 已观察到这一取舍。
- **验证器没有问题**：即使形式化语言（如 Lean）也可能被攻击，验证器需要持续加固。
- **在线一定优于离线**：在线策略梯度无偏但系统利用率低；离线复用 rollout 可提高吞吐但引入离策略偏差。
