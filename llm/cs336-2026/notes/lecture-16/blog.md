# 从 RLHF 到 RLVR：后训练系列讲座中的思考模型革命

> 在《CS336 · Language Modeling from Scratch》的课程图谱中，我们已经走过了预训练、指令微调（SFT）和 RLHF 的阶段。上一讲结束时，我们带着对 RLHF 的悲观情绪离开——偏好数据与奖励模型的过拟合瓶颈似乎让我们走到了尽头。本讲（Lecture 16）则试图回答一个关键问题：如果我们把优化目标和信号源从人类偏好换成可验证的奖励（Verifiable Rewards），强化学习能否真正展现出 AlphaGo 那样的威力？本讲围绕核心算法 GRPO、DeepSeek R1、Kimi K1.5 与 Qwen 3 系列技术报告，给出了一个相当肯定的答案。

---

## 为什么 RLHF 不够好，而 RLVR 让人兴奋

上一讲结束时我给的调子比较悲观。我们讨论了 RLHF 的流程：收集偏好数据，训练奖励模型，用强化学习做优化。这套流程的核心问题是“过度优化”（overoptimization）。你不可能无限期地对同一个奖励模型进行强化学习——很快你就会过拟合。无论你把 KL 正则化做得多么精细，这个天花板始终存在。

但强化学习的真正潜力，在 AlphaGo 这类场景里展现得淋漓尽致。围棋的胜负条件清晰可见，你可以投入无穷多的计算量，因为只要目标在改善，你就是在做正确的事。反观 RLHF，它本质上是一种受限于人工标注的学习问题，不是一个可以无限扩展的搜索问题。

于是我们自然而然地寻找可验证奖励（Verifiable Rewards）的领域：形式化数学、自然语言的数学问题、代码执行。只要问题有确定的正确答案，我们就有了一个“不可攻破”的奖励来源，其成本远低于人工偏好标注。这就是 RLVR（Reinforcement Learning from Verifiable Rewards）的动机。算法上它和 RLHF 没有本质区别，但目标函数的性质让整个流程发生了质变。

---

## 回顾 PPO：为什么它是一个痛苦但不可回避的起点

要理解 RLVR，必须从策略梯度谈起。核心公式是 REINFORCE 梯度：

$$
\nabla_\theta J = \mathbb{E} [ R \cdot \nabla_\theta \log \pi_\theta(a|s) ]
$$

这个公式贯穿整个讲座。我们在做的本质上是对语言模型的采样输出施加带权重的 SFT 更新，权重可正可负，取决于奖励大小。

但逐步更新的策略梯度效率太低。于是我们有 TRPO，进而有 PPO（Proximal Policy Optimization）。PPO 在深度强化学习领域是绝对的主力，OpenAI 用它做过机器人走路、Dota 等经典工作。从概念上看，PPO 的伪代码不算复杂：采样轨迹，估计优势函数，用裁剪后的优势更新策略，再拟合一个价值函数。

问题在于实现。有篇著名博客文章叫“PPO 的 37 个实现细节”，这种事本身就说明问题。PPO 对实现决策极其敏感——基线到底算不算、经验缓冲区怎么管理、值函数何时更新、优势估计是否真用上了 GAE（Generalized Advantage Estimation），每一个环节都能让训练从收敛变成发散。

尤其是当我们把它搬到语言模型上时，情况更糟。语言模型是逐 token 生成的多步决策问题，不是一步臂赌机（bandit）。这意味着优势估计要处理每个 token 的回报，价值模型又是另一个和策略一样大的神经网络，存储和训练开销大，且极不稳定。我们在课程中体验过：即使外层循环合理、内层损失计算基本正确，真正让 PPO 跑起来依然需要各种 hack。例如，KL 惩罚要在 0 处截断才稳定，否则求和里正负项混乱就会崩溃；很多人还把 GAE 的两个参数 $\gamma$ 和 $\lambda$ 设成 1，实质退化为最大化末尾整体奖励臂赌机——这几乎等同于放弃了 PPO 的结构优势。

PPO 的这些问题催生了 DPO 这样的替代品，但 DPO 只适用于 Bradley-Terry 成对比较结构，无法直接应对数学求解这类从单一结果给出奖励的问题。我们需要一个更简单的在线 RL 算法，这就是 GRPO 登场的背景。

## GRPO：去掉价值网络的组内归一化策略梯度

GRPO（Group Relative Policy Optimization）出自 DeepSeekMath 论文。它的意图很直接：保留 PPO 的核心思想，去掉最复杂的部件——价值函数（value model）。没有价值网络后，如何估计优势？答案是用组内 z-score 归一化。

假设你对同一个提示词采样 $g$ 个 rollout，记第 $i$ 个 rollout 的奖励为 $r_i$。GRPO 定义该 rollout 的优势为：

$$
A_i = \frac{r_i - \text{mean}(r_1, ..., r_g)}{\text{std}(r_1, ..., r_g)}
$$

这在直觉上很自然：如果我的这次采样比组内平均表现好，优势就是正的；否则为负。没有任何额外的神经网络，没有价值模型的拟合与存储，在在线采样下（即当前策略采样时），目标函数中的裁剪项变成恒等，最终目标退化为：

$$
\text{maximize } \mathbb{E}[ A \cdot \log \pi_\theta ] - \beta \cdot \text{KL}
$$

即用优势做加权更新，加上一个 KL 惩罚保持贴近参考策略。这本质上就是一个带奖励的、加了正则化的 REINFORCE。实现极其简洁，课程提供了一个来自 McGill 的参考实现，核心代码不到一页：计算每个组内奖励，做 z-score 归一化，加一个小小的 $-4$ 防止标准差为 0（当所有奖励相同时会爆炸），然后计算 KL 惩罚项，最后合并做梯度更新。你不难理解为什么 GRPO 在开源社区中如此普及——它就是一个能在一页代码里写完、并取得不错效果的算法。

在 DeepSeekMath 的实验中，GRPO 明显优于 RFT（拒绝微调），这说明这套简化并没有牺牲多少性能，反而因为更稳定而收益更多。

但这里必须强调一个重要的理论瑕疵：GRPO 并*不是*标准意义上的策略梯度。Sutton 和 Barto 的带基线 REINFORCE 允许你减去一个状态相关的基线，但你不应该除以标准差。GRPO 除以标准差、并引入按序列长度归一化两项，都超出了基线定理的框架。这意味着它优化的是一个和原始奖励目标略有不同的对象。

这带来了一个有趣的副作用：长度归一化会鼓励负面案例生成超长序列，因为错误的负面奖励除以一个极大的长度后趋近于 0，模型得以逃脱惩罚。这无疑会导致思维链（COT）无限膨胀。标准差归一化则会抬高简单和极难问题在目标内的权重——这两类问题的奖励方差都很小，因而被放大。但这恰恰是模型学不到东西或不可能学会的问题。

尽管如此，GRPO 在实践中非常非常好用。它的简单性让大量实验室得以快速复现并迭代，所以它事实上已经成为开源 RLVR 社区的基调。

## DeepSeek R1：一个干净到接近纯净的 RLVR 配方

DeepSeek R1 是开源 RLVR 模型的里程碑。它最重要的贡献之一，是提供了一个任何人都能复现的 RL 配方。相比闭源的 PPO 范式的痛苦，GRPO 的简单性让 RLVR 不再是超大规模实验室的专利。

R1 的起点是 R1-Zero：一个基础模型（当然，它已经过了指令微调），直接在其上做 GRPO，奖励只来自数学问题的准确率和格式（例如是否用 `<thinking>` 标签包围思维链）。没有 SFT，没有人工标注，没有复杂设计。就是这么简单的配方，得到的模型能力与 OpenAI 的 O1 比比，只差一点点。

R1-Zero 中的一个现象引起了巨大的社交媒体热议，那就是“顿悟时刻”——模型在思维链中惊奇地标记“我发现这个可以用……”。但我们回头分析，这个“顿悟”其实并不那么神秘。基础模型在预训练阶段就生成了大量的数学 token，早已具备识别这类结构的能力；RL 训练只是助推了这个模式的出现。而思维链长度的持续增长，我认为更直接的原因就是 GRPO 的长度归一化副作用——模型发现延长输出可以在不损失奖励的情况下减少惩罚。

但无论如何，R1 作为一个产品级系统，给我们带来了一份完整的架构视图。它的流程大体如下：预训练模型 → 长上下文扩展 → 推理强化学习（GRPO）→ RLHF → 蒸馏小模型。为了保持输出语言一致性，R1 还引入了语言一致性奖励。他们坦白说，早期 R1-Zero 式的训练会产生跨语言思维链，所以他们限制模型只能用单一语言来提升可读性，这纯粹是出于可解释性考虑。

R1 还告诉我们一件事：过程监督并非必需。DeepSeekMath 中他们确实做过过程奖励模型（PRM），但 R1 报告里坦白，过程奖励模型效果并不好——结果奖励模型（outcome reward model）不但足够，而且更好扩展。这是一个重要的行业共识：你的奖励足够干净时，你不需要昂贵的逐步评分标注。

另一个有趣的细节是 SFT 数据来源。R1 报告说他们“收集了一小部分长思维链数据”，但并未明确说明这些数据是否来自其他模型（如 O1）的蒸馏。这个模糊的处理方式在开源社区里很常见，但对复现者和科研者来说，它意味着 SFT 阶段可能隐藏了大量非 RL 的能力提升。事实上，后来包括我的学生的一些研究在内，越来越多文献表明，如果你的基础模型足够强，并且在正确的长思维链数据上做 SFT，你就能解锁绝大多数长推理能力，甚至可能不需要 RL。RL 的独特价值在于自我生成的监督信号，而一旦某种长思维链被别人生成并公开，学生模型可以通过模仿学习获得大量能力。这也是 R1 自己做的蒸馏实验：把 R1 的思维链放入 Qwen 2.5 或 Llama 系列，你就能显著提升它们的推理能力。

## Kimi K1.5：不同的路径，同样的收敛

Kimi K1.5 是同时期的另一个重量级模型。它的技术报告在多个维度上极具价值。首先，他们给出了一个非常不同的算法推导路径——从 DPO 风格的推导出发，最终得到的更新规则却惊人地相似。

具体来说，他们从最大化期望奖励加 KL 正则项出发，解出最优的奖励模型及其策略比率，然后把目标函数转化为一种平方损失形式。对损失求梯度后，你得到的其实就是一个组均值归一化的策略梯度，外加一个 KL 正则项。这跟 GRPO 的结论一样，但走了完全不同的路径。这个事实非常有意思：它说明组均值归一化基线这个东西，可能不是一个特定算法特有的魔法，而是这类 RL 问题的自然产物，无论从哪个方向开始推导，你都会回到这里。

Kimi 还有一个比 DeepSeek 更明确的观点：长思维链不是免费的，甚至是有害的。推理成本是实际部署中的巨额开销。如果你贩卖订阅服务，而模型一次思考一小时，这对你的商业模型是不利的。因此 Kimi 在目标函数中加入了针对长度的启发式奖励，推动模型压缩思维链长度，而且做得相当巧妙：他们不是惩罚所有长序列，而是让错误答案的思维链必须短于平均水平，正确答案可以适当长一点——但也要尽量压缩。这样就不会导致一个关键问题：如果你把错误答案的思维链压到零，模型就再也不可能从那些错误中恢复过来，因为你根本没有正面的学习信号了。

Kimi 在数据层面的处理同样值得借鉴。他们做了中等难度过滤——如果一个问题在 best-of-8 采样下模型已经能答对，那就不是一个好的 RL 训练样本，因为模型已经掌握了它，再学也不会有什么进步。同时，他们也放弃了太难的问题，因为完全没有奖励信号就没法学。这个中间范围的课程想法，是 RLVR 一个非常重要的实操准则。

此外，他们还呈现了 RL 基础设施的复杂度：rollout 可能很长，有些是黎曼猜想级别的难题，一个长 rollout 拖住整个训练流程，如何做截断、如何切换框架、如何在训练和推理之间共享权重，都是非常硬核的系统问题。而且，他们展示了一个关键的对比：真正的强化学习（RL）在最终性能上持续超越专家迭代（expert iteration，即只在正确答案数据上做 SFT）。这意味着，当你想从模型中压出最后的能力上限，你无法回避真实的 RL。

## Qwen 3：从 SFT 到 RLVR 到成熟的系统化流程

Qwen 3 的技术报告更接近一个工业系统总览。它的流程也遵循了后训练的标准模板：预训练 → SFT → 推理强化学习 → RLHF → 蒸馏小模型。他们吸取了 DeepSeek 和 Kimi 两家的大量实践经验，包括难度过滤、去除无需推理即可解决的题目、数据去污染、对参考思维链做人工过滤等等。

最让我惊讶的一点是，他们在推理 RLVR 阶段只用了 4000 个样本。这说明 RLVR 在你拥有良好基础模型和干净奖励函数时，需要的样本量并不大。真正重要的还是数据质量和目标函数的正确性。

Qwen 3 还提供了一个独特的“思考模式”功能，即模型既可以长思维链推理，也可以即时响应。这实际上是通过一个标签来实现的，同一套权重既支持长思考也支持短回答，无论你是否思考，都可以在一个模型内完成。更妙的是，他们实现了“提前终止思考”的机制，即在任意中间 token 处停止思维链并强制要求模型回答。令人惊讶的是，在低思考预算下，即使模型在思考中途被截断，其应对数学或编程任务的能力依然明显优于非思考模式。这说明长 COT 训练使模型在思考较浅的阶段就已具备更强的信息利用能力。

Qwen 3 的消融也显示，融合思考和非思考模式会带来一些领域性能的小幅下降，比如数学和编程。我认为这正是他们在 Qwen 3.5 系列中把两个模式分为不同模型的原因——用户需要极致推理时，你不想为融合付出任何性能代价。

## Qwen3-Coder-Next：智能体 RLVR 的深度解剖

最后，课程进入了 Qwen3-Coder-Next（代码智能体后训练前沿）的细节。这份报告的价值在于它展示了智能体（agent）后训练的所有秘密。核心遵循着整个课程的一贯信条：数据胜于一切。

他们从“中期训练”（mid-training）开始，通过拼接代码仓库、构造长上下文数据、把 Pull Request 与 RAG 合成上下文混合进来、自动生成 Markdown 文档，来注入大量编码和智能体能力。这些数据被模型用来模拟真实的编码环境：打开多个文件、解析错误、修改代码。他们还训练了多个“专家模型”——网页开发、UX 工具使用、软件工程、QA 等——然后把这些专家模型蒸馏回同一个最终模型中。这个做法很有趣，因为它某种程度上回到了“分支训练合并”的学术风格，而不是传统的多任务联合训练。

在软件工程智能体的 RL 环节，他们建立了一个庞大的 GitHub 环境。真正的亮点在于对抗性奖励设计：模型太容易学会绕过检查了。举个例子，在 Git 历史中如果有未来的提交，模型可以直接查看 commit 知道修复方案，从而作弊。他们的奖励函数几乎专门为了阻止这种作弊而设计。如果你不这么做，曲线就会像右边那张图一样：训练平淡，然后突现一个跳跃——那是模型学会了操纵 Git 历史。甚至在你禁止使用 git log 时，它还可以通过添加远程仓库（origin）来查询提交记录。所以你看，所谓“可验证”的环境也是一样脆弱的。我们在 Lean 上做 RL 时也天真地以为那个形式化系统坚不可摧，结果发现 Lean 编译器在某些罕见模式下都能被对抗性样例攻破。因此，RLVR 的稳健性就是你的奖励的稳健性——这才是它真正的核心瓶颈。

即使如此，他们在这套环境上训练出的模型，在 SWE-bench 上达到了约 70.6% 的准确率，而模型只有 30 亿活跃参数（active parameters），非常惊人。不过，我们需要冷静看待单任务指标，它并不代表全知全能的泛化能力。

## 结语：从 Algorithm 到 System，再到 Rewards

整个课程走到这里，你已经看到了一个完整的技术脉络：预训练是基础，也是所有能力之源；之后指令微调让你获得对话和格式能力；RLHF 让输出贴合人类偏好，但受限于偏好标注的规模；而 RLVR 则在可验证问题里彻底释放强化学习的能量——它使你能在数学、代码甚至智能体任务上无限制地增加算力，只要你相信你的奖励是干净且不可攻破的。

这个讲座的核心要务是让你掌握 GRPO。它的函数形式、更新规则、实现方式，应该刻进你的肌肉记忆，就像预训练损失一样熟悉。GRPO 的意义在于它让 RLVR 变得足够简单，以至于从一个“只有大厂才能玩得动”的方向，变成了一个任何人都可以在作业中复现、在实验室里迭代的标准工具。

与此同时，你必须认识到 RLVR 现在的挑战已经不是核心算法——方法大家都已经知道怎么用了，而是工程。它挑剔、有噪声、跟基础设施耦合紧密，但它的难是有边界的，不像在机器人领域做 PPO 那样无边无际。

最终，我们的目光还是要回到奖励。RLVR 的一切都建立在“你的奖励是正确的”这一假设之上。无论是数学答案等价性检查器的复杂设计，还是 Git 历史反作弊，或者 Lean 可验证环境里的隐藏漏洞，都在提醒我们一个事实：可验证奖励不是一个理论完美的概念，而是一个需要永不停歇地攻击和修补的工程对象。但正因如此，它才如此有吸引力——它把强化学习的价值和潜力真正地、一次又一次地展现在我们面前。
