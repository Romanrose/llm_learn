## 一、并行化的动机与硬件背景

### 1.1 两个核心瓶颈

并行化要解决两个问题：

- **算力不足**：单个 GPU 无法提供训练大模型所需算力。
- **内存不足**：模型参数、优化器状态、梯度与激活值无法放入单卡显存。

### 1.2 节点内 vs. 节点间

- **节点内（intranode）**：GPU 间通过高速互联（如 NVLink）连接，通信开销低，可承受频繁通信的并行策略。
- **节点间（internode）**：通过网络（如 InfiniBand）连接，速度较慢，应选择通信量小、模式规则的并行策略。

### 1.3 TPU 与 GPU 的硬件哲学差异

- **TPU**：采用环形网格（toroidal mesh）拓扑，每个芯片只与邻居通信，邻居数量恒定，可无限扩展且成本低。适合通信模式固定、规则的工作负载（如稠密模型的张量并行）。
- **GPU**：采用胖树（fat-tree）拓扑，支持全对全通信，灵活性高。适合通信模式不确定的工作负载（如 MoE 的 token 路由）。
- **趋同趋势**：现代工作负载（如 MoE）越来越需要全对全能力，新的 TPU 设计也在向更接近 GPU 的交换网络靠拢。

**结论**：硬件的通信拓扑直接影响并行策略的选择，不同的工作负载应匹配不同的硬件。

## 二、集合通信原语回顾

### 2.1 关键原语

- **all-reduce**：所有 GPU 的梯度求和后广播给所有人。
- **reduce-scatter**：将各 GPU 的梯度按索引分块求和，每个 GPU 只持有自己负责的那一块。
- **all-gather**：收集所有 GPU 持有的分块数据，拼接成完整向量。

### 2.2 关键恒等式（本讲反复使用）

```
all-reduce = reduce-scatter + all-gather
```

该恒等式意味着：如果某种并行策略的通信量可以表达为 reduce-scatter 加 all-gather，那么它的通信成本与一次 all-reduce 完全相同——即“免费”实现内存节省。

## 三、数据并行与 ZeRO

### 3.1 朴素数据并行（DDP）

将批次 B 切分为 M 份，分别送入 M 个 GPU，各自计算梯度后做一次 all-reduce 同步。

- **计算扩展**：理想，只要每个 GPU 上有足够样本。
- **通信成本**：每个批次需通信 2 倍参数量。
- **内存扩展**：完全无节省——每个 GPU 持有完整模型副本。

### 3.2 内存核算：为什么 DDP 糟糕

每个训练步骤需要存储：

- **模型参数**（权重本身）
- **梯度**（更新前的累加器）
- **优化器状态**（SGD 的高精度累加器；Adam 的一阶矩 + 二阶矩，通常需高精度存储）

粗略经验法则：每参数约需 **16 字节**存储（约为 5 份权重复制）。其中优化器状态占大头，是内存消耗的主因。

### 3.3 ZeRO 三个阶段

| 阶段 | 分片内容 | 通信成本 | 内存节省 |
|------|---------|---------|---------|
| 1 | 优化器状态 | 与 DDP 相同（零额外成本） | 优化器状态除以 GPU 数 |
| 2 | 优化器状态 + 梯度 | 与 DDP 相同（零额外成本） | 上述两者均分片 |
| 3（FSDP） | 优化器状态 + 梯度 + 参数 | 略多于 DDP（多一次 all-gather） | 三者均分片 |

### 3.4 ZeRO-1 与 ZeRO-2 为何“免费”

- **ZeRO-1**：每个 worker 只负责更新参数的一个切片。先对梯度做 reduce-scatter（分发到各 GPU 的更新对应部分），各 GPU 完成本地更新后，再对更新后的参数做 all-gather。两个操作之和等价于一次 all-reduce，通信成本与 DDP 相同。
- **ZeRO-2**：在反向传播时**增量**计算梯度——每算完一层的梯度立即做 reduce 并发送给对应 worker，然后释放该梯度。通信总量不变，但无需物化完整梯度向量。

### 3.5 ZeRO-3 / FSDP：按需抓取参数

FSDP 的关键机制：

- 前向：逐层 all-gather 该层权重 → 计算 → 释放权重。
- 反向：逐层 all-gather 权重 → 计算梯度 → reduce-scatter 梯度 → 释放权重。
- 更新：每张卡更新自己持有的参数切片。

**两个关键设计**：

1. **沿计算图扫描**：通信紧贴计算发生，用完立即释放内存。
2. **通信与计算重叠（overlap）**：在前向计算第 k 层的同时，预取第 k+1 层参数。若计算量足够大且网络足够快，FSDP 可实现近乎零额外开销。

**注意**：FSDP 中每个 GPU 都遍历整个模型（与流水线并行不同，不是按层切分）。

### 3.6 FSDP 的局限

- 不能减少**激活值**内存——这在长序列任务中往往是主要瓶颈。
- 并行度受限于**全局批次大小**：如果批次大小为 8，最多只能使用 8 个 GPU。

## 四、模型并行：切分层与矩阵

### 4.1 核心区别：从通信参数到通信激活值

- **FSDP / 数据并行**：通信的是参数（权重），计算本身是单 GPU 的完整前向/反向。
- **模型并行**：通信的是**激活值**——各层分布在不同的 GPU 上，GPU 间传递的是层间的中间结果。

### 4.2 流水线并行（Pipeline Parallelism）

**概念**：按层切分模型，不同层放在不同 GPU 上，前向传播时激活值逐层传递，反向传播时梯度逐层回传。

**问题——Bubble**：朴素实现中，任意时刻只有一个 GPU 在计算，其他 GPU 全部空闲。利用率极低。

**解决——微批次（micro-batch）流水线**：将批次切分为多个微批次，第一个微批次算完第 0 层后立即交给第 1 层，同时第 0 层开始处理第二个微批次。利用率 ≈ 1 - (阶段数 / 微批次数量)。

**通信特性**：仅做**点对点**通信，数据量为 b × s × h（批次 × 序列长度 × 隐藏维度），远小于通信完整参数矩阵。这是所有模型并行策略中通信最温和的。

**实践建议**：流水线并行最常用于**慢速链路**（如跨数据中心、跨 Pod），因为它的通信模式最温和。

**“零气泡”（ZeroBubble）思想**：在反向传播中，有两件事必须做——(a) 将偏导数向计算图深处传播（必须尽快完成），(b) 计算当前权重的梯度（可以随时完成）。将两者解耦：优先做 (a)，把 (b) 推迟到计算间隙执行，可几乎完全填满流水线。

### 4.3 张量并行（Tensor Parallelism）

**概念**：沿宽度维度切分矩阵乘法。MLP 的输入投影按**列切分**，输出投影按**行切分**；注意力同理。层归一化、dropout、路由器等小操作**完全复制**到每张卡上。

**前向/反向对偶性**：

- 前向：输入复制（f = identity），输出做 all-reduce（g = all-reduce）。
- 反向：对偶——g 变 identity，f 变加法（偏导数需要累加）。

**通信代价**：每次矩阵乘法后都需要一次 all-reduce，通信量约为 2 × b × s × h，且是**全局**通信。因此张量并行**只能在节点内（约 8 张卡）使用**，跨节点性能急剧下降。

**与 TPU 的关系**：TPU 的环形网格天然适合高带宽、规则通信的张量并行，因此 TPU 上可以做到更大的张量并行度；GPU 上张量并行超过 8 后性能下降明显。

### 4.4 激活值内存的精确核算

**基础经验公式**（存储所有中间结果时）：

```
激活值 ≈ 34 × s × b × h + 5 × a_s / h
```

- 34 项中，MLP 占 24，注意力占 10。
- 第二项来自注意力 softmax 的 dropout，可通过 Flash Attention + 重计算消除。

**张量并行的效果**：

- MLP 与注意力部分除以张量并行度 t：✓ 可扩展
- 残差输入、层归一化输入等不随 t 缩减：✗ 固定项（约 10 × s × b × h）

**序列并行（Sequence Parallelism）**：将剩余的不随张量并行缩减的项沿**序列轴**分片存储。需要时 all-gather，用完 release。这与 FSDP 的思路一致（分片存储、按需物化），前向的 all-gather 在反向中变为 reduce-scatter。

**激活内存下限公式**：

```
激活值下限 ≈ 34 × s × b × h / t  （t = 张量并行度，配合激活重计算）
```

此公式可用于快速估算模型能否装入单卡。

## 五、专家并行（Expert Parallelism）

### 5.1 基本思想

将 MoE 的 FFN（专家）分布到不同设备。与前几种策略类似，专家并行也属于模型并行家族——切分 MLP 而不切分注意力。

### 5.2 与张量并行的比较

**优先选择专家并行而非张量并行**（Megatron 官方指南）：

- 张量并行把矩阵切小，降低 GPU 利用率。
- MoE 的 token 路由天然稀疏，专家并行可以精确路由，避免无谓计算。
- 专家并行同样能减少激活内存。

**代价**：专家并行需要大量**全对全通信**，延迟极其敏感。工程实现非常复杂（如 DeepSeek 的 DPP 库甚至使用了未公开的 PTX 指令来优化网络通信）。

### 5.3 关键约束：DP 与 EP 的耦合

朴素实现中，EP 的副本与 DP 的副本相同——即 EP 是 DP 切分的子集。这限制了 EP 可扩展的最大并行度。

### 5.4 注意力层与 MLP 层的张量并行冲突

- 注意力层需要较高的张量并行度才能有效切分。
- MLP 层如果张量并行度过高，矩阵被切得太碎，利用率下降。
- 现代系统将注意力层的张量并行与 MoE 层的张量并行**解耦**，分别独立设定。

## 六、上下文并行（Context Parallelism）

将长序列的激活值沿序列维度拆分到多个加速器，采用环形传递方式。主要用于长上下文扩展阶段和推理服务。与序列并行不同，它是独立于张量并行的并行原语，多用于 TPU 等具备环形拓扑的硬件。

## 七、并行策略总览与组合原则

### 7.1 各策略的局限总结

| 策略 | 优点 | 局限性 |
|------|------|--------|
| FSDP / ZeRO-3 | 内存节省大、通信可重叠 | 不省激活值；受全局批次大小限制 |
| 流水线并行 | 通信最小、适合慢链路 | 气泡开销大、依赖批次大小 |
| 张量并行 | 无气泡、省激活值 | 通信量大、只能节点内用 |
| 专家并行 | 省激活值、适合 MoE | 全对全通信延迟敏感、工程复杂 |
| 上下文并行 | 处理超长序列 | 需要专门硬件拓扑支持 |

### 7.2 实用组合策略（简单的经验法则）

两层策略：

1. **装进内存**：先用张量/专家并行处理快速互联（每机 8 卡），再用流水线或 FSDP 处理慢速互联。

2. **充分利用算力**：模型装下后，剩余 GPU 全部用于数据并行。批次太小时用梯度累积弥补。

**优先级顺序**（从高到低）：

1. 最小化模型并行，最大化数据并行。
2. GPU 上保持张量/专家并行在节点内（NVLink 范围）。
3. 跨节点用流水线并行。
4. MoE 模型优先使用专家并行。
5. 长序列使用上下文并行（环形注意力）。

### 7.3 性能分析框架

对给定模型和并行配置，计算每层的计算量与通信量，绘制“计算时间 / 通信时间”图表。只要计算时间 > 通信时间，通信就可被完全隐藏，GPU 利用率达到 100%。策略选择的目标是：在不同批次大小下都保持计算受限。

## 八、实践案例

- **Olmo（7B 稠密）**：纯 FSDP 训练。小模型规模下 FSDP 扩展性良好。
- **DeepSeek V1**：数据并行 + ZeRO-1 + 张量并行 + 序列并行 + 流水线并行。
- **DeepSeek V3**：MoE 模型，用大规模专家并行（64 路）替代部分张量并行，结合流水线技巧避免气泡。
- **Yi**：数据并行 + 张量并行 + 流水线并行（经典组合）。
- **Llama 3 405B**：预训练阶段为 TP=8 + CP=1 + PP=16 + DP=128；长上下文阶段将 CP 提升、DP 降低。
- **Gamma 2**：仅用 FSDP + 张量并行 + 序列并行，无流水线（利用 TPU 大网格拓扑）。
- **Mixtral 8x22B**：EP=8 + PP=4 + TP=4（用于注意力层）。
- **Qwen 3**：EP=32 + PP=8 + TP=2。

**共性规律**：

- 数据并行最大程度使用。
- 张量并行不超过 8（GPU 环境）。
- 专家并行可做大（受 MoE 工作负载影响，DeepSeek 推动了大专家并行规模）。

## 常见误区

1. **认为 FSDP 省一切内存**：FSDP 不省激活值，长序列场景下激活值才是主要瓶颈。
2. **混淆序列并行与上下文并行**：序列并行是张量并行的附属（切序列分片存储，目的是省激活值）；上下文并行是处理超长序列的独立并行策略。
3. **认为流水线并行的气泡可以忽略**：气泡随微批次数量下降，需要足够大的批次才有效率。
4. **在节点间使用张量并行**：超出 8 张卡范围，通信开销急剧上升。
5. **混淆 all-reduce 与 reduce-scatter + all-gather 的成本**：二者等价，这是 ZeRO-1/2 免费的关键。
6. **认为专家并行可无限扩展**：EP 的扩展受限于 DP 切分结构，且全对全通信延迟极难优化。
7. **忽视上下文并行在长上下文阶段的作用**：模型服务与长上下文扩展中，上下文并行是必需的。
