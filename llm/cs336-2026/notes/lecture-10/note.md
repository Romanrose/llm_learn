## 课程主线

本讲围绕一个核心问题展开：**如何让已训练好的模型尽可能快、尽可能准确地生成输出？**

课程从推理效率的重要性出发，依次展开以下内容：

3. **有损优化技术**——通过减少 KV 缓存、量化、剪枝等降低推理成本
4. **无损优化技术**——投机采样（speculative sampling）保证采样质量的同时加速推理
5. **动态工作负载处理**——面向真实服务场景的连续批处理和分页注意力

## 第一部分：推理工作负载的数学分析

### 推理的重要性

推理（inference）在多个场景中都有重要应用：

- **实际使用**：聊天机器人、代码补全、智能体（agents）、批量数据处理
- **模型评估**：特别是需要生成式输出的评估任务
- **强化学习**：生成轨迹（trajectories）后进行评分并更新权重

**关键观察**：训练是一次性成本，而推理是重复性成本。推理 token 的消耗量可以达到惊人的规模。更重要的是，随着智能体时代的到来，大部分生成的 token 并非供人类阅读，而是用于模型自身的思考、工具调用和反思过程，因此推理的算力消耗没有自然的上限。

### 推理与训练的根本差异

**训练（以监督微调为例）**：可以一次性看到所有 token，并在序列维度上并行化。在 Transformer 中，注意力、MLP 的计算都将序列作为一个维度处理，因此可以一次性处理所有 token。

**推理**：由于自回归（autoregressive）特性，必须顺序生成 token，无法在序列维度上并行化。这使得获得高计算强度（compute intensity）或充分利用算力变得更加困难。

### 符号约定

本讲采用类似 einops 的图示符号来表示张量维度：

- **B**：批次维度（batch），也代表序列数量
- **T / S**：序列维度（sequence），也代表 token 数量。S 代表输入 token 数（条件 token），T 代表输出 token 数（生成 token）
- **D**：模型维度（model dimension）
- **F**：MLP 投影维度，约定 F = 4D
- **N**：查询头数量（query heads）
- **K**：键/值头数量（key/value heads），也是 GQA 中的组数
- **H**：每个头的维度（head dimension），D = N × H
- **L**：层数（layers）
- **V**：词表大小（vocabulary size）

**维度符号规则**：
- **红色（contracting）**：同时出现在两个操作数中，从结果中消失（被收缩）
- **黑色（regular）**：只出现在一个操作数中，保留在结果中
- **蓝色（attaching / batching）**：同时出现在两个操作数中，保留在结果中

### 算术强度（Arithmetic Intensity）回顾

**算术强度** = 浮点运算次数（FLOPs）/ 传输字节数（bytes transferred）

目标是让算术强度尽可能高。

以矩阵乘法 X(B×D) @ W(D×F) 为例：

**内存读写**：
- 读取 X（B×D）：2BD 字节（bf16 格式）
- 读取 W（D×F）：2DF 字节
- 写入 Y（B×F）：2BF 字节

**FLOPs**：2BDF

**算术强度** = 2BDF / (2BD + 2DF + 2BF)

假设 B 远小于 D 和 F，强度简化为 **B**。

**加速器强度**（accelerator intensity）= 每秒 FLOPs / 内存带宽。

对于 H100：加速器强度约 295。这意味着：
- 算术强度 > 295 → **计算受限**（compute-bound），好
- 算术强度 < 295 → **内存受限**（memory-bound），差

**极端情况**：B = 1 时（矩阵向量乘法），算术强度 = 1，属于内存受限。这正是推理中常见的场景。

### KV 缓存（KV Cache）

**朴素推理**：每次生成一个 token，把整个历史序列重新喂给模型。每次前向传播的复杂度是 O(T²)，生成 T 个 token 总复杂度为 O(T³)。

**关键观察**：由于因果（causal）Transformer 的激活只依赖过去的 token，前缀的计算可以在多次生成之间共享。因此，将计算出的键（keys）和值（values）存储在 HBM 中，称为 **KV 缓存**。

**KV 缓存结构**：对于每个序列（B）、每个 token（S）、每一层（L）、每个 KV 头（K），存储一个 H 维向量。每个 token 需要存储 key 和 value 两个向量。

**推理的两个阶段**：

1. **预填充（Prefill）**：给定提示词，并行编码所有 token，计算并填充 KV 缓存。这类似训练，可以并行化。
2. **生成（Generation）**：顺序生成新的响应 token，每个 step 只生成一个 token。

### MLP 层的算术强度分析

**内存读写**（仅关注矩阵乘法）：
- 读取 X（B×T×D）：2BTD
- 读取 Wup、Wgate、Wdown（各 D×F）：3 × 2DF
- 写入 U（B×T×F）：2BTF
- 写入 G（B×T×F）：2BTF
- 写入 Y（B×T×D）：2BTD

**FLOPs**：6BTDF（上投影、门控、下投影各 2BTDF）

**算术强度** = 6BTDF / (4BTD + 4BTF + 6DF)

假设 BT 远小于 D 和 F，强度简化为 **BT**。

**结论**：
- **预填充阶段**：BT 可以很大（大批次、长序列），容易达到计算受限
- **生成阶段**：T = 1，强度降为 B。B 代表并发请求数，对于交互式应用不可预测且可能很低

### 注意力层的算术强度分析

**内存读写**：
- 读取 Q（B×T×D）、K（B×S×D）、V（B×S×D）：2BTD + 4BSD
- 写入 Y（B×T×D）：2BTD

**FLOPs**：4BSTD（QK^T 和 softmax(A)@V 各 2BSTD）

**算术强度** = ST/(S+T)

**关键观察**：**强度不依赖 B**！

**预填充阶段**（T = S）：强度 = S/2，还不错。

**生成阶段**（T = 1）：强度 = S/(S+1) < 1，很差。

**为什么批次大小对注意力没有帮助？**

- **MLP**：所有序列共享相同的 MLP 权重。增加 B 只需要加载一次权重，就能处理所有序列，因此算术强度随 B 提高。
- **注意力**：每个序列有自己的 KV 缓存（Q、K、V 都依赖 B）。增加 B 相当于给每个序列做独立的矩阵向量乘法，并不能分摊参数加载成本。

**总结**：
| 组件 | 预填充强度 | 生成强度 |
|------|-----------|---------|
| MLP | B×S（很好） | B（需要并发请求） |
| 注意力 | S/2（可用） | <1（根本瓶颈） |

**核心结论**：预填充是计算受限的，生成是内存受限的。生成阶段的注意力是 Transformer 推理的根本性瓶颈。

## 第二部分：延迟与吞吐量

### 推理性能指标

1. **首 token 延迟（TTFT，Time-to-First-Token）**：用户从提交查询到收到第一个 token 的等待时间。对交互式应用很重要。
2. **延迟（Latency，秒/token）**：单个查询中 token 流式输出的速度。对交互式应用重要。
3. **吞吐量（Throughput，tokens/秒）**：多个查询整体上 token 产生的速度。对批处理任务重要。

**关键洞察**：推理是内存受限的，因此延迟和吞吐量主要由需要传输的内存量决定。假设计算和通信可以完美重叠，瓶颈就是内存 I/O。

### 实例：Llama 2 13B 在 H100 上的性能分析

**模型配置**：S=1024，D=5120，F=13824，N=40，K=40（MHA），H=128，L=40，V=32000

**参数数量**：约 130 亿参数，与宣称一致

**内存占用**：
- 参数（bf16）：约 26 GB
- KV 缓存（每个序列）：2 × S × K × H × L × 2 字节
- 总内存 = B × KV缓存每序列大小 + 参数大小，是 B 的线性函数

**延迟** = 总内存 / 内存带宽

**吞吐量** = B / 延迟

**关键结果**：

| 批次大小 B | 延迟（秒/token） | 吞吐量（tokens/秒） | 说明 |
|-----------|----------------|-------------------|------|
| 1 | 0.008 | 124 | 最低延迟 |
| 64 | 增加 | 增加 | 延迟变差，吞吐量改善 |
| 256 | 进一步增加 | 进一步增加 | 内存溢出（超过 80GB H100 内存） |

**增加批次大小的效果**：
- **延迟变差**：KV 缓存随 B 线性增长，需要读写更大的内存
- **吞吐量改善**：参数加载成本在更大批次中分摊
- **收益递减**：吞吐量渐近于某个上限，且最终受限于内存容量

**延迟与吞吐量的权衡**：
- 小批次 → 更好延迟，更差吞吐量
- 大批次 → 更好吞吐量，更差延迟

**实际含义**：
- TTFT 本质上由预填充时间决定。想要更快的 TTFT，应使用较小批次；想要更高吞吐量，应使用较大批次
- 简单并行化：启动 M 个模型副本，延迟不变，吞吐量增加 M 倍

## 第三部分：有损优化——减少 KV 缓存

### 为什么减少 KV 缓存很重要

推理受内存限制，而 KV 缓存占据大量内存（大批次时甚至可能超过参数大小）。减少 KV 缓存大小可直接转化为延迟和吞吐量的提升。关键是**在减少内存的同时不损失太多精度**。

### 分组查询注意力（GQA，Grouped-Query Attention）

**背景**：
- 多头注意力（MHA）：每个 token 有 N 个查询头，每个头有对应的 key 和 value（K = N）
- 多查询注意力（MQA）：K = 1，所有查询头共享一组 KV，效果很差
- 分组查询注意力（GQA）：K 介于 1 和 N 之间，每个 KV 头服务 N/K 个查询头

**效果**：KV 缓存减少因子 N/K

**验证**：在 Llama 2 13B 配置中，将 K 从 40 降为 8（1:5 稀疏度）：
- 延迟和吞吐量都得到改善（减少内存使用同时改善两者）
- 之前批次 256 会内存溢出，现在可以放入内存

**精度影响**：GQA 论文显示在多种评估中表现良好，但应持保留态度——DeepSeek 论文表明 GQA 实际有精度损失。

### 多潜变量注意力（MLA，Multi-head Latent Attention）

**核心思想**：不是直接存储 K 和 V，而是将激活压缩到低维潜空间，需要时再投影回来。

**实现方式**：
- 正常注意力：K = W_K·h，V = W_V·h，维度为 N×H
- MLA：存储压缩向量 c = W_c·h（C 维），需要时计算 K = W_K·c，V = W_V·c
- DeepSeek-V2：将 16384 维压缩到 512 维（+64 维用于 RoPE 兼容，总计 576）

**注意**：MLA 与 RoPE 不兼容，需要添加额外维度处理。

**精度**：MLA 比 MHA 略好（且更便宜），而 MHA 优于 GQA。这意味着"越激进压缩不一定越差"，关键在于压缩方式。

### 跨层注意力（CLA，Cross-Layer Attention）

**核心思想**：像 GQA 在头之间共享 KV 一样，在层之间共享 KV。只为一小部分层计算 KV，其他层直接使用相邻层的 KV。

**效果**：经验上改善精度与 KV 缓存大小的帕累托前沿。

### 局部（滑动窗口）注意力

**核心思想**：生成 token 时只看最后 K 个 token，而非全部历史。

**优势**：
- KV 缓存独立于序列长度（只依赖批次大小和其他变量）
- 有效上下文长度可随层数线性增长

**问题**：损害精度，降低表达能力。

**改进方案**：将局部注意力与全局注意力交错（混合模型），在部分层使用完整注意力，其余层使用局部注意力。

### 线性注意力与状态空间模型

不是存储 KV 缓存，而是将整个历史压缩为某种表示（如状态向量）。包括：
- 朴素线性注意力：将 KV 值求和为单一向量
- 门控网络（gated nets）、delta 网络（delta nets）、Mamba 等更复杂的压缩方法

**权衡**：线性注意力对长上下文的整体总结更高效，但会丢失细节。对于"大海捞针"式检索，滑动窗口注意力可能更好。可组合使用不同类型的注意力以捕捉不同方面。

### DeepSeek 稀疏注意力

- **压缩稀疏注意力（CSA）**：每 M 个 token 压缩为 1 个
- **DeepSeek 稀疏注意力（DSA）**：选择保留 token 子集（通过计算轻量级注意力分数确定）
- **重度压缩注意力（HCA）**：进一步压缩

## 第四部分：有损优化——量化与剪枝

### 量化（Quantization）

**核心思想**：降低数字精度，减少内存占用，从而提升延迟和吞吐量。

**精度选择**：
- fp32（4 字节）：训练时参数和优化器状态
- bf16（2 字节）：推理默认
- fp8（1 字节）：H100 支持，可以训练但需谨慎
- int8（1 字节）：便宜但精度较低，仅推理
- int4（0.5 字节）：更便宜，精度更低

**量化感知训练（QAT，Quantization-Aware Training）**：
- 训练前向传播中模拟量化和反量化，让权重适应量化误差
- 优点：效果更好；缺点：需要昂贵的大规模训练

**训练后量化（PTQ，Post-Training Quantization）**：
- 训练完成后进行，成本低
- 简单方法：对每层或张量确定缩放因子和零点
- **GPTQ**：利用 Hessian 信息逐层量化，跟踪误差并传播到未量化权重中

**激活感知量化（AWQ，Activation-aware Weight Quantization）**：
- 观察：某些激活通道值较大，与其交互的权重更重要
- 方法：基于激活为少数重要通道分配更高精度
- 效果：fp16 到 int3 降低 4 倍内存，3.2 倍加速

### 模型剪枝（Model Pruning）

**核心思想**：移除模型中不重要的部分，然后修复它。

**算法**：
1. 在小的校准集（约 1024 样本）上估计不同组件（层、头、隐藏维度）的重要性
2. 移除不重要的部分，得到更小的模型
3. 将原始模型蒸馏到剪枝后的模型中

**效果**：可将 15B 模型剪到 8B，精度损失不大，训练成本远低于从头训练。

## 第五部分：投机采样（Speculative Sampling）

### 核心洞察

预填充（同时编码所有 token）比生成（一次一个 token）快得多。**"检查"比"生成"更快**——给定一个序列评估它比逐步生成快得多。

### 算法

1. 使用廉价的**草稿模型**（draft model）p 猜测 K 个 token
2. 使用目标模型 q 并行计算这些 token 的对数几率
3. 以概率 min(1, q/p) 接受每个 token
4. 拒绝时从残差分布采样，然后退出

**关键性质**：保证从目标模型中精确采样（无损）！

**简要证明**（两元素词表例）：
- 假设 p(A) > q(A)，则 p(B) < q(B)
- P[采样 A] = p(A)·(q(A)/p(A)) + p(B)·1·0 = q(A)
- P[采样 B] = p(B)·1 + p(A)·(1 - q(A)/p(A))·1 = q(B)

### 性能与调优

- 草稿 token 数太少：无法充分利用目标模型的批处理能力
- 草稿 token 数太多：被拒绝概率增加
- 最佳值通常约 3-4 个 token
- 草稿模型应尽量接近目标模型（通过蒸馏）

### 扩展

- **Medusa**：草稿模型并行生成多个 token
- **EAGLE**：草稿模型利用目标模型的高层特征

**实用观点**：你在减少 KV 缓存方面的所有努力都可以用于构建更好的草稿模型——如果模型好到可以直接服务，就不需要投机采样；否则可以作为投机采样的草稿模型。

## 第六部分：动态工作负载处理

### 问题描述

实时网站场景：请求在不同时间到达，具有共享前缀和不同长度，远不同于训练中整齐划一的 token 块。

### 连续批处理（Continuous Batching）

**问题**：静态批处理等待慢请求，浪费算力。

**方案（Orca 系统引入）**：
- 迭代级调度：每一步为所有序列解码一个 token
- 序列完成时从批次移除
- 新请求到达时加入批次

**选择性批处理**：处理不同序列长度时的策略：
- 注意力计算：因长度不同无法有效共享张量，分别处理
- 非注意力部分（如 MLP，占大量 FLOPs）：拼接所有序列为一个大序列处理

### 分页注意力（PagedAttention）

**问题**：KV 缓存的碎片化：
- **内部碎片化**：为最大 token 长度（如 1024）分配连续内存，但实际生成更短，浪费空间
- **外部碎片化**：不同序列之间的空隙太小，无法有效利用

**方案**（借鉴操作系统分页）：
- 将序列的 KV 缓存划分为非连续块（blocks）
- 通过索引跟踪块的位置
- 块级对齐保证统一性

**共享机制**：
- 系统提示词可缓存一次，多个查询共享
- 多个生成（如程序合成中多个候选响应）可共享前缀 KV 缓存
- **写时复制（copy-on-write）语义**：采样到相同 token 时继续共享，分叉时拆分块

**其他优化**：
- 融合块读取和注意力的内核
- 使用最新内核（FlashAttention、FlashDecoding）
- CUDA graphs 避免内核启动开销

## 常见误区

1. **"推理和训练差不多快"**——错。推理因自回归特性无法在序列维度并行化，生成阶段尤其受内存限制。

2. **"增加批次总是更好"**——不一定。增加批次改善吞吐量但恶化延迟，且受内存容量限制。

3. **"GQA 没有精度损失"**——论文中的结论需持保留态度。DeepSeek 论文表明 GQA 实际有精度损失。经验性结果需要具体模型具体验证。

4. **"减少 KV 缓存就是减少模型维度"**——不对。关键是找到模型中可压缩的位置，不加区分地减少一切通常更差。

5. **"投机采样会有损精度"**——不会。投机采样的数学保证它精确采样自目标模型。

6. **"滑动窗口注意力有效上下文只是窗口大小"**——不对。信息可以在层间传播，有效上下文长度随层数线性增长。

7. **"内存受限意味着加速器完全闲置"**——确实让人沮丧，但这是推理的本质特性。

## 课程总结

本讲的中心思想可以概括为：

**推理非常重要**，与训练在计算特性上完全不同。推理受内存限制，生成阶段尤其如此。减少 KV 缓存是提升推理效率的关键方向，可以通过架构设计（GQA、MLA、CLA）、量化、剪枝、投机采样等多种方式实现。同时，面对动态的实时工作负载，需要借鉴操作系统思想（分页、连续批处理）来管理推理资源。

**未来方向**：新架构（状态空间模型、线性注意力、扩散模型）可能在推理效率上有更大潜力，因为注意力机制和 KV 缓存的构建方式从根本上使其对推理不友好。如果能够设计出为推理而生的新架构，或许能解锁更多可能。
