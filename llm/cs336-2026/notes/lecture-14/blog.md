# 数据即命运：从原始语料到高质量训练集的完整流水线

## 导语

在构建大型语言模型的过程中，有一个经常被低估却至关重要的环节：数据。我们往往关注模型架构的创新、训练技巧的突破，却忽略了最基础的问题——模型究竟在什么样的数据上学习？斯坦福大学 CS336 课程的第 14 讲，正是围绕这个核心问题展开的深入探讨。这一讲构建了一个完整的数据处理框架：从原始的网络爬取数据开始，经过格式转换、智能过滤、精确去重，再到多源数据的合理混合，最终抵达如今备受关注的合成数据领域。这是一条从"原始噪音"到"高质量信号"的必经之路，也是决定模型能力上限的关键所在。

## 第一站：数据转化——将混沌变为有序

当我们谈论互联网数据时，一个常见的误解是认为网络内容天然就是文本形式。事实上，无论是 Common Crawl 这样的公开数据集，还是自建的网络爬虫，获取的原始数据几乎都不是干净的文本。它们可能是 HTML 格式的网页、PDF 文档，甚至是代码仓库的目录结构。这种异构的原始数据必须经过一个关键的转化步骤，才能成为语言模型可以理解的序列。

对于占据互联网内容主体的 HTML 文件，处理过程充满了启发式规则。开发者需要编写程序去除网页中的样板内容——那些无处不在的导航栏、广告模块和页脚信息——然后提取出真正的"内容主体"。这个看似简单的任务实际上充满挑战：什么构成"内容"并没有绝对的标准。在某些情况下，导航元素可能反而有助于模型理解网页的结构和功能。更棘手的是，网页中的图片和表格如何处理？这是一个本质上有损的过程：你必须将带有层级结构和视觉布局的 HTML 线性化为一个连续的 token 序列。特别是表格，简单的表格或许可以用 Markdown 格式呈现，但嵌套表格几乎没有完美的解决方案，你必须在某处做出妥协或近似。

这种转换通常采用基于规则的方法，原因很简单：速度。在动辄万亿 token 规模的数据集上，任何复杂的处理都可能成为瓶颈。然而，基于规则的方法必然存在失败率，这也是后续过滤步骤之所以必要的原因之一。但即便有这些不足，基于规则的转换仍然是主流选择，因为纯规则方法的并行化和优化相对成熟。

PDF 的处理则更为特殊。从 FinePDFs 等项目可以看到，PDF 虽然只占互联网内容的一小部分，但其价值密度通常更高——如果有人愿意花精力制作一份 PDF，往往意味着内容本身有其独到之处。但 PDF 的转换面临着独特挑战：文件可能被截断、可能只是扫描件（本质上就是图像）、布局信息与语义结构难以对应。这些问题的解决往往需要更重的工具，比如使用视觉语言模型进行 OCR 识别，成本远高于纯文本处理。但考虑到 PDF 的稀缺性和高质量特性，这笔投入是值得的。

## 第二站：数据过滤——定义何为"优质"

完成格式转换后，我们面对的仍然是一个庞杂的文本集合。这里的核心问题是：如何从中筛选出我们真正想要的内容？课程提出了一个优雅的通用框架：给定目标数据 T 和原始数据 R，目标是找到 R 中与 T 相似的子集。这个框架之所以强大，在于它可以应用于各种不同的过滤需求。

最基础的应用之一是语言识别。Meta 训练了一系列 fastText 语言识别模型，支持 176 种语言，可以直接用于判断文本属于哪种语言。这类任务通常相对简单——几个词就能看出是西班牙语还是日语。但随着语码转换、方言变体和网络用语的普及，这个问题也并非完全解决。不过在大多数场景下，语言识别已经是一个成熟工具。

更复杂的是质量过滤。这里的关键洞察是：**不存在普适的"质量"定义**。质量永远针对具体的训练目标而言。OpenMathText 项目展示了一种针对数学领域的数据筛选策略：先通过规则过滤（是否包含 LaTeX 命令），再用 KenLM 语言模型检查困惑度（基于 ProofPile 数学数据集训练），最后再用 fastText 分类器判断是否为数学写作。这种多层次的筛选策略，使得他们能够从海量 Common Crawl 数据中提取出约 150 亿个数学相关 token。更有说服力的是实验证据：经过这种针对性筛选的模型，其数学能力优于用 20 倍未筛选数据训练的模型。

GPT-3 的过滤策略则是另一种思路：以维基百科、WebText2、书籍等高质量来源作为正样本，以 Common Crawl 采样作为负样本，训练一个线性分类器。LLaMA 的做法略有不同，正样本选择的是**被维基百科页面引用的网页**，而非维基百科本身。这种细微的差别反映了数据选择中的设计智慧。

微软的 phi-1 项目展示了一个更为精妙的过滤流程。他们的原始数据是 The Stack 的 Python 子集，但研究者定义了"教育价值"这个标准，先用 GPT-4 对 10 万个子集样本进行打分，将正样本作为目标集，然后训练一个随机森林分类器来外推评分。这个流程的启示是：你甚至可以用一个昂贵的大模型来定义"优质"，然后训练一个便宜的分类器来大规模应用。实验结果具有说服力：在 HumanEval 上，筛选后的数据仅用 36K 步就超过了未筛选数据 96K 步的性能。

毒性过滤则展示了数据伦理的考量。通过 Jigsaw Toxic Comments 数据集，可以训练分类器识别并过滤掉含有毒性内容的评论。这在多语言模型中尤为重要，因为互联网上确实存在大量令人不适的内容。

但课程的深度不止于此。它提出了一个关键观察：**过滤阈值不存在全局最优解**。这个观点基于一个重要的规模效应：如果你计划训练很短的时间，那么应该使用高质量数据；但如果训练期非常长，低质量数据反而可能更有价值，因为数据池是有限的。一个初步实验清楚地展示了这一点：在小规模训练中，高质量数据的优势明显（损失下降更快）；但随着训练时间的延长，模型开始在高质量数据上重复训练（epoch 数增加），出现过拟合现象，此时低质量数据的表现反而更优。这表明，数据过滤策略必须与训练计划协同设计，任何孤立的"最优阈值"都是不存在的。

## 第三站：去重——消除数据中的幽灵

过滤完成后，数据集中仍然存在大量重复内容。这些重复有两种形式：**完全重复**和**近似重复**。完全重复的成因主要是镜像网站和仓库的 fork——爬虫可能无法智能识别两个域名指向同一份内容。近似重复则更为隐蔽：服务条款和许可证文本几乎相同但分属不同页面、同一篇文章的略微修改版本、模板化生成的低质量内容等。

还有更极端的案例：审计 C4 数据集时发现，一个防毒面具的产品描述竟然出现了 61,000 次。这种数据不仅浪费计算资源，更可能导致模型记忆化，引发版权和隐私问题。

去重面临的根本挑战是**计算复杂度**。与过滤不同（每个文档独立判断，可以线性并行处理），去重本质上是条目间的两两比较，朴素的实现是 O(n²) 复杂度，在互联网规模的数据集上完全不可行。解决方案来自算法社区的几个经典思想。

首先是 **哈希函数**。通过将文档映射为较短的哈希值，可以快速比较文档是否相同。但对于近似重复检测，简单的哈希不够用，我们需要能够度量相似度的哈希方法。这时引入了 **Jaccard 相似度**：两个集合交集大小除以并集大小，得到 0 到 1 之间的相似度分数。关键在于，我们需要一种能够在**线性时间内**找到高 Jaccard 相似度配对的方法。

答案就是 **MinHash**。这种随机哈希函数的巧妙之处在于：两个集合的哈希值碰撞的概率恰好等于它们的 Jaccard 相似度。课程用一个具体的例子（集合 {1,2,3,4} 和 {1,2,3,5}）验证了这一点：用 100 个不同的 MinHash 函数计算，得到的碰撞率正好约等于 0.6——和 Jaccard 相似度一致。

但 MinHash 本身还不够。碰撞概率等于 Jaccard 相似度意味着：即使两个文档相似度高达 0.9，每次哈希碰撞的概率也只有 0.9，重复验证 100 次，其中 10 次可能不碰撞。这种随机性对于真正高效的匹配仍然不够。于是 **局部敏感哈希（LSH）** 登场了。

LSH 的核心思想是通过"与-或"结构来**锐化概率曲线**。具体做法是将 n 个哈希函数分成 b 个波段（band），每个波段包含 r 个哈希函数。一个波段"匹配"指该波段内所有 r 个哈希函数都产生碰撞；两个文档若**至少一个**波段匹配，则判定为碰撞。这个结构创造了一条 S 形曲线：当相似度低于某个阈值时，碰撞概率趋近于零；高于阈值时，概率迅速逼近 1。通过调整参数 b 和 r，你可以精确控制这个相变点的位置和锐利程度。例如，典型的设置包括 b=20, r=450，对应的阈值约为 0.9。

一个值得一提的细节是：C4 数据集采用的去重单元是三句话的跨度。如果两个文档中的三句话完全相同，就删除其中之一。这个做法的副作用是可能破坏文档的连贯性——从文档中间截掉三句话会造成不自然的跳跃。这提醒我们，即使是最基础的预处理步骤，也需要仔细考虑设计权衡。

## 第四站：数据混合——高质量与多样性的平衡艺术

经过过滤和去重，我们得到了干净、高质量但相互独立的数据集。但大型语言模型的训练通常涉及**多个来源的数据**：可能来自 Common Crawl 的通用文本、维基百科的百科条目、GitHub 的代码、学术论文、数学教材等。如何为这些来源分配权重，是数据混合要解决的核心问题。

最朴素的基线方法包括：凭直觉（"vibes"）手动调整，均匀采样，或按 token 数量比例采样。但课程揭示了一个**关键的陷阱**：不同来源的数据量差异可能是三个数量级。假设低质量数据源有 10 万亿 token，高质量数据源只有 100 亿 token。如果采用均匀混合（各占 50%），训练 1 万亿 token，那么低质量数据只被使用 5%（1 万亿 × 50% ÷ 10 万亿），而高质量数据将被**重复训练 50 遍**（1 万亿 × 50% ÷ 100 亿）。这种隐性的高 epoch 数必然导致过拟合——实际上，几个大型模型的训练事故就源于此。

解决方案之一是 UniMax 提出的 **epoch 硬上限**：对每个数据源设置重复训练的最大次数。这意味着，如果一个数据源已经贡献了足够的 token（概率乘以训练总数达到上限），就不再从它采样。这个约束可以被纳入混合方案的优化中。

更系统的方法是**基于回归的混合**（如 RegMix、Olmix）：先训练多个小规模的代理模型（参数规模通常数千万），每个模型使用不同的数据混合权重。然后用回归模型将这些混合权重映射到目标指标（如困惑度、下游任务得分）。最终，优化这个回归函数，找到预测效果最好的混合方案，再将其应用于大规模训练。这个过程本质上是**用便宜的计算搜索最优的超参数空间**——与缩放定律的研究思路一脉相承。

但这种方法有两个"信仰飞跃"：第一，回归模型在最小化器处是否仍然准确？因为你优化它，可能把你推向采样分布之外的极端，而经典泛化理论只承诺分布内的预测质量。第二，最优混合方案能否从 3 亿参数迁移到 700 亿参数？这里存在明显的规模效应——高资源与低资源数据的"最优比例"可能随训练长度变化。课程提出了**模拟 epoching** 的解决方案：按比例下采样所有数据源，使小规模的 epoch 特性与大规模一致。如果你在小规模实验中只用 100 亿 token，而大规模训练是 1 万亿 token，那么将每个来源都缩小 100 倍。这样在小规模优化时，重复训练过高权重的代价就会显现——模型会过拟合，迫使优化算法寻找更平衡的方案。这是一个"让评估环境与实际运行环境尽量一致"的思想，与课程中反复出现的主题（如 muP 的超参数迁移）一脉相承。

## 第五站：后训练与合成数据

数据工作不仅限于预训练阶段。当前端到端的训练流程中，后训练数据的重要性正在快速上升。这里的基本流程是：定义环境（如 GitHub 仓库），定义任务（如修复 bug），从**教师模型**（通常是一个能力强大的模型）获取回复，构成训练数据。在开源社区，这意味着几乎所有的后训练数据都是**合成生成**的。不过，即使是前沿实验室也常采用人机混合的方式——让模型先生成候选，再由人工筛选或修正。

OpenThoughts 是合成数据的一个典型案例。他们从 27 个来源收集问题（包括 StackExchange、NuminaMath 等人类来源，以及合成生成的问题），然后用 QwQ-32B 作为教师模型生成了 120 万个包含推理过程的示例。有趣发现包括：更强的模型未必是更好的教师（QwQ-32B 作为教师优于当时最强的开放模型之一 DeepSeek-R1）；对每个问题采样多个回答（16 个）是有帮助的；但简单的答案过滤并无助益。这说明了高质量合成数据的关键在于**教师模型的选择和生成策略**——生成过程的多样性往往比事后筛选更有效。

SWE-smith 则是针对代码智能体的创新：给定一个真实代码仓库，用语言模型自动生成任务（如引入 bug），然后要求模型修复。用这种方式从 128 个仓库生成了 50K 个任务，构建了一个逼近真实软件开发场景的训练集。SWE-Zero 更进一步，核心观察是：与数学问题不同，软件工程任务有**重依赖问题**——大多数仓库需要安装众多依赖包，且版本过时导致环境搭建是一场噩梦。但实验发现，经过充分训练的模型已经具备了内部的代码语义理解能力，即使不运行代码也能解决很多任务（允许运行得分 80，禁止运行也能达到 70）。基于此，研究者用了 150K 个真实 GitHub PR，生成 30 万个无需执行的智能体轨迹。他们用 Qwen3-Coder-480B 蒸馏，并严格过滤掉那些试图规避"禁止执行"指令的样本。

SWE-rebench 则展示了另一种规模化路径：从 450K 个 GitHub PR 中通过模型评估质量，构建了 21K 个可执行的交互式 Python 任务。最新的工作把 SWE-Zero 的思想扩展到了 1200 万个智能体轨迹，使用更小的模型（mini-coder-1.7b）和更轻量的 agent 脚手架。这些案例清晰展示了合成数据的演进方向：从无环境依赖的数学推理，到有环境依赖的代码修复，最终走向真实的软件开发过程。尽管环境配置是痛苦的，但已经出现了多种绕过或简化环境依赖的策略。

## 本讲在课程体系中的位置

CS336 课程系统性地覆盖了从数据获取、模型架构、训练技术到部署评估的全链路。第 13 讲（数据来源）讨论了数据的**获取渠道**——从 GitHub 等实时服务导出，或从 Common Crawl 爬取，以及由此涉及的版权、服务条款等社会性考量。第 14 讲则围绕**数据质量提升**展开，从单一的"有文本"状态，通过转化、过滤、去重、混合，达到"适合训练的语料库"标准。

这一讲与后续内容的联系同样紧密：数据的质量直接决定了模型能力的上限——好数据可以让小模型（如 phi-1 的 1.5B）在特定任务上超越用 20 倍数据训练的模型。同时，本讲展示的方法论——在小规模上做实验寻找规律，再外推至大规模——与课程前期的缩放定律研究、muP 的参数化策略一脉相承。无论你选择研究哪种模型架构，数据处理的这些基本思想都是通往优秀模型的关键阶梯。

## 结语

回顾整个数据处理流程，课程强调了几个贯穿始终的原则。

其一，**数据的质量评估是相对的、有条件的**。你无法脱离训练目标单独谈论"质量"——想要数学能力就筛选数学数据，想训练英语语种就先用语言识别。最优的过滤阈值、最优的数据混合权重，都取决于你计划的训练长度和可用的算力预算。

其二，**数据处理存在深刻的规模效应**。过滤器的优劣会随训练步数变化，数据混合的"最优"也会随训练数据规模改变。你不仅需要思考"什么是最好的数据"，更需思考"在给定的计算预算下，什么样的数据策略是最优的"。

其三，**算法思想的价值**。MinHash 和 LSH 是来自理论计算机科学的经典技术，却在实际的大规模数据处理中发挥关键作用——它们将 O(n²) 的问题转化为线性时间即可处理的近似查询，在碰撞概率的设计上将随机性变成了可控的工具。这种"用概率换效率"的思维，值得我们反复揣摩。

其四，**动手实验的不可或缺性**。正如课程所说，数据工作高度依赖具体领域，需要逐个查看具体实例才能构建出高质量的数据集。宏观的框架只是起点——真实的数据踩坑、清洗、调优，才是通往好模型的正途。
