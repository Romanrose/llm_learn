## 课程主线

本讲是"数据"主题的第二部分。上一讲讨论了数据的来源：实时服务（如 GitHub）→ 转储/爬取（如 GitHub Archive）→ 处理后的数据（如 The Stack），以及相关的服务条款、版权等社会考量。本讲聚焦数据进入训练之前的技术流水线，分为四个阶段：

1. **转换（Transformation）**：原始 HTML/PDF → 文本
2. **过滤（Filtering）**：从海量原始数据中筛选高质量子集

4. **混合（Mixing）**：确定不同数据源之间的权重分配

最后简要讨论后训练阶段（mid-training + SFT）的合成数据。

## 核心概念

### 一、数据转换（Transformation）

#### 原始数据并非文本

即使你爬取了网页，原始数据也不是以文本形式呈现的。Common Crawl 内部存放的是 HTML，也有 PDF；GitHub 数据则是目录结构。因此第一步是将这些格式转换为模型可用的 token 序列。

#### HTML 到文本的处理

这是转换的主要关注点，因为互联网大部分内容是 HTML。处理方式基本是**基于规则（rule-based）** 的启发式方法：

- **去除样板内容（boilerplate）**：导航栏、广告、页脚、页眉等
- **提取主要内容**：页面的核心文本部分

关键认知：

- **有损过程**：HTML 本质上是层级化的（或渲染后可视化的），而文本是线性的。将 HTML 线性化为 token 序列必然丢失信息
- **表格处理困难**：简单表格可用 Markdown 渲染，但嵌套表格极具挑战，必须近似处理或放弃
- **"内容"的定义模糊**：某些导航元素可能有助于语言模型学习网页结构，因此"什么是内容、什么不是"并不总是清晰

**为什么用规则而非模型？** 两个原因：

1. 规则方法**速度快**，能处理海量数据
2. 这项任务**不需要太多智能**，规则通常足够

但基于规则的方法有一定失败率，所以数据中会存在瑕疵。工具选择会影响准确性——例如在 DCLM 的扩展评估中，Resiliparse 的表现优于其他工具。

#### PDF 处理

PDF 在 Common Crawl 中存在，但只占一小部分。处理有几个额外难点：

- 许多 PDF 因文件过大会被**截断**，需要重新爬取
- 扫描版 PDF 本质是图像，需要用视觉语言模型（VLM）做 OCR——这比纯文本处理昂贵得多
- PDF 从设计上讲是排版格式，**缺乏语义结构**（如 HTML 的 `h1`、`p` 标签），布局信息大量丢失

但 PDF 有独特价值：能费心制作 PDF，通常意味着内容比普通网页更有趣，所以 PDF 的平均质量高于 HTML。这项工作（FinePDFs）由 Hugging Face 完成，从 Common Crawl 提取 PDF，使用 OCR 工具（如 RolmOCR、Docling）转换，并进行大量清理。

### 二、数据过滤（Filtering）

#### 一般框架

过滤是一个通用算法构件：

- 给定**目标数据 T**（通常是一小部分高质量数据）和**海量原始数据 R**（上一步转换得到的全部爬取内容）
- 目标是找到 R 中与 T 相似的子集 T′

**通用方案**：

1. 基于 R 和 T 估计某个模型
2. 推导出评分函数 score(x)
3. 根据得分保留 R 中的样本（可设阈值，有时随机保留）

#### 两类分类器

| 类型 | 方法 | 示例 |
|------|------|------|
| **生成式模型** | 直接在目标数据上估计模型 | KenLM（5-gram 语言模型） |
| **判别式分类器** | 预测文档属于 T 的概率 | fastText（线性分类器/词袋模型） |

判别式方法更常见：以 T 中的样本为正例，从 R 的随机子集取负例（可做平衡），训练分类器，然后对每一篇新文档打分并设阈值。

**关键要求**：

- **能从目标数据泛化**：希望 T 和 T′ 不完全相同
- **极快**：要运行在整个互联网规模的数据上（可达约 100 万亿 token）

#### 过滤类型

**1. 语言识别（Language Identification）**

- 目标：判断文本是否属于特定语言（如英语或德语）
- Meta 的 fastText 语言识别模型是现成工具，支持 176 种语言
- 训练数据来自多语言网站（维基百科、翻译网站、不同语言的新闻站）
- 这是一个相对简单的问题——看几个词就能判断语言，但语码转换、方言等仍存在微妙之处
- Dolma 项目采用 p(English) ≥ 0.5 作为保留标准

**2. 质量过滤：OpenMathText 实例**

该工作目标是从 CommonCrawl 构建大规模数学文本语料库，流程分为多步：

1. 用规则过滤（例如：是否包含 LaTeX 命令）
2. 用 KenLM 在已认证的数学数据集 ProofPile 上训练，保留困惑度低于阈值的样本
3. 训练 fastText 分类器预测是否为数学文本
   - 含 LaTeX 的样本：阈值较低（0.17）
   - 不含 LaTeX 的样本：阈值较高（0.8）

结果：构建了 147 亿 token 的数学语料。论文表明，用这种针对性过滤得到的数据训练模型，数学能力优于用 20 倍量但未过滤数据训练的模型。

**结论**：质量过滤是工具——你可以按任何方式定义质量。若想擅长数学，就收集数学数据。

**3. 质量过滤：GPT-3 与 LLaMA**

- **GPT-3**：正样本来自维基百科、WebText（高赞 Reddit 帖子链接的页面）、书籍；负样本从 CommonCrawl 采样。训练线性分类器，按分数随机保留（`keep = np.random.pareto(9) > 1 - score`）
- **LLaMA**：正样本是被维基百科页面**引用**的网页（而非维基百科文章本身），负样本从 CommonCrawl 采样。保留被分类为正类的文档

**4. 质量过滤：phi-1**

- 原始数据：The Stack 的 Python 子集
- 用 GPT-4 定义了"教育价值"的 prompt，只对 R 的 10 万子集做分类（昂贵但只在子集上做）
- 得到正类集合 T 后，用**随机森林**训练便宜的替代分类器（基于预训练 CodeGen 模型的输出嵌入）
- 最终在 HumanEval 上，用过滤数据训练的 1.3B 模型（36K 步达到 17.68%）胜过直接用原始 Python 子集训练的模型（96K 步仅达 12.19%）

**启示**：你可以用昂贵分类器在小子集上定义"好"数据，然后训练廉价分类器外推到全部数据。

**5. 毒性过滤**

- Jigsaw Toxic Comments 数据集：维基百科讨论页的评论，标注了毒性类型
- 同样的正负样本 + 分类器的框架

#### 过滤的规模依赖效应

**不存在单一最优阈值**。数据过滤的取舍取决于训练规模：

- 训练 **token 数较少**时：想要更高质量的数据（低质量数据无法通过更长训练来弥补）
- 训练 **token 数较多**时：可以容忍更低质量的数据，因为算力充裕不浪费

实验证据（约 1.57 亿参数模型，数据池仅约 100 个词条的极小规模）：在尚未重复使用数据的阶段，高质量数据（DCLM）明显优于无过滤数据（Resiliparse）。但随着训练推进、数据开始重复遍历（epoch），高质量数据的优势缩小——因为每个数据集都有边际收益递减。如果数据有限，训练再久也只是在重复相同的 token。

**实践结论**：无限算力下过滤非必需；现实中大多数人是算力受限的，必须在低质量内容上浪费算力与过滤成本之间做明智权衡。

### 三、去重（Deduplication）

#### 重复的类型

**精确重复（Exact Duplicates）**：

- 镜像网站（镜像的意义就是复制）
- GitHub fork：即使修改，可能只有几个文件不同

**近似重复（Near Duplicates）**：

- 服务条款和许可证（MIT 许可证可能出现在无数页面）
- 同一模板生成的页面，仅替换实体（如"加拿大"→"美国"）
- 排版差异（如逗号的有无）
- 页眉页脚相同

极端案例：C4 数据集中某个产品描述出现了 **61,036 次**——防毒面具描述在 Common Crawl 被反复收录。

#### 为什么去重

1. **训练效率**：减少数据规模且不丢失信息
2. **避免记忆化**：被大量重复的受版权保护内容或隐私信息如果进入训练，模型会记住它们

#### 关键挑战

过滤是**单条目**判断——好坏与否，可线性时间并行化。但去重本质是**条目间比较**。若做 O(n²) 两两比较，无法在网络规模下扩展。因此需要线性时间的哈希方法。

#### 设计空间

1. **去重单元**：句子？段落？文档？
2. **匹配判据**：精确匹配？公共子项存在？公共子项比例？
3. **处理动作**：移除所有实例？保留一个？

#### 精确去重

概念简单：取字符串做哈希，保留每组哈希的一个，删除其余。

- **优点**：简单明确、高精度
- **缺点**：无法处理近似重复
- 实现可用 MapReduce 风格，便于并行扩展

**C4 的做法**：单元是**三句话片段**，做精确匹配，保留一个删除其余。注意：从文档中间删除三句话会破坏文本连贯性——这是当时的权衡。

#### 近似去重

**Jaccard 相似度**：`J(A,B) = |A ∩ B| / |A ∪ B|`

- 取值 [0,1]，0 为不相交，1 为完全相同
- 两文档是近似重复当且仅当 J > 阈值（如 0.99）

**MinHash 的核心性质**：

> 随机哈希函数 h 使得 Pr[h(A) = h(B)] = Jaccard(A, B)

直觉：随机哈希函数诱导元素的随机排列，看排列后 A 与 B 各自第一个元素是否相同。若排列第一个元素属于交集（概率 = J/|A∪B| 的累积），则两者相同；否则不同。

**为什么需要 LSH？** MinHash 的碰撞概率恰好等于 Jaccard——这很好，但这太随机，方差大。我们需要锐化概率：相似度低于阈值时不碰撞，高于阈值时碰撞。

#### 局部敏感哈希（LSH）

**设置**：n 个哈希函数分成 b 个波段，每波段 r 个哈希函数（n = b·r）

**碰撞定义**：A 和 B 碰撞 ⟺ **某个**波段内**所有** r 个哈希值都相同（与-或结构）

**概率计算**：

```
P(某固定波段匹配) = sim^r
P(碰撞) = 1 - (1 - sim^r)^b
```

这是一个 **S 形曲线**（相变）：相似度 < 阈值时碰撞概率低，> 阈值时碰撞概率趋近 1。

**调整 b 和 r 的效果**：

- **增大 r**（波段内哈希函数更多）：阈值变尖锐，曲线**右移**（更难匹配）
- **增大 b**（波段数量更多）：曲线**左移**（更容易匹配）

**相变阈值**：`threshold = (1/b)^(1/r)`。若想按 Jaccard > 0.9 过滤，需让此值等于 0.9。

**实际参数**（去重论文）：n = 9000, b = 20, r = 450。

**为何碰撞概率在阈值处约为常数？** 在阈值处，P(固定波段匹配) = 1/b，碰撞概率 ≈ `1 - (1 - 1/b)^b ≈ 1 - 1/e ≈ 0.64`。

#### 去重的注意事项

- 数据源不断到来——可能单个数据集内部做了去重，但**跨数据集去重**同样必要
- 有时不同数据集之间高度冗余，应做全局去重

### 四、数据混合（Data Mixing）

#### 问题定义

语言模型在多个数据源上训练（如 Wikipedia、Common Crawl、GitHub、书籍等）。数据混合即确定各数据源的**采样分布 p(s)**。

#### 基线方法

| 方法 | 定义 | 问题 |
|------|------|------|
| **拍脑袋（Vibes）** | 凭直觉手动设置 | 主观性极强，但比想象的更常见 |
| **均匀采样** | p(s) ∝ 1 | 忽视数据量差异 |
| **按比例混合** | p(s) ∝ num_tokens(s) | 巨大低质量数据源会吞噬预算；应上调高质量源权重 |

**上调高质量源权重时需要记住两件事**：

1. **多样性**：文学、代码、论文不可直接比较，不应把所有权重放在单一类型
2. **数据源有限性**：对小数据源权重过高会导致重复轮次过多 → 持续训练完全相同的 token

#### 关键陷阱：重复轮次（Epoching）

示例：低质量数据源 10T token，高质量数据源 10B token。均匀混合（各 0.5），训练 1T token：

- 低质量源：`(0.5 × 1T) / 10T = 0.05` 轮——只有 5% 的 token 被看到
- 高质量源：`(0.5 × 1T) / 10B = 50` 轮——每个数据点重复训练 50 次！

**50 轮不一定必要**——最坏情况下过拟合，最好情况下浪费算力。关键教训：**必须检查各数据源实际训练轮数**。

#### 混合的实现方式

按 token 级采样？不。通常做法：采样每个元素所属的混合组件，然后从该组件抽序列填满一个 batch。每个序列属于单一组件，batch 是混合的——目标是减少方差。

#### UniMax（硬上限方案）

- 场景：多语言模型，低资源语言必须特殊处理
- 之前的工作：在按比例混合上取幂 α（使分布更平坦），但仍不够显式
- **UniMax 方案**：均匀采样数据源，但对每个数据源的训练轮数设置**硬上限 C**
  - 约束条件：`p(s) × num_training_tokens ≤ C` 对所有 s
  - 达到上限后无法再获取该源的 token，转向下一个数据源
  - 这是安全网

#### 基于回归的混合（Regression-based Mixing）

**核心思路**（RegMix、Olmix 等）：

1. 在小规模（如 3 亿参数）尝试不同数据混合方案
2. 每种混合训练一个小模型，在某目标指标（下游评估、困惑度）上得到损失
3. 用这些数据点拟合回归模型（输入：混合权重 → 输出：损失）
4. **优化该回归模型**，找到最小化损失的数据混合
5. 将此混合用于大规模训练

这与缩放定律（scaling laws）的研究范式类似——用廉价实验推断大规模设置。

**设计决策**：

- **采样混合方案**：用 Dirichlet 分布（关于分布的分布）
- **回归方法**：线性模型或梯度提升树
- **优化目标**：通常基于下游评估——但**必须小心过拟合**！若评估集全是代码任务，权重会全部偏向代码——当你想生成诗歌时就暴露了。均匀/按比例混合无此风险，因为它们不看下游评估

**两个"信仰跃迁"**：

1. **回归模型在极小值处仍然准确**：随机采样的混合在分布内预测没问题，但优化时会走向极值区域，可能缺少覆盖。需要小心
2. **最优混合从小规模迁移到大规模**：目前开放社区的经验表明大致成立，但存在规模相关效应——例如更长的训练会使低质量数据变得可容忍

#### 模拟重复轮次（Simulated Epoching）

**问题**：如果小规模训练（token 数少）时没有重复轮次，而大规模训练时有，则小规模实验的最优混合严重偏向高质量小数据源，不适用于大规模。

**解决方案**：让"小规模看起来像大规模"（这是整个课程的主题——如 muP 也在做类似的事）。

具体做法：按**下采样比例**缩小各数据源。如小规模 10B token、大规模 1T token，比例 1:100。在缩小后的混合上，反复"只训练维基百科"的方案会暴露为高重复轮次、差损失，于是优化自然偏向更平衡的方案。**在小规模模拟大规模会遇到的数据稀缺性**。

#### 数据混合的粒度

除了跨数据源混合，还可对单一数据源（如 Common Crawl）细分：按领域（用网路组织工具分组）和按质量形成二维网格，每格是一个混合组件。Nemotron 论文正是这样做的。

### 五、后训练数据与合成数据

#### 一般配方

1. 定义一组**环境**（如代码场景中的 GitHub 仓库）
2. 定义一组**任务/提示**
3. 从**强模型（教师）** 收集回复

几乎所有开源社区的后训练数据大部分是合成生成的。前沿机构可混合使用人工标注，但成本极高。教师模型的能力是瓶颈。

#### OpenThoughts（推理/数学科学）

- 背景：o1 模型激发了对推理能力的关注
- 用 QwQ-32B（非最强模型！）生成 120 万个示例（约 7.5 万个问题 × 16 个采样）
- 来源：27 个人类与合成来源（Stack Exchange、NuminaMath、化学等）
- 关键发现：
  - **更强≠更好的教师**：QwQ-32B 作为教师优于当时最强大的 DeepSeek-R1
  - **多采样有帮助**：每个 prompt 采样 16 个回复比少采样好
  - **答案过滤无用**
  - **少而精的来源优于大而杂**：利用较少的高质量来源（如 OpenMath-2-Math）胜过用所有来源

#### 编码智能体数据

**SWE-smith**：

- 给定仓库，用语言模型生成任务（通过修改代码引入 bug）
- 128 个 GitHub 仓库生成 5 万个任务

**SWE-Zero**（NVIDIA）：

- 观察：SWE 任务依赖极重（要安装依赖、环境过时），但强模型即使**不执行代码**也能解决约 70% 的任务（有执行时约 80%）——模型对代码有内部语义理解（"world model"）
- 不用 Docker 镜像，直接生成 30 万条智能体轨迹（来自 15 万真实 GitHub PR）
- 使用 OpenHands 脚手架；**防止作弊**：移除未来 git 提交防止 agent 通过 git 历史获取答案；禁止执行 Python，只能用 grep/set 等
- 从 Qwen3-Coder-480B 蒸馏，并做过滤（Qwen 有时忽略指令仍执行）

## 关键公式与原则

### MinHash 核心性质

```
Pr[h(A) = h(B)] = Jaccard(A, B)
```

### LSH 碰撞概率

```
P(固定波段匹配) = sim^r
P(碰撞) = 1 - (1 - sim^r)^b
```

### LSH 相变阈值

```
threshold = (1/b)^(1/r)
```

### 数据混合的重复轮次检查

```
source_epochs = (p(s) × train_tokens) / num_tokens(s)
```

如果该值远大于 1，意味着该数据源被反复训练——需警惕过拟合。

### UniMax 约束

```
p(s) × num_training_tokens ≤ C   （对所有数据源 s）
```

## 课程作业关联

- 作业中可能需要实现或评估过滤/去重流程——记住**先用小子集做原型**，再扩展到全量
- LSH 参数（b、r）的选择取决于你想要锐化的相似度阈值：`threshold = (1/b)^(1/r)`
- 若你的作业涉及多源数据训练，务必在合并前计算各源的**有效训练轮数**
- 小规模实验的混合方案推导到大规模型时，考虑模拟重复轮次（按比例下采样各源）

## 常见误区

1. **认为存在普适的"高质量"定义**：质量因目标而异。数学、代码、文学是不可比对象
2. **忽略重复轮次**：给定混合后直接训练，直到过拟合才发现某个小型高质量源已被训练了几十轮
3. **在小规模调出混合方案后直接用于大规模**：小规模（无重复轮次）与大规模（有重复轮次）的最优混合不同
4. **LSH 中以为碰撞就是最终答案**：MinHash 碰撞只是初步候选，仍需后续确认（如直接计算 Jaccard）来过滤假阳性
5. **在回归混合中过拟合下游评估集**：评估集中代码任务多 → 所有权重偏向代码 → 模型失去通用性
6. **假设更强的教师模型一定产生更好的合成数据**：OpenThoughts 证明 QwQ-32B 优于当时最强的 DeepSeek-R1
7. **忘记跨数据集去重**：单数据集内部去重"看似做了"，但数据集之间可能高度冗余
8. **基于规则的处理有 100% 成功率**：即使规则方法很快，也会在数据中留下瑕疵
