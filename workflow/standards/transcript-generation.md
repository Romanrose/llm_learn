# 课程逐字稿生成规范

版本：1.0
适用范围：本仓库内所有课程视频、公开演讲和技术访谈的 Markdown 逐字稿。

本规范以 `CS336 2026 / Lecture 04` 的成稿形式为主要范本：保留来源说明和段落级时间戳，将连续字幕合并为自然段，只修正明显的断句、重复、语序和术语错误，不把逐字稿润色成脱离原讲述的文章，也不压缩成课程摘要。在此基础上，增加统一的来源记录、文件命名、翻译边界和质量门禁。历史整理稿可以保留已有内容，但必须在 `sources.yaml` 和 `review.yaml` 中明确标记缺失的原语言稿或时间轴异常。

## 1. 目标与非目标

逐字稿的目标是形成一份可以回听、检索、校对和继续生成 Lecture Note、Blog、PDF 的可信中间文本。

逐字稿必须：

- 完整保留讲者的论证顺序、例子、提问、回答和课堂互动。
- 能通过段落时间戳回到原视频核验。
- 明确记录视频、字幕语言、字幕类型、处理方式和审核状态。
- 保留重要英文术语、缩写、模型名、论文名和代码标识符。
- 将事实性整理与内容重写严格分开。

逐字稿不是：

- 课程摘要、Lecture Note 或 Blog。
- 对讲者观点的补充解释或事实纠错文章。
- 为了“读起来更专业”而重新创作的演讲稿。
- 删除课堂口语、失败尝试和问答后的精简讲义。

## 2. 数据位置与文件命名

每个 Lecture 使用 catalog 中的完整 ID：

```text
<category>/<course-id>/notes/<lecture-id>/
├── sources.yaml
├── generation.yaml
├── review.yaml                 # 完成人工审核时创建
├── transcript.en.md
├── transcript.zh-CN.md
├── note.md
├── blog.md
├── references/
└── assets/
```

规则：

- 原语言逐字稿命名为 `transcript.<语言标签>.md`。
- 中文简体统一使用 `transcript.zh-CN.md`，英文使用 `transcript.en.md`。
- 语言标签采用 BCP 47 风格，不使用 `_zh`、`_en` 或重复 Lecture 编号的旧命名。
- 原始字幕、补充视频逐字稿和历史稿放在该 Lecture 的 `references/`。
- 图片、截图和其他附件放在 `assets/`。
- 临时音频、视频、字幕下载件和模型缓存默认放临时目录，不提交到 Git。
- PDF、XeLaTeX 和其他派生产物写入课程的 `exports/`，不与逐字稿混放。

## 3. 来源优先级与授权边界

按以下顺序选择输入，找到可用来源后停止降级：

1. 官方人工字幕。
2. 平台提供的人工字幕。
3. 官方或平台自动字幕。
4. 课程方提供的逐字稿文件。
5. 本地 ASR 音频转写。

默认只获取字幕，不下载视频或音频。只有视频没有可用字幕，并且用户明确授权后，才允许提取音频并运行本地 ASR。

不得绕过私密权限、付费墙、DRM、地区限制或验证码。需要登录态时，必须取得当次授权；Cookie 不写入仓库、日志、命令参数示例或生成文档。

## 4. 标准生成流程

### 4.1 确认课程身份

开始前确认：

- `course-id` 与 `lecture-id`。
- 官方课程页和视频链接。
- Lecture 标题、讲师、日期和顺序。
- 目标语言和是否需要保留英文对照稿。

课程目录和 Lecture 目录必须已经在 catalog 中存在或能够唯一确定。不能只用“第 4 讲”推断保存位置。

### 4.2 探测字幕

记录所有可用字幕轨道的语言、人工/自动类型和来源，按来源优先级选择一条主字幕。技术课程优先保留原语言字幕，再从原语言生成中文稿。

字幕可用时：

```text
视频 → 字幕提取 → 格式解析 → 去重与断句 → 原语言逐字稿
```

无字幕且已获授权时：

```text
视频 → 临时音频 → 本地 ASR → 去重与断句 → 原语言逐字稿
```

无字幕且未获授权时，只更新 `sources.yaml` 和 catalog 状态为 `needs-audio-authorization`，不得自行下载音频。

### 4.3 生成原语言逐字稿

先形成可核验的原语言逐字稿，再生成翻译稿。清洗动作仅限于：

- 删除字幕序号、VTT/SRT 时间范围、HTML 标签和位置标记。
- 合并相邻且语义连续的字幕片段。
- 删除自动字幕造成的完全重复和明显的滑窗重叠。
- 修复显然错误的断句、大小写和标点。
- 依据课程讲义修正能够确认的模型名、人名和技术术语。
- 将一个完整论述合并成自然段，并保留该段第一条字幕的起始时间。

不得：

- 摘要、删减论证或省略问答。
- 添加字幕和讲义中没有的解释、结论、公式或引用。
- 为了语言流畅而改变讲者立场、因果关系或不确定语气。
- 静默修正讲者的事实错误；必要时使用简短编者注，并在 `review.yaml` 留痕。
- 把听不清的内容凭常识补全。无法确认时标记 `[听不清]` 或 `[术语待核]`。

### 4.4 生成中文翻译稿

中文稿必须以原语言逐字稿为唯一主文本，视频和讲义只用于校对，不直接参与扩写。

翻译要求：

- 不摘要、不删减、不补写。
- 保持原段落顺序和时间戳。
- 保留问答、玩笑、停顿说明和课堂互动，只删除不承载意义的机械重复。
- 首次出现的重要术语可写为“中文（English, Abbreviation）”，后续使用通行中文或缩写。
- 模型名、论文名、函数名、变量名、库名和命令通常保留英文。
- 公式不得根据口述自行推导；只有讲义或画面能够确认时才整理为 LaTeX。
- 对无法确认的专名使用 `[术语待核：原文]`，不得用相似词强行替换。

长视频允许分块翻译，但必须：

- 只在自然段边界切分。
- 为每块保留前后少量上下文或术语表。
- 按原顺序合并，不重复块边界内容。
- 合并后执行全文术语一致性和覆盖率检查。

## 5. Markdown 排版规范

### 5.1 文件头

逐字稿使用以下最小模板；中文翻译稿沿用同一结构：

```markdown
# CS336 Lecture <序号>：完整中文逐字稿

- 视频：[官方视频](<url>)
- 来源：<字幕或音频来源>；保留段落起始时间戳，只修正明显的断句、重复和语序
- 说明：这是逐字稿，不是讲义摘要；相邻且语义连续的片段已合并为阅读段落；术语按课程约定保留必要英文

---

## 正文

[00:04] 第一段正文……
```

文件头必须说明来源和处理程度。不能只写“整理自网络”，也不能把自动字幕写成官方人工字幕。

### 5.2 时间戳

- 每个自然段只保留一个起始时间戳。
- 优先使用 `[MM:SS.xx]`；超过一小时使用 `[HH:MM:SS.xx]`。没有毫秒时使用 `[MM:SS]` 或 `[HH:MM:SS]`。
- 如果原始字幕提供毫秒，保留原始精度并在同一文件中统一；不要因为翻译或段落合并重新估算时间。
- 时间戳必须对应原文段落的首条字幕，中文稿必须继承对应英文段落的时间戳。
- 如果来源字幕本身出现时间戳倒序，不要为了形式重排正文；记录异常并提交人工复核。
- 时间戳对应段落第一句在视频中的真实起始位置，不能使用翻译或合并完成后的估算时间。
- 不把每句字幕或每个 ASR 切片单独排成一行。

### 5.3 段落

- 以完整语义段为单位，一般为 3–8 句。
- 建议每段约 150–800 个中文字符；技术公式、代码讲解和短问答可以更短。
- 话题转换、讲者切换、课堂提问或明显长停顿时另起一段。
- 同一论点被字幕切成多个碎片时应合并；不同论点不能为了减少段落而强行合并。
- 段落之间保留一个空行。

### 5.6 逐字稿与讲义/文章的边界

- `transcript.en.md` 与 `transcript.zh-CN.md` 是可回听、可对照的完整逐字稿，保留段落时间戳、课堂互动、例子和必要的口语表达。
- `note.md` 是讲义型整理，可以重组概念、公式、结论、误区和练习，不需要逐段时间戳。
- `blog.md` 是面向读者的独立文章，可以重新组织叙事和补充解释，不需要逐段时间戳。
- Note 和 Blog 可以引用视频链接，但不能伪装成逐字稿，也不要求复制逐字稿的段落时间轴。

### 5.4 说话人和非语言信息

- 单讲者课程默认不重复标注讲者。
- 多讲者访谈或课堂问答使用 `**讲师：**`、`**学生：**`；身份未知时用 `**提问者：**`。
- 只保留影响理解的非语言信息，例如 `[笑声]`、`[展示代码]`、`[播放演示]`。
- 背景噪声、无意义停顿和每一次语气词不需要逐项标注。

### 5.5 术语、公式与代码

- 为每门课程维护统一术语表；同一术语不得在一篇稿件中反复更换译法。
- `attention`、`MoE`、`router`、`KV cache` 等没有必要强译时保留英文。
- 代码、变量、命令和文件名使用反引号。
- 行内公式使用 `$...$`，块级公式使用 `$$...$$`。
- 公式只在证据充分时录入；不确定的口述公式保持文字描述并标记待核。

## 6. 来源与生成记录

`sources.yaml` 至少记录：

```yaml
schemaVersion: 1
course: cs336-2026
lecture: lecture-04
video:
  title: <官方标题>
  url: <视频 URL>
  durationSeconds: <时长>
caption:
  state: extracted
  kind: manual | auto | asr
  language: en-US
  transcript: llm/cs336-2026/notes/lecture-04/transcript.en.md
  processor: video-subtitle-transcript | qwen3-asr | faster-whisper
```

`generation.yaml` 记录翻译输入、输出、生成工具、分块数量和审核状态。来源文件路径必须使用仓库相对路径，不能写个人机器的绝对路径。

## 7. 质量门禁

逐字稿进入 `reviewed` 或 `published` 前必须通过以下检查。

### 7.1 自动检查

- 文件存在且非空。
- Markdown 标题、来源区、正文标题和时间戳齐全。
- 时间戳可以解析；若来源本身倒序，必须列入人工复核，不得静默重排正文。
- 不存在相邻完全重复段落或高相似度滑窗重复。
- 第一条时间戳接近视频开头，最后一条时间戳合理接近视频结尾。
- 不存在无解释的超长时间缺口；默认将超过 5 分钟的缺口列为人工复核项。
- catalog、`sources.yaml`、`generation.yaml` 中的路径全部存在。
- 中文翻译不能出现明显截断；可结合原文段落数、结尾时间戳和字符长度比例判断，不能只依赖字符数。
- 不包含 Cookie、临时目录、用户绝对路径或下载令牌。

候选稿使用 `course validate <course-id> <lecture-id> --provider <provider>` 检查；已经登记到 catalog 的正式稿使用 `course validate <course-id> <lecture-id> --published` 检查。两者不能混用：候选稿必须有完整的原语言输入，历史正式稿可以在明确警告的前提下缺少原语言逐字稿。

### 7.2 人工抽查

至少抽查：

- 开头、结尾各 2–3 分钟。
- 每 15–20 分钟一个随机片段。
- 所有公式、数字、模型名、人名和论文名密集片段。
- 课堂问答和讲者切换位置。
- ASR 低置信度、`[听不清]`、`[术语待核]` 标记附近。

人工审核重点是完整性、术语、数字、否定关系和因果关系，不需要把口语改造成书面论文。

### 7.3 Lecture 04 暴露出的必要检查

Lecture 04 证明段落级时间戳和轻度清洗适合长技术课程，但也说明生成后必须额外检查：

- 合并字幕片段后可能出现时间戳倒序。
- 自动字幕滑窗可能产生重复或近重复段落。
- ASR 加机器翻译的两阶段误差可能把技术词误译成普通词。
- 长视频分块翻译可能在边界处重复、遗漏或改变术语译法。

因此，Lecture 04 的成稿形式是本规范的排版参考，不是无需复核的质量基准。

## 8. 状态流转

推荐状态：

```text
source-discovered
  → subtitle-ready / needs-audio-authorization
  → transcript-source-ready
  → transcript-draft
  → transcript-reviewed
  → published
```

- `source`：直接提取的原语言字幕稿，尚未人工校对。
- `draft`：已清洗或翻译，但仍需核对。
- `reviewed`：通过自动门禁和人工抽查。
- `published`：已在 catalog 的 `outputs` 中登记并通过网站构建。

如果某一讲来自历史整理稿，`published` 不代表具备完整的中英对照证据；必须从 `sources.yaml` 的 `sourceState: historical` 和 `review.yaml` 的 `warnings` 中看到具体限制。

逐字稿默认 `searchable: false`，Lecture Note 和 Blog 才是网站搜索与阅读的主要入口。

## 9. 标准任务提示词

```text
为 <course-id> 的 <lecture-id> 生成完整逐字稿。

1. 优先使用官方人工字幕，其次自动字幕；没有可用字幕时停止并请求音频下载授权。
2. 先保存原语言逐字稿，再生成 transcript.zh-CN.md。
3. 参考 Lecture 04 的成稿形式：保留段落起始时间戳，连续语义片段合并为阅读段落，不逐句或逐 cue 换行。
4. 中文翻译保持原段落顺序和时间戳，不摘要、不删减、不扩写；只修正明显断句、滑窗重复、标点和能够确认的术语错误。
5. 逐字稿保留必要的英文术语、课堂互动和口语信息；Note 和 Blog 另行组织，不继承逐字稿时间轴。
6. 按 workflow/standards/transcript-generation.md 执行来源记录和质量检查。
7. 完成后报告字幕来源、生成文件、待核术语、时间戳异常、重复检测和人工抽查结果。

视频：<url>
目标目录：<category>/<course-id>/notes/<lecture-id>/
```

## 10. 完成定义

一次逐字稿任务只有同时满足以下条件才算完成：

- 原始来源和授权状态明确。
- 文件保存到完整课程 ID 和 Lecture ID 对应目录。
- 原语言稿和目标语言稿按需要生成。
- `sources.yaml`、`generation.yaml` 和 catalog 路径一致。
- 自动质量门禁通过，必要的人工抽查有记录。
- 所有待核内容显式标记，没有用猜测替代证据。
- VitePress 构建不产生该逐字稿相关的死链。
